Chapter 28

Transport Layer

IP gets a packet to the right computer. But a computer runs many programs at once (a browser, a mail client, a game), and the data has to reach the right one. That is the transport layer's job. It labels every piece of data with a 16-bit port number that identifies the program, and it offers two styles of delivery: TCP (reliable, ordered, connection-oriented) and UDP (fast, connectionless, no guarantees). Chapters 29–31 cover each in detail.

28.0Three Kinds of Delivery

🎓 From the lecture The fourth floor, just above the network layer: the transport layer, which talks in even more detail. The network layer did host-to-host (source-to-destination) delivery. The transport layer goes one step further: end-to-end delivery.
Students often think end-to-end and source-to-destination are the same; they are not. End-to-end delivery = port-to-port delivery (port numbers come in here); source-to-destination = host-to-host; and the DLL did hop-to-hop / node-to-node. Know all three variations.

28.1Process-to-Process Delivery and Port Numbers

🎓 From the lecture A host on network 1 and a host on network 2 each run many processes / applications. Which application on this host should talk to which application on that one? Each process is identified uniquely by a port number. Say the processes on host 1 have ports 1, 2, 3, 4 and on host 2 ports 5, 6, 7, 8: we want data from process 3 on host 1 to reach process 7 on host 2. This is port-to-port or process-to-process delivery, and the transport layer is responsible for it.
Also note: the transport layer's checksum / error control works end to end, not hop to hop.
➕ Why end-to-end error control too? The DLL's CRC checks each link, but a packet can still be damaged inside a router (in memory, between links). Only a check made by the two end hosts catches that, the "end-to-end argument". TCP and UDP checksums cover the header, the data, and a pseudo-header containing the source and destination IP addresses.

28.2TCP vs UDP: Basic Overview

🎓 From the lecture We'll compare TCP and UDP in detail later; for now the basics.
• TCP: more reliable, receives packets in order, connection-oriented.
• UDP: connectionless, unreliable, packets may arrive out of order at the destination.

28.3Port Number Ranges (Well-known, Registered, Dynamic)

🎓 From the lecture A port number is a 16-bit number, so it ranges from 0 to about 65 535. The division into categories is made by IANA (Internet Assigned Numbers Authority):
• 0 – 1023: well-known ports, e.g. DNS 53, POP3 110, FTP 20 (data) and 21 (control), SMTP 25, HTTPS (with SSL) 443.
• 1024 – 49 151: registered ports, the biggest range: registered with IANA but not controlled by it.
• 49 152 – 65 535: dynamic (private) ports: neither registered nor controlled by IANA; used for temporary communications that need a port only for a moment ("kaam chalao").
⚠️ Exam traps The exact boundaries are 1023 / 1024 and 49 151 / 49 152, top 65 535. FTP uses two ports: 21 = control (commands), 20 = data. Well-known ports are used by servers; a client picks a temporary ephemeral port for its side of each connection.

28.4Socket Address

🎓 From the lecture A socket address is just the combination IP address + port number, e.g. 200.23.56.8 : 20 (an FTP-data socket). Just as we have MAC addresses, IP addresses and port numbers, know what a socket address is.
socket address = IP address : port e.g. 200.23.56.8:20 connection (TCP) = (client IP, client port, server IP, server port) ← socket pair, 4-tuple + protocol ← 5-tuple
➕ Why the pair matters A web server listens on one socket (e.g. 93.184.216.34:443), yet serves thousands of clients at once. Each connection is told apart by the whole socket pair: the clients differ in IP and/or ephemeral port. In programming, a "socket" is the OS object (the API endpoint) bound to such an address.

➕ Other transport protocols SCTP (Stream Control Transmission Protocol): message-oriented, reliable, multi-streaming and multi-homing; used in telecom signalling. QUIC: a modern reliable protocol built on UDP, used by HTTP/3. Exams mostly stick to TCP and UDP.

Solved questions Q1. Size of a port number and its range? 16 bits, 0 – 65 535.

Q2. Which range is called well-known? 0 – 1023. Dynamic/ephemeral? 49 152 – 65 535.

Q3. Who assigns well-known ports? IANA.

Q4. What is a socket address? IP address + port number.

Q5. Which delivery does the transport layer provide? Process-to-process (port-to-port, end-to-end). The network layer? Host-to-host. The DLL? Node-to-node.

Q6. Which port does HTTPS use? 443. SMTP? 25. DNS? 53. POP3? 110.

Q7. Data unit of the transport layer? Segment (TCP), user datagram (UDP).
🎯 IBPS exam alert Port numbers are among the most-asked one-liners in IT officer exams: memorise 20/21, 22, 23, 25, 53, 67/68, 80, 110, 143, 161, 443, and which ones run over UDP (DNS, DHCP, TFTP, SNMP, NTP, RIP).

  • Port number picks the process (lecture: process 3 on host 1 → process 7 on host 2). Transport checksum works end to end.
  • TCP: reliable, in order, connection-oriented. UDP: connectionless, unreliable, may be out of order. Flow and congestion control live here (TCP).
  • Port = 16 bits, 0–65 535 (IANA): 0–1023 well-known · 1024–49 151 registered · 49 152–65 535 dynamic/private.
  • DNS 53, POP3 110, FTP 20 data / 21 control, SMTP 25, HTTPS 443, HTTP 80.
  • Socket address = IP + port; a connection = socket pair (4-tuple).
  • Duties: multiplexing/demultiplexing, segmentation, connection, flow, error and congestion control.
