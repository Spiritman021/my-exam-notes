Chapter 15

Ethernet (IEEE 802.3)

Everything from the last few chapters comes together here. Ethernet is a real data link layer protocol: it uses a shared bus (chapter 4), CSMA/CD (chapter 12), Manchester encoding (chapter 8) and a CRC trailer (chapter 14). The exam favourite is the frame format: know every field's size and job, and why the frame must be between 64 and 1518 bytes.

15.1Characteristics of Ethernet

🎓 From the lecture
  • Topology: bus. A multipoint connection: one backbone link (a shared channel) with every host station attached to it.
  • Access control: CSMA/CD. Obvious, because it is a bus and CSMA/CD is the wired method; Ethernet is wired.
  • No acknowledgement. Ethernet does not send ACKs for frames.
  • Encoding: Manchester. (Of Manchester and Differential Manchester, Ethernet uses Manchester.)
  • Data rates: 10 Mbps is the normal, common one; 100 Mbps is Fast Ethernet; 1 Gbps is Gigabit Ethernet.
FeatureClassic Ethernet
IEEE standard802.3 (802.5 = Token Ring, 802.11 = Wi-Fi)

➕ Points the lecture skipped Ethernet was developed at Xerox PARC (Bob Metcalfe, 1973) and standardised by DEC–Intel–Xerox (DIX) and then IEEE as 802.3. Its service is connectionless and unreliable: a damaged frame is dropped and recovery is left to higher layers (TCP). CSMA/CD backoff: after the n-th collision a station waits a random K × 512 bit times, K ∈ {0 … 2min(n,10) − 1}; it gives up after 16 attempts.
⚠️ Exam trap Manchester is only for 10 Mbps Ethernet. Fast Ethernet (100Base-TX) uses 4B/5B + MLT-3, and Gigabit Ethernet uses 8B/10B (1000Base-X) or PAM-5 (1000Base-T). If the question says "classic/standard Ethernet", answer Manchester.

15.2Drawbacks: Real-Time and Interactive Applications

🎓 From the lecture Ethernet performs poorly for two kinds of applications:
1. Real-time applications. In real time the deadline is everything; missing it can have disastrous consequences. But Ethernet is a shared bus, several stations want to transmit, collisions keep happening, and every collision adds delay. With unpredictable delay, you can never promise to meet a deadline.
2. Interactive applications. These are known for sending very small amounts of data. But an Ethernet frame has a minimum size of 64 bytes; you cannot send less. So small interactive messages do not fit well either ("iski daal nahi gal paayegi").
➕ Exam wording Classic Ethernet is non-deterministic: CSMA/CD gives no upper bound on access delay, and there are no priorities. That is why Token Ring (802.5) and Token Bus (802.4), which have bounded, predictable access, were preferred for real-time and factory use (next chapters). Small payloads must be padded up to 46 bytes, which wastes bandwidth.

15.3Ethernet Frame Format

🎓 From the lecture Field by field, in bytes: Preamble 7 · SFD 1 (Start Frame Delimiter) · Destination address 6 · Source address 6 · Length 2 · Data · CRC 4. As said in chapter 14, the CRC sits at the very end, in the trailer (tail).
🎯 IBPS exam alert Memorise the order P – S – D – S – L – D – C ("Please Send Data Safely, Later Don't Crash") and the sizes 7-1-6-6-2-(46…1500)-4. The destination address comes before the source address (the reason is in 15.5).

15.4Preamble and Start Frame Delimiter (SFD)

🎓 From the lecture Preamble = a run of alternating 1s and 0s (1010…) for 7 bytes = 56 bits.
SFD = 1 byte. Its first 6 bits carry on the same 10 pattern, but the last two bits are 11: 10101011. That 11 says "this is the beginning of the frame". The two are often lumped together as one 8-byte field because they do the same job: announce to everyone that a frame is coming on the link.
Railway-station analogy: the preamble is the platform announcement ("train XYZ is arriving on platform N"). The SFD is the loud horn when the train is right at the platform: the last warning. Get ready, synchronise yourself with the frame, step off the tracks!
Preamble : 10101010 10101010 10101010 10101010 10101010 10101010 10101010 (7 bytes = 56 bits) SFD : 10101011 (1 byte, ends in 11)
➕ Why it is needed The alternating pattern produces a regular square wave, so the receiver's clock can lock on (bit synchronisation). The 11 at the end of the SFD gives frame (byte) synchronisation: the next bit is the first bit of the destination address. Both are added by the physical layer, so they are not counted in the 64–1518-byte frame size.

15.5Destination and Source Address Fields

🎓 From the lecture 6 bytes = 48 bits each. In the DLL, "address" means the MAC address. Example: station A sends to station C, so source = A and destination = C.
On a bus everyone gets alerted that a frame is coming ("the train is coming"). But only the valid recipient receives and reads it. Each station first checks the destination address: B sees "C? not for me, drop it"; C sees "C, that's me", accepts and reads it; D drops it.
Look how cleverly the fields are ordered: the destination comes first, so the other stations can discard the frame before even reaching the source address.
➕ Address types (more in chapter 16) The destination can be unicast (one station), multicast (a group; the least significant bit of the first byte = 1) or broadcast (FF:FF:FF:FF:FF:FF, all stations). The source is always unicast.

15.6Data Field: Minimum and Maximum Size

🎓 From the lecture Data field: minimum 46 bytes, maximum 1500 bytes. Where do these come from? Two universal facts about Ethernet: the minimum frame is 64 bytes and the maximum frame is 1518 bytes. Remove everything that is not data, the 18 bytes of overhead (6 + 6 + 2 + 4):
• 64 − 18 = 46 bytes minimum data
• 1518 − 18 = 1500 bytes maximum data
So you derive ("retrieve") the data range from the frame size.
➕ Padding and MTU If the upper layer hands down less than 46 bytes, the MAC layer adds padding bytes to reach 46. 1500 bytes is Ethernet's MTU (Maximum Transmission Unit), the largest IP packet it can carry without fragmentation (chapter 22). Jumbo frames (non-standard, up to ~9000 bytes) are used inside data centres.
⚠️ Exam trap "Minimum frame size" = 64 bytes, "minimum data/payload" = 46 bytes. "Maximum frame size" = 1518 bytes (1526 if you include the preamble + SFD; 1522 with an 802.1Q VLAN tag), "maximum data" = 1500 bytes. Read which one is asked.

15.7Length Field

🎓 From the lecture As the name says: a 2-byte field that tells the length. 2 bytes = 16 bits, so it can hold 2¹⁶ different values, i.e. 0 to 65 535.
➕ Length vs Type (Ethernet II) In IEEE 802.3 the field gives the length of the data field in bytes (so in practice ≤ 1500). In the older DIX / Ethernet II format the same 2 bytes are a Type (EtherType) that names the upper-layer protocol: 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6. Rule: a value ≤ 1500 is a length; a value ≥ 1536 (0x0600) is a type. Almost all traffic today uses the Ethernet II (Type) form.
⚠️ Exam trap The range of a 16-bit field is 0 to 2¹⁶ − 1 = 65 535 (65 536 values). Don't write 65 534 or 65 536 as the maximum.

15.8Why 64 Bytes? CSMA/CD and Minimum Frame Size ADDED

Rule: for CSMA/CD to work, a station must still be transmitting when news of a collision gets back to it. So the transmission time must be at least the round-trip propagation time: Tt ≥ 2Tp, i.e. Lmin = 2 × Tp × B.
Where 64 bytes comes from Classic 10 Mbps Ethernet allows a maximum network span of about 2500 m (with repeaters). The worst-case round trip including repeater delays was budgeted at 51.2 µs.
Lmin = 51.2 × 10⁻⁶ s × 10 × 10⁶ bps = 512 bits = 64 bytes. That 512-bit time is called the slot time.
➕ Consequences If you raise the speed 10× (Fast Ethernet) with the same 64-byte frame, the maximum collision domain shrinks about 10× (to ~200 m). Gigabit Ethernet in half-duplex used carrier extension (512-byte slot) to keep a usable span. Modern switched Ethernet is full-duplex: each link has its own collision-free path, so CSMA/CD is effectively switched off. The 64-byte minimum is kept for compatibility.

15.10Solved Questions ADDED

Solved questions Q1. An application sends 20 bytes of data in one Ethernet frame. How many pad bytes, and what is the frame size?
Pad = 46 − 20 = 26 bytes; frame = 14 + 46 + 4 = 64 bytes.

Q2. Maximum efficiency (data/frame) of a full-size Ethernet frame, excluding preamble?
1500 / 1518 ≈ 98.8%. Of a minimum frame carrying 46 bytes: 46/64 ≈ 71.9%.

Q3. A CSMA/CD LAN runs at 1 Gbps over 1 km of cable with v = 2 × 10⁸ m/s. Minimum frame size?
Tp = 10³ / (2 × 10⁸) = 5 µs; L = 2 × 5 × 10⁻⁶ × 10⁹ = 10 000 bits = 1250 bytes.

Q4. Total bits on the wire for a maximum frame including preamble and SFD?
1518 + 8 = 1526 bytes = 12 208 bits.

Q5. The 2-byte field reads 0x0800. Length or type?
0x0800 = 2048 ≥ 1536 → it is a Type: IPv4.

⚡ Rapid Revision — Chapter 15

  • Ethernet = IEEE 802.3: bus topology, CSMA/CD (wired), no ACK, Manchester (10 Mbps only), 48-bit MAC, CRC-32.
  • Speeds: 10 Mbps standard · 100 Mbps Fast Ethernet (802.3u) · 1 Gbps Gigabit (802.3z/ab) · 10 Gbps (802.3ae).
  • Bad for real-time (collisions → unpredictable delay → deadlines missed) and interactive apps (min 64-byte frame for tiny messages).
  • Frame: Preamble 7 · SFD 1 · DA 6 · SA 6 · Length 2 · Data 46–1500 · CRC 4.
  • Preamble = 56 alternating bits (train announcement, clock sync). SFD = 10101011 (the horn: last warning; frame starts). Not counted in frame size.
  • Destination first, so other stations can drop the frame early. Only the matching MAC reads it.
  • Frame 64–1518 bytes; overhead 18; data 46–1500 (pad if less; 1500 = MTU).
  • Length field 16 bits → 0–65 535. Ethernet II reads it as Type when ≥ 1536 (0x0800 IPv4, 0x0806 ARP).
  • 64 bytes = 512 bits = slot time, from Tt ≥ 2Tp → Lmin = 2·Tp·B.
