Chapter 1

Introduction to Computer Networks

This is the opening chapter of the Computer Networks volume. Before going layer by layer through the OSI model, the lecture "learns the work from the name": what a network is, what devices sit on it, the rules they follow (protocols), how each one is identified (IP, MAC, port), how names become addresses (DNS), and the two basic ways of organising a network (client-server and peer-to-peer).

1.0How This Subject Is Organised

🎓 From the lecture The whole story of Computer Networks is divided into the 7 layers of the OSI model. The lecture goes layer by layer through each one's functions, roles, responsibilities, concepts and terms. First come some prerequisites and basic terminology, which are needed for every later concept. "Start from the beginning with me."

1.1What is a Computer Network

Computer network: a group of interconnected devices (nodes), linked through wired or wireless media, that can communicate and exchange data and share resources (hardware and software) by following common rules (protocols).
🎓 From the lecture — "Network is the new net worth" Elders used to say "hard work karo". Then came "smart work". Today they say hard work and smart work are fine, but "kaisa hai aapka network? Network is the new net worth." The same idea applies to computers.
  • Myth buster: "Computer network" does not mean the network has only computers. Any digital device can be a member (printers, servers, routers, phones).
  • They are connected through wired or wireless media.
  • Why connect? To communicate ("vaartalaap"), to exchange, transfer and share data, and to share resources, both hardware and software.

1.2Basic Terminology: Nodes

Node: the general term for any device connected to a network that can send, receive or forward data.
🎓 From the lecture Computers are nodes, but if you think only computers are nodes, "you've gained wrong knowledge". Printers, servers, routers, switches and all the other hardware we'll study are also nodes connected in the network.

Latency / delayThe time for data to travel from source to destination (propagation + transmission + queuing + processing)

1.3Protocols

Protocol: a set of rules that governs data communication: what is sent, how it is sent and when it is sent. Every communicating device must agree on and follow it.
🎓 From the lecture — "You have to follow this protocol" As in the movies: "you have to follow the protocol". A protocol is a set of rules, ways and laws that you must agree to. Why? A network is heterogeneous: computers, printers, servers and routers each do different jobs and have different features. To connect them and transfer data without disturbance, they must all accept one set of rules.
Examples to come: TCP, IP, UDP, FTP, SMTP, POP and many more at the application and transport layers.
➕ Analogy Two people can only talk if they share a language (vocabulary = syntax, meaning = semantics) and etiquette (don't talk over each other = timing). Protocols are the "language plus etiquette" of devices.

🎯 IBPS exam alert — standards bodies
  • ISO: International Organization for Standardization, which created the OSI model.
  • IEEE: Institute of Electrical and Electronics Engineers. LAN standards: 802.3 Ethernet, 802.11 Wi-Fi, 802.15 Bluetooth, 802.5 Token Ring.
  • IETF: Internet Engineering Task Force, which publishes Internet standards as RFCs (Request for Comments). IANA/ICANN assigns IP addresses, port numbers and domain names.
  • ITU-T (telecom), ANSI (American), EIA/TIA (cabling).
  • A de facto standard is adopted through widespread use; a de jure standard is legislated by an official body.

1.4IP Address, MAC Address and Port Number

🎓 From the lecture There are three kinds of address, each working at a different layer:
  • MAC address → Data Link Layer (L2)
  • IP address → Network Layer (L3)
  • Port number → Transport Layer (L4)
IP address: any device that wants to join a network gets an IP address, so it can be uniquely identified in that network.
Analogy: in a class, if the teacher calls "Rajesh", 10 Rajeshes stand up; "Suresh", 20 stand up; "Akshay", 50. Common names can't identify anyone uniquely, so we use roll numbers. The IP address is the device's roll number. (Details come in the Network Layer chapter.)

⚠️ Exam trap Port numbers are 16-bit, so the maximum is 65,535. FTP uses two ports (20 for data, 21 for control). DNS uses UDP 53 for queries and TCP 53 for zone transfers. A MAC address is 48 bits (12 hex digits); IPv4 is 32 bits; IPv6 is 128 bits.

1.5DNS (Domain Name System)

DNS: an application-layer protocol and distributed database that translates domain names into IP addresses. It is the "phone book of the Internet".
🎓 From the lecture Input: a domain name like 5minutesengineering.com. Output: its IP address. That is, DNS translates a domain name into an IP address. The full hierarchy of how it does this comes in the Application Layer chapter, at the very end.
➕ DNS essentials
  • Hierarchy: root (.) → top-level domains: generic (.com, .org, .net, .gov, .edu) and country code (.in, .uk) → second-level (sbi.co.in) → subdomains (www, mail).
  • Port 53: UDP for normal queries, TCP for zone transfers and large replies.
  • Recursive query: "give me the final answer" (client → resolver). Iterative query: "tell me whom to ask next" (resolver → root → TLD → authoritative).
  • Records: A (name → IPv4), AAAA (name → IPv6), CNAME (alias), MX (mail server), NS (name server), PTR (IP → name, reverse lookup).
  • Before DNS existed, every host used a single hosts file, which still overrides DNS locally. DNS spoofing / cache poisoning is an attack that sends users to fake sites (relevant for bank phishing).

1.6Client-Server and Peer-to-Peer Architecture

🎓 From the lecture Client-server: there is a central server unit. Many clients connect to it and send requests for resources or data. The server doesn't ignore them; it examines each request and replies with a response.
Peer-to-peer: "remove the central server unit; we don't need a central controlling or coordinating unit." The nodes are interconnected directly. Sometimes one acts as the server and another as the client, and sometimes the roles reverse, so peers finish the work among themselves.
Basis ADDEDClient-ServerPeer-to-Peer (P2P)
Central serverYes: a dedicated, powerful serverNo: every peer is equal
RoleFixed: client requests, server servesEach node is both client and server
Data storageCentralised on the serverDistributed across peers
Security and backupBetter: central control and access managementWeaker: each peer manages its own
CostExpensive (server hardware and admin)Cheap and easy to set up
ScalabilityLimited by the server; the server is a single point of failure and a bottleneckScales well; no single point of failure
ExamplesWeb (browser ↔ web server), e-mail, net banking, ATM ↔ bank's core banking serverBitTorrent, early Skype, blockchain/Bitcoin, LAN file sharing in a small office
🎯 IBPS exam alert Banking systems (CBS, ATM, UPI switch) are client-server, for central control, security and audit. BitTorrent is the classic P2P example. Hybrid models also exist: Skype used central login with P2P calls.

  • ARPANET (1969, US Department of Defense) was the forerunner of the Internet. It adopted TCP/IP on 1 January 1983.
  • Vint Cerf and Bob Kahn are the "fathers of the Internet" (TCP/IP). Tim Berners-Lee invented the World Wide Web (1989, HTTP/HTML). The Internet is the network; the Web is a service running on it.
  • India: ERNET (1986) was the first; public Internet came through VSNL on 15 August 1995.

⚡ Rapid Revision — Chapter 1

  • CN = interconnected nodes (any digital device, not only computers) over wired or wireless media, to communicate, share data and share hardware and software resources. "Network is the new net worth."
  • Five components of data communication: sender, receiver, message, medium, protocol. Characteristics: delivery, accuracy, timeliness, jitter. Criteria: performance, reliability, security.
  • Node = any connected device (computer, printer, server, router, switch). Host = end device; intermediate node = forwarder.
  • Protocol = an agreed set of rules, needed because the network is heterogeneous. Elements: syntax, semantics, timing. Examples: TCP, IP, UDP, FTP, SMTP, POP.
  • Standards: ISO (OSI), IEEE (802.x), IETF (RFC), ITU-T.
  • Addresses: MAC → L2 (48-bit hex, on the NIC) · IP → L3 (IPv4 32-bit, IPv6 128-bit; the "roll number" analogy) · Port → L4 (16-bit, 0–65535). Socket = IP + port.
  • Ports: FTP 20/21, SSH 22, Telnet 23, SMTP 25, DNS 53, DHCP 67/68, HTTP 80, POP3 110, IMAP 143, SNMP 161, HTTPS 443.
  • DNS: domain name → IP (application layer, port 53, UDP). Root → TLD → authoritative; A, AAAA, MX, CNAME, PTR records.
  • Client-server: central server, request/response, secure, single point of failure (banking, web). P2P: no central server, peers swap roles, cheap and scalable (BitTorrent).
  • Internet (public) · intranet (private) · extranet (private plus partners). ARPANET 1969; TCP/IP in 1983.
