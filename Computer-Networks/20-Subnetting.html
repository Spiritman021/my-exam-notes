Chapter 20

Subnetting

Chapter 19 ended with a problem: one class A network holds 16 million hosts and one class B 65 534, far more than any single LAN can use. Subnetting fixes this inside an organisation. Keep the network ID untouched, borrow the leftmost bits of the host ID, and use them to number smaller subnets. A subnet mask records how many bits are now "network", and a bitwise AND with that mask tells a router which subnet a packet belongs to.

20.0What is Subnetting?

🎓 From the lecture Subnetting is just dividing huge networks into smaller networks. "Huge" usually means class A and class B. The input is the huge network; the output, the smaller pieces you get after dividing, are called subnets.
Subnetting: splitting one IP network into several smaller networks (subnets) by moving the boundary between network and host bits to the right. Address = network ID + subnet ID + host ID.
➕ Why subnet? Smaller broadcast domains (less broadcast traffic), better security and management (one subnet per department), less address waste, and simpler routing inside the organisation. Outside routers still see only the original network; the subnet structure is visible only inside.

20.1Types of Subnetting: FLSM vs VLSM

🎓 From the lecture Two types. Fixed Length Subnetting (FLSM): divide equally; if one subnet gets this much, every other subnet gets the same. Variable Length Subnetting (VLSM): as the name says, the chunks are unequal; one subnet's size need not match another's.

20.2Fixed Length Subnetting: Class C Example

🎓 From the lecture FLSM means every subnet gets an equal number of addresses. Example network: 201.1.10.0. Check the first byte: 201 is in the class C range, so the first 3 bytes are the network ID and the last byte (8 bits) is the host ID.
To divide equally into two, look at the MSB of the host byte: it can be 0 or 1. If 0, the address belongs to one subnet; if 1, to the other.
Golden rule: when subnetting, never touch the network ID ("iska baal bhi baanka nahi hona chahiye"). Only the host part changes, starting with the host bit right next to the network ID.
With that bit fixed, the remaining 7 bits run from all 0s to all 1s: subnet A = 0–127, subnet B = 128–255 in the last byte.

20.3Subnet ID, Broadcast Address and Hosts per Subnet

🎓 From the lecture Just as a network has an ID, each subnet needs an ID. The first address of a subnet's range is its subnet ID; the last address is its broadcast address.
• Subnet A: ID 201.1.10.0, broadcast 201.1.10.127
• Subnet B: ID 201.1.10.128, broadcast 201.1.10.255
Each subnet has 128 addresses, but the two extremes (ID and broadcast) are not given to hosts, so 126 host IDs per subnet.

20.4Subnet Mask

🎓 From the lecture Class C's default mask is 255.255.255.0: all 1s in the 3 network bytes. In subnetting, we used one host bit to split the network, so that bit must also become 1 in the mask. The last byte becomes 1 0000000 = 128.
Subnet mask = 255.255.255.128. Rule: every host bit you borrow for subnetting is turned into a 1 in the mask; the bits you didn't use stay 0.
default class C mask : 11111111.11111111.11111111.00000000 = 255.255.255.0 (/24) after borrowing 1 bit: 11111111.11111111.11111111.10000000 = 255.255.255.128 (/25)
⚠️ Exam trap An octet value of 255 means all eight bits are 1s (the transcript once says "258", which cannot exist in a byte). The only valid values inside a mask octet are 0, 128, 192, 224, 240, 248, 252, 254, 255, because a mask's 1s must be contiguous from the left.

20.5Using the Subnet Mask to Find the Destination Subnet (Bitwise AND)

🎓 From the lecture What is the mask for? A packet arrives addressed to 201.1.10.10. Where should it go?
Step 1: which network? AND the address with the class mask (255.255.255.0). The last byte: 10 AND 0 = 0, giving 201.1.10.0, so the packet belongs to this network.
Step 2: which subnet? The network is split, so AND with the subnet mask (last byte 128): 00001010 AND 10000000 = 00000000 → 0 → result 201.1.10.0 = subnet A's ID. So the packet goes to subnet A, not B. Check with the ranges: 10 lies in 0–127.
The network's broadcast address is 201.1.10.255 (all host bits 1).
The AND test, worked
IP 201.1.10.10 → last byte 0000 1010 mask 255.255.255.128 → last byte 1000 0000 AND last byte 0000 0000 = 0 → 201.1.10.0 = Subnet A ✔ IP 201.1.10.200 → last byte 1100 1000 AND with 1000 0000 → last byte 1000 0000 = 128 → 201.1.10.128 = Subnet B
AND rule: 1 AND 1 = 1, anything AND 0 = 0. So the mask keeps the network + subnet bits and wipes the host bits; what remains is the subnet ID.

20.6Variable Length Subnetting (VLSM)

🎓 From the lecture Now the addresses are not equally distributed. Same network, 201.1.10.0 (class C), divided into three subnets of different sizes.
"First divide into two, then go further," exactly like the class-division trick of ch 19. Again, don't touch the network ID.
• Fix the MSB of the host byte. 0 → subnet A: range 0 to 127; 128 addresses minus subnet ID and broadcast = 126 hosts.
• The 1 half needs dividing further; one bit isn't enough, so take the next bit too. 10 → subnet B (128–191), 11 → subnet C (192–255). Each has 64 addresses, so 62 hosts after removing ID and broadcast.
Final sizes: 126, 62, 62. Unequal, which is the point of VLSM.

20.7Subnet Masks in VLSM

🎓 From the lecture Each part gets its own mask, based on how many host bits it used.
• Subnet A used 1 bit → 1 0000000 = 128 → mask 255.255.255.128. This mask answers "A side or not-A side?"
• The not-A side was split with 2 bits → 11 000000 = 192 → mask 255.255.255.192. This answers "inside not-A, B or C?" (the lecture also calls these b1 and b2).

20.8Routing a Packet Through VLSM Subnets

🎓 From the lecture A packet arrives for 201.1.10.10.
1. AND with the class C mask 255.255.255.0 → 201.1.10.0: the right network.
2. AND the last byte with 128 (A or not-A?) → 10 AND 128 = 0 → 201.1.10.0 = subnet A. Done.
Twist it: the packet is for 201.1.10.129.
1. Class mask → 201.1.10.0: the right network.
2. AND with 128 → 129 AND 128 = 128 → 201.1.10.128: not A; it is in the second half.
3. That half is split again, so AND with 192 → 129 AND 192 = 128 → 201.1.10.128 = the ID of subnet B (b1). Deliver it there.
Whatever the AND produces is some subnet's ID; the packet is routed to that subnet.
The AND chain for .129 and .200
129 = 1000 0001 AND 1000 0000 (128) → 1000 0000 = 128 → not A AND 1100 0000 (192) → 1000 0000 = 128 → Subnet B (201.1.10.128) ✔ 200 = 1100 1000 AND 1000 0000 (128) → 1000 0000 = 128 → not A AND 1100 0000 (192) → 1100 0000 = 192 → Subnet C (201.1.10.192)
➕ How real routers do it: longest prefix match A router's table holds every subnet with its prefix (201.1.10.0/25, 201.1.10.128/26, 201.1.10.192/26). For each packet it ANDs the address with each entry's mask, and if several entries match it picks the one with the longest prefix (most 1s in the mask), the most specific route. More in ch 21 and ch 27.

⚠️ Exam traps Subnets: 2ⁿ or 2ⁿ − 2? Old textbooks (and some exam keys) subtract 2 for the all-0s and all-1s subnets ("subnet zero" rule). Modern practice (RFC 1878, CIDR) uses all 2ⁿ. Use 2ⁿ unless the question says subnet zero/all-ones subnets are not allowed. Hosts are always 2ʰ − 2.
Count h correctly: h = 32 − prefix, not "8 − n" when the mask spans more than the last octet (e.g. /20 → h = 12).
➕ VLSM design method 1. Sort the requirements from largest to smallest. 2. For each, pick the smallest block with 2ʰ − 2 ≥ hosts needed. 3. Allocate blocks one after another from the start of the space, each on its own block boundary. 4. Use /30 (or /31) for router-to-router links.

20.10Solved Numericals ADDED

Solved numericals Q1. Divide 192.168.1.0/24 into 4 equal subnets.
2ⁿ = 4 → n = 2 → /26, mask 255.255.255.192, block 64. Subnets: .0, .64, .128, .192; broadcasts .63, .127, .191, .255; 62 hosts each.

Q2. For host 172.16.45.200/20, find the mask, subnet ID, broadcast and host count.
/20 → 255.255.240.0; block = 256 − 240 = 16 in the 3rd octet. 45 lies in 32–47 → subnet 172.16.32.0, broadcast 172.16.47.255, hosts 2¹² − 2 = 4094.

Q3. A class C network needs subnets of at least 50 hosts. Mask and number of subnets?
2ʰ − 2 ≥ 50 → h = 6 (62 hosts) → n = 2 → /26 (255.255.255.192), 4 subnets.

Q4. A class B network needs 500 subnets. Mask and hosts per subnet?
2ⁿ ≥ 500 → n = 9 (512) → /16 + 9 = /25 (255.255.255.128); h = 7 → 126 hosts.

Q5. 10.0.0.0 with mask 255.255.255.0. How many subnets and hosts?
Class A default /8 → n = 16 → 65 536 subnets; h = 8 → 254 hosts each.

Q6. Are 192.168.1.70 and 192.168.1.130 on the same subnet with /26?
Block 64: 70 → subnet .64; 130 → subnet .128 → different subnets (they need a router).

Q7. VLSM: from 192.168.10.0/24, give LANs of 100, 50 and 20 hosts plus one point-to-point link.
100 → /25 (126): .0 – .127 · 50 → /26 (62): .128 – .191 · 20 → /27 (30): .192 – .223 · link → /30 (2): .224 – .227. Left over: .228 – .255.

Q8. Which mask gives exactly 30 hosts per subnet? 2ʰ − 2 = 30 → h = 5 → 255.255.255.224 (/27).
🎯 IBPS exam alert Most-asked: "how many hosts with mask X" (2ʰ − 2), "how many subnets" (2ⁿ), "find the network/broadcast address of host Y/Z" (block-size method), "which mask for N hosts", and "valid host range". Do the block-size shortcut in your head; only write binary when the interesting octet is awkward.

⚡ Rapid Revision — Chapter 20

  • Subnetting = divide a huge network (class A/B) into smaller subnets; never touch the network ID; borrow host bits from the left.
  • FLSM: equal sizes, one mask. VLSM: unequal sizes, a mask per subnet, less waste.
  • Lecture FLSM: 201.1.10.0 → borrow 1 bit → .0–.127 and .128–.255; first address = subnet ID, last = broadcast; 126 hosts each; mask 255.255.255.128.
  • Mask = default mask + a 1 for every borrowed bit (1 bit = 128, 2 = 192, 3 = 224 …).
  • To route: IP AND mask → subnet ID. 201.1.10.10 AND .128 → .0 → subnet A.
  • Lecture VLSM: A .0/25 (126 hosts), B .128/26 (62), C .192/26 (62). 201.1.10.129: AND 128 → 128 (not A), AND 192 → 128 → subnet B.
  • Formulas: subnets 2ⁿ; hosts 2ʰ − 2; block = 256 − mask octet; broadcast = next subnet − 1.
  • /25 126 · /26 62 · /27 30 · /28 14 · /29 6 · /30 2 hosts.
