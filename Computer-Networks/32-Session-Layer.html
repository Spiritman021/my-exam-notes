Session Layer

The transport layer gives two processes a pipe for bytes. The session layer organises the conversation that runs through that pipe. It decides who may start one, keeps related streams in step, places save-points so a broken session can resume instead of restarting, and controls whose turn it is to talk. In the real Internet (TCP/IP) these jobs are done inside applications, so exams ask only a few direct questions on this layer, mostly about its functions.

32.0Where the Session Layer Sits

🎓 From the lecture Counting from the bottom it is the 5th layer; from the top, the 3rd: above the transport layer, below the presentation layer.
A fact first: exams ask very few questions on the session and presentation layers ("ikka-dukka"), as their weightage is low. Still, know the key functional points.
As the name says, the session is this layer's central entity; everything revolves around it. Creating, initiating, establishing, maintaining, managing and terminating a session is the session layer's job.

32.1Session Establishment: Authentication and Authorization

🎓 From the lecture A client machine wants to access its account data on a server, i.e. establish a communication session. Not just anyone can walk in: you need an account.
Authentication: first prove you are a valid user: send your credentials (username, password). Only if they are valid do you get the successful login screen / dashboard.
Authorization: then what you may see and do: your view, permissions and data differ from other users'. An admin has admin-level permissions; you have only user-level permissions. You are authorised for some data and actions, not all of them.
Once the server responds, the session is open: you send requests, it replies. Establishing this communication is the session layer's job.

32.2Synchronization

🎓 From the lecture Within session management, the first key point is synchronization. Take an audio file (sound only) and a video file (pictures only) to be merged. What I say must match my lips: lip-sync. Imagine a keynote speaker at a meeting whose voice arrives 10 minutes late: is that a good session? No. The session layer prevents this by keeping the streams of a session accurately synchronised.
➕ Synchronization points In OSI terms, synchronization means inserting sync points into the data stream. Major sync points split the dialogue into units that must be acknowledged before continuing; minor sync points are lighter markers inside a unit. They are also what makes checkpoint recovery (next) possible.

32.3Checkpointing

🎓 From the lecture Editing an online document, you notice it saves itself periodically without you pressing Save. In Word you press Ctrl+S after a chunk of work: that is a checkpoint created by hand.
Why it matters: you've worked on a presentation for 10 days and the system suddenly shuts down. With no checkpoints you start again from scratch. To avoid this overhead, checkpoints save the session's progress at intervals. If a session fails (fault, error, shutdown), the session layer lets it resume from the last checkpoint instead of from the beginning.
➕ Classic exam example A 2000-page file is being sent with a checkpoint every 100 pages. If the connection breaks at page 523, transfer resumes from page 501 (after the last checkpoint at 500), so only pages 501–523 are resent, not all 523.

32.4Dialog Control

🎓 From the lecture Another popular function: dialog management / dialog control. In a communication session there is an exchange of data (requests and replies). Which direction may data flow, and when? One way at a time (half-duplex) or both ways at once (full-duplex)? The session layer takes care of this for the dialogue.
➕ Token management For half-duplex dialogues, OSI uses a token: only the side holding the data token may send; it passes the token when its turn ends (like the talking stick in a meeting, or Token Ring in ch 18 at a higher level). This also prevents both sides from attempting a critical operation at the same time.

➕ Protocols and the TCP/IP view Protocols usually listed at the session layer: NetBIOS, RPC (Remote Procedure Call), PPTP, SOCKS, SMB session set-up, SQL sessions, H.245. In the TCP/IP model there is no separate session layer: its jobs are done by the application (e.g. web logins with session cookies/tokens, TLS session resumption, download managers resuming from a byte offset). The OSI data unit for layers 5–7 is simply "data".
Solved questions Q1. Which OSI layer establishes, manages and terminates sessions? Session layer (layer 5).

Q2. Which layer inserts checkpoints for recovery? Session layer.

Q3. Dialog control (half/full duplex) is the job of? Session layer.

Q4. Session layer lies between? Transport (4) and presentation (6).

Q5. Checkpoints every 100 pages; failure at page 750 of 1000. From which page does transfer resume? 701.

Q6. Verifying a password is authentication or authorization? Authentication. Allowing only admins to delete records? Authorization.
🎯 IBPS exam alert Pure one-liners: session layer = dialog control + synchronization (checkpoints); presentation layer = translation, encryption, compression (next chapter); transport = end to end; network = routing. Don't mix up "dialog control" (session) with "flow control" (data link / transport).

⚡ Rapid Revision — Chapter 32

  • Session layer = OSI layer 5 (5th from bottom, 3rd from top), between transport and presentation; low exam weightage.
  • Central entity = session: create, establish, maintain, manage, terminate.
  • Establishment: authentication (username/password: who are you) then authorization (admin vs user permissions: what may you do).
  • Synchronization: audio + video must be lip-synced; sync points (major/minor).
  • Checkpointing: like auto-save / Ctrl+S; after a crash resume from the last checkpoint, not from scratch.
  • Dialog control: half-duplex vs full-duplex turn-taking; token management.
  • Protocols: NetBIOS, RPC, PPTP, SOCKS. In TCP/IP these jobs live in the application layer.
