Chapter 10

Switching Techniques

Chapter 9 introduced switches and routers, the intermediate nodes. This chapter covers how data travels through a chain of them from source to destination. There are three strategies: reserve a whole path first (circuit), hop the whole message node to node (message), or chop it into packets (packet switching, with two flavours, virtual circuit and datagram).

10.0What is Switching?

Switching: the technique of moving data from source to destination through a series of intermediate nodes (switches), deciding at each node which outgoing link to use.
🎓 From the lecture — Changing taxis You are a data packet going from source to destination. You take a taxi to one point, switch to another taxi there, and switch again until you reach the destination. A packet likewise "switches" from node to node across the network. Types: circuit switching, message switching and packet switching (with the variants datagram and virtual circuit).

10.1Circuit Switching

Circuit switching: a dedicated physical path between sender and receiver is set up before communication, reserved for the whole conversation, and torn down afterwards. It works at the physical layer. Example: the traditional telephone network (PSTN).
🎓 From the lecture — The cup-and-string telephone Remember the childhood game of two cups joined by a thread? One person speaks into a cup, the other listens at the other cup.
  1. Connection setup first: before anyone talks, the thread (a dedicated link / path) is connected. Many other paths may exist, but this one is reserved for us. That takes the setup time.
  2. Data transfer: transmission time + propagation delay (10.2).
  3. Teardown: when the game is over, break the thread so others can use it. That takes the teardown time.
Other properties:
  • Guaranteed in-order delivery: if I say A, B, C, the receiver hears A, B, C, never B, A, C.
  • Resources are reserved and can't be used by others: "Mummy needed the thread for sewing, but my brother and I were playing, so she couldn't use it."
  • No store-and-forward, so delay is low and it is fast; no obstacle stops and checks the data midway.
Total time = setup time + transmission time + propagation delay + teardown time.
➕ Pros, cons and types Pros: a guaranteed, constant data rate; in-order delivery; no congestion once the circuit is set up; ideal for real-time voice. Cons: setup delay; bandwidth is wasted when nobody speaks (silences); inefficient for bursty data; if a link fails, the call drops. Implemented with space-division (crossbar) and time-division switching (TDM, TSI).

10.2Transmission Time and Propagation Delay

🎓 From the lecture
  • Transmission time (Tt): the time to completely place the whole packet onto the link at the sender. It is directly proportional to the packet length (bigger packet, more time) and inversely proportional to bandwidth (100 Mbps puts it on faster than 1 Mbps). So we want a smaller length and a higher bandwidth.
  • Propagation delay (Tp): once on the link, the time for it to travel to the receiver. It is directly proportional to the distance (d) and inversely proportional to the speed.
  • These come back in the DLL chapters (CSMA, flow control).
Essential formulas
Transmission time Tt = L / B (L = packet length in bits, B = bandwidth in bps) Propagation delay Tp = d / v (d = distance, v = propagation speed; ≈ 2×10⁸ m/s in cable/fibre, 3×10⁸ in air) Total delay (one link) = Tt + Tp (+ queuing + processing delay) a = Tp / Tt (used later in efficiency formulas)
Numericals (added) Q1. A 1500-byte frame on a 100 Mbps link: Tt = 1500×8 / 10⁸ = 12000 / 10⁸ = 120 µs.
Q2. A 2000 km fibre at v = 2×10⁸ m/s: Tp = 2×10⁶ / 2×10⁸ = 10 ms.
Q3. 1 MB sent over 10 Mbps across 3000 km (v = 3×10⁸): Tt = 8×10⁶ / 10⁷ = 0.8 s; Tp = 3×10⁶/3×10⁸ = 0.01 s. Total ≈ 0.81 s. Here transmission dominates.
Trap: 1 KB = 1024 bytes in storage, but bandwidth uses decimal units (1 Mbps = 10⁶ bps). Many exams use 1 KB = 1000 bytes for simplicity, so read the question.

10.3Message Switching

Message switching: no dedicated path is set up. The whole message (a block of data) is sent hop by hop; each intermediate node stores the entire message, then forwards it to the next node (store-and-forward).
🎓 From the lecture — Passing the message along "Why do all that setup? Just call out: 'Hey, listen, pass this on to him!'" The receiver is far away, so you hand the message to someone in between. They too find the receiver too far, so they catch another person and hand it on, until it reaches the receiver.
  • No setup and no teardown; no resources reserved in advance. That is its big advantage.
  • Hop-by-hop delivery: the message or data block is forwarded node by node, so there is delay.
  • The whole message is forwarded across the network, so traffic increases.
➕ More facts Every node needs large storage (messages can be big). Long delays make it unsuitable for real-time or interactive use. Examples: telegram networks, early e-mail. It is the ancestor of packet switching. Messages may arrive out of order (in a multi-path network).

10.4Packet Switching

Packet switching: the message is divided into small packets, each with a header. Packets are sent individually, store-and-forward, through switches or routers. It works at the network layer (and data link layer). This is how the Internet works.
🎓 From the lecture It is a mixed flavour of message and circuit switching. The sender doesn't send the whole big message; it divides it into packets and sends packet by packet, hence the name. Each packet is placed on the link (transmission), propagates, then at each switch is stored, then forwarded: store → forward → store → forward → receiver. So there is delay: total time = transmission times at the sender and switches + propagation times on all links. Two variants: virtual circuit (resources reserved) and datagram (no reservation).

10.5Virtual Circuit vs Datagram

🎓 From the lecture — Planned trip vs spontaneous trip
  • Virtual circuit is like a fully planned trip: where to stop, where to eat, the budget, who comes, the vehicle number, all reserved in advance. Resources (bandwidth, CPU, buffers) are reserved first, so all packets follow the same path and arrive in order (A then B), a benefit of circuit switching.
  • Datagram is like "man aa gaya, chalo ghoomne": no planning, no idea of cost, transport or food. There is no reservation, so packets may or may not take the same path. Packet B may take a shorter path and arrive before A, giving out-of-order delivery (message switching's disadvantage).
  • Virtual circuit is connection-oriented, with setup and teardown overhead; it is costlier but reliable and efficient ("tikau"). Datagram is connectionless, has no such phases, is less costly and less reliable.

⚠️ Exam trap A virtual circuit is a logical path. The physical links are still shared with other circuits (unlike circuit switching's dedicated physical path). IP is a datagram service; TCP makes the communication reliable and ordered end to end on top of it.

10.6Delay Numericals & Master Comparison ADDED

Essential formulas: k links (k − 1 intermediate switches), ignoring processing and queuing
Circuit switching: Total = setup + M/B + k·Tp + teardown (no store-and-forward) Message switching: Total = k × (M/B + Tp) (whole message stored at each node) Packet switching: Total = (k + n − 1) × (P/B) + k·Tp (n packets of size P, pipelined)
Numerical: message vs packet switching A message of 3000 bits goes over 3 links (2 switches). Each link is 1 Mbps with Tp = 1 ms. Ignore headers.
Message switching: Tt = 3000 / 10⁶ = 3 ms per link. Total = 3 × (3 + 1) = 12 ms.
Packet switching (3 packets × 1000 bits): Tt per packet = 1 ms. Total = (3 + 3 − 1) × 1 + 3 × 1 = 5 + 3 = 8 ms.
Conclusion: pipelining makes packet switching faster (8 ms vs 12 ms). With 1 link (k = 1), both give the same 4 ms; the gain comes from intermediate nodes. (Real packets add header overhead, so very small packets aren't always better.)

🎯 IBPS exam alert "Telephone network uses?" → circuit switching. "Internet uses?" → packet switching (datagram). "Store-and-forward of the entire message?" → message switching. "Dedicated path reserved for the duration?" → circuit switching. "ATM / X.25 / Frame Relay?" → virtual circuit. Transmission time depends on length and bandwidth; propagation delay on distance and speed.

⚡ Rapid Revision — Chapter 10

  • Switching = moving data through intermediate nodes (like changing taxis). Circuit, message, packet (virtual circuit or datagram).
  • Circuit (cup-and-string phone): setup → data → teardown; a dedicated reserved path; in order; no store-and-forward, so fast; resources wasted when idle. Total = setup + Tt + Tp + teardown. PSTN.
  • Tt = L/B (∝ length, ∝ 1/bandwidth): putting the packet on the link. Tp = d/v (∝ distance, ∝ 1/speed): travel time. 1500 B at 100 Mbps = 120 µs; 2000 km fibre = 10 ms.
  • Message ("pass the message along"): no setup; the whole message is stored and forwarded hop by hop; more delay and traffic; needs storage. Telegram.
  • Packet: chop into packets, store-and-forward per packet, pipelining, so it is faster than message switching (3 links: 8 ms vs 12 ms). Total = (k + n − 1)·Tt + k·Tp.
  • Virtual circuit (planned trip): connection-oriented, reserved, same path, in order, VCI, costlier and reliable. X.25, Frame Relay, ATM.
  • Datagram ("man aa gaya"): connectionless, independent paths, out of order possible, cheaper, robust. IP / the Internet.
