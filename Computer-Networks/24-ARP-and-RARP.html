Chapter 24

ARP and RARP

A host knows where it wants to send a packet in IP terms (layer 3), but on the wire the frame needs a MAC destination (layer 2, chapters 15–16). ARP bridges the gap: it asks the whole LAN "who has this IP?" and the owner answers with its MAC. RARP does the reverse for a machine that knows only its own MAC and needs to learn its IP. In both, the question is broadcast and the answer comes back unicast.

24.0Why Address Resolution?

🎓 From the lecture ARP = Address Resolution Protocol; RARP = Reverse Address Resolution Protocol. ARP's situation: I know the IP address, but not the MAC address. That MAC is what we must find (resolve, locate). To do it, ARP sends a request packet and gets a response.

24.1ARP Request and Reply

🎓 From the lecture A network (bus topology) has hosts A, B, C … and a router. Host A wants to send data to host B. A knows B's IP address (IB) but not B's MAC address (MB).
Going down the layers: at the network layer A can fill in source IP = IA and destination IP = IB. But at the data link layer it needs B's MAC. It knows its own MAC (source), but the destination MAC is unknown.
So A asks a question: "I know your IP, I don't know your MAC (?). My MAC is MA; send your MAC to this address." This is the ARP request packet. Why all those Fs? An ARP request is broadcast throughout the network: the destination MAC is the broadcast address, 12 Fs (ch 16). It reaches everyone, but only the host whose IP matches reads it and responds.
B receives it: "I know my MAC." It sends the ARP reply: the IP A asked about (IB) with the answer attached (MB); source MAC = MB, destination MAC = MA. This time it is unicast, one-to-one between B and A, because now the address is known. A notes "your MAC is MB", fills it in, and sends the data.
🎯 IBPS exam alert Golden rule (lecture): ARP request = broadcast; ARP reply = unicast. ARP works only within one local network (one broadcast domain), because routers do not forward broadcasts.

24.2Reverse ARP (RARP)

🎓 From the lecture The situation flips: host A knows its own MAC address (MA) but not its own IP address, and must find it.
A builds a RARP request: "I know my MAC (MA), but not my IP." Since the IP is unknown, the 4 bytes of the IP field are filled with 0.0.0.0.
Who can answer? The RARP server, a very important station on the network. It holds a static table mapping every host's MAC address to its IP address. But the host doesn't know the server's MAC either, so just like ARP, the RARP request is broadcast over the whole network. Everyone is alerted, but only the RARP server reads and responds, because only it has the mapping table and the authority.
The server searches its table for MA: M1? no. M2? no. MA? match → its IP is IA. It replies: your MAC (as sent) plus the answer, IA; source MAC = the server's MAC, destination MAC = MA, sent unicast. Host A receives it and is happy: it finally knows its IP.
Always remember: ARP or RARP, the request is always broadcast and the response is always unicast.
➕ Who needed RARP? Diskless workstations booting from the network: they had a MAC burned into the NIC but nowhere to store an IP configuration. Today this job is done by DHCP (24.4).

24.3ARP Cache, Packet Format & Remote Destinations ADDED

ARP cache: a table of recently resolved IP → MAC pairs kept by every host, so it doesn't broadcast for every packet. Entries are dynamic (learned, expire after a timeout, typically a few minutes) or static (configured by hand). View it with arp -a. When B receives A's request it also caches A's mapping, since A's IP and MAC are in the request.

➕ Where ARP sits The ARP packet is 28 bytes, carried directly inside an Ethernet frame (EtherType 0x0806; RARP = 0x8035), not inside an IP packet. That is why it is often described as a layer-2.5 protocol; Forouzan places it in the network layer, and many exams accept "network layer".
➕ Destination on another network If B is not on A's network (A sees this by ANDing B's IP with its subnet mask, ch 20), A does not ARP for B. It ARPs for its default gateway (router), sends the frame to the router's MAC, and the router repeats the process on the next network. The IP addresses stay the same end to end; the MAC addresses change at every hop.

Solved questions Q1. Which protocol finds the MAC address for a known IP address? ARP.

Q2. A diskless workstation knows only its MAC. Which protocol gives it an IP? RARP (today: DHCP).

Q3. Destination MAC in an ARP request frame? FF:FF:FF:FF:FF:FF (broadcast). In the reply? the requester's MAC (unicast).

Q4. Host 192.168.1.10/24 wants to send to 8.8.8.8. Whose MAC does it ARP for? The default gateway's, since 8.8.8.8 is on another network.

Q5. Which command shows the ARP cache? arp -a.

Q6. Which IPv6 mechanism replaces ARP? Neighbour Discovery (ICMPv6).

Q7. Which attack exploits ARP's lack of authentication? ARP spoofing / poisoning (man-in-the-middle).

⚡ Rapid Revision — Chapter 24

  • ARP: know the IP, need the MAC (IP → MAC). RARP: know my MAC, need my IP (MAC → IP).
  • Network layer fills both IPs; the DLL needs the destination MAC → ask with ARP.
  • ARP request goes to FF:FF:FF:FF:FF:FF (12 Fs, broadcast); everyone hears, only the IP owner answers.
  • ARP reply: source MAC_B, destination MAC_A → unicast.
  • RARP: request carries IP 0.0.0.0; broadcast; only the RARP server (static MAC→IP table) replies, unicast.
  • Golden rule: request = broadcast, reply = unicast, for both.
  • ARP cache (arp -a), 28-byte packet, EtherType 0x0806, op 1/2 (RARP 3/4). Remote destination → ARP for the gateway.
  • Proxy ARP, gratuitous ARP (duplicate-IP check), ARP spoofing (MITM). IPv6 uses NDP. RARP → BOOTP → DHCP (UDP 67/68).
