Chapter 27

Routing

A router forwards each packet by looking up its routing table. This chapter is about how that table gets built. Either an admin types it in (static), or the routers work it out among themselves (dynamic). The two dynamic families are Distance Vector (each router trusts its neighbours' summaries and improves its table round by round) and Link State (every router learns the whole map and runs Dijkstra on it). Both are worked on the same small network below, so you can compare the answers.

27.1Routing vs Switching vs Flooding

🎓 From the lecture These three terms confuse many people.
• Routing: in the algorithm sense, "the process of designing / creating a routing table" (the general meaning, choosing the best path, from ch 19 also holds).
• Switching: just sending a packet along some path, node to node, until it reaches the destination.
• Flooding: sending the packet on all possible paths: whatever arrives on a router's incoming link is copied onto every outgoing link. No routing table is used at all.

➕ Taming flooding Flooding is used where robustness matters more than efficiency (military networks, distributing link-state packets in 27.7). To stop endless copies: put a hop counter in each packet (like TTL), keep a sequence number so a router forwards each packet only once, or use selective flooding (only on links roughly in the right direction).

27.2Static vs Dynamic Routing

🎓 From the lecture Routing algorithms fall into two categories, by how the routing table is created, built, updated and maintained.
Static (manual): an admin edits every table by hand. If router R2 goes down, the alternative path from source to destination must be written in manually. If one road is jammed and a quiet side street exists, that too must be updated by hand, as must any new shorter path. This is effort- and time-consuming, so it is not used much.
Dynamic: no manual intervention, no manual maintenance, no manual table building: the routers do it themselves. Two popular dynamic algorithms asked in exams: DVR (Distance Vector Routing) and LSR (Link State Routing).

27.3Distance Vector Routing: Initial Routing Table (Round 1)

🎓 From the lecture Goal: a routing table for each of the n = 4 routers A, B, C, D. Each table has three columns: Destination, Distance (it could equally be cost or delay; we always want the minimum, a minimisation problem), and Next hop (the next router to send to).
In round 1 a router knows only its directly connected neighbours (one link, one edge). Reading A's table: to A, distance 0; to B, the direct link costs 15, next hop B (there are shorter ways, but round 1 doesn't know them); to C there is no direct link, so distance ∞ and next hop blank ("I don't know"); to D, 5, next hop D.
Round 1to Ato Bto Cto D
A0 / A15 / B∞ / –5 / D
B15 / A0 / B1 / C8 / D
C∞ / –1 / B0 / C4 / D
D5 / A8 / B4 / C0 / D

Each cell = distance / next hop. Each row is that router's distance vector.

27.4DVR Round 2: Sharing Distance Vectors with Neighbours

🎓 From the lecture Round 2 considers paths of up to 2 links: maybe taking two links is cheaper than one. Each router's direct neighbours send it their distance vectors (one column of distances, hence "distance vector routing"). A's neighbours are B and D: B sends (15, 0, 1, 8) and D sends (5, 8, 4, 0). A builds a new table from these.
Notation: A,B (comma) = the direct link; A–B (dash) = any path, possibly through other nodes.
• A → B: direct = 15, or via D = A→D 5 + D→B 8 = 13. 13 < 15 → distance 13, next hop D.
• A → C: via B = 15 + 1 = 16, via D = 5 + 4 = 9. 9 beats ∞ and 16 → 9, next hop D (A must jump to D first).
• A → D: direct = 5; via B = 15 + 8 = 23 → keep 5, next hop D.
B, C and D do the same with their own neighbours' vectors (B receives from A, C and D).
Round 2to Ato Bto Cto D
A0 / A13 / D9 / D5 / D
B13 / D0 / B1 / C5 / C
C9 / D1 / B0 / C4 / D
D5 / A5 / C4 / C0 / D

27.5DVR: Number of Rounds (n − 1)

🎓 From the lecture How many times must "share vectors with neighbours, then update" be repeated? n − 1 rounds: with 4 routers, 3 rounds.
Watch A → B improve: round 1 (1 link) = 15; round 2 (2 links: A–D–B) = 13; round 3 (3 links: A–D–C–B = 5 + 4 + 1) = 10, the true minimum. The guarantee: after n − 1 rounds every table holds the minimum distance. With many routers this is long and slow, which is why the shortcut matters.
Round 3 (final)to Ato Bto Cto D
A0 / A10 / D9 / D5 / D
B10 / C0 / B1 / C5 / C
C9 / D1 / B0 / C4 / D
D5 / A5 / C4 / C0 / D
➕ Why n − 1 A shortest path in an n-node network uses at most n − 1 links, and each round lets information travel one more link. This is the Bellman–Ford algorithm run in a distributed way. In practice routers do not count rounds; they keep exchanging vectors (RIP every 30 s) and stop changing when the tables converge.

27.6DVR: Shortcut Method for Routing Tables

🎓 From the lecture The fast way to fill a router's new table. Write the neighbours' vectors side by side; above each, write the cost of the link to that neighbour. For each destination, add the link cost to the neighbour's distance, take the minimum, and record that neighbour as the next hop.
Router A, round 2, by the shortcut
neighbour: B (link 15) D (link 5) min → next hop to B : 15 + 0 = 15 5 + 8 = 13 13 → D to C : 15 + 1 = 16 5 + 4 = 9 9 → D to D : 15 + 8 = 23 5 + 0 = 5 5 → D
Router C, round 2, by the shortcut
neighbour: B (link 1) D (link 4) min → next hop to A : 1 + 15 = 16 4 + 5 = 9 9 → D to B : 1 + 0 = 1 4 + 8 = 12 1 → B to D : 1 + 8 = 9 4 + 0 = 4 4 → D
The formula behind it: Dx(y) = min over neighbours v of { c(x, v) + Dv(y) } (the Bellman–Ford equation).

27.7Link State Routing: Flooding and Global Knowledge

🎓 From the lecture Much simpler: no n − 1 rounds. Every router keeps a link-state packet (LSP) listing its direct links: A: B 15, D 5 · B: A 15, D 8, C 1 · D: A 5, B 8, C 4 · C: D 4, B 1. (The same information as the round-1 vectors.)
The big difference: in DVR a router got only its neighbours' vectors (local knowledge). In LSR every router floods its packet to everyone, neighbour or not. So C's information also reaches A, and every router gets every other router's packet: global knowledge. This is the most important difference between DVR and LSR.
With global knowledge, each router draws the whole network diagram for itself (A–B 15, A–D 5, D–C 4, C–B 1, B–D 8).

27.8LSR: Applying Dijkstra's Algorithm

🎓 From the lecture On that diagram the router runs Dijkstra's algorithm (a strange name, but very useful) and gets its final table. (The full Dijkstra method is covered in the lecturer's DAA one-shot.) In the exam you can often see the shortest paths by inspection:
• A → B: options 15, 5 + 8 = 13, 5 + 4 + 1 = 10 → 10, next hop D.
• A → C: 15 + 1 = 16 or 5 + 4 = 9 → 9, next hop D.
• A → D: direct 5 (15 + 8 = 23 or 15 + 1 + 4 = 20 are far longer), next hop D.
Very fast, and the same answer DVR reached only after 3 rounds.
Dijkstra from A, step by step
step settled B C D init {A} 15 (A) ∞ 5 (A) 1 {A, D} 13 (D) 9 (D) 5 ✔ ← D is the closest; relax via D 2 {A, D, C} 10 (C) 9 ✔ ← C next; B via C = 9 + 1 = 10 3 {A, D, C, B} 10 ✔ Final table of A: B 10 via D · C 9 via D · D 5 via D

27.9LSR: Sequence Numbers in Link State Packets

🎓 From the lecture The LSP has one more field. Routers R1 … R5: R1 floods its packet version 1; one copy takes a long road (R2, R3, R4) to R5. Meanwhile R1 sends packets 2 and 3, which reach R5 quickly. A higher number means newer (updated) information, and routers always want the latest. So when the slow packet 1 finally arrives, R5 already has packet 3 from R1: packet 1 is old news and is discarded.
That number is the sequence number, carried in every LSP: higher = updated, lower = outdated.
LSP = [ source router | sequence number | age | list of (neighbour, cost) ]

27.10LSR: Corrupted Sequence Number Problem and Timer Field

🎓 From the lecture R5 keeps the latest sequence number from each router: R1 = 3, R2 = 5, R3 = 10, R4 = 9. R1's next packet should carry 4, but the field gets corrupted into, say, 101. Being higher, it is accepted. Now R1's real packets 4, 5, 6 … 100 all look older than 101 and are discarded: R5 sits on stale information while the updates are thrown away.
Fix: a timer (age) field. Each stored latest packet may be kept only for a limited time. When the timer runs out, it is discarded and the next packet that arrives (say 5) is accepted. Even if a sequence number was corrupted, the router recovers after the timeout and stays up to date.
➕ How real protocols handle it OSPF uses a large 32-bit sequence number space (so wrap-around is rare) plus an age field: every LSA is refreshed every 30 minutes and removed when its age reaches MaxAge = 1 hour. Every LSA is also protected by a checksum, so corrupted ones are rejected rather than stored.

27.11Count-to-Infinity & Its Fixes ADDED

⚠️ The classic DVR weakness "Good news travels fast, bad news travels slowly." Chain A — B — C, cost 1 each. If link A–B breaks, B no longer reaches A directly, but C still advertises "A at distance 2". B believes it: "A via C = 3". Then C updates to 4 via B, B to 5 via C … the two keep counting up towards infinity, possibly forming a routing loop meanwhile. This is the count-to-infinity problem; link state does not suffer from it.
FixIdea
Define infinity smallRIP treats 16 hops = unreachable, so counting stops quickly (and RIP networks are limited to 15 hops)
Split horizonnever advertise a route back out of the interface you learned it from
Poison reverseadvertise it back, but with distance ∞ ("don't use me for this")
Triggered updates / hold-down timerssend changes immediately; ignore worse news for a while after a route fails

Solved questions Q1. With 6 routers, how many DVR rounds guarantee the shortest paths? n − 1 = 5.

Q2. In the lecture's network, what is C's distance and next hop to A after convergence? 9 via D.

Q3. Router X has neighbours Y (link 2) and Z (link 6). Y says "W at 7", Z says "W at 1". X's route to W? Via Y: 9, via Z: 7 → 7 via Z.

Q4. Which algorithm suffers from count-to-infinity? Distance vector (RIP).

Q5. Which routing protocol uses Dijkstra? OSPF. Which uses Bellman–Ford? RIP.

Q6. RIP's maximum hop count? 15 (16 = unreachable).

Q7. Which protocol routes between autonomous systems? BGP (path vector, TCP 179).

Q8. In LSR, why are sequence numbers used? To tell new LSPs from old ones arriving late; an age field fixes the corrupted-sequence problem.
🎯 IBPS exam alert Frequent MCQs: "RIP is based on?" (distance vector / Bellman–Ford), "OSPF is based on?" (link state / Dijkstra), "RIP metric?" (hop count), "BGP is?" (exterior, path vector), "flooding drawback?" (duplicates, congestion), "count-to-infinity fix?" (split horizon / poison reverse).

⚡ Rapid Revision — Chapter 27

  • Routing = build the routing table; switching = send along a path; flooding = all outgoing links, no table: reliable but duplicates and congestion.
  • Static = manual, slow to adapt; dynamic = automatic: DVR and LSR.
  • DVR round 1: only direct neighbours (A: 0, 15, ∞, 5). Each round: get neighbours' vectors, new distance = min(link cost + neighbour's distance), next hop = that neighbour.
  • Rounds needed = n − 1. A→B: 15 → 13 → 10 (A–D–C–B). Final A: B 10/D, C 9/D, D 5/D.
  • Shortcut: write neighbours' vectors, add link costs, take the minimum per row.
  • LSR: each router floods its LSP to all → global knowledge → draws the map → Dijkstra. Same answers, faster.
  • LSP sequence number: higher = newer; old ones discarded. Corrupted big number blocks updates → timer/age field.
  • DVR weakness: count-to-infinity → infinity = 16, split horizon, poison reverse.
  • RIP (DV, hop count ≤ 15, 30 s, UDP 520) · OSPF (LS, cost, Dijkstra, IP 89, areas) · BGP (path vector, inter-AS, TCP 179).
