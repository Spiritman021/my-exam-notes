Chapter 6

OSI Model

Chapters 1 to 5 introduced the parts of a network: devices, links, topologies and network types. The OSI model organises everything a network must do into 7 layers, each with its own job. The rest of this volume goes through these layers one by one, so this chapter is the map for everything that follows.

6.0Why a Layered Model?

OSI (Open Systems Interconnection) model: a 7-layer reference model developed by ISO (published in 1984). It describes how data moves from an application on one computer to an application on another, by splitting the communication functions into layers.
🎓 From the lecture Every activity in a network (sharing, transferring and transmitting data) involves many different functions, responsibilities and roles at different levels. Only when all of them are performed does data transmission work efficiently. These functions are divided among layers. "It's simply a game of 7 layers. No shortcuts."
➕ Benefits of layering Modularity (change one layer without touching the others) · interoperability between vendors ("open" systems) · easier troubleshooting and teaching · standard interfaces between layers. OSI is a reference / conceptual model; the Internet actually runs on the TCP/IP model (6.12).

6.1The Seven Layers of the OSI Model

🎓 From the lecture Bottom to top: Physical → Data Link → Network → Transport → Session → Presentation → Application (at the top). The lecture star-marks where you need deep knowledge: the Data Link layer, the Network layer, to some extent the Transport layer, and to some extent the Application layer. These carry the most questions in semester and competitive exams. Physical-layer detail is studied more by electronics students, though topology and transmission modes (already covered) belong to it. For Session and Presentation, what this lecture covers is "more than enough".
➕ Mnemonics Layer 1 → 7: "Please Do Not Throw Sausage Pizza Away". Layer 7 → 1: "All People Seem To Need Data Processing".

6.2Encapsulation at the Sender (Headers and Trailer)

Encapsulation: as data moves down the layers at the sender, each layer takes what it received from the layer above as its payload, adds its own header (control information, the metadata of its job), and passes the result down. The Data Link layer also adds a trailer.
🎓 From the lecture
  • At the sending end data moves top to bottom, starting at the application layer. At the receiving end it moves bottom up.
  • Each layer's job-related metadata goes into its header, which is attached to the data, forming a "packet". The layer passes it down.
  • The next layer treats the whole thing it received as data / payload, adds its own header, and passes it down again.
  • Special case: the DLL adds a header and a trailer (tail).
  • At the physical layer, everything is just 0s and 1s, data bits, put onto the transmission medium.
  • Analogy: we put the letter into an envelope, then another envelope, then another… and send it.
➕ What is in the trailer? The DLL trailer carries the FCS (Frame Check Sequence), usually a CRC, for error detection (Chapter 14). Only the DLL adds a trailer. In practice, layers 5–7 are often handled together by the application and add no separate headers.

6.3Decapsulation at the Receiver and Peer-Layer Communication

Decapsulation: at the receiver the data moves up. Each layer removes the header added by its peer layer at the sender, uses that information, and passes the payload upward.
Peer-to-peer communication: each layer logically communicates with the same layer on the other machine through its header (a virtual communication), while the actual data flows down, across and up.
🎓 From the lecture — "Only the one who sealed it can open it" At the receiver (bottom up), one envelope comes off at each layer until the host finally gets the data. Very important: it never happens that the network layer's envelope is opened by the DLL, transport, session or presentation layer. The header added by the network layer at the sender is opened only by the network layer at the receiver, because only it understands that information and can act on it (compute, handle errors). It removes its header, takes out the payload and sends it up: "you open yours, transport layer". This matching is the synchronisation between peer layers.

6.4Physical Layer Functions

🎓 From the lecture
  • Data here is just a sequence of 0s and 1s.
  • Encoding: bits can't travel on a medium as they are. At the sender they are converted into compatible signals; at the receiver, signals are converted back to bits. Manchester and differential Manchester encoding are covered in Chapter 8.
  • Data transfer rate of the transmission medium is handled here.
  • Connection type / line configuration (point-to-point, multipoint), topology and transmission modes (simplex, half- and full-duplex) are all physical-layer responsibilities, already covered in Chapters 2–4.
➕ Also at the physical layer Physical characteristics of interfaces and media (connectors, pins, voltages, cables, Chapter 7) · bit synchronisation (sender and receiver clocks match) · bit rate (bits per second) · multiplexing. Devices: hub, repeater, cables, connectors, modems (partly). The PDU is the bit.

6.5Data Link Layer Functions

🎓 From the lecture (DLL = layer 2 from the bottom)
  • Framing: divide the data into frames. Analogy: a big biscuit and a little child with a tiny mouth. You don't hand over the whole biscuit; you break it into small pieces the child can eat one at a time. (Related terms MTU and MSS come later.)
  • Physical addressing: MAC addresses.
  • Access control: on a shared link (bus), if two hosts access the link and send together, a collision occurs. So there must be control over who can access the link, when and how (CSMA etc.).
  • Flow control: the golden statement "Don't send me more than what I can receive." If the receiver's buffer is full and the sender keeps sending, frames are discarded, data is lost and must be retransmitted.
  • Error control: even with no collision and no overflow, bits may get corrupted in transit, a single bit or a burst. The meaning changes, so errors must be detected and handled using checksum and CRC.
  • Delivery is hop-to-hop (node to node): host → router → router → host, one "kudi" (jump) at a time.
➕ Sublayers and devices IEEE splits the DLL into LLC (Logical Link Control: flow and error control, IEEE 802.2) and MAC (Media Access Control: addressing and channel access). Devices: switch, bridge, NIC. Protocols: Ethernet, PPP, HDLC, Wi-Fi MAC, ARP (often placed between L2 and L3).
⚠️ Exam trap The lecture calls the biscuit pieces "fragments". At the DLL they are frames. Fragmentation (with MTU) is a network-layer (IP) job, and segments (with MSS) belong to the transport layer.

6.6Network Layer Functions

🎓 From the lecture (layer 3)
  • The DLL is concerned only with hop-to-hop delivery. The network layer handles source-to-destination delivery of the data packet.
  • Logical addressing: IP addresses, as opposed to the DLL's MAC addresses.
  • Routing: many routers lie between the source and the destination. Choose the best, optimal path. Routers consult their routing tables to decide where each packet should go, to reach the destination in the least time.
  • Packetization (dividing into packets) is also done here.
➕ Also Fragmentation and reassembly (when a packet is larger than the next link's MTU) · congestion control (partly) · internetworking between different networks. Devices: router, layer-3 switch. Protocols: IP (v4/v6), ICMP, IGMP, ARP/RARP (Chapters 19–27), and routing protocols such as RIP, OSPF and BGP.

6.7Transport Layer Functions

🎓 From the lecture (layer 4)
  • It deals with port addressing / port numbers.
  • Process-to-process delivery: the network layer delivers from the source machine to the destination machine. But each machine runs many processes. Which process of the sender is sending to which process of the receiver? Each process carries a port number, which makes this possible.
  • The data unit is the segment.
  • Congestion control (too much traffic in the network), plus flow control and error control, here at the process-to-process level (end to end).
➕ Also Segmentation and reassembly (with sequence numbers) · connection control: connection-oriented TCP (reliable, 3-way handshake) vs connectionless UDP (fast, unreliable) · multiplexing and demultiplexing. Devices: none specific; gateways and firewalls operate here. Protocols: TCP, UDP, SCTP.

6.8Session Layer Functions

🎓 From the lecture Session and presentation are asked only occasionally. The session layer manages the whole session established between sender and receiver, controls the dialogs between them, and handles synchronisation and checkpoint creation.
➕ The three functions explained
  • Dialog control: lets two systems enter a dialog, in half- or full-duplex.
  • Synchronisation (checkpoints): inserts synchronisation points into the data stream. Example: sending a 2000-page file with a checkpoint every 100 pages. If a crash happens at page 523, only pages 501–523 are resent, not the whole file.
  • Session establishment, maintenance and termination, and token management (who may perform a critical operation).
  • Examples: RPC, NetBIOS, PPTP, SQL session handling.

6.9Presentation Layer: Translation, Encryption and Compression

🎓 From the lecture
  • Translation: machine M1 understands language L1 and M2 understands L2 (different code formats). Someone must translate in between: the presentation layer "presents" M1's information in L2.
  • Encryption / decryption: if an unauthorised third person grabs the message in transit, they must not understand it. At the sender, plain text (understandable) is converted to cipher text (non-understandable). At the authorised receiver, the reverse process (decryption) restores the plain text. Both ends know the keys.
  • Compression: make big data smaller, like a ZIP file. There are lossless and lossy kinds.
➕ Details
  • Translation: character codes (ASCII ↔ EBCDIC, Unicode), data formats; sometimes called the "syntax layer".
  • Encryption: symmetric (the same key, e.g. AES, DES) vs asymmetric (public/private keys, RSA). SSL/TLS is often placed here (or between L4 and L7).
  • Compression: lossless (no data lost; ZIP, PNG, GIF, used for text and programs) vs lossy (some detail dropped for a much smaller size; JPEG, MP3, MPEG, used for media).
  • Formats associated with this layer: JPEG, GIF, PNG, MPEG, MIDI, ASCII.

6.10Application Layer Functions

🎓 From the lecture The top layer: 7th from the bottom, 1st from the top. At the sender it is the first layer the data passes through ("data nikalta hai, header lagta hai, neeche jaata hai"). At the receiver it is the last, 7th layer the data reaches. Popular protocols here: HTTP, HTTPS (secure), FTP (file transfer), POP (Post Office Protocol), and SMTP for mail, which is a push protocol. Details come in Chapter 34.
➕ Services provided The interface between the user/application and the network: file transfer and access (FTP), mail services (SMTP, POP3, IMAP), directory services (DNS, LDAP), remote login (Telnet, SSH), the web (HTTP/HTTPS), network management (SNMP), and the Network Virtual Terminal. Device: gateway (it can work at all layers). Note: the browser itself is not the application layer; the protocols it uses are.

🎯 IBPS exam alert
  • "Which layer does routing?" → Network. "Encryption and compression?" → Presentation. "Checkpoints / dialog control?" → Session. "End-to-end, process-to-process delivery?" → Transport. "Framing and MAC?" → Data Link. "Bits to signals?" → Physical.
  • "Switch works at?" → L2. "Router?" → L3. "Hub and repeater?" → L1. "Gateway?" → all layers (often L4–7).
  • Trailer added only at the → Data Link layer. Sender is top-down; receiver is bottom-up.

⚡ Rapid Revision — Chapter 6

  • OSI = 7-layer ISO reference model (1984). Physical → Data Link → Network → Transport → Session → Presentation → Application ("Please Do Not Throw Sausage Pizza Away"). The lecture's focus: DLL, Network, Transport, Application.
  • Encapsulation (sender, top-down): each layer adds a header and treats what came from above as payload; the DLL adds a trailer (FCS/CRC); the physical layer sends bits. Letters inside envelopes.
  • Decapsulation (receiver, bottom-up): only the peer layer opens its own envelope (the network-layer header is read only by the network layer). Routers use only L1–3.
  • L1 Physical: bits ↔ signals (encoding), data rate, line configuration, topology, transmission modes. Hub, repeater.
  • L2 DLL: framing (biscuit pieces), MAC addressing, access control (collisions), flow control ("don't send more than I can receive"), error control (checksum, CRC), hop-to-hop. LLC + MAC sublayers. Switch, bridge.
  • L3 Network: source-to-destination packet delivery, IP addressing, routing (best path via routing tables), packetization, fragmentation. Router.
  • L4 Transport: process-to-process via ports, segments, congestion, flow and error control end to end. TCP, UDP.
  • L5 Session: manage the session, dialog control, synchronisation and checkpoints.
  • L6 Presentation: translation (L1 ↔ L2 code formats), encryption/decryption (plain ↔ cipher text with keys), compression (ZIP; lossless and lossy).
  • L7 Application: the first layer at the sender and the last at the receiver. HTTP, HTTPS, FTP, POP, SMTP (push).
  • PDUs: data → segment → packet → frame → bits. TCP/IP has 4 layers (Application, Transport, Internet, Network Access).
