ICMP (Internet Control Message Protocol)

IP is best-effort: when a router drops a packet, IP alone says nothing. ICMP fills that gap. A router or host that drops a packet sends an ICMP error message back to the original source, saying who dropped it, why, and which packet it was. ICMP also carries query messages, the request/reply pairs behind tools like ping. The exam asks mostly for the message types, the rules on when no error may be sent, and how ping and traceroute use ICMP.

25.0Where ICMP Lives and Why

🎓 From the lecture Another protocol: the Internet Control Message Protocol. As said in ch 22, its importance (priority) is the lowest compared with IGMP, UDP and TCP. It operates in the network layer: IP occupies the major portion, and ICMP sits alongside it ("top-left corner" in the layer diagram). It is used for error handling and for request–reply exchanges.
➕ Placement facts ICMP is a network-layer protocol, but its messages travel inside IP datagrams (IP header Protocol field = 1). It does not correct errors; it only reports them to the original source (the only address the router knows). ICMPv4 is RFC 792; ICMPv6 (RFC 4443) also absorbs ARP and IGMP functions (Neighbour Discovery, MLD).

25.1Error Reporting and Query Messages

🎓 From the lecture 1. Error handling (feedback). A packet goes source → R1 → R2, and at R2 something goes wrong, so R2 discards it. Discarding a host's packet without telling it would be wrong; the source deserves feedback. So R2 sends an ICMP packet back, hop by hop, to the source, which learns that its packet was dropped.
2. Request and reply. The sender sends an ICMP request to the destination to ask for some information; the destination answers with an ICMP reply.

25.2No ICMP Error for a Discarded ICMP Packet

🎓 From the lecture An important rule. If an IP packet is discarded, sending an ICMP report is correct. But what if the packet discarded is itself an ICMP packet?
Suppose R2 drops an ICMP packet and sends an ICMP report towards the source. At R1 the buffer is full, and ICMP has the lowest priority, so R1 drops that report too. R1 must now report to R2 with another ICMP packet; R2 is busy and drops it; R2 reports back to R1; R1 drops it… An endless circle.
Tie a knot: do not generate an ICMP packet when an ICMP packet is discarded.
⚠️ Exam trap: the exact rule The standard (RFC 792/1122) forbids ICMP errors about ICMP error messages. An ICMP query (e.g. an echo request) that is dropped can still produce an error. The full list of cases where no ICMP error is sent:
  • for a datagram that carries an ICMP error message;
  • for a fragment that is not the first fragment;
  • for a datagram with a multicast (or broadcast) destination address;
  • for a datagram with a special source address such as 127.0.0.0 or 0.0.0.0.

25.3ICMP Error Message Format: Who, Why, Which Packet

🎓 From the lecture The source must get the answers to three questions: Who had the nerve to discard my packet? Why was it discarded? Which packet was it (so I can retransmit)?
• Who: the ICMP message rides in an IP datagram whose source IP is the router that discarded it (IR2) and whose destination IP is the original source (IS). Looking at the source IP, the sender knows it was R2's doing.
• Why: the ICMP packet inside has a Type field that names the kind of error (3, 11, 5, 4, 12 …).
• Which: the router gets "a bit violent": it cuts off the head (the header) of the discarded packet, which holds its source and destination IP, and attaches it plus a small part of its data, so the sender can identify the packet and retransmit.
⚠️ Exam trap The data part copied is the original IP header + the first 8 bytes (64 bits) of the original data, not 8 bits as said in the lecture. Those 8 bytes contain the TCP/UDP port numbers (and the TCP sequence number), which tell the source which connection the packet belonged to.
ICMP header: Type (8 bits) | Code (8 bits) | Checksum (16 bits) | rest of header (32 bits) Type = category of message · Code = the specific reason within that type

25.4Destination Unreachable

🎓 From the lecture The sender's packet reaches R1, then R2, and R2 finds the destination is down: the house where the letter must go is locked. The router has many other letters to deliver; it won't wait for the owner to come home with the key. It simply discards the packet and reports type "destination unreachable".
➕ Type 3 codes worth knowing 0 network unreachable · 1 host unreachable · 2 protocol unreachable · 3 port unreachable (sent by the destination host itself, e.g. no process on that UDP port) · 4 fragmentation needed but DF set (used by Path MTU Discovery, ch 22) · 5 source route failed · 13 communication administratively prohibited (firewall).

25.5Time Exceeded

🎓 From the lecture Time exceeded = TTL exceeded (the TTL idea from IPv4). Say the source sends with TTL = 2: it drops to 1 at R1 and to 0 at R2, while the packet is still at a router and has not reached the destination. So R2 discards it and reports "time exceeded": the timer ran out before you reached the destination. Next time the source can send with TTL = 3 and the packet will get through.
➕ Two codes Code 0: TTL reached 0 in transit (sent by a router). Code 1: fragment reassembly time exceeded: the destination did not receive all fragments of a datagram in time, so it discards the pieces it has (sent by the destination host).

25.6Redirection

🎓 From the lecture The source routes its packets the long way: via R2, then R3, then to the destination. Router R2 says "are you joking? Why take such a long road when you can reach the destination directly through R1?" So R2 sends an ICMP redirect message to the source: next time use the shorter route; you will arrive sooner.
➕ How it works in practice A redirect is sent by a router to a host on the same local network when the host has used the router as its next hop but another router on that same network is a better first hop. The router still forwards this packet (it is not discarded); the host updates its routing table for that destination. Redirects go only from routers to hosts, never router to router.

25.7Source Quench

🎓 From the lecture The source is overflowing and fires packets phat-phat-phat, packet after packet, as if it hadn't sent data in years. The router says "ruk, ruk, ruk! Have you gone mad? I have a life too; my buffers are busy, I have other work." It sends an ICMP source quench message: "slow down, send more gently; too much load at once will congest the network."
⚠️ Exam trap Source quench (type 4) is ICMP's congestion / flow-control message and is still asked in exams. But it was deprecated (RFC 6633, 2012): routers no longer send it. Congestion is now handled by TCP's own congestion control (ch 31) and ECN.

25.8Parameter Problem

🎓 From the lecture The source uses strict source routing (Mummy's exact route, ch 22): "go R1, then R2, then the destination, no other road". At R1 it turns out R2 is down. R3 is free and also reaches the destination, but strict routing forbids using it. So the router reports a problem with the parameters the source gave: loosen them (use loose source routing) or change the route (go via R3).
⚠️ Exam trap In the standard, parameter problem (type 12) means a field in the IP header is wrong or ambiguous (e.g. an invalid option or bad header length); the Pointer field shows the bad byte. A strict source route that cannot be followed is reported as destination unreachable, code 5 "source route failed". If a question says "header field error", answer parameter problem.

➕ ping ping host sends ICMP echo request (type 8); a live host answers with echo reply (type 0). It reports reachability, packet loss and round-trip time. A blocked or silent ping does not prove the host is down; many firewalls drop ICMP.
➕ traceroute / tracert Sends packets with TTL = 1, 2, 3 …. The router where TTL hits 0 replies with time exceeded (type 11), revealing itself, hop by hop. The final destination answers with port unreachable (type 3, code 3) (Unix, UDP probes) or echo reply (Windows tracert, ICMP probes), which ends the trace.

25.10Solved Questions ADDED

Solved questions Q1. ICMP is encapsulated in? An IP datagram, protocol number 1.

Q2. Which ICMP message does ping use? Echo request (8) and echo reply (0).

Q3. Which message is returned when TTL reaches 0? Time exceeded (11), code 0.

Q4. A UDP packet reaches a host with no process on that port. Message? Destination unreachable, code 3 (port unreachable).

Q5. Is an ICMP error generated when an ICMP error message is dropped? No. When a non-first fragment is dropped? No. When a multicast datagram is dropped? No.

Q6. What does an ICMP error carry from the original packet? Its IP header + first 8 bytes of data.

Q7. Which ICMP message did routers use for congestion control? Source quench (4).

Q8. To whom is an ICMP error sent? Always to the original source of the datagram.
🎯 IBPS exam alert Remember the type numbers 0, 3, 4, 5, 8, 11, 12; that ICMP reports but does not correct errors; that errors go to the source; that ping = echo, traceroute = TTL + time exceeded; and the four "no ICMP error" cases.

⚡ Rapid Revision — Chapter 25

  • ICMP = network-layer messenger for IP; travels inside IP (protocol 1); lowest priority in the lecture's ordering.
  • Two jobs: error reporting (feedback to the source when a packet is discarded) and query request/reply.
  • Never send an ICMP error about an ICMP error (the endless R1 ↔ R2 loop); also none for non-first fragments, multicast destinations, special addresses.
  • Error message answers Who (source IP = router), Why (Type), Which (original IP header + first 8 bytes of data).
  • 3 Destination unreachable: house locked, router won't wait. 11 Time exceeded: TTL hit 0 at a router (or reassembly timeout).
  • 5 Redirect: "use the shorter route via R1". 4 Source quench: "ruk, ruk, slow down" (deprecated). 12 Parameter problem: bad header field.
  • ping = echo request 8 / reply 0. traceroute = TTL 1, 2, 3 … + time exceeded.
