Presentation Layer

The application at one end produces data; the application at the other end must understand it. The presentation layer sits just below the application and handles the form of the data, not its meaning. It translates between the two machines' formats, encrypts so outsiders can't read it (and can tell who sent it), and compresses so less has to be sent. Its nickname in exam notes is the "translator" of OSI.

33.0Three Jobs of the Presentation Layer

🎓 From the lecture The next layer up. Its important functions are translation, encryption and compression. As the name says, it is about presenting information and data in the right way.

33.1Translation

🎓 From the lecture Machines M1 and M2 are exchanging data and want to get work done together, but M1 uses code format C1 and M2 uses C2.
Real-life version: a person from one region speaks language C1, a person from another region speaks C2, and both are put in one team. They must exchange ideas and finish the job, but neither understands the other. You need a translator in between: "this is what he's trying to say", "and this is his reply". That intermediate translation is the presentation layer's job: presenting what M1 says in a format M2 understands and accepts, and vice versa.
➕ Concrete examples Character codes: ASCII (7-bit), EBCDIC (IBM mainframes), Unicode / UTF-8. Number representation: big-endian vs little-endian byte order. Data structures sent between different systems are encoded in a common syntax such as ASN.1 (with BER), XDR, or today JSON/XML. This is called data representation or "syntax and semantics of information exchanged".

33.2Encryption and Decryption

🎓 From the lecture I don't want anyone who grabs my data in transit to understand it: they may get hold of it, but must not be able to tell what the sender meant. So at the sender, the plaintext is turned into ciphertext using a key: encryption. At the receiver, the valid user must be able to read it, so the ciphertext is turned back into the original plaintext using a key: decryption. An invalid user must not understand it; the valid user must.

33.3Symmetric and Asymmetric Keys: Confidentiality

🎓 From the lecture Symmetric (shared key): sender and receiver have agreed to use the same key for both encryption and decryption.
Asymmetric: two keys: a public key (as the name says, everyone knows it) and a private key (known only to that station/host).
Confidentiality with asymmetric keys: on the way from sender to receiver, anyone who intercepts the data must not understand it. The sender encrypts with the receiver's public key; only the receiver's private key can decrypt. An intruder or third party in between doesn't have the receiver's private key, so it can do nothing: the message stays confidential.

➕ How real systems combine them TLS/HTTPS uses asymmetric cryptography only to agree on a symmetric session key (key exchange, authenticated with certificates), then encrypts all the bulk data with fast symmetric AES. Many textbooks therefore place SSL/TLS at the presentation layer.

33.4Digital Signature (Authentication)

🎓 From the lecture The other variant: a digital signature, for authentication. This time the sender does not use the receiver's public key; it encrypts with its own private key. Only the sender knows that key, so the receiver can be sure the message didn't come from any random person ("aira-gaira"); it came from that very sender. The receiver decrypts with the sender's public key. If the original message comes out correctly, it must have been encrypted with the sender's private key: the message is from the authentic sender.
➕ What a digital signature really guarantees In practice the sender signs a hash (message digest, e.g. SHA-256) of the message, not the whole message. A valid signature gives authentication (who sent it), integrity (not changed: any change breaks the hash) and non-repudiation (the sender can't deny sending it). It does not give confidentiality, since anyone with the public key can verify (read) it. In India, digital signatures have legal validity under the IT Act, 2000.
⚠️ Exam trap: the key-use rule Confidentiality → encrypt with the receiver's public key. Signature → sign with the sender's private key. Want both? Sign with your private key, then encrypt with the receiver's public key.

33.5Compression: Lossless vs Lossy

🎓 From the lecture Compression is a subject of its own; here is the gist. A huge file of many MB or GB: right-click → Compress, and you get a ZIP file. Two kinds:
Lossless (also called data compression): no information is lost; after decompressing you get exactly the original. The compression ratio is lower.
Lossy: sometimes a video is compressed so much you can hardly make out what's happening. The loss of information is clearly visible, because the compression ratio is very high.

Solved questions Q1. Which OSI layer does translation, encryption and compression? Presentation (layer 6).

Q2. Caesar cipher with shift 3: encrypt "HELLO". → KHOOR (a classic symmetric substitution cipher).

Q3. 10 users each need private communication with every other. Keys needed with symmetric crypto? 10 × 9 / 2 = 45. With asymmetric? 2 × 10 = 20.

Q4. For 100 users? Symmetric 4950, asymmetric 200.

Q5. A sends a confidential message to B with public-key crypto. Which key does A use? B's public key. Which key does B use? B's private key.

Q6. To verify A's digital signature, B uses? A's public key.

Q7. JPEG compression is lossy or lossless? Lossy. PNG? Lossless. ZIP? Lossless.

Q8. A 50 MB video becomes 5 MB. Compression ratio? 10 : 1.
🎯 IBPS exam alert Remember the trio translation, encryption, compression for layer 6; AES/DES = symmetric, RSA = asymmetric; public key encrypts for secrecy, private key signs; JPEG/MP3/MPEG are lossy, ZIP/PNG/GIF lossless.

⚡ Rapid Revision — Chapter 33

  • Presentation layer = OSI layer 6: translation, encryption, compression; presents data properly.
  • Translation: M1 speaks code C1, M2 speaks C2 → a translator between two people from different regions (ASCII ↔ EBCDIC, Unicode, byte order).
  • Encryption: plaintext + key → ciphertext (meaningless to intruders); decryption at the receiver gives the plaintext back.
  • Symmetric = one shared key (AES, DES): n(n−1)/2 keys. Asymmetric = public + private (RSA): 2n keys.
  • Confidentiality: encrypt with receiver's public, decrypt with receiver's private.
  • Digital signature: sign with sender's private, verify with sender's public → authentication (+ integrity, non-repudiation).
  • Compression: lossless (no info lost, lower ratio: ZIP, PNG) vs lossy (visible loss, high ratio: JPEG, MP3, MPEG).
