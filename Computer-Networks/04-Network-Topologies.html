Chapter 4

Network Topologies

Chapter 3 showed that a single link is either dedicated (point-to-point) or shared (multipoint). A topology combines many such links into a whole network. The choice decides the cost (number of cables), the reliability (what happens when a link or device fails), and later which access protocols are needed.

4.0What is a Topology?

Topology: the structure or arrangement that defines how the nodes of a network are connected to each other.
🎓 From the lecture A network contains many nodes. The topology answers in what fashion they are connected: "it's trying to define the structure, how the nodes are connected to each other". Many types exist, and questions on them carry high weightage.
➕ Physical vs logical topology Physical topology: the actual layout of cables and devices. Logical topology: how data actually flows. Example: a hub-based star is physically a star but logically a bus (every frame reaches everyone). A Token Ring wired to a central MAU is physically a star but logically a ring.

4.1Point-to-Point Topology

🎓 From the lecture The most basic, "primitive" topology: a dedicated link between station 1 and station 2. Each takes turns as sender and receiver. It is simple, durable and low-cost, and works well locally, but it is not convincing at a large or global scale. The next topologies cost more because they need many cables.

4.2Mesh Topology

Mesh (full mesh): every node has a dedicated point-to-point link to every other node in the network.
🎓 From the lecture Node (station, machine, device) A connects through a dedicated link to B, C, D and E. B also connects to everyone, and so on: each node is connected to every other node. All those cables make it expensive and clumsy. With 10, 20 or 25 nodes the diagram becomes very complex.
Advantages ADDEDDisadvantages
  • Dedicated links: no traffic sharing, no collisions
  • Robust / fault-tolerant: if one link fails, others take over
  • Privacy and security: data goes directly to the receiver
  • Easy to isolate faults
  • Huge cabling and I/O ports, so very expensive
  • Complex installation and reconfiguration
  • Bulky wiring; many links are rarely used

Used where reliability is critical: WAN and Internet backbones, connections between bank data centres, military networks. A partial mesh (only some nodes fully connected) is the common compromise.

4.3Numerical: Number of Links in Mesh, n(n−1)/2

Essential formulas
Full mesh with n devices: Number of links (duplex) = n(n − 1) / 2 I/O ports per device = n − 1 Total ports in the network = n(n − 1) Links if simplex (one-way) = n(n − 1)
Numerical (lecture) n = 5: links = 5 × 4 / 2 = 20 / 2 = 10. The lecture counts all 10 on the diagram.
n = 10: links = 10 × 9 / 2 = 90 / 2 = 45.
Conclusion: doubling the devices from 5 to 10 increased the links 4.5× (10 to 45), more than 4 times. The cost grows roughly with n².
More practice (added) n = 6 → 15 links, 5 ports per device, 30 ports in total. n = 8 → 28 links. n = 20 → 190 links.
Reverse: a mesh has 21 links; how many devices? n(n−1)/2 = 21 → n(n−1) = 42 → n = 7.

4.4Star Topology

Star: every device has a dedicated link only to a central device (hub or switch). Devices are not linked directly to each other; all traffic passes through the centre.
🎓 From the lecture
  • All nodes connect to a central hub, a single point of contact. They are not interconnected as in mesh.
  • It needs far fewer links than mesh, so it is not expensive and not complex.
  • If B sends a message to A, it goes through the hub, which sends it to everyone (C and D too), but only A, the destination, reads it.
  • If an ordinary node goes down, the others are not affected. But if the central hub goes down, the whole network crashes. That is its biggest disadvantage.
Advantages ADDEDDisadvantages
  • Cheaper than mesh: one link and one port per device
  • Easy to install, add or remove devices
  • Easy fault isolation; one node failure doesn't affect others
  • Centralised management
  • The hub/switch is a single point of failure
  • More cable than bus or ring
  • Performance depends on the central device
⚠️ Exam trap (Hub vs switch) The lecture's "goes to everyone" behaviour is true for a hub (it broadcasts every frame, so it is logically a bus with one collision domain). A switch sends a frame only to the destination port (Chapter 9). Modern office LANs are switched stars, the most widely used LAN topology today.

4.5Bus Topology

Bus: all devices connect to one shared backbone cable (the bus) through drop lines and taps. The ends of the cable carry terminators. It is a multipoint configuration.
🎓 From the lecture
  • A single cable (the transmission medium) is laid out, with a terminator marking the end ("the link won't extend after this").
  • Every station connects to the bus through a drop line. It is a multipoint, shared link / shared channel.
  • The biggest problem is collision: if A and B send data at the same time, the signals collide and both are destroyed, "no use". Collision detection and avoidance (CSMA/CD, CSMA/CA) come in the Data Link Layer chapters, where bus topology is used heavily.
Advantages ADDEDDisadvantages
  • Least cabling: one backbone, so cheapest
  • Easy to install for small networks
  • Easy to extend by tapping in
  • Collisions; performance drops as nodes increase
  • A backbone break / fault brings the whole network down (single point of failure)
  • Hard to find faults; limited cable length and number of nodes
  • Signal reflection without terminators

Examples: early Ethernet over coaxial cable (10Base2 "thinnet", 10Base5 "thicknet").

4.6Ring Topology

Ring: each device connects to exactly two neighbours, forming a closed loop. Data travels in one direction from device to device until it reaches the destination. Each device has a repeater that regenerates the signal.
🎓 From the lecture The nodes form a ring structure. A token circulates around the whole ring (detailed in Token Ring, Chapter 18). As the packet or token keeps revolving, its strength can fall, so repeaters attached to every host boost it back to the original strength.
Advantages ADDEDDisadvantages
  • No collisions: an orderly token-based turn
  • Equal access for all nodes; predictable performance under heavy load
  • Easy to locate faults
  • A single node or link break disrupts the whole ring (unidirectional)
  • Adding or removing a node is difficult: the ring must be broken (lecture: "thoda mushkil, thoda expensive")
  • Delay grows with the number of nodes

Fix: a dual ring (two counter-rotating rings, as in FDDI and SONET) keeps working if one ring breaks. Examples: IBM Token Ring (IEEE 802.5), FDDI.

4.7Number of Links: Mesh vs Star vs Bus

🎓 From the lecture
  • Mesh: n(n−1)/2 links.
  • Star: the count drops sharply. Each device has one link to the central point, so n devices need n links.
  • Bus: even fewer, only one link: the shared channel, shared link or backbone.
  • Ring's big drawback: adding a new node to an existing ring is difficult and expensive.

4.8Tree Topology

Tree (hierarchical / extended star): a hierarchy of stars. A central (root) hub connects to secondary hubs, which connect to further hubs or to devices, top-down like a tree.
🎓 From the lecture Tree topology covers ring's disadvantage (difficulty adding nodes). It follows a top-down approach, like a tree: a root, its children, their children, and so on. The most important point is the root point of contact, the central hub. At the next level down are the secondary hubs (SH), then further secondary hubs, and devices connect to these hubs. Adding a device is very easy: just connect it to a hub.
Advantages ADDEDDisadvantages
  • Scalable; easy to add segments and devices
  • Hierarchical, so it suits organisations (HQ → zone → branch) and campuses
  • Fault isolation per branch
  • Root hub failure cuts off the whole network (the backbone is critical)
  • More cabling; complex configuration at scale

🎯 IBPS exam alert
  • "Most reliable / fault-tolerant" → mesh. "Most expensive" → mesh. "Least cable" → bus.
  • "Central device failure brings down the network" → star. "Needs terminators" → bus. "Uses a token" → ring. "Hierarchy of stars" → tree.
  • "Most commonly used LAN topology today" → star (switched Ethernet). "Number of cables for 7 computers in a mesh" → 7×6/2 = 21.

⚡ Rapid Revision — Chapter 4

  • Topology = how nodes are connected (physical layout vs logical flow; a hub star is logically a bus).
  • Point-to-point: dedicated link between 2 stations; simple and cheap, local only.
  • Mesh: every node to every node; links = n(n−1)/2 (5 → 10, 10 → 45), ports per device = n − 1. Robust, private, no collisions, but most expensive and clumsy.
  • Star: all to a central hub, so n links. Cheap and easy; a hub broadcasts to all but only the destination reads it. Central hub down → network crashes.
  • Bus: one backbone + drop lines + terminators; multipoint shared channel; collisions (CSMA/CD later); backbone failure kills everything.
  • Ring: a loop with a circulating token; repeaters boost the signal; no collisions; adding a node is hard; one break disrupts it (dual ring / FDDI fixes this).
  • Links: mesh n(n−1)/2 › star n = ring n › bus 1.
  • Tree: root central hub → secondary hubs → devices; easy to add nodes; the root is critical. Hybrid = a mix (the Internet).
