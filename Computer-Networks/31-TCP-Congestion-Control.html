Chapter 31

TCP Congestion Control

Flow control (chapter 13, and TCP's window) protects the receiver. Congestion control protects the network in between. A TCP sender doesn't know how much capacity the path has, so it probes. It starts small, grows exponentially (slow start) until a threshold, then grows linearly (congestion avoidance). When packets start getting lost, it cuts back sharply and starts probing again. The size it is allowed to have outstanding is the congestion window (cwnd), counted in MSS units.

31.0What Congestion Means

🎓 From the lecture In the transport layer, talking about TCP without congestion would be wrong; many questions come from it. "The network is congested" works like "the bus is congested": it is full. Every buffer in use on the network is filled to capacity. If any host now dares to send a packet or segment, it is brutally dropped or discarded. When packets in the queue are being cut down like this at a high rate, congestion is severe, and congestion control must come into action.

31.1Congestion Control Phases and Congestion Detection

🎓 From the lecture Three phases: slow start, congestion avoidance, and congestion detection. Detection has two cases:
Case 1: Time-out. The sender sends a packet and starts its timer; the timer runs out and no ACK has come. There is a high possibility of congestion: the packet was very likely dropped by the network.
Case 2: Three duplicate ACKs. The sender receives three duplicate acknowledgements. There is a low possibility of congestion (not as high as a time-out).
➕ Why 3 duplicate ACKs means "mild" TCP's ACK is cumulative. If segment 5 is lost but 6, 7 and 8 arrive, the receiver answers each with "ACK 5" again: three duplicate ACKs. So later segments are getting through; only one was lost, and the network is still working. A time-out means nothing came back at all, which is far worse. On 3 duplicate ACKs, TCP resends the missing segment at once, without waiting for the timer: fast retransmit.

31.2Slow Start Phase

🎓 From the lecture Plot the congestion window (cwnd) in MSS on one axis and time on the other. In slow start the window begins at 1 MSS (= 2⁰): only one segment fits. After 1 round trip it becomes 2 MSS (2¹); in general after n round trips it is 2ⁿ MSS: 1 → 2 → 4 → 8 → 16 …, growing exponentially. It can't grow for ever; there is a limit.
⚠️ Exam trap "Slow" start isn't slow at all; it doubles every RTT. It is called slow only because it starts from a single segment instead of a full window. Strictly, cwnd grows by 1 MSS for every ACK received, which doubles it each round trip.

31.3Threshold and Congestion Avoidance Phase

🎓 From the lecture The limit is the threshold: receiver window size ÷ 2. When cwnd grows to half the receiver's window (its buffer size), slow start ends and the congestion avoidance phase begins.
In congestion avoidance cwnd no longer doubles; it grows linearly, only +1 per RTT (+1, +1, +1 …).
Up to what? The full receiver window. Congestion avoidance takes you from half the receiver window to the full receiver window one step at a time. Then it stops, and cwnd stays constant at the receiver window size from then on.
Slow start : cwnd = 1, 2, 4, 8 … (×2 per RTT) while cwnd < threshold Threshold (initial) : rwnd / 2 Congestion avoidance : cwnd = threshold + 1, + 2 … (+1 per RTT) until cwnd = rwnd Data the sender may send = min(cwnd, rwnd)

➕ AIMD: the big picture In congestion avoidance TCP does Additive Increase (+1 MSS per RTT), and on loss Multiplicative Decrease (halve). The result is the well-known sawtooth graph of cwnd. AIMD is what makes many TCP flows share a link fairly. The first congestion-control TCP was Tahoe (1988: slow start, congestion avoidance, fast retransmit); Reno added fast recovery. Today's default in Linux is CUBIC; Google uses BBR.
⚠️ Exam trap The new threshold is half of cwnd at the moment congestion was detected, not half of the old threshold and not half the receiver window (rwnd ÷ 2 is only the lecture's initial threshold). Also note: if slow start would overshoot the threshold (8 → 16 with threshold 10), cwnd is capped at the threshold and congestion avoidance takes over from there.

➕ General congestion-control techniques Open loop (prevention): retransmission, window, acknowledgement, discarding and admission policies; traffic shaping with the leaky bucket (smooth constant output) and token bucket (allows bursts up to the saved tokens). Closed loop (removal): back-pressure, choke packets (e.g. ICMP source quench, ch 25), implicit signalling (TCP noticing losses), explicit signalling (ECN bits set by routers). Router queue policies: tail drop, RED (Random Early Detection).

31.6Solved Numericals ADDED

Solved numericals Q1. Receiver window = 64 KB, MSS = 2 KB, no losses. Initial threshold, and how many RTTs until the full window is reached?
rwnd = 32 MSS → threshold = 16 MSS (32 KB). Slow start: 1 → 2 → 4 → 8 → 16 takes 4 RTTs. Congestion avoidance: 16 → 32 takes 16 RTTs. Total 20 RTTs.

Q2. cwnd = 20 MSS when a timeout occurs. New threshold and cwnd over the next 6 RTTs?
Threshold = 10, cwnd = 1 → 2 → 4 → 8 → 10 (capped at the threshold) → 11 → 12.

Q3. Same, but 3 duplicate ACKs with TCP Reno?
Threshold = 10, cwnd = 10 → 11 → 12 → 13 … (linear).

Q4. With threshold 8 MSS, starting from cwnd 1, what is cwnd after 6 RTTs? 1 → 2 → 4 → 8 → 9 → 10 → 11 MSS.

Q5. cwnd = 12 KB, rwnd = 8 KB. How much may the sender transmit? min(12, 8) = 8 KB.

Q6. Which event indicates more severe congestion: timeout or 3 duplicate ACKs? Timeout.
🎯 IBPS exam alert Remember three words: exponential (slow start), linear (congestion avoidance), halve (on congestion). And: slow start begins at 1 MSS; timeout → back to 1; 3 dup ACKs → fast retransmit (Reno: fast recovery to half).

⚡ Rapid Revision — Chapter 31

  • Congestion = network buffers full ("bus is congested") → packets brutally dropped.
  • Phases: slow start, congestion avoidance, congestion detection.
  • Detection: timeout = high possibility of congestion; 3 duplicate ACKs = low possibility (fast retransmit).
  • Slow start: cwnd = 1 MSS, then ×2 per RTT (2ⁿ): 1, 2, 4, 8, 16 … until the threshold = rwnd / 2.
  • Congestion avoidance: +1 MSS per RTT from rwnd/2 up to the full rwnd, then constant.
  • On timeout: threshold = cwnd/2, cwnd = 1 → slow start. On 3 dup ACKs: threshold = cwnd/2; Tahoe cwnd = 1, Reno cwnd = threshold.
  • Send window = min(cwnd, rwnd). AIMD → sawtooth. Flow control protects the receiver; congestion control protects the network.
