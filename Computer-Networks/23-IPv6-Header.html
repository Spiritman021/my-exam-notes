IPv6 Header Format

IPv6 was designed to fix IPv4's two biggest problems: running out of addresses (32 bits → 128 bits) and making routers do too much work per packet. So its header is fixed at 40 bytes and much simpler: there is no header-length field, no checksum, and no fragmentation fields in the base header. Anything optional is moved into separate extension headers that are chained one after another using the Next Header field.

23.0Why IPv6, and How to Approach It

🎓 From the lecture "We just finished one war (the IPv4 header, field by field) and now you've started another!" Don't worry: no great effort is needed. Some names are different but the work is the same as in IPv4, and there are a few new things. Most questions are asked on IPv4; IPv6 is asked only up to a point, and that is what is covered here.
➕ Why IPv6 was needed IPv4's 2³² ≈ 4.3 billion addresses ran out (IANA's free pool was exhausted in 2011). IPv6 gives 2¹²⁸ ≈ 3.4 × 10³⁸ addresses. It also brings a simpler fixed header (faster routing), built-in support for IPsec, auto-configuration (SLAAC), no need for NAT, better multicast, and flow labels for real-time traffic. Standard: RFC 2460, now RFC 8200.

23.1Base (Fixed) Header Size

🎓 From the lecture A common misunderstanding: "Sir, IPv6 addresses are 128 bits, so how can you write 32 bits as the width?" The 32 bits refers only to the first two horizontal rows: row 1 = 4 + 8 + 20 = 32 bits, row 2 = 16 + 8 + 8 = 32 bits. Then the source and destination addresses are 128 + 128 = 256 bits.
Total = 32 + 32 + 256 = 320 bits = 40 bytes. This part is called the base header or fixed header: it is always there. After it come the extension headers (new; not seen in IPv4) and then the data / payload.
⚠️ Exam trap The base header is 320 bits = 40 bytes (the transcript slips once and says "320 bytes"). It is fixed: unlike IPv4 (20–60 bytes), there is no header-length field because the size never changes. Exams love: IPv4 header 20–60 B, IPv6 header 40 B fixed.

23.2Version and Traffic Class (Priority)

🎓 From the lecture Version (4 bits) = 0110 → IPv6.
Priority / Traffic Class: the same job as IPv4's TOS field: give the packet a priority. It is shown as 8 bits, of which only 4 are used for priority (the rest reserved), giving 0 to 15. The bigger the number, the higher the priority and the faster it should be handled during congestion (the ambulance again).
• 0 – 7: for congestion-controlled traffic
• 8 – 15: for non-congestion-controlled traffic, which gets the higher priority values
Priority (0–7)Congestion-controlled traffic
0no specific traffic
1background data (e.g. news)
2unattended data transfer (e.g. e-mail)
3, 5reserved
4attended bulk transfer (e.g. FTP)
6interactive traffic (e.g. Telnet)
7control traffic (routing, network management)
➕ What "uncontrolled" means Congestion-controlled traffic (TCP) slows down when the network is busy, so it can tolerate delay. Non-congestion-controlled traffic is real-time audio/video (often UDP): it won't slow down and late packets are useless. Within 8–15, the higher numbers mark data that should be discarded last (e.g. high-quality video), the lower ones data that may be discarded first.
⚠️ Exam trap The 4-bit 0–15 priority scheme comes from the original IPv6 draft (RFC 1883) and older textbooks (Forouzan). The current standard (RFC 2460 / 8200) uses the full 8-bit Traffic Class as DSCP (6 bits) + ECN (2 bits), exactly like IPv4's modern TOS byte. With the 4-bit priority the flow label was 24 bits; with the 8-bit traffic class it is 20 bits. Most exams follow the current layout: 4 + 8 + 20 = 32.

23.3Flow Label

🎓 From the lecture Between source and destination there can be many routes and many flows. IP is datagram style: any packet can take any path, so packets can arrive out of order and reliability drops (recall the datagram vs virtual-circuit discussion). For real-time data, where loss must be low and delivery fast, give all packets of one flow the same flow label: "treat these specially". It works like a virtual circuit: the handling is set up in advance (like a reservation) and routers treat every packet of the flow the same way.
➕ Precise definition Flow label = 20 bits. A flow is identified by (source address, destination address, flow label). Routers can keep per-flow state and forward the whole flow along the same path with the same QoS, without looking deeper into the packet. Flow label 0 = not part of any special flow.

23.4Hop Limit and Payload Length

🎓 From the lecture Hop Limit (8 bits): a limit on how many hops the packet may take: exactly what TTL did in IPv4. "Naam alag, kaam wahi" (different name, same job).
Payload Length (16 bits): the size of the payload.
➕ Payload Length precisely It counts everything after the 40-byte base header: extension headers + upper-layer data, maximum 65 535 bytes. (IPv4's Total Length included the header; IPv6's does not, because the base header is always 40.) Larger packets, jumbograms up to 4 GB, use a hop-by-hop option and set Payload Length to 0.

23.5Next Header and Extension Headers

🎓 From the lecture Next Header holds a number saying which header comes after the base header. Extension headers give additional functionality; they are not part of the fixed/base header, and which ones you add (and how many) is up to you. If Next Header = 0, a hop-by-hop options extension header follows, and after it the payload.
Next Header valueExtension headerPurpose (lecture)
0Hop-by-hop optionsspecial information every router on the path must read and process
43Routingthe source chooses which routers the packet passes through (like IPv4 source routing)
44Fragmentfragmentation information, if the packet was fragmented
51Authentication (AH)authentication information
50Encapsulating Security Payload (ESP)security / encryption of the payload
60Destination optionsinformation meant only for the destination; routers on the way don't process it
59No next headernothing follows
➕ More about extension headers Next Header also names the upper-layer protocol at the end of the chain, using the same numbers as IPv4's Protocol field: 6 = TCP, 17 = UDP, 58 = ICMPv6. Recommended order: hop-by-hop → destination options → routing → fragment → AH → ESP → destination options → upper layer. Only the hop-by-hop header is examined by every router; the rest are processed by the destination (or by routers named in a routing header).
⚠️ Exam trap "Destination options" means information for the destination to process (it is not encryption). Confidentiality comes from ESP. And in IPv6 only the source fragments (using the fragment header); routers never fragment. The minimum link MTU in IPv6 is 1280 bytes.

23.7IPv6 Addresses: Notation, Types & Transition ADDED

Notation: 128 bits written as 8 groups of 4 hex digits (16 bits each), separated by colons: 2001:0db8:0000:0000:0008:0800:200c:417a.
Rule 1, drop leading zeros in a group: 0db8 → db8, 0008 → 8, 0000 → 0.
Rule 2, replace ONE run of all-zero groups with :: (only once per address, the longest run; if tied, the leftmost).
full : 2001:0db8:0000:0000:0008:0800:200c:417a rule 1 : 2001:db8:0:0:8:800:200c:417a rule 2 : 2001:db8::8:800:200c:417a loopback : 0:0:0:0:0:0:0:1 → ::1 unspecified: 0:0:0:0:0:0:0:0 → ::
Type / prefixMeaning
Unicast, multicast, anycastthe three types; no broadcast in IPv6. Anycast = delivered to the nearest member of a group
2000::/3global unicast (public, like IPv4 public addresses)
fe80::/10link-local (every interface auto-configures one; never routed)
fc00::/7unique local (like IPv4 private addresses)
ff00::/8multicast (ff02::1 = all nodes, ff02::2 = all routers)
::1 / ::loopback / unspecified
::ffff:a.b.c.dIPv4-mapped IPv6 address
➕ IPv4 → IPv6 transition Dual stack: a host runs both IPv4 and IPv6. Tunnelling: IPv6 packets travel inside IPv4 packets across IPv4-only networks (protocol 41; 6to4, Teredo). Header translation: NAT64/DNS64 converts between the two when one side speaks only IPv6.

23.8Solved Questions ADDED

Solved questions Q1. Size of the IPv6 base header? 40 bytes (320 bits), fixed.

Q2. Compress 2001:0DB8:0000:0000:0008:0800:200C:417A. → 2001:db8::8:800:200c:417a.

Q3. Compress FE80:0000:0000:0000:0202:B3FF:FE1E:8329. → fe80::202:b3ff:fe1e:8329 (a link-local address).

Q4. Compress 2001:db8:0:0:1:0:0:1. Two zero runs of equal length → compress the leftmost: 2001:db8::1:0:0:1. Writing 2001:db8::1::1 is invalid (:: used twice).

Q5. A packet has a 40-byte base header, an 8-byte hop-by-hop header and 1000 bytes of TCP data. Payload Length? 8 + 1000 = 1008.

Q6. Which IPv4 fields were removed in IPv6? HLEN, Identification, Flags, Fragment Offset, Header Checksum, Options (and TOS/TTL/Protocol were renamed).

Q7. How many bits in the flow label and in the hop limit? 20 and 8.
🎯 IBPS exam alert One-liners: IPv6 address = 128 bits, written as 8 × 16-bit hex groups; base header 40 bytes; no checksum, no broadcast; TTL → Hop Limit; Protocol → Next Header; loopback ::1; new address type anycast; IPv6 uses ICMPv6 Neighbour Discovery instead of ARP.

⚡ Rapid Revision — Chapter 23

  • "Naam alag, kaam wahi": most IPv6 fields are renamed IPv4 fields, plus a few new ideas.
  • Base/fixed header = row 1 (4 + 8 + 20) + row 2 (16 + 8 + 8) + 128 + 128 = 320 bits = 40 bytes, always.
  • Version 0110. Traffic Class = priority like TOS (lecture: 0–7 congestion-controlled, 8–15 real-time; current standard: DSCP + ECN).
  • Flow Label (20 bits): same label for every packet of a real-time flow → virtual-circuit-like special treatment.
  • Hop Limit (8) = TTL. Payload Length (16) = everything after the base header.
  • Next Header (8): which extension header or upper protocol follows: 0 hop-by-hop, 43 routing, 44 fragment, 51 AH, 50 ESP, 60 destination options, 59 none, 6 TCP, 17 UDP, 58 ICMPv6.
  • Removed vs IPv4: HLEN, fragmentation fields, checksum, options. Only the source fragments; min MTU 1280.
  • Addresses: 8 hex groups; drop leading zeros; one ::; ::1 loopback; unicast/multicast/anycast, no broadcast.
