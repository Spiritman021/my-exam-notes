IGMP (Internet Group Management Protocol)

Multicast (class D, 224.0.0.0 – 239.255.255.255, ch 19) sends one stream to a whole group, like the festival WhatsApp group of ch 16. But a router has to know whether anyone on its LAN wants that group before it bothers forwarding the stream there. IGMP is how hosts tell their local router "I've joined group G" and "I've left". It manages membership only; moving multicast traffic between routers is the job of multicast routing protocols such as PIM.

26.0IGMP in the Lecture: Purpose and IGMPv1 Packet

🎓 From the lecture Not many questions are asked on IGMP; knowing this much is more than enough. IGMP = Internet Group Management Protocol. The key thing to remember is the kinds of communication involved: one-to-one (unicast) and one-to-many (multicast).
IGMPv1 packet format: it runs from bit 0 to 31, two 32-bit slots, so the whole packet is 8 bytes.
  • Version = 1
  • Type
  • Unused bits
  • Checksum: 16 bits, computed the same way as before (ch 14)
  • and the "chhupa rustam" (hidden hero) field: the group address, 32 bits, the multicast group the message is about.
⚠️ Exam trap IGMP itself is a multicast protocol: it exists only to manage group membership. It does not set up unicast communication (unicast needs no group management). The precise one-liner: "IGMP is used by hosts and adjacent routers to establish multicast group memberships." In IGMPv2 the first byte is a single 8-bit Type field and the unused byte becomes Max Response Time.

26.1What IGMP Really Does ADDED

IGMP: a network-layer protocol (IP protocol number 2) by which hosts report their multicast group memberships to their directly connected (local) multicast router, and the router periodically checks whether any members are still there.
➕ Key facts
  • Scope is local: IGMP messages are sent with TTL = 1 and never cross a router.
  • The router does not track which hosts are members, only whether at least one member of each group exists on each interface.
  • IGMP is not a routing protocol. Between routers, multicast trees are built by PIM (Protocol Independent Multicast), DVMRP or MOSPF.
  • Applications: IPTV, live video, stock tickers, software distribution, online gaming, routing protocols themselves (OSPF uses 224.0.0.5/6).
  • IPv6 equivalent: MLD (Multicast Listener Discovery), carried in ICMPv6 (MLDv1 ≈ IGMPv2, MLDv2 ≈ IGMPv3).

The life cycle 1. Join: an application wants group G; the host sends an unsolicited membership report for G at once. The router starts forwarding G onto the LAN.
2. Monitor: the router sends periodic general queries. Each host waits a random delay before reporting; if it hears another host report G first, it suppresses its own report (the router only needs one answer per group). This is called report suppression.
3. Leave: (v2) the host sends leave group; the router sends a group-specific query; if nobody reports within the timeout, the router stops forwarding G. (In v1 there is no leave message; the router simply times the group out after several unanswered queries.)

26.4Delivering Multicast on a LAN: MAC Mapping & Snooping ADDED

IPv4 multicast → Ethernet MAC: take the fixed prefix 01:00:5E, set the next bit to 0, and copy the low-order 23 bits of the group IP address. (A class D address has 28 variable bits, so 5 bits are lost: 2⁵ = 32 different groups share each MAC address.)
224.1.1.1 → low 23 bits: (1 AND 0x7F).1.1 = 01.01.01 → 01:00:5E:01:01:01 239.129.1.1 → 129 = 1000 0001 → drop the top bit → 0000 0001 → 01:00:5E:01:01:01 (same MAC!) 224.0.0.251 → 01:00:5E:00:00:FB (mDNS)
➕ Why the overlap matters Because 32 groups share a MAC, a NIC may accept frames for a group it did not join; the IP layer then checks the full group address and discards the extras. (IPv6 maps multicast to 33:33 + the low 32 bits.)
➕ IGMP snooping A plain layer-2 switch floods multicast frames out of every port, like broadcast. With IGMP snooping, the switch listens to IGMP reports and leaves passing through it and forwards each group only to the ports where members are. This is essential for IPTV on switched LANs.

Solved questions Q1. IGMP is used for? Managing multicast group membership between hosts and their local router.

Q2. IP protocol number of IGMP? 2.

Q3. Size of an IGMPv1 message? 8 bytes.

Q4. Which IGMP version introduced the leave-group message? IGMPv2. Source-specific multicast? IGMPv3.

Q5. To which address does a router send a general query? 224.0.0.1 (all hosts). A v2 leave goes to? 224.0.0.2 (all routers).

Q6. Ethernet MAC for group 230.10.20.30? 10 = 0000 1010 (top bit already 0) → 01:00:5E:0A:14:1E.

Q7. Which switch feature limits multicast flooding? IGMP snooping.

Q8. IPv6 replacement for IGMP? MLD (Multicast Listener Discovery).
🎯 IBPS exam alert Typical MCQs: "IGMP works at which layer?" (network), "IGMP is used for?" (multicasting / group management), "class D addresses are for?" (multicast), and "which protocol is used for IPTV group joins?" (IGMP).

⚡ Rapid Revision — Chapter 26

  • IGMP = Internet Group Management Protocol: hosts tell their local router which multicast groups they belong to. Network layer, IP protocol 2, TTL 1.
  • Lecture: unicast (1→1) and multicast (1→many); IGMPv1 packet = Version (1) + Type + Unused + Checksum (16) + Group address (32, the "chhupa rustam") = 8 bytes.
  • Messages: general query (→ 224.0.0.1), group-specific query, membership report (→ group), leave (→ 224.0.0.2, v2+).
  • Join = unsolicited report; monitor = periodic queries + report suppression; leave = leave message + group-specific query.
  • v1 query/report · v2 + leave, max response time, querier election · v3 + source filtering (SSM).
  • Multicast MAC = 01:00:5E + low 23 bits → 32 groups per MAC. Switches use IGMP snooping.
  • Not a routing protocol (that's PIM). IPv6 uses MLD.
