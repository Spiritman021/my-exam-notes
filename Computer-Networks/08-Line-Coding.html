Chapter 8

Line Coding

Chapter 7's media carry signals, but the physical layer receives bits (Chapter 6.4). Line coding is the rule that converts a sequence of 1s and 0s into a digital signal (voltage levels and transitions) that can go onto the wire.

8.0What is Line Coding, and Why?

Line coding: the process of converting digital data (bits) into a digital signal. Each bit pattern is represented by voltage levels and/or transitions.
🎓 From the lecture At the physical layer we finally have a sequence of 1s and 0s that must be encoded. Digital signals have two levels: 1 = high and 0 = low. Line coding is simply the rule for "what to draw when I see a 1, and what to draw when I see a 0". (Real signals aren't perfect square waves, but we draw them that way.)
➕ What a good line code must provide
  • Self-synchronisation (clock recovery): a long run of identical bits (0000…) gives no transitions, so the receiver's clock drifts. Codes with a transition in every bit (Manchester) carry their own clock.
  • No DC component / no baseline wandering: a long run at one level shifts the receiver's average and causes errors.
  • Built-in error detection: some codes make certain patterns illegal.
  • Low bandwidth and noise immunity.
Types: unipolar (0 and +V), polar (+V and −V: NRZ, RZ, Manchester), bipolar (+V, 0, −V: AMI).

8.1Manchester Encoding

Manchester encoding: each bit is split into two halves, with a transition in the middle of every bit. The direction of the mid-bit transition tells the bit value. Because every bit has a transition, the signal is self-clocking.
🎓 From the lecture — "Z" and "reverse Z"
  • Bit 1 = high → low: start high, drop to low mid-way. Draw it like a "Z". The first state is the bit itself (1 = high).
  • Bit 0 = low → high: start low, rise mid-way, a "reverse Z".
  • Logic, not rote memory: "seeing a 1, the starting state is 1 (high), then go to 0. Seeing a 0, start at 0 (low), then go up."
  • If two identical bits come together (1 1 or 0 0), there is a gap at the bit boundary; just connect it with a vertical line. Whenever you must add a connecting line, the two bits are the same. When the bits change (1→0 or 0→1), the waveform is continuous with no extra line. This rule catches drawing mistakes.
⚠️ Exam trap (Which convention?) There are two conventions. The lecture uses G.E. Thomas (1 = high→low). IEEE 802.3 (Ethernet) uses the opposite: 0 = high→low, 1 = low→high. Forouzan's textbook also uses the IEEE form. In an MCQ, read the convention stated; if none is given, mention which you assume. The key fact holds either way: there is always a transition in the middle of each bit.
➕ Properties Self-synchronising; no DC component. But it needs twice the bandwidth (baud rate = 2 × bit rate). Used in 10 Mbps Ethernet (10Base-T).

8.2Differential Manchester Encoding

Differential Manchester: there is always a transition in the middle of every bit (used for the clock). The bit value is shown by the presence or absence of a transition at the start of the bit: 0 → transition at the start and 1 → no transition at the start (standard convention). So a bit is encoded relative to the previous bit, not by an absolute level.
🎓 From the lecture — four "options"
  • For 1, both shapes are allowed: Z (option 1) and reverse Z (option 2).
  • For 0, take the same two shapes and add a connecting line on the LEFT (at the start of the bit): option 3 (Z with a left bar) and option 4 (reverse Z with a left bar). "Always the left. Never get confused about this in your life."
  • The left bar is exactly the transition at the start of a 0.

8.3Example: Differential Manchester Encoding

🎓 From the lecture — rules for choosing the option
  1. First bit: free choice (the lecture takes option 1 for the first 1).
  2. 1 → 0: use the 0-option that extends the previous shape. After option 1 comes option 3; after option 2 comes option 4. "Whatever it's the extension of, use that one."
  3. 0 → 0: repeat the same 0-option (option 3 → option 3). It joins continuously, with no extra connecting line needed; this is an advantage of differential Manchester.
  4. 0 → 1: "the twist": go crosswise, using the opposite shape. After option 3 comes option 2 (reverse Z); after option 4 comes option 1.
The lecture's worked sequence covers all four options. Simply put, every rule above is "make the waveform continuous at the boundary when the next bit is 1, and jump at the boundary when the next bit is 0".
Worked example (generated): bits 1 0 0 0 1 0 1, assuming the line was HIGH before the first bit Check each bit: the first 1 has no jump at its start (it stays high, then falls mid-bit, option 1). Each 0 has a jump at its start. Each 1 has no jump at its start. Every bit has a mid-bit transition.
Decoding rule: look only at the bit boundaries. A transition means 0; no transition means 1.
➕ Why use differential Manchester? Since it encodes changes, not absolute levels, it still works if the two wires are swapped (polarity inversion), and it is more noise-tolerant. Used in IEEE 802.5 Token Ring. Like Manchester, it needs 2× bandwidth.

8.5Bit Rate vs Baud Rate, Block Coding, Digital-to-Analog ADDED

Bit rate = bits sent per second (bps). Baud rate (signal / modulation rate) = signal elements (symbol changes) per second. Baud ≤ bit rate for multilevel schemes, but baud = 2 × bit rate for Manchester and differential Manchester.
Numericals Q1. 10 Mbps Ethernet uses Manchester. Baud rate? Two signal changes per bit, so 20 Mbaud (and about 20 MHz bandwidth is needed).
Q2. A signal with 4 levels (2 bits per symbol) at 1000 baud. Bit rate = 1000 × log₂4 = 2000 bps.
Q3. Bit rate 9600 bps with 16-QAM (log₂16 = 4 bits per symbol). Baud = 9600 / 4 = 2400 baud.
  • Block coding adds redundancy for synchronisation and error detection. 4B/5B: every 4 data bits become a 5-bit code with no long runs of 0s (100 Mbps Fast Ethernet; 80% efficiency). 8B/10B: Gigabit Ethernet, USB 3.0.
  • Digital-to-analog (modulation) for telephone lines and radio: ASK (Amplitude Shift Keying: vary amplitude), FSK (Frequency Shift Keying), PSK (Phase Shift Keying), and QAM (amplitude + phase; used in modems and Wi-Fi). A modem = modulator–demodulator.
  • Analog-to-digital: PCM (Pulse Code Modulation: sampling, quantising, encoding). Nyquist sampling rate ≥ 2 × the highest frequency (voice at 4 kHz → 8000 samples per second × 8 bits = 64 kbps).
🎯 IBPS exam alert "Encoding used in Ethernet?" → Manchester. "In Token Ring?" → Differential Manchester. "Which encoding has a transition in the middle of every bit?" → Manchester and differential Manchester. "A modem converts?" → digital ↔ analog. Baud rate for Manchester = 2 × bit rate.

⚡ Rapid Revision — Chapter 8

  • Line coding = bits → digital signal. Goals: self-clocking, no DC, error detection. Types: unipolar, polar, bipolar.
  • Manchester (lecture): 1 = high→low ("Z"), 0 = low→high (reverse Z); always a mid-bit transition. Same consecutive bits need a connecting line; different bits flow continuously. IEEE 802.3 uses the opposite convention. Ethernet.
  • Differential Manchester: mid-bit transition always (clock). 0 = transition at the START (the lecture's "left bar"), 1 = no start transition. Lecture options: 1 → opt 1/2, 0 → opt 3/4; 1→0 extends, 0→0 repeats, 0→1 crosses. Relative coding; polarity-proof. Token Ring.
  • Others: NRZ-L (level), NRZ-I (1 = invert), RZ (return to 0), AMI (1s alternate ±V).
  • Manchester baud = 2 × bit rate (10 Mbps → 20 Mbaud). 4B/5B, 8B/10B. ASK/FSK/PSK/QAM; PCM = 64 kbps voice.
