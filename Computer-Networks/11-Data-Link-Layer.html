Chapter 11

Data Link Layer

Chapter 6 was only a trailer of each layer. The lecture says the physical layer is now done "more than enough" (Chapters 7–10). This chapter starts the full movie of layer 2, the Data Link Layer (DLL). It is an overview; the following chapters cover each DLL responsibility in depth.

11.0Position & Roadmap of the DLL

🎓 From the lecture The DLL is the second layer from the bottom, "sandwiched" between the network layer above and the physical layer below. Its roles and responsibilities: flow control, error control, access control, physical addressing and framing. Coming up in detail:
  • Access control, covered first even though it is listed last: CSMA, CSMA/CD, CSMA/CA, pure and slotted ALOHA, token passing in Token Ring.
  • Flow control: simple stop-and-wait, Go-Back-N, Selective Repeat.
  • Error control: CRC, checksum.
  • Framing: how frames are generated. Physical addressing: MAC.

11.1DLL Sublayers: LLC and MAC

The IEEE 802 standards divide the DLL into two sublayers: the upper LLC (Logical Link Control) and the lower MAC (Media Access Control).
🎓 From the lecture The DLL as a whole is divided into two sublayers:
  • Higher sublayer: LLC (Logical Link Control). It handles flow control, error control and, to some extent, framing.
  • Lower sublayer: MAC (Media Access Control). It handles access control and physical addressing.
BasisLLC (upper)MAC (lower)
Standard ADDEDIEEE 802.2, common to all LANsSpecific to each LAN: 802.3 Ethernet, 802.11 Wi-Fi, 802.5 Token Ring

⚠️ Exam trap "Which sublayer handles media access and the MAC address?" → MAC. "Which provides flow and error control and is common to all IEEE LANs?" → LLC (802.2). The order is LLC on top, MAC below.

11.2Framing and Node-to-Node Delivery

🎓 From the lecture
  • What comes down from the network layer (its header + data) is treated by the DLL as data / payload. "This term is important."
  • The DLL attaches its own header and trailer and sends the result down to the physical layer.
  • The finished unit is called a frame. Other layers have other names, but in general you can call it a "packet".
  • Delivery is node-to-node (hop-to-hop): to get from host H1 to host H2, frames don't make one big "long jump" ("they aren't long-jump experts"). They make short jumps: H1 → nearby router (hop 1) → next router (hop 2) → H2 (hop 3).
🎯 IBPS exam alert As a packet travels across routers, the source and destination IP addresses stay the same (except with NAT), but the source and destination MAC addresses are rewritten at every hop. That is why the DLL is "node-to-node" and the network layer is "end-to-end". The DLL's data unit = frame.

11.3DLL Services, Link Types & Protocols (HDLC, PPP) ADDED

Service offered to the network layerMeaningUsed on
Unacknowledged connectionlessSend frames; no ACK, no connection; lost frames are not recovered hereEthernet (low-error links)
Acknowledged connectionlessEach frame is acknowledged; no connectionWi-Fi (unreliable channels)
Acknowledged connection-orientedConnect → numbered frames in order, each acknowledged → releaseHDLC, long or unreliable links
  • Two kinds of links: point-to-point (one sender, one receiver, so no access control is needed: PPP, HDLC) and broadcast / multipoint (a shared medium, so the MAC sublayer's multiple-access protocols are needed: Ethernet, Wi-Fi).
  • HDLC (High-level Data Link Control, ISO): bit-oriented, flag 01111110, bit stuffing. Frame types: I-frames (data), S-frames (supervisory: ACK, RR, RNR, REJ), U-frames (unnumbered: link management). Modes: NRM, ABM, ARM.
  • PPP (Point-to-Point Protocol): byte-oriented (byte stuffing), used on dial-up, DSL and leased lines. LCP (Link Control Protocol) sets up the link; NCP configures network protocols (IPCP for IP); authentication with PAP (plain password) or CHAP (challenge-response, more secure). PPP has no flow control and only error detection.
  • Other DLL protocols and technologies: Ethernet (802.3), Wi-Fi MAC (802.11), Token Ring (802.5), Frame Relay, ATM, SLIP. Devices: switch, bridge, NIC.

⚡ Rapid Revision — Chapter 11

  • DLL = layer 2, sandwiched between network (L3) and physical (L1). Jobs: flow, error and access control, physical addressing, framing.
  • Roadmap: access control (CSMA/CD/CA, ALOHA, token) · flow control (stop-and-wait, GBN, SR) · error control (CRC, checksum) · framing · MAC.
  • Two sublayers: LLC (upper, IEEE 802.2: flow and error control, framing in part) and MAC (lower: access control and physical addressing; 802.3, 802.11, 802.5).
  • The network-layer packet becomes the payload; the DLL adds a header + trailer, giving a frame. The trailer = FCS/CRC.
  • Node-to-node / hop-to-hop delivery ("short jumps, not a long jump"): H1 → R1 → R2 → H2. MAC changes at every hop; IP stays the same.
  • Services: unacknowledged connectionless, acknowledged connectionless, acknowledged connection-oriented. HDLC (bit-oriented, I/S/U frames) and PPP (byte-oriented, LCP/NCP, PAP/CHAP).
