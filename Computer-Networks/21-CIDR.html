Classless Addressing (CIDR)

Classful addressing hands out addresses in only three sizes (16 million, 65 534 or 254 hosts), so most organisations get far too many or too few. CIDR (Classless Inter-Domain Routing) drops the classes. An address block of any power-of-two size is given out on demand, and the address itself carries its own boundary: /n says how many leading bits are the network (block) part. Everything from chapter 20 (masks, AND, FLSM, VLSM) carries over unchanged, only now the starting prefix can be any number, not just 8, 16 or 24.

21.0What is Classless Addressing?

🎓 From the lecture Classless addressing, lovingly called CIDR. As the name says, there are no classes: no pre-dividing addresses into A, B, C. Instead there are blocks, and IP addresses are supplied as per demand.
A 32-bit IPv4 address is divided into a block ID (think of it as the network ID) and a host ID. The notation is the usual dotted decimal plus /n, where n = the number of bits for the block / network ID.
Example: 201.1.10.5/28: 28 of the 32 bits are the network ID, the remaining 4 bits are the host ID, so this block holds 2⁴ = 16 addresses.
⚠️ Exam trap A /28 block has 16 addresses but only 14 usable hosts (minus the network ID and the broadcast address). The lecture says "16 host IDs"; when an exam asks for hosts, answer 2^(32−n) − 2 = 14; when it asks for addresses in the block, answer 2^(32−n) = 16.

21.1CIDR Network Mask

🎓 From the lecture Same rule as for classes: put a 1 in every network bit and a 0 in every host bit. For classes the network part was 1, 2 or 3 bytes; here it is whatever n says. For /28: 28 ones followed by 4 zeros.
/28 mask = 11111111.11111111.11111111.11110000 = 255.255.255.240

21.2Finding the Network ID: Shortcut Method

🎓 From the lecture "Find the network ID of the given IP address": many questions are asked on this. The shortcut: the 28 network bits are known from /28; don't touch them, copy them as they are. Just make the remaining 4 host bits all 0. The last byte of 201.1.10.5 is 0000 0101; zeroing its last 4 bits gives 0000 0000 = 0. Network ID = 201.1.10.0/28.
The same shortcut in decimal (block size) /28 → block size 2⁴ = 16 in the last octet. The network ID is the largest multiple of 16 that is ≤ 5 → 0. The block runs 201.1.10.0 – 201.1.10.15 (broadcast = network + block − 1).

21.3Finding the Network ID: AND with Mask

🎓 From the lecture The "ideal / legal" way: AND the IP address with the network mask. AND gives 1 only when both bits are 1. Where the mask has 1s, the output simply copies the address bit (201 stays 201, 1 stays 1, 10 stays 10). Where the mask has 0s, the output is 0. Last byte: 5 = 00000101 AND 240 = 11110000 → 00000000 = 0. Network ID = 201.1.10.0. So you have a legal method and a simple trick.
IP 201 . 1 . 10 . 00000101 (5) mask 255 .255 .255 . 11110000 (240) AND 201 . 1 . 10 . 00000000 (0) → network ID 201.1.10.0/28

21.4Fixed Length Subnetting in CIDR

🎓 From the lecture Same address, 201.1.10.5/28, network ID 201.1.10.0/28: 28 network bits, 4 host bits. For equal (fixed-length) subnets, leave the 28 network bits alone and fix the host bit closest to the network ID (the MSB of the host part). 0 → subnet A, 1 → subnet B. Three bits remain: 000 to 111.
• Subnet A: 201.1.10.0 – 201.1.10.7
• Subnet B: 201.1.10.8 – 201.1.10.15
Why /29? We fixed one host bit, so include it in the network ID: 28 + 1 = 29. The 3 remaining bits pick the host inside each 8-address subnet.

21.5Variable Length Subnetting in CIDR

🎓 From the lecture Same idea, slightly harder. Keep the 28 bits; fix the host MSB. 0 → subnet A with all 8 addresses (.0 – .7), as before. On the 1 side we want unequal pieces (4 + 4 instead of one 8), so one bit is not enough: use the next host bit too. A stays as it is; only B is divided. 10 → B1 (.8 – .11), 11 → B2 (.12 – .15).
The beautiful part is the prefix: subnet A used only 1 host bit → /29. B1 and B2 used 2 host bits → 28 + 2 = /30.

21.6CIDR Block Rules, Supernetting & Longest Prefix Match ADDED

Rules for a valid CIDR block (Forouzan): (1) the number of addresses must be a power of 2; (2) the addresses are contiguous; (3) the first address must be divisible by the block size (its host bits are all 0).
addresses in block N = 2^(32 − n) first address = IP AND mask (host bits → 0) last address = IP OR (NOT mask) (host bits → 1) usable hosts = N − 2
➕ Supernetting (route aggregation) The reverse of subnetting: combine several contiguous blocks into one bigger block by moving the boundary left. Four /24s, 192.168.0.0 – 192.168.3.0, become one 192.168.0.0/22. Conditions: the blocks must be contiguous, their count a power of 2, and the first block must start on the bigger block's boundary. This keeps Internet routing tables small, which is why CIDR was introduced (1993, RFC 1519).
➕ Longest prefix match With CIDR a packet may match several routing entries. The router picks the most specific one, the longest prefix. Table: 10.0.0.0/8 → R1, 10.1.0.0/16 → R2, 10.1.2.0/24 → R3. A packet for 10.1.2.5 matches all three and goes to R3 (/24). One for 10.1.9.9 goes to R2; one for 10.9.9.9 goes to R1.

Solved numericals Q1. For 167.199.170.82/27: first address, last address, number of addresses?
Block 2⁵ = 32 → multiples of 32 ≤ 82 → 64. First = 167.199.170.64, last = 167.199.170.95, 32 addresses (30 hosts).

Q2. Mask for /20 and number of addresses? 255.255.240.0, 2¹² = 4096.

Q3. Can 200.10.20.40/28 be the first address of a block? Block 16; 40 is not a multiple of 16 → no. The block containing it starts at 200.10.20.32.

Q4. Aggregate 192.168.0.0/24, .1.0/24, .2.0/24, .3.0/24. → 192.168.0.0/22.

Q5. An organisation needs 60 hosts. Smallest CIDR block? 2ʰ − 2 ≥ 60 → h = 6 → /26 (64 addresses, 62 hosts).

Q6. 201.1.10.13 belongs to which subnet in the lecture's VLSM plan? 13 lies in 12–15 → B2 (201.1.10.12/30).
🎯 IBPS exam alert CIDR stands for Classless Inter-Domain Routing. Typical questions: "number of hosts in /27" (30), "mask for /22" (255.255.252.0), "first and last address of a.b.c.d/n", "which prefix aggregates these networks", and "private 172.16.0.0/12 range" (172.16.0.0 – 172.31.255.255).

⚡ Rapid Revision — Chapter 21

  • CIDR = no classes, only blocks, given on demand. Notation a.b.c.d/n, n = network (block ID) bits.
  • 201.1.10.5/28: 28 network + 4 host bits → 16 addresses (14 hosts). Mask = 28 ones = 255.255.255.240.
  • Network ID: zero the host bits (shortcut) or AND with the mask (legal) → 201.1.10.0/28.
  • FLSM in CIDR: borrow 1 host bit → /29: .0–.7 and .8–.15.
  • VLSM in CIDR: A .0/29; B split again with a 2nd bit → B1 .8/30, B2 .12/30. Prefix = original + bits borrowed.
  • Addresses = 2^(32−n); hosts = 2^(32−n) − 2; first = IP AND mask; last = host bits all 1.
  • Valid block: power-of-2 size, contiguous, first address divisible by size.
  • Supernetting = merge blocks (four /24 → one /22). Routers use the longest prefix match.
