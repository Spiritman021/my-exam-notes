Chapter 13

Flow Control

A fast sender must not drown a slow receiver. This chapter starts with the simplest rule (stop and wait after every frame). It fixes its problems one by one (time-out, sequence numbers on data, sequence numbers on ACKs) to get Stop-and-Wait ARQ. Then it raises the window to N for Go-Back-N, and finally retransmits only what was lost in Selective Repeat. Every step comes with its efficiency formula and window and sequence-number rules, which are a favourite numerical area.

13.0What is Flow Control? (the bucket)

Flow control: a set of procedures that tells the sender how much data it may send before it must wait for an acknowledgement, so that a fast sender does not overwhelm a slow receiver's buffer. Error control (detecting lost or damaged frames and retransmitting them) is done in the DLL with ARQ (Automatic Repeat reQuest) ADDED.
🎓 From the lecture A big tank feeds a bucket through a tap and pipe; you bathe slowly with a mug (soap first, then water). If the tap is opened at full force, the bucket fills faster than you empty it, and the water overflows. In networking, water = data, the bucket = the receiver's buffer, and overflow = lost packets. The receiver works at its own (slower) speed, so the sender's "tap" must be tightened; that is flow control. The strategies are sliding window protocols.
➕ The family tree (Forouzan) Noiseless channel: Simplest protocol (no flow control), Stop-and-Wait. Noisy channel: Stop-and-Wait ARQ, Go-Back-N ARQ, Selective Repeat ARQ. The last two are sliding window protocols. Flow control also exists end-to-end in the transport layer (TCP's sliding window with the receiver window rwnd); here it is node-to-node (DLL).

13.1Stop-and-Wait Protocol

🎓 From the lecture The simplest, most primitive flow control. The sender sends one frame, then stops and waits for the acknowledgement. Until the ACK comes it will not send another frame ("ek aur bhej deta hoon na?" No!). Many add-ons will follow.
Problem: if the frame is lost, the receiver never got it, so it never sends an ACK, and the sender waits forever (an infinite wait or deadlock): "wait, wait, wait becomes its life story".

13.2Timeout Timer for Lost Frames

🎓 From the lecture Add-on #1: a time-out timer. As soon as a frame is sent, start a timer (say 5 minutes). If no ACK arrives before it expires, retransmit the frame and restart the timer. When the ACK finally arrives, the frame was delivered successfully. This solves the lost-frame deadlock.

13.3Lost Acknowledgement and Corrupted Frames

🎓 From the lecture
  • Lost ACK: the frame reached the receiver and the ACK was sent, but the ACK got lost on the way back. The sender's timer expires, so it retransmits the same frame. The receiver had already accepted it, which causes a duplicate packet problem. Fix: sequence numbers (13.12).
  • Corrupted frame: neither the frame nor the ACK is lost, but the frame arrives corrupted (non-acceptable). The receiver's error detection finds it and discards it. Stop-and-wait does not send a NAK (negative ACK), so the sender only learns through the time-out and resends. The second, clean copy is acknowledged in time.

13.4Total Time in Stop-and-Wait

🎓 From the lecture Full expression: Total = Tt(data) + Tp(data) + Queuing delay + Processing delay + Tt(ACK) + Tp(ACK).
  • Queuing delay: time a packet sits in a router's input/output queue ("lined up"). Taken as ≈ 0.
  • Processing delay: time to check the packet at the destination. Negligible, ≈ 0.
  • Tp(data) = Tp(ACK) = Tp, so together they give 2Tp.
  • Tt(ACK): a pure ACK is tiny ("typing 'Hi' takes no time"), so it is negligible.
Total time (pure ACK) = Tt + 2Tp.

13.5Piggybacking and Round Trip Time

🎓 From the lecture — the WhatsApp reply A pure ACK carries no data (someone texts you; you reply only "Hi"). With piggybacking the ACK travels together with data: "Hi, who are you? Where did you get my number? What work?" Now sending the ACK takes about as long as sending data, so Tt(ACK) ≈ Tt(data) = Tt.
Total time (piggybacking) = 2Tt + 2Tp.
Round Trip Time (RTT) = 2 × Tp: data goes sender → receiver (Tp), and the ACK comes back (Tp).
⚠️ Exam trap RTT (the 2Tp part) ignores Tt. If a question says "RTT = 20 ms", then Tp = 10 ms. "Total cycle time" in stop-and-wait = Tt + RTT.

13.6Efficiency of Stop-and-Wait

🎓 From the lecture The sender is "working" only while it transmits. So efficiency = useful time ÷ total time = Tt / (Tt + 2Tp). Dividing numerator and denominator by Tt gives η = 1 / (1 + 2a), where a = Tp / Tt.
Essential formulas
η (stop-and-wait, pure ACK) = Tt / (Tt + 2Tp) = 1 / (1 + 2a), a = Tp / Tt η (with piggybacking) = 2Tt / (2Tt + 2Tp) = 1 / (1 + a) [counting data both ways]

13.7Throughput of Stop-and-Wait

🎓 From the lecture Throughput S = bits sent ÷ total time = L / (Tt + 2Tp). It is ∝ L and ∝ 1/time: the most bits in the least time means high throughput; few bits in a long time means low. Multiplying and dividing by B gives L/B = Tt, so S = B × Tt/(Tt + 2Tp) = η × B. Throughput rises with efficiency and with bandwidth. "Don't memorise; understand."
Essential formula
Throughput (effective bandwidth) S = L / (Tt + 2Tp) = η × B

13.8Numerical: Efficiency and RTT

From the lecture Q. Tt = 1 ms, Tp = 1 ms. Efficiency? RTT?
a = Tp / Tt = 1 / 1 = 1 → η = 1 / (1 + 2×1) = 1/3 ≈ 33.3%. RTT = 2 × Tp = 2 ms.
The lecture notes a common confusion: a = Tp / Tt (propagation over transmission), not Tt/Tp.

13.9Condition for 50% Efficiency and Packet Length

🎓 From the lecture For η ≥ ½: Tt / (Tt + 2Tp) ≥ ½ → 2Tt ≥ Tt + 2Tp → Tt ≥ 2Tp. Since Tt = L/B: L ≥ 2 × Tp × B.
Numerical (lecture) Q. B = 4 Mbps, Tp = 1 ms, efficiency 50%. Find the frame length and throughput.
L = 2 × Tp × B = 2 × 10⁻³ × 4×10⁶ = 8 × 10³ bits = 8000 bits (1000 bytes).
Throughput = η × B = 0.5 × 4 Mbps = 2 Mbps.
⚠️ Exam trap This is the same Tt ≥ 2Tp as CSMA/CD's minimum frame (Chapter 12), but for a different reason: here it is for ≥ 50% efficiency in stop-and-wait; there it was for collision detection.

13.10Factors Affecting Efficiency

🎓 From the lecture Substitute a = Tp/Tt = (d/v)/(L/B). The efficiency formula has d in its denominator, so η ∝ 1/d: greater distance, lower efficiency. L sits in the denominator of the denominator, so effectively η ∝ L: bigger frames, higher efficiency. The lecture treats bandwidth as almost constant (a property of the backbone link).
Expanded formula (added)
η = 1 / (1 + 2·d·B / (v·L)) ↑ L → ↑ η ↑ d → ↓ η ↑ B → ↓ η ↑ v → ↑ η
⚠️ Exam trap — bandwidth Higher bandwidth lowers stop-and-wait efficiency: frames go out faster (smaller Tt), but the sender still sits idle for the same 2Tp. That is why stop-and-wait is terrible on long, fast links (satellite, fibre), and why sliding windows (N > 1) exist.

13.11Stop-and-Wait ARQ: Lost Data Problem

🎓 From the lecture Problem #1, the lost data packet, was solved with the time-out. Adding a time-out to stop-and-wait turns it into Stop-and-Wait ARQ (Automatic Repeat reQuest): wait a while, then automatically resend the frame whose ACK didn't arrive. The time-out pulls the sender out of the infinite-wait "deadlock".

13.12Duplicate Packet Problem and Sequence Numbers

🎓 From the lecture Problem #2, the lost ACK: the receiver had accepted the frame, the ACK vanished, the timer expired and the sender resent the same frame. Without numbering, the receiver can't tell it is the same, so it accepts it twice: a duplicate packet.
Fix: put a sequence number on each data frame. The sender sends "frame 0" and the receiver ACKs it. The ACK is lost, so the sender resends "frame 0". The receiver sees the same number again, so it discards the duplicate and re-sends the ACK (the earlier one must have been lost) so the sender can move on.

13.13Delayed Acknowledgement and Missed Packet Problem

🎓 From the lecture Problem #3: the ACK is not lost but delayed (a long route or traffic).
  1. Frame 1 is received and the ACK is sent, but it is slow, so the sender's timer expires and it resends frame 1.
  2. The receiver discards the duplicate (thanks to the sequence number) and ACKs again. The sender gets this ACK and sends the next frame, which gets lost.
  3. Now the old, delayed ACK finally arrives. The sender thinks it is the ACK for the frame it just sent and eagerly sends the next-to-next frame. One frame is never delivered: the missed packet problem.
Cause: the ACK carried no number. Fix: attach a sequence number to the ACK as well; the ACK names the next frame expected ("ACK 2 = I got 1, send 2"). Now a late "ACK 2" is recognised as a duplicate ACK and ignored, and the lost frame is resent after its time-out.
Final Stop-and-Wait ARQ = pure stop-and-wait + time-out + sequence number on data + sequence number on ACK.
➕ How many numbers does stop-and-wait need? Only two: 0 and 1 (a 1-bit field), alternating 0, 1, 0, 1. Frame 0 gets ACK 1; frame 1 gets ACK 0. Hence the other name, the Alternating Bit Protocol. Ws = Wr = 1.

13.14Go-Back-N ARQ

Go-Back-N (GBN) ARQ: a sliding-window protocol where the sender may have up to N unacknowledged frames outstanding (Ws = N > 1). The receiver window is 1 (accepts only the next in-order frame). On a time-out or error, the sender goes back and resends that frame and every frame after it.
🎓 From the lecture In stop-and-wait, Ws = 1 and Wr = 1; the numbers run 0, 1, 0, 1 (after frame 0 the ACK says "send 1"; after frame 1, "send 0"). In Go-Back-N the sender window = N, hence the name. N must be strictly greater than 1; with N = 1 it is just stop-and-wait. Window 10 → "Go-Back-10"; window 4 → "Go-Back-4".

13.15Go-Back-N Efficiency and Throughput

🎓 From the lecture Simply replace the 1 in the numerator with N (the sender window): η = N / (1 + 2a), a = Tp/Tt. Throughput = η × B = N × B / (1 + 2a).
⚠️ Exam trap — efficiency can't exceed 100% η = min(1, N / (1 + 2a)). Once N ≥ 1 + 2a, the sender never idles (the pipe is full), so efficiency = 100%. The optimal window for full utilisation: N = 1 + 2a.

13.16Go-Back-N Working Example

🎓 From the lecture GB4 (N = 4), frames 0–5 for simplicity.
  1. Frames 0, 1, 2, 3 sit in the window; GBN sends all of them straight away, each with its own time-out timer.
  2. The receiver (window 1) gets 0 and ACKs it. When ACK for 0 arrives, the window slides (a frame counts as done only once its ACK is received); now 1, 2, 3, 4 are in focus, so frame 4 is sent immediately.
  3. The ACK for 1 arrives before its time-out, so the window slides again and frame 5 is sent.
  4. Frame 2 is lost. Its ACK never comes and its timer expires. Instead of going forward (6, 7), the sender goes back to the oldest un-ACKed frame, 2, and retransmits everything in the window: 2, 3, 4, 5.
Unlike stop-and-wait (resend 1 frame), GBN resends up to N frames. That extra overhead can create traffic in the network.
➕ Why resend 3, 4, 5 if they arrived? The receiver window is 1: it accepts only the next expected frame (2). Frames 3, 4 and 5 arrived out of order, so they were discarded, not buffered. Hence the receiver needs only one buffer and stays simple; the cost is wasted bandwidth.

13.17Types of Acknowledgement: Cumulative

🎓 From the lecture — the talkative friend Cumulative ACK: frames 1, 2, 3 and 4 arrive, and the receiver sends one ACK: "send 5 next", meaning 1–4 are all safely received.
  • Advantage: fewer ACKs, so less traffic.
  • Disadvantage: less reliable. A chatty friend talks non-stop on the phone and you just say "achha, theek hai" at the end (low energy). But if he then asks "were you even listening?" and you say "didn't hear properly", he has to repeat everything. Likewise, if that single cumulative ACK is lost, it is as if all those frames are unacknowledged.

13.18Independent (Individual) Acknowledgement

🎓 From the lecture A friend who says one sentence, and you acknowledge it, then the next, and you acknowledge that. Each frame gets its own ACK: got 1, send 2; got 2, send 3; and so on. More reliable, but more traffic (many more ACK packets from receiver to sender).

⚠️ Exam trap Textbooks often state the opposite strength of cumulative ACKs: if ACK 3 is lost but ACK 5 arrives before the time-out, ACK 5 alone confirms frames 1–4, so nothing is resent. A lost cumulative ACK costs retransmission only if no later ACK arrives in time. Remember both views.

13.19Acknowledgement Timer vs Timeout Timer

🎓 From the lecture The sender has a time-out timer. The receiver has an acknowledgement timer (mainly with cumulative ACKs: it waits a little to collect frames, then sends one ACK). The rule: time-out timer > acknowledgement timer.
  • Example: time-out 10 min, ACK timer 8 min. Fine: the ACK leaves at 8 and reaches the sender before 10.
  • Reversed (time-out 8, ACK timer 10): the sender's timer expires every time before the ACK is even sent, so there are needless retransmissions again and again.
  • The ACK timer must be not too long, nor too short. If it is too short, every frame is ACKed separately, so it behaves like independent ACKs and loses the cumulative advantage.

13.20Go-Back-N: Timeout Timer Considerations

🎓 From the lecture With an ACK timer that is too long, the sender's time-out timer keeps expiring repeatedly. So always keep the sender's timer greater than the receiver's timer.
➕ Choosing the time-out The time-out must exceed the RTT (2Tp + Tt + any ACK delay). Too small causes premature retransmissions (duplicates and traffic); too large means slow recovery after a real loss. In GBN, a time-out triggers resending of all outstanding frames. Implementations often run one timer for the oldest outstanding frame.

13.21Sequence Numbers and the Duplicate Packet Problem (N+1)

🎓 From the lecture A common student belief: "the number of sequence numbers needed = the window size N". That is wrong: you need N + 1, because of duplicate packets.
  • Take Ws = 4 with only 4 numbers 0, 1, 2, 3. Send all 4; the receiver accepts all and ACKs each. After 3 it now expects 0 (the cycle 0 1 2 3 0 1 2 3 …).
  • All 4 ACKs are lost. The sender's time-out expires, so it resends the old 0, 1, 2, 3.
  • The receiver was expecting a new frame 0 and receives the old frame 0 with the same number. It accepts the duplicates as new: wrong.
  • With 5 numbers (0–4): after 0–3 the receiver expects 4. The resent old 0 doesn't match ("I wanted 4, you sent 0"), so it is rejected as a duplicate. Just one extra sequence number fixes it.

13.22Number of Bits Required for Sequence Numbers

🎓 From the lecture If N + 1 sequence numbers are needed, the bits to represent them = ⌈log₂(N + 1)⌉ (ceil = take the higher integer; floor = the lower).
Quick examples (added) GBN, N = 7 → 8 numbers → ⌈log₂ 8⌉ = 3 bits. N = 8 → 9 numbers → ⌈log₂ 9⌉ = 4 bits. N = 100 → ⌈log₂ 101⌉ = 7 bits.

13.23General Rule: Available Sequence Numbers ≥ Ws + Wr

🎓 From the lecture The most general and important condition, valid for every sliding-window protocol:
Available sequence numbers ≥ Ws + Wr
  • GBN: Ws = N, Wr = 1, so at least N + 1. More (6, 7, 8 …) also works; 5 (for N = 4) is the minimum, and 4 fails.
  • Stop-and-wait: 1 + 1 = 2 numbers (0 and 1).
  • Selective repeat: N + N = 2N (13.25).

13.24Numerical: Window Sizes from k Sequence Bits (Go-Back-N)

🎓 From the lecture With k bits for sequence numbers you get 2ᵏ numbers. In Go-Back-N: Ws = 2ᵏ − 1 (one less than the total) and Wr = 1 (always).
Numericals (added) k = 3: 8 numbers (0–7). GBN: Ws = 7, Wr = 1. SR: Ws = Wr = 4. Stop-and-wait: needs only 1 bit.
k = 4: 16 numbers. GBN Ws = 15. SR Ws = Wr = 8.
k = 5: GBN Ws max = 31; SR Ws max = 16.

13.25Selective Repeat ARQ: Window Sizes and Sequence Numbers

Selective Repeat (SR) ARQ: both sender and receiver have windows of size N (Ws = Wr > 1). The receiver buffers out-of-order frames, and only the specific lost or damaged frame is retransmitted, usually triggered by a NAK.
🎓 From the lecture
  • Condition 1: Ws > 1 (as in GBN).
  • Condition 2 (very, very important): Ws = Wr, the same size.
  • With k bits there are 2ᵏ numbers; divide them equally between the two windows: 2ᵏ/2 = 2ᵏ⁻¹ each. So Ws = Wr = 2ᵏ⁻¹.
  • Minimum sequence numbers = Ws + Wr = N + N = 2N (more is fine; fewer is not).
Essential formulas
Selective repeat: Ws = Wr = 2^(k−1) Seq numbers ≥ 2N bits = ⌈log₂(2N)⌉ Go-Back-N: Ws = 2^k − 1, Wr = 1 Seq numbers ≥ N + 1 bits = ⌈log₂(N + 1)⌉ Stop-and-wait: Ws = Wr = 1 Seq numbers = 2 bits = 1

13.26Selective Repeat Working and Negative Acknowledgement

🎓 From the lecture "As the name, so the work": repeat selectively. In GBN one frame's problem punishes everyone: the whole window is resent, and with a big N that floods the network. In SR, "what did the others do wrong? They reached safely." Resend only the problem frame.
Example (Ws = Wr = 4): frames 0, 1, 2 and 3 are sent; frame 1 is lost. The receiver keeps 0 (and 2, 3) and sends a negative acknowledgement (NAK) for frame 1, the one that was lost or looked corrupted / compromised. As soon as the NAK reaches the sender, it retransmits only frame 1.
➕ Details The receiver delivers frames to the network layer in order only after the gap is filled (here 1, 2, 3 together). If a NAK itself is lost, the sender's per-frame time-out still recovers. Practical example: TCP with SACK (selective acknowledgement); HDLC's SREJ frame.

13.27Comparison: Stop-and-Wait vs Go-Back-N vs Selective Repeat

🎓 From the lecture SR inherits the best of both:
  • From stop-and-wait: no bulk retransmission (only the lost frame is resent). GBN's practice of resending the whole window is "totally forbidden".
  • From GBN: the big window (N > 1) ("think bigger than 1"), so the same efficiency, N/(1 + 2a), versus stop-and-wait's 1/(1 + 2a).
Buffers / window total: stop-and-wait 1 + 1 = 2; GBN N + 1; SR N + N = 2N, which is also the minimum sequence numbers. ACKs: stop-and-wait uses independent; SR uses independent plus NAK; GBN generally uses cumulative (sometimes independent). Implementation: stop-and-wait very easy; GBN moderate (leaning easy); SR complex, because frames arrive out of order (e.g. 0, 2, 3, then 1) and must be sorted / searched internally. In stop-and-wait and GBN, frames are accepted only in order.

13.28Piggybacking

Piggybacking: in two-way (full-duplex) communication, the receiver attaches the ACK to its own outgoing data frame instead of sending a separate ACK frame.
🎓 From the lecture A pure ACK is like someone says "Hello" and you only reply "Hi". Piggybacking: you reply "Hi" plus data ("who are you? how did you get my number? what work?") and send it back to the sender together.
➕ Pros and cons Pros: better use of bandwidth (fewer separate frames, less overhead); fewer frames to process. Cons: if the receiver has no data to send, the ACK is delayed. So an ACK timer is used: if no data is ready in time, a separate ACK is sent anyway. It slightly complicates implementation. Total time per cycle = 2Tt + 2Tp (13.5).

13.29Solved Numericals & Formula Sheet ADDED

Numericals Q1. A 1 Mbps link, 1000-bit frames, 2000 km of cable (v = 2×10⁸ m/s), stop-and-wait. η and throughput?
Tt = 1000/10⁶ = 1 ms; Tp = 2×10⁶/2×10⁸ = 10 ms; a = 10. η = 1/(1 + 20) = 1/21 ≈ 4.76%. Throughput = 0.0476 × 1 Mbps ≈ 47.6 kbps.

Q2. Tt = 1 ms, Tp = 49.5 ms. (a) Stop-and-wait η? (b) GBN with N = 10? (c) Window for 100%? (d) Sequence bits for (c) in GBN and in SR?
1 + 2a = 1 + 99 = 100. (a) η = 1/100 = 1%. (b) η = 10/100 = 10%. (c) N = 1 + 2a = 100.
(d) GBN: N + 1 = 101 numbers → ⌈log₂ 101⌉ = 7 bits. SR: 2N = 200 numbers → ⌈log₂ 200⌉ = 8 bits.

Q3. GBN with a 4-bit sequence field and a = 7. Max efficiency?
Ws = 2⁴ − 1 = 15; 1 + 2a = 15 → η = 15/15 = 100%. With SR (Ws = 8): η = 8/15 ≈ 53.3%.

Q4. For stop-and-wait to reach ≥ 50% on a 10 Mbps link with Tp = 2 ms, the minimum frame length?
L ≥ 2 × 2×10⁻³ × 10⁷ = 40 000 bits = 5000 bytes.

⚡ Rapid Revision — Chapter 13

  • Flow control = don't overflow the receiver's buffer (tank → tap → bucket → mug). Error control = ARQ (Automatic Repeat reQuest).
  • Stop-and-wait: send 1, wait for the ACK. Lost frame → deadlock → fix with a time-out (giving S&W ARQ). Lost ACK → duplicate → seq number on data. Delayed ACK → missed packet → seq number on the ACK. Corrupted frame → silently discarded, no NAK, time-out resend.
  • Total = Tt + Tp + queuing (≈0) + processing (≈0) + Tt(ACK) (≈0) + Tp = Tt + 2Tp. Piggyback: 2Tt + 2Tp. RTT = 2Tp.
  • η = 1/(1 + 2a), a = Tp/Tt. Throughput = η × B. Tt = Tp = 1 ms gives η = 1/3, RTT = 2 ms.
  • η ≥ 50% ⇔ Tt ≥ 2Tp ⇔ L ≥ 2·Tp·B: 4 Mbps, Tp 1 ms → 8000 bits; throughput 2 Mbps.
  • η rises with frame length L; falls with distance d and (trap) bandwidth B.
  • GBN: Ws = N > 1, Wr = 1. η = N/(1 + 2a) (≤ 100%). A loss means resending it and everything after it (the whole window). Out-of-order frames are discarded.
  • ACKs: cumulative (one for many, less traffic, less reliable per the lecture), independent (one each, reliable, more traffic), NAK (SR). Time-out timer > ACK timer.
  • Seq numbers ≥ Ws + Wr. GBN needs N + 1 (else old frames are accepted as new); bits ⌈log₂(N + 1)⌉. k bits: GBN Ws = 2ᵏ − 1; SR Ws = Wr = 2ᵏ⁻¹; SR needs 2N numbers.
  • SR: resend only the lost frame (via NAK); the receiver buffers out-of-order frames, so it is the most complex but the best bandwidth use. It inherits S&W's single retransmission and GBN's big window.
  • Piggybacking: the ACK rides on reply data; saves bandwidth, but the ACK may wait (ACK timer).
