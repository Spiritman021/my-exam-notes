Chapter 19

Network Layer

The data link layer moved frames one hop at a time inside a single network. The network layer takes a packet from a host on one network to a host on another network, possibly across many routers. To do that it needs an address that says which network as well as which host: the IP address. This chapter introduces the layer's jobs (addressing, routing, fragmentation) and then classful addressing, which is the base for subnetting (ch 20) and CIDR (ch 21), the most numerical-heavy part of CN.

19.0Host-to-Host Delivery

🎓 From the lecture The second floor of the OSI "building" (the DLL) is done; now we go up to the third floor: the network layer. Its biggest speciality is host-to-host delivery: host H1 in one network sends data to host H2 in another network. The DLL did hop-to-hop / node-to-node delivery; the network layer talks at a higher level, source-to-destination. Higher still, the transport layer does process-to-process delivery between programs running on the machines.
➕ Network layer at a glance Data unit: packet / datagram. Device: router (layer-3 switch). Protocols: IP (IPv4, IPv6), ICMP, IGMP, routing protocols (RIP, OSPF, BGP); ARP sits between layers 2 and 3. Functions: logical addressing, routing, forwarding, fragmentation and reassembly, and (partly) congestion control. IP is connectionless and best-effort: no guarantee of delivery or order.

19.1Logical Addressing (Network ID and Host ID)

🎓 From the lecture The network layer uses IP addresses, which are logical addresses (classful and classless addressing in detail ahead). An IP address is divided into two parts: the NID (network ID), which tells which network, and the HID (host ID), which tells which host inside that network.
IP address = Network ID + Host ID "which street" "which house on that street"

19.2Routing Overview

🎓 From the lecture Between source and destination there are many nodes and many alternative paths (three are visible in the lecture's picture alone). Which one should we take? Routing decides where to send the packet next so that the overall path is the optimal / best route. Later we study it with numericals: RIP (Routing Information Protocol), which uses DVR (Distance Vector Routing), and OSPF (Open Shortest Path First), which uses the link-state algorithm.
➕ Routing vs forwarding Routing = building the routing table (deciding the best paths, a control-plane job, done by routing protocols). Forwarding = for each arriving packet, looking up the table and sending it out of the right interface (a data-plane job, done per packet).

19.3Fragmentation and MTU

🎓 From the lecture A host in network 1 wants to send a 500-byte packet to a host in network 2, whose MTU (Maximum Transmission Unit) is 200 bytes: "I can't digest anything bigger than 200 bytes." So before sending, the packet is divided into fragments: 200 + 200 + 100. Each is ≤ 200, so network 2 accepts them. We will dismantle this field by field in the IPv4 header (ch 22).
➕ Key facts Ethernet's MTU = 1500 bytes (ch 15). In IPv4, routers and the source may fragment; fragments are reassembled only at the destination. In IPv6, only the source fragments (routers never do; they drop the packet and send an ICMPv6 "Packet Too Big").

19.5IP Address Notations (Binary and Dotted Decimal)

🎓 From the lecture Two popular notations. Dotted decimal: MAC used hex digits separated by : or -; IPv4 uses decimal numbers separated by dots, one number per byte, 4 bytes. Binary: the same 4 bytes written as 8 bits each, only 0s and 1s.
4 bytes = 32 bits, so the total number of IPv4 addresses is 2³².
dotted decimal : 192 . 168 . 10 . 5 binary : 11000000 10101000 00001010 00000101 each byte = 8 bits → value 0 to 255
➕ Validity rules for dotted decimal Exactly 4 numbers, each 0–255, no leading zeros in strict notation, no other characters. 192.168.1.256 is invalid (256 > 255); 10.0.0 is invalid (only 3 parts). 2³² = 4 294 967 296 addresses (about 4.3 billion).

19.6Classful Addressing

🎓 From the lecture Take all 2³² possible addresses (the address space) and divide them into classes A, B, C, D, E: that is classful addressing. Many questions come from this.
The network/host split differs by class. Class A: only the first byte is the network ID; bytes 2–4 (three bytes) are the host ID. Class B: the network ID grows to 2 bytes, host ID 2 bytes. Class C: network ID 3 bytes, host ID only 1 byte. Most questions focus on A, B and C.

19.7Unicast (Classes A–C) vs Multicast (Class D) and Reserved (Class E)

🎓 From the lecture Classes A, B and C are for unicast (one host). Class D holds only multicast addresses (group IDs, like the WhatsApp group of ch 16). Class E is reserved for future use. D and E have no network ID / host ID split.

19.8Network ID and Host ID: Two-Bit Example

🎓 From the lecture Shrink the idea to just 2 bits: combinations 00, 01, 10, 11. Let the MSB be the network ID and the LSB the host ID. Then there are two networks (0 and 1), and inside each, two hosts (0 and 1).
Address 00 = network 0, host 0. 01 = network 0, host 1. 10 = network 1, host 0. 11 = network 1, host 1. The network ID takes you to the right network; then the host ID picks the host inside it.

19.9Division of the Address Space Among Classes

🎓 From the lecture Out of the whole address space: give 50% straight to class A. Of the remaining 50%, half (25%) goes to class B. Of what remains, half (12.5%) to class C. The last 12.5% is split equally: 6.25% to class D and 6.25% to class E.
⚠️ Exam trap The total is 2³² = 4 294 967 296 (the transcript's number has a slip). Class A = 2³¹ ≈ 2.1 billion, B = 2³⁰ ≈ 1.07 billion, C = 2²⁹ ≈ 537 million, D = E = 2²⁸ ≈ 268 million each.

19.10Identifying the Class from the First Byte (Decimal Ranges)

🎓 From the lecture To tell an address's class, look only at the first byte. 8 bits → values 0 to 255 (256 values). Halve it the same way: 0–127 (128 values) → class A; half of the remaining 128 → 64 values, 128–191 → class B; half of the next 64 → 32 values, 192–223 → class C; the last 32 split equally: 224–239 → class D, 240–255 → class E.

19.11Identifying the Class from the Leading Bits

🎓 From the lecture The same split, bit-wise. Look at the MSB (left-most bit) of the first byte. To divide 50/50, the MSB can be 0 or 1: 0 → class A. If it is 1, keep dividing by adding one more bit each time:
• 10 → class B; 11 → divide further
• 110 → class C; 111 → divide further
• 1110 → class D; 1111 → class E
Method: write the first byte in binary. MSB 0? Class A. Otherwise check the next bit: 0 → B; 1 → check the next: 0 → C; 1 → check the next: 0 → D, 1 → E.

19.12Class A: Networks and Hosts

🎓 From the lecture Focus on the first byte. Its MSB is fixed at 0, so 7 bits remain for the network: 2⁷ = 128 networks (first byte 0 to 127).
Host bits = 32 − 8 = 24 → 2²⁴ ≈ 16 million addresses per network.
But not all are usable: the all-0s host part is the network ID (the address of the network itself) and the all-1s host part is the broadcast address. Remove these two: 2²⁴ − 2 = 16 777 214 hosts per network. Of the first-byte values, only 1 to 126 are used for networks.
⚠️ Why 1–126 and not 0–127 First byte 0 is reserved (0.0.0.0 = "this host / this network", default route), and 127 is reserved for loopback (127.0.0.1 = localhost). So usable class A networks = 2⁷ − 2 = 126. The −2 for networks is class A only; the −2 for hosts applies to every class.

19.13Class B: Networks and Hosts

🎓 From the lecture 16 bits network, 16 bits host. Two bits (10) are fixed, so the network ID has 14 free bits: 2¹⁴ = 16 384 networks. Logic: the more bits, the more space; class A had only 7 network bits, class B has double (14), so far more networks.
In the first byte, 6 free bits → 64 values: 128–191, proving the range given earlier.
Hosts: 2¹⁶ addresses, minus 2 (all-0s network ID, all-1s broadcast) → 2¹⁶ − 2 = 65 534 hosts per network.

19.14Class C: Networks and Hosts

🎓 From the lecture The network space grows again: 3 bytes network, only 1 byte host. Three bits (110) are fixed, leaving 21 network bits: 2²¹ = 2 097 152 networks. Hosts: 2⁸ = 256 addresses per network (254 usable after removing network ID and broadcast).
First byte: 5 free bits → 2⁵ = 32 values: 192–223.
Tracking: MSB 1 → not A. Next bit 1 → not B. Next bit 0 → C. (If it were 1, check the next bit: 0 → D, 1 → E.)

19.15Class D and Class E Ranges

🎓 From the lecture Class D (1110): multicast, so there is no network ID / host ID split. First byte: 4 bits fixed, 4 free → 16 values: 224–239.
Class E (1111): reserved. 4 free bits → 16 values: 240–255.
Notice the pattern of first-byte counts: E 16, D 16, C 32, B 64, A 128: each doubles.
➕ Well-known class D addresses 224.0.0.1 all hosts · 224.0.0.2 all routers · 224.0.0.5/6 OSPF · 224.0.0.9 RIPv2. Group membership is managed by IGMP (ch 26). 255.255.255.255 (in the E range) is the limited broadcast address.

19.16Hosts per Network

🎓 From the lecture A detail "most people won't tell you": the host count is per network.
Back to the 2-bit example: 1 network bit → 2¹ = 2 networks; 1 host bit → 2¹ = 2 host IDs per network.
With 3 bits (1 network + 2 host): 2 networks, each with 2² = 4 host IDs. Switch it (2 network + 1 host): 2² = 4 networks, each with 2 host IDs.
Scale it up: in class A, 2²⁴ hosts is the number in each network; in class B, 2¹⁶ per network; in class C, 2⁸ = 256 per network. 16 million hosts in one network is huge, so let's break big networks into smaller ones. That is subnetting, next chapter.
networks = 2^(network bits − fixed class bits) addresses / network = 2^(host bits) usable hosts / network = 2^(host bits) − 2

🎯 IBPS exam alert Private addresses are not routable on the Internet; home and office networks use them behind NAT. Loopback = 127.0.0.1. Frequently asked: "which is a private IP?" (10.x, 172.16–31.x, 192.168.x), "default mask of class B?" (255.255.0.0), and "what is 255.255.255.255?" (limited broadcast).
➕ Why classful addressing was abandoned It wastes addresses: a company needing 300 hosts is too big for class C (254) and must take a class B (65 534), wasting ~65 000. Class A networks were far too large to fill, and class C too small for most organisations. Fixes: subnetting (ch 20), CIDR / classless addressing (ch 21), NAT + private addresses, and finally IPv6 (ch 23).

Solved questions Q1. Classes of 10.5.6.7, 172.20.1.1, 200.1.1.1, 230.0.0.9, 245.3.3.3? A, B, C, D, E (first bytes 10, 172, 200, 230, 245).

Q3. For 150.20.30.40: class, network address, broadcast address?
150 → class B; network = 150.20.0.0; directed broadcast = 150.20.255.255; usable hosts 150.20.0.1 – 150.20.255.254.

Q5. Is 192.168.300.4 valid? No: 300 > 255.

Q7. Which is a private address: 172.32.1.1, 172.20.1.1, 11.0.0.1? 172.20.1.1 (172.16–172.31 only).

⚡ Rapid Revision — Chapter 19

  • Network layer = 3rd floor: host-to-host (source-to-destination) delivery. DLL = hop-to-hop; transport = process-to-process.
  • Jobs: logical addressing (IP = network ID + host ID), routing (best path: RIP/DVR, OSPF/link state), fragmentation (500 B packet, MTU 200 → 200 + 200 + 100).
  • IP vs MAC: 32/128 bits vs 48 bits; ISP vs NIC maker; logical vs physical; layer 3 vs 2; changeable vs fixed.
  • IPv4 = 4 bytes, dotted decimal, each byte 0–255; 2³² ≈ 4.29 billion addresses.
  • Classes split the space 50 / 25 / 12.5 / 6.25 / 6.25%.
  • First byte: A 0–127 · B 128–191 · C 192–223 · D 224–239 · E 240–255. Leading bits 0 · 10 · 110 · 1110 · 1111.
  • A: 1 net byte, 2⁷ networks (126 usable), 2²⁴ − 2 hosts. B: 2 bytes, 2¹⁴ networks, 2¹⁶ − 2 = 65 534 hosts. C: 3 bytes, 2²¹ networks, 254 hosts.
  • −2 hosts = all-0s (network address) and all-1s (broadcast). Host counts are per network.
  • D = multicast, E = reserved; no net/host split. 127.x = loopback; 255.255.255.255 = limited broadcast.
  • Private: 10/8, 172.16–31/12, 192.168/16. Default masks /8, /16, /24. Classful wastes addresses → subnetting, CIDR.
