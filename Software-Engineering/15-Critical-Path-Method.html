Chapter 15

Critical Path Method (CPM)

A project is a network of tasks, and some must wait for others. Design can't start before requirements are done; testing can't start before coding. Given each task's duration and dependencies, how soon can the whole project finish, and which tasks have no room to slip? The Critical Path Method answers both questions with two simple passes through the network.

15.1Critical Task and Critical Path

🎓 From the lecture
  • Critical task: a task that cannot be delayed. Any delay in it delays the whole project.
  • Critical path: the chain of critical tasks. Its length is the minimum time needed to complete the project.
Steps: identify the tasks → work out their sequence (dependencies) → estimate each task's time → draw the network → find the critical path.
⚠️ Exam trap The critical path is the longest path through the network (by total duration), and its length is the shortest possible project duration. Both words appear in options; they describe the same thing from two angles. Every task on it has zero float. A network can have more than one critical path.

15.2Node Block: ES, EF, LS, LF, Duration and Float

🎓 From the lecture Each task is drawn as a node block holding six values:
  • ES = earliest start, D = duration, EF = earliest finish (top row).
  • The task label (middle).
  • LS = latest start, Float (slack), LF = latest finish (bottom row).
The forward pass fills ES and EF; the backward pass fills LF, LS and float.
Forward pass: EF = ES + D ES of a task = max(EF of all its predecessors) (first task: ES = 0) Backward pass: LS = LF − D LF of a task = min(LS of all its successors) (last task: LF = its EF) Float (slack): Float = LS − ES = LF − EF
⚠️ Exam trap Forward pass: when several arrows merge into a task, take the maximum EF, because the task must wait for its slowest predecessor. Backward pass: when a task bursts into several successors, take the minimum LS, because it must finish in time for the most urgent one.

15.3Forward and Backward Pass — Worked Example (A → B → C)

🎓 From the lecture

Forward pass: A: ES 0, EF 2 → B: ES 2, EF 5 → C: ES 5, EF 10.
Backward pass: the last task's LF = its EF = 10. Then LS = LF − D, working backwards, and Float = LF − EF.
All floats are 0, so A → B → C is the critical path, and the project needs 10 months. The critical path is the one with zero slack.
➕ Added for exam A purely linear chain is always entirely critical, because there is no alternative route to create slack. CPM becomes interesting when tasks run in parallel, as in the next example.

Critical path: A → B → D → F = 3 + 4 + 5 + 2 = 14 weeks. The other path, A → C → E → F, takes only 10 weeks, which is why C and E each have 14 − 10 = 4 weeks of float.
➕ Added for exam Total float (LS − ES) is how long a task can slip without delaying the project. Free float is how long it can slip without delaying the next task's earliest start: free float = ES of the successor − EF of the task.
  • Task C: free float = ES(E) − EF(C) = 5 − 5 = 0, although its total float is 4. Any slip in C pushes E later, but E has room to absorb it.
  • Task E: free float = ES(F) − EF(E) = 12 − 8 = 4.

15.5PERT, Gantt Charts and CrashingADDED

➕ Added for exam

PERT (Program Evaluation and Review Technique)

PERT was developed for the US Navy's Polaris missile project (1958). It handles uncertain durations with three time estimates per task:
o = optimistic, m = most likely, p = pessimistic Expected time te = (o + 4m + p) / 6 Variance σ² = ((p − o) / 6)²
Example: o = 2, m = 4, p = 12 → te = (2 + 16 + 12) / 6 = 5; σ = (12 − 2) / 6 ≈ 1.67.

Gantt chart

A Gantt chart (Henry Gantt) is a bar chart with tasks on the y-axis and time on the x-axis. It is excellent for showing schedule and progress, but it shows dependencies poorly. Use CPM or PERT for dependencies and a Gantt chart for tracking.

Other terms

  • Crashing: shortening the project by adding resources to critical tasks. Crashing a non-critical task saves no time.
  • Fast-tracking: running sequential tasks in parallel.
  • AON vs AOA: activity-on-node (tasks are boxes, as above) vs activity-on-arrow (tasks are arrows between event circles). AOA sometimes needs dummy activities, with zero duration, to show a dependency.
🎯 IBPS exam alert Common one-liners:
  • "PERT expected time formula?" → (o + 4m + p) / 6.
  • "Float of a critical activity?" → 0.
  • "Which chart shows the schedule as horizontal bars over time?" → Gantt.
  • "Reducing project duration by adding resources to critical activities?" → crashing.

15.6Solved Exam QuestionsADDED

Q1The float (slack) of every activity on the critical path is:
Answer: zero.
Q2A task has ES = 4, D = 3 and LF = 10. Find its EF, LS and float.
Answer: EF = 4 + 3 = 7; LS = 10 − 3 = 7; float = 7 − 4 = 3.
Q3A PERT activity has o = 3, m = 6, p = 15 days. Find the expected time.
Answer: (3 + 24 + 15) / 6 = 42 / 6 = 7 days.
Q4Task X depends on P (EF = 6) and Q (EF = 9). What is the ES of X?
Answer: 9. In the forward pass, take the maximum of the predecessors' EF.
Q5The critical path is the: (a) shortest path (b) longest path (c) path with the most tasks (d) path with the highest cost
Answer: (b) longest path (by duration). Its length is the minimum project time.

⚡ Rapid Revision

  • Critical task = can't be delayed. Critical path = longest chain by duration = minimum project time; every task on it has zero float.
  • Node: ES · D · EF on top, label in the middle, LS · Float · LF at the bottom.
  • Forward: EF = ES + D; ES = max of the predecessors' EF. Backward: LS = LF − D; LF = min of the successors' LS.
  • Float = LS − ES = LF − EF. Free float = ES(next) − EF(this).
  • Lecture: A2 → B3 → C5 → 0–2, 2–5, 5–10, all floats 0, critical path = 10 months.
  • Branching example: A-B-D-F = 14 (critical); A-C-E-F = 10, so C and E have float 4.
  • PERT: te = (o + 4m + p) / 6, σ = (p − o) / 6; probabilistic. CPM: deterministic. Gantt = bars over time. Crashing = add resources to critical tasks.
