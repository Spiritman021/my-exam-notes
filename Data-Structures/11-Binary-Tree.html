Chapter 11

Binary Tree

The lecture calls it "the most talked-about tree". Limiting every node to two children gives each child a name, left or right. That one restriction gives clean formulas for node counts, a neat array layout (used by heaps), three classic traversals, and the basis for BSTs and AVL trees in the next chapters.

11.1Definition: At Most Two Children

🎓 From the lecture A binary tree can have at most two children per node: 0, 1 or 2. If every node stays in this range, it is a binary tree. A node with three children takes it out of the range, so that is not a binary tree.
Binary tree: a tree in which every node has at most two children, distinguished as the left child and the right child. It may also be empty.
⚠️ Exam trap Left and right are different positions. A root with only a left child and a root with only a right child are two different binary trees, even though as general trees they look the same.

11.2Levels; Maximum and Minimum Nodes for Height h

🎓 From the lecture A very popular question: given the height h, what are the maximum and minimum numbers of nodes? Levels are numbered 0 (root), 1, 2, 3, …
  • Maximum: fill every level, so every parent has two children. With h = 3, counting gives 15 nodes.
    max nodes = 2^(h+1) − 1 h = 3 → 2⁴ − 1 = 16 − 1 = 15
  • Minimum: a skewed tree, where every node has one child. Going down to the left is a left-skewed tree; to the right, right-skewed. With h = 3 there are 4 nodes.
    min nodes = h + 1 h = 3 → 3 + 1 = 4
The height of the tree is the height of the root, measured from the bottom leaves up (1, 2, 3).
➕ Added for exam (the reverse question) Given n nodes:
  • the maximum height is n − 1 (skewed);
  • the minimum height is ⌈log₂(n + 1)⌉ − 1, which is ⌊log₂ n⌋.
Example: n = 15 → min height 3, max height 14. The maximum number of nodes at level l is 2^l.
⚠️ Exam trap If a book counts height in nodes (root at height 1), the formulas shift to 2^h − 1 (max) and h (min). The lecture uses edges (root at level 0). Check which convention the question uses before choosing an option.

11.3Full Binary Tree

🎓 From the lecture In a full binary tree every node has either 0 or 2 children; nothing in between. If any node has exactly one child, the tree is not full. A node with three children isn't even a binary tree. (The lecture says "with one child it is not a binary tree"; it means not a full binary tree. A one-child node is still allowed in an ordinary binary tree.)
➕ Added for exam A full binary tree is also called a strict or proper binary tree. With i internal nodes it has i + 1 leaves and 2i + 1 nodes in total, so its node count is always odd.

11.4Complete Binary Tree

🎓 From the lecture This one is a bit complicated, but very useful later for the heap, which is also seen in tree form. Nodes may have 0, 1 or 2 children, but at the lowest (leaf) level, filling must go left to right.
  • A node with only a left child is fine; one child is allowed.
  • If a node has a right child but no left child, the right was filled before the left. That is not complete.
➕ Added for exam (the full definition) Complete = every level except possibly the last is completely filled, and the last level's nodes are as far left as possible.
  • A complete tree with n nodes has height ⌊log₂ n⌋.
  • It fits an array with no gaps, which is why heaps use it.
  • In a complete tree, at most one node has exactly one child, and that child is a left child.

11.5Perfect Binary Tree

🎓 From the lecture In a perfect tree, at every level all the children should be present, "happily playing". A tree whose bottom level is missing children is imbalanced: those nodes should also have had two children each. Only when every level is completely full is it a perfect binary tree.
TypeRuleNodes for height h
Binaryevery node has 0, 1 or 2 childrenh + 1 to 2^(h+1) − 1
Full / strictevery node has 0 or 2 children2h + 1 to 2^(h+1) − 1

Skewedevery node has one child (all left or all right)exactly h + 1
⚠️ Exam trap
  • Every perfect tree is both full and complete.
  • A full tree need not be complete, and a complete tree need not be full.
  • Some (mostly older) books use "complete" to mean "perfect" and "almost complete" for the left-filled tree. Use the context.

11.6Tree Traversal: Preorder, Inorder and Postorder

🎓 From the lecture Traversal is a very basic and important idea. The orders are named after where the root goes, just like prefix, infix and postfix in chapter 8:
  • Preorder: root first, then left, then right (Root–L–R).
  • Inorder: root in the middle (L–Root–R).
  • Postorder: root last (L–R–Root).
For a tree with root A, left child B and right child C:
  • preorder A B C;
  • inorder B A C;
  • postorder B C A.
void preorder(struct node *t) { if (t) { visit(t); preorder(t->left); preorder(t->right); } } void inorder(struct node *t) { if (t) { inorder(t->left); visit(t); inorder(t->right); } } void postorder(struct node *t) { if (t) { postorder(t->left); postorder(t->right); visit(t); } }

11.7Traversal Example: All Three Orders in One Pass

🎓 From the lecture Use the same technique as chapter 8. Walk round the tree top to bottom, left to right, and add dummy branches under leaves and missing children. Every node is then met three times:
  • the 1st meeting (left side) → write it in preorder;
  • the 2nd (underneath) → inorder;
  • the 3rd/last (right side; you won't see it again) → postorder.
One full walk fills in all three lists together.
Preorder (1st visit): A B D H E I J C F G Inorder (2nd visit): H D B I E J A F C G Postorder (3rd visit): H D I J E B F G C A
➕ Added for exam (quick checks)
  • Preorder starts with the root; postorder ends with it.
  • In inorder, everything left of the root belongs to its left subtree: H D B I E J | A | F C G.
  • The first node in inorder is the leftmost node (H); the last in preorder is usually a leaf.

11.8Array Representation (Children at 2i and 2i + 1)

🎓 From the lecture A binary tree with 7 nodes gets 7 array cells. Place the nodes level by level, left to right, at indices 1 to 7. Then, using only the parent's index i:
left child = 2·i right child = 2·i + 1
  • i = 1 (the root): left at 2·1 = 2, right at 2·1 + 1 = 3.
  • i = 3: left at 6, right at 7, matching the tree.
Formula1-based (lecture)0-based (C arrays)
Left child of i2i2i + 1
Right child of i2i + 12i + 2
Parent of i⌊i / 2⌋⌊(i − 1) / 2⌋
⚠️ Exam trap The array form is ideal for complete trees (no gaps), but it wastes space on sparse or skewed trees. A right-skewed tree of height h needs an array of size 2^(h+1) − 1 to hold just h + 1 nodes. For h = 3 that is 15 cells for 4 nodes.

11.9Linked Representation (Left and Right Pointers)

🎓 From the lecture Each node has three parts:
  • data in the centre;
  • a left pointer to the left child;
  • a right pointer to the right child.
Every node follows this same structure. If a child doesn't exist (for example C is a leaf), store NULL there: "nothing after this, it's a leaf".
struct node { struct node *left; int data; struct node *right; };
➕ Added for exam A binary tree with n nodes has 2n pointer fields but only n − 1 edges, so it has n + 1 NULL pointers. Threaded binary trees (chapter 15) put these wasted NULLs to use.

11.10Properties, Level Order, Rebuilding a Tree & Solved QuestionsADDED

➕ Key properties
  • n₀ = n₂ + 1: in any non-empty binary tree, leaves = (nodes with two children) + 1.
  • Max nodes at level l = 2^l; max nodes for height h = 2^(h+1) − 1.
  • Minimum height for n nodes = ⌈log₂(n + 1)⌉ − 1.
  • n nodes give n − 1 edges and n + 1 NULL links.
  • Number of structurally different binary trees with n nodes = Catalan C(n) = (2n)! / ((n+1)! n!), giving 1, 2, 5, 14, 42.
➕ Level-order traversal (BFS) Visit level by level, left to right, using a queue (chapter 9): enqueue the root; repeatedly dequeue a node, visit it, and enqueue its children. For the lecture tree: A B C D E F G H I J. Pre-, in- and postorder are depth-first and use a stack (or recursion).
➕ Rebuilding a tree from two traversals
  • Inorder + preorder or inorder + postorder gives a unique tree.
  • Preorder + postorder alone does not (unless the tree is full).
Method: take the root from preorder (first) or postorder (last). Find it in inorder: the left part is the left subtree and the right part is the right subtree. Repeat for each part.
🎯 IBPS exam alert
  • Max nodes in a binary tree of height h: 2^(h+1) − 1; min: h + 1.
  • Inorder traversal of a BST gives sorted order (chapter 12).
  • "Which traversal uses a queue?" → level order.
  • Array storage: children of i at 2i and 2i + 1 (1-based); parent at ⌊i/2⌋.
  • A binary tree with 20 leaves has 19 nodes of degree 2 (n₂ = n₀ − 1).
Q1Preorder A B D E C F, inorder D B E A F C. Find the postorder.
Root A (first in preorder). Inorder splits: [D B E] A [F C] Left: preorder B D E, inorder D B E → root B, left D, right E Right: preorder C F, inorder F C → root C, left F Postorder = D E B F C A
Q2Maximum and minimum number of nodes in a binary tree of height 5? → Max 2⁶ − 1 = 63; min 5 + 1 = 6.
Q3A binary tree has 10 nodes with two children. How many leaves? → n₀ = n₂ + 1 = 11.
Q4Minimum height of a binary tree with 100 nodes? → ⌈log₂ 101⌉ − 1 = 7 − 1 = 6.
Q5How many different binary tree shapes have 3 nodes? → C(3) = 5.
Q6In the 1-based array representation, where is the parent of the node at index 11? Where are its children? → Parent ⌊11/2⌋ = 5; children at 22 and 23.

⚡ Rapid Revision

  • Binary tree: each node has 0, 1 or 2 children (left and right are distinct). Three children means not binary.
  • Height h: max 2^(h+1) − 1 (all full; h = 3 → 15), min h + 1 (skewed; h = 3 → 4).
  • Full = 0 or 2 children. Complete = all levels full except the last, filled left → right (used by heaps). Perfect = every level full. Skewed = one child per node.
  • Pre = Root L R, In = L Root R, Post = L R Root. One walk: 1st visit → pre, 2nd → in, 3rd → post.
  • Lecture tree: pre ABDHEIJCFG, in HDBIEJAFCG, post HDIJEBFGCA.
  • Array (1-based): children at 2i and 2i + 1, parent at ⌊i/2⌋. Wasteful for skewed trees.
  • Linked: left · data · right, with NULL for a missing child. n nodes give n + 1 NULLs.
  • n₀ = n₂ + 1. Level order uses a queue. Inorder plus pre- or postorder gives a unique tree. Shapes with n nodes = Catalan.
