Chapter 15

Threaded Binary Tree

In the linked representation of a binary tree (chapter 11), every leaf wastes both its pointer fields on NULL. A threaded binary tree stores something useful there instead: a pointer, called a thread, to the node that comes just before or after it in inorder. You can then walk the tree in order by following pointers, with no stack and no recursion.

15.1Single and Double Threading (Inorder Predecessor/Successor)

🎓 From the lecture "One last, simple topic left in trees." The leaf nodes aren't using their child links, since they have no children. So why not attach threads there that give us some information? Threads can be single or double.
  • Single threading: write out the inorder of the tree. Each leaf's thread points to its inorder predecessor, the same predecessor used in BST deletion (chapter 12), now available directly through the thread.
    • D's predecessor is B;
    • E's is A;
    • F's is C;
    • H's is G.
  • Double threading: besides the predecessor, the leaf also points to its inorder successor, the element just after it in the inorder sequence. Leaves such as E, F and H then carry both threads.

⚠️ Exam trap
  • Strictly, threads replace every NULL link, not just those of leaves. G has an empty left link (its only child H is on the right), so in a fully threaded tree that link also becomes a thread. G is first in inorder, so it points to NULL or the header.
  • Textbooks most often define a one-way (single) threaded tree as right-threaded: NULL right links point to the inorder successor. The lecture's single threading uses the predecessor (left-threaded); both exist. Read which side the question means.

15.2Why Threads, Flag Bits, Traversal & Solved QuestionsADDED

➕ Why it's worth doing A binary tree with n nodes has 2n link fields but only n − 1 edges, so n + 1 links are NULL, more than half. Threading turns that waste into navigation. Here n = 8, so there are 9 NULL links available for threads.
➕ Telling a thread from a child: flag bits A pointer alone can't say whether it leads to a real child or is a thread, so each node carries two boolean flags:
struct tnode { struct tnode *left; int lthread; /* 1 = left is a thread (to predecessor) */ int data; struct tnode *right; int rthread; /* 1 = right is a thread (to successor) */ };
Many implementations add a header (dummy) node, so that the first node's left thread and the last node's right thread point to it instead of NULL.
➕ Inorder traversal with no stack or recursion
  1. Start at the leftmost node.
  2. Visit it.
  3. If its right link is a thread, follow it: that is the successor.
  4. Otherwise, go to the right child and then as far left as possible.
  5. Repeat until you run out of nodes.
This takes O(n) time and O(1) extra space, compared with O(h) stack space for a normal traversal. Finding a node's inorder successor or predecessor also becomes fast.

🎯 IBPS exam alert
  • "In a threaded binary tree, NULL pointers are replaced by…" → pointers (threads) to inorder predecessor/successor.
  • "Number of NULL links in a binary tree with n nodes" → n + 1.
  • "Main advantage" → traversal without a stack/recursion.
  • "How to distinguish a thread from a link?" → a flag (tag) bit per pointer.
  • One-way threading = one side (usually right → successor); two-way = both sides.
Q1A binary tree has 20 nodes. How many threads can a fully (double) threaded version have? → NULL links = 20 + 1 = 21, all become threads. With a header node, the first and last of them point to the header.
Q2In the lecture tree (inorder G H B D A E C F), where does E's right thread point? → To its inorder successor, C.
Q3Which traversal does threading speed up most directly? → Inorder.
Q4Why can't you drop the flag bits? → Without them, a right pointer to C could be either a real child or a thread, so traversal wouldn't know whether to "go left as far as possible" or "visit directly".

⚡ Rapid Revision

  • Threaded binary tree: NULL child links become threads to inorder neighbours.
  • Single: one thread per node. The lecture uses the inorder predecessor; many books use right threads to the successor. Double: both.
  • Lecture tree (inorder G H B D A E C F): predecessors D→B, E→A, F→C, H→G. Successors H→B, D→A, E→C, F→none.
  • n nodes ⇒ n + 1 NULL links available. Flag bits (lthread/rthread) tell a thread from a child. A header node avoids NULL ends.
  • Benefit: inorder traversal in O(n) time with no stack/recursion. Cost: flags and more complex insert/delete.
