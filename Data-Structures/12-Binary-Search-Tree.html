Binary Search Tree (BST)

A BST is a binary tree with one ordering rule at every node. Because of that rule, each comparison throws away an entire subtree, which is binary search done on a tree instead of an array. The lecture says many questions are asked on this variation: build a tree from a sequence, give its traversals, delete a node.

12.1BST Property and Sorted Inorder

🎓 From the lecture If the tree concepts so far are clear, the BST is very simple, because it follows one rule:
  • the parent's left child is always less than the parent;
  • its right child is always greater than the parent.
Example: parent 10, left 8 (< 10), right 12 (> 10). The rule holds from the root down to the leaves.
Benefit: the inorder traversal of a BST gives the numbers in sorted (ascending) order. It is also asked the other way: if the inorder comes out sorted, the tree is a BST.
Binary search tree: a binary tree in which, for every node, all keys in the left subtree are smaller than the node's key and all keys in the right subtree are larger. Both subtrees are themselves BSTs.
⚠️ Exam trap The rule is about whole subtrees, not just the immediate children. A tree in which every parent is bigger than its left child and smaller than its right child can still fail to be a BST (see 12.3). Checking "inorder is strictly increasing" is the reliable test.

12.2Searching in a BST

🎓 From the lecture It is a binary tree, but it helps searching a lot, which is why it is called a binary search tree. Always start at the root:
  • Find 13: 13 > 10, go right. 13 > 12, go right. 13 < 15, go left: found 13.
  • Find 9: 9 < 10, go left to 8. 9 > 8, go right: found 9.
In an ordinary tree you would check every option and every subtree. Here there is no need: if the key is greater, it can only be on the right, so "don't even try the left, don't waste time". The left subtree of 10 is never searched for 13, because 13 can't be there.
struct node* search(struct node *t, int key) { while (t != NULL && t->data != key) t = (key < t->data) ? t->left : t->right; return t; /* NULL if not found */ }
➕ Added for exam
  • The number of comparisons = the depth of the node + 1. Searching for 13 takes 4 comparisons (10, 12, 15, 13).
  • An unsuccessful search ends at a NULL link, which is exactly where that key would be inserted.

12.3Insertion and Construction (Compare from the Root)

🎓 From the lecture Build a BST by inserting 50, 40, 30, 60, 80, 20, 70, each time comparing from the root:
  • 50 becomes the root.
  • 40 < 50 → left of 50.
  • 30 < 50, < 40 → left of 40.
  • 60 > 50 → right of 50.
  • 80 > 50, > 60 → right of 60.
  • 20 < 50, < 40, < 30 → left of 30.
  • 70 > 50, > 60, < 80 → left of 80.
The trap students fall into: in a tree with root 60, 80 on its right and some node as 80's left child, why can't 50 be that left child? Locally 50 < 80, so it looks fine. But you must check globally, all the way up: that position is in 60's right subtree, so it must be > 60, and 50 isn't.
If you always insert by comparing from the top down, you can never make this mistake.
struct node* insert(struct node *t, int key) { if (t == NULL) return newNode(key); /* found the empty spot */ if (key < t->data) t->left = insert(t->left, key); else t->right = insert(t->right, key); return t; }
➕ Added for exam
  • A new key is always inserted as a leaf.
  • The first key inserted is the root forever, unless it is deleted.
  • The same set of keys in a different order gives a different tree.
  • Inserting keys in sorted order (10, 20, 30, …) builds a skewed tree, which is effectively a linked list.

12.4Deletion: Leaf, One Child, Two Children

🎓 From the lecture The tree has root 8: left 4 (children 2 and 6, with 6's children 5 and 7), and right 10 → 14 → 13.
  1. Leaf (7, or 13): just delete it. There is no impact on the tree; this is the easiest case.
  2. One child (14, whose only child is 13): you can't simply free 14 and lose 13, because that's stored information. Replace 14 with its child and connect 13 to 10. The BST rule is preserved: 13 < 14 but still > 10, so it is 10's right child.
  3. Two children (4): take the inorder sequence, which is always sorted for a BST (2, 4, 5, 6, …). Replace the node with its inorder predecessor, the value just before it, which is 2. Now 2's right child is 6, and 6's left child is 5. No rule is broken.
  4. Deleting the root 8 (two children): the inorder is 2, 5, 6, 8, 10, 13, so the predecessor is 6. 6 becomes the root, with 2 on its left and 10 on its right; 5 becomes 2's right child, and 13 stays 10's right child.
➕ Added for exam
  • Predecessor or successor: for two children you may use either the inorder predecessor (largest key in the left subtree, its rightmost node) or the inorder successor (smallest key in the right subtree, its leftmost node). Most textbooks and GATE-style answers use the successor unless the question says otherwise. The lecture uses the predecessor.
  • The predecessor or successor has at most one child, so removing it from its old place is always case 1 or case 2.
  • With the successor rule, deleting 8 from the original tree would put 10 at the root.
⚠️ Exam trap Read whether the question says "predecessor" or "successor". The two give different trees, and both are valid BSTs, so each answer has a trap option built from the other rule.

12.5Complexity, Min/Max, Successor, Counting & Solved QuestionsADDED

OperationBalanced BST (h ≈ log n)Skewed BST (h = n − 1)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)
Find min / maxO(log n)O(n)
Inorder (sorted output)O(n)O(n)
➕ Why AVL exists Every operation costs O(h). The height can be anywhere from log₂ n (balanced) to n − 1 (skewed, e.g. sorted input). Self-balancing trees such as AVL (chapter 13) and red-black trees keep h = O(log n) always.
➕ More facts
  • Minimum = keep going left; maximum = keep going right.
  • Sorting with a BST (tree sort): insert everything, then do an inorder walk. That is O(n log n) on average and O(n²) in the worst case.
  • Number of distinct BSTs with n distinct keys = Catalan C(n): 1, 2, 5, 14, 42.
  • A BST can be rebuilt from its preorder alone (or postorder alone), because the inorder is just the sorted keys.
  • Duplicates: either disallow them, or consistently send equal keys to one side (here, the right).
🎯 IBPS exam alert
  • "Which traversal of a BST gives sorted output?" → inorder.
  • "Worst-case search time in a BST?" → O(n). Average → O(log n).
  • "Where is a new key inserted?" → as a leaf.
  • "Smallest element in a BST?" → the leftmost node.
  • Delete with two children → replace with the inorder successor (or predecessor).

Worked question: insert 45, 15, 79, 90, 10, 55, 12, 20, 50 into an empty BST.

Inorder : 10 12 15 20 45 50 55 79 90 (sorted ✔) Preorder : 45 15 10 12 20 79 55 50 90 Postorder : 12 10 20 15 50 55 90 79 45 Height : 3 (45 → 15 → 10 → 12, or 45 → 79 → 55 → 50) Leaves : 12, 20, 50, 90
Q1In the tree above, how many comparisons does a search for 50 take? → 45, 79, 55, 50 = 4.
Q2Delete 45 (the root) using the inorder successor. → The successor is 50 (leftmost in the right subtree). 50 becomes the root, and 55 loses its left child.
Q3Is a tree with inorder 10, 20, 15, 30 a BST? → No. The inorder isn't sorted (20 > 15).
Q4Keys 1 to 7 are inserted in ascending order. What is the height? → Skewed, so the height is 6. Inserted in the order 4, 2, 6, 1, 3, 5, 7, the height is 2 (perfect).
Q5How many different BSTs can be built from the keys {1, 2, 3}? → C(3) = 5.

⚡ Rapid Revision

  • BST rule: left subtree < node < right subtree, at every node and for the whole subtree. Inorder ⇒ sorted.
  • Search from the root: key smaller → left, larger → right. Lecture: 13 found via 10 → 12 → 15 → 13; 9 via 10 → 8 → 9.
  • Insert by comparing from the root; a new key becomes a leaf. 50, 40, 30, 60, 80, 20, 70 gives 50(40(30(20)), 60(—, 80(70))).
  • Check globally: a node in 60's right subtree must be > 60, so 50 can't be the left child of 80 there.
  • Delete: leaf → remove. One child → replace it with the child. Two children → replace with the inorder predecessor (lecture) or successor (common in books).
  • Cost O(h): O(log n) balanced, O(n) skewed (sorted input), hence AVL. Min = leftmost, max = rightmost. Number of BSTs = Catalan.
