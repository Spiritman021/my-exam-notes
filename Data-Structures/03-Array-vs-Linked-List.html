Chapter 3

Array vs Linked List

Both are linear: each element has one predecessor and one successor. They differ in where elements live and how you reach them. An array keeps elements side by side in memory, so it can compute any address. A linked list scatters its nodes and chains them with pointers, so it must follow the chain. Every difference below follows from that single design choice.

3.1Contiguous vs Non-Contiguous Memory

🎓 From the lecture Round 1. An array's elements get continuous memory locations, one right after another. A linked list's cells can be anywhere: one here, the next in some other location, the third somewhere else. Nothing is continuous.
A basic singly-linked-list node has two fields: a data field and a link field. The link holds the address of the next node. In memory cells 1–5:
  • cell 1 holds data 10, link 3: "go and check cell 3";
  • cell 3 holds data 20, link 5;
  • cell 5 holds data 30, link NULL, so the list ends here.
There are gaps (cells 2 and 4), so the nodes are not contiguous, but they are linked.

3.2Random Access vs Sequential Access

🎓 From the lecture Round 2. An array allows random access: to reach index 5, just use the index and jump straight there.
A linked list does not allow random access; you can't jump into the middle. A head pointer points to the first node, and from there you follow the links node by node. That is sequential access.
➕ Added for exam Reaching the k-th element costs O(1) in an array and O(k), i.e. O(n) in the worst case, in a linked list. So binary search is useless on a plain linked list: finding the middle alone takes O(n).

3.3Insertion/Deletion Cost, Static vs Dynamic, Variations and Representation

🎓 From the lecture
  • Round 3 — insert/delete: in an array they take more time because of heavy shifting. In a linked list only pointers change, so it's quick (shown in chapter 4).
  • Round 4 — nature: an array is fixed / static, which causes memory problems. A linked list is dynamic: it uses memory better, and changes are "welcomed" and easy to implement.
  • Round 5 — variations: arrays come as 1D, 2D… multi-dimensional. Linked lists come as singly, doubly and circular (chapters 4–6).
  • Round 6 — representation (different from access): an array has a sequential representation; a linked list has a linked representation, with nodes joined by links. The last node points to NULL, which marks the end of the list.
⚠️ Exam trap "Linked-list insertion/deletion is O(1)" is true only once you have a pointer to the place. Inserting at position k or deleting a given value still needs an O(n) walk to find the spot. The real saving is no shifting, not "no work".
⚠️ Exam trap "Dynamic, so better memory use" is only half the story. A linked list wastes nothing on unused slots, but every node pays for an extra pointer (and two in a doubly linked list). For small data such as ints, a full array can use less memory than the same list (numerical in 3.4).

Memory numericalStore 1,000 integers (4 bytes each); pointers are 8 bytes.
Array: 1,000 × 4 = 4,000 bytes.
Singly linked list: 1,000 × (4 + 8) = 12,000 bytes (3× the array).
Doubly linked list: 1,000 × (4 + 8 + 8) = 20,000 bytes.
But if the array were declared for 10,000 ints "to be safe", it would take 40,000 bytes, and the linked list wins.
🎯 IBPS exam alert
  • "Which allows random access?" → array. "Which needs extra memory for pointers?" → linked list.
  • "Which is better for frequent insertions and deletions?" → linked list. "For binary search?" → array.
  • The pointer that marks the start of a list is the head (also called start/first); the last node's link is NULL.
  • Memory for linked-list nodes is allocated from the heap.
Q1Time to access the 50th element of a singly linked list of 100 nodes, starting from head? → 49 link-follows, i.e. O(n). In an array: O(1).
Q2Which operation is faster in a linked list than in an array? (a) access by index (b) binary search (c) insertion at the beginning (d) cache use → (c).
Q3Why can't binary search be done efficiently on a linked list? → Finding the middle element needs O(n) traversal; there is no random access.
Q4A program reads an unknown number of records and frequently deletes from the front. Which structure? → Linked list: dynamic size, and front deletion in O(1).

⚡ Rapid Revision

  • Lecture's six rounds: contiguous vs non-contiguous · random vs sequential access · insert/delete slow (shifting) vs fast (pointers) · static vs dynamic · variants (1D/2D/multi vs singly/doubly/circular) · sequential vs linked representation.
  • Node = data + link; link = address of the next node; head → first node; last link = NULL. Lecture example: 10 in cell 1 → 3, 20 in cell 3 → 5, 30 in cell 5 → NULL.
  • Array access O(1), linked-list access O(n); binary search needs an array.
  • Linked-list insert/delete is O(1) only at a known node; finding it is O(n).
  • Linked list pays for a pointer per node (12 B vs 4 B per int); an array pays for unused slots.
  • Linked-list nodes come from the heap (malloc) at run time; arrays are sized at compile time.
