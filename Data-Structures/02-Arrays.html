Chapter 2

Arrays

The array is the most fundamental data structure, and other structures (stacks, queues, heaps, hash tables, graph matrices) are often built on top of it. Three properties define it: the elements sit in contiguous memory, they are all of the same type, and each is reached by an index. Contiguity is what makes the address of any element computable in one step. It is also why inserting or deleting in the middle means shifting every element after it.

2.1Array Basics (Classroom Example)

🎓 From the lecture Picture class A, a classroom with 10 students on benches numbered 100, 101, 102, 103, 104…, each student with a roll number 0, 1, 2, 3, 4…. Map it onto an array:
  • students = data; bench numbers = memory addresses, allocated in a continuous fashion (contiguous memory locations);
  • data is stored in an adjacently attached arrangement, so the array is a linear data structure;
  • all elements are of the same type: if it holds characters, every element is a character; if integers, every element is an integer;
  • roll numbers = indexes, which give unique identification. Calling "Rakesh" in class makes ten Rakeshes stand up; calling "Akshay" might bring fifty. Calling roll number 6 brings exactly one student. Likewise, an index such as 6 picks exactly one element.
Array: a finite, ordered collection of elements of the same data type, stored in contiguous memory locations and accessed by an index (subscript).

2.2Array Declaration

🎓 From the lecture In C the declaration has three parts: the data type of every element, the name of the array, and its size in square brackets (how many elements). For the 10 students as integers:
int arr[10]; /* type name[size] */ arr[6] /* the element at index 6 */
➕ Added for exam
  • Initialisation: int a[5] = {1, 2, 3}; sets the rest to 0. int a[] = {1, 2, 3}; gets size 3 from the list.
  • Memory used = number of elements × size of one element. int a[10] with 4-byte ints takes 40 bytes; char c[10] takes 10 bytes.
  • In C the array name holds the base address: a[i] means *(a + i). That's why C indexes start at 0: the first element sits 0 places from the base.
  • C does no bounds checking. a[10] on a 10-element array compiles fine and reads or writes outside the array (undefined behaviour). Java throws ArrayIndexOutOfBoundsException.

2.3Advantages and Disadvantages of Arrays

🎓 From the lecture Advantages
  • Random access: no need to start from the beginning. arr[6] goes straight to index 6.
  • Easy to understand, use and retrieve from.
Disadvantages
  • Fixed (static) size: declare size 10, store only 4 values, and the other 6 slots are reserved and wasted. This is the memory-waste point from chapter 1.
  • Insertion and deletion are costly: removing an element means shifting the rest left; adding one means shifting the rest right (sections 2.8–2.10).

2.41D Array: Size Formula (u − l + 1)

🎓 From the lecture For array arr with lower index l (lower bound) and upper index u (upper bound), the number of elements is:
Size (length) = u − l + 1
🎓 From the lecture Indexes 0 to 8: size = 8 − 0 + 1 = 9.
A common doubt is that the +1 is there only because indexing starts at 0. It isn't. Number the same nine cells from 1 to 9: size = 9 − 1 + 1 = 9, the same answer. The +1 counts both end-points, so the formula works whatever index you start from (0, 1, 2…).
⚠️ Exam trap Bounds can be negative in exam questions (Pascal-style arrays): A[−5 … 10] has 10 − (−5) + 1 = 16 elements. Subtract carefully, and don't forget the +1.

2.51D Array: Address Calculation

🎓 From the lecture To find the address of element i you need: the base address BA (address of the first element, here 1000), the lower bound l = 0, and the size of one element w in bytes (taken as 1 byte for simplicity; it would be 2, 4… depending on the data type).
LOC(A[i]) = BA + w × (i − l)
🎓 From the lecture
  • i = 0: 1000 + 1 × (0 − 0) = 1000, the base address itself.
  • i = 1: 1000 + 1 × (1 − 0) = 1001; then 1002, 1003 … for each next index.
  • i = 8: 1000 + 1 × (8 − 0) = 1008.
Solved (added)A[−10 … 30] of 2-byte integers, base address 2000. Address of A[5]?
LOC = 2000 + 2 × (5 − (−10)) = 2000 + 2 × 15 = 2030.
⚠️ Exam trap Multiply by the element size w. With 4-byte ints, A[3] from base 1000 is at 1000 + 4 × 3 = 1012, not 1003. Also: if the question says "base address is the address of A[1]", then l = 1, so subtract 1 from i.

2.62D Array: Row-Major vs Column-Major Address

🎓 From the lecture In 2D arrays the address depends on the order the elements are laid out in memory. Take a 3 × 3 array (rows 0–2, columns 0–2), base 1000, element size 1, and find the address of element [1][2].
  • Column-major: lay out the columns one after another. Column 0 = 00, 10, 20; column 1 = 01, 11, 21; column 2 = 02, 12, 22.
  • Method: [1][2] is in column 2. Count the elements in the columns before it: 2 columns × 3 entries each (number of rows = 2 − 0 + 1 = 3) = 6. Then add the elements before it within its column: i − lr = 1 − 0 = 1 (only 02 comes before 12). Total offset 7, so the address is 1007.
  • The column-major formula is the row-major one with the terms swapped: j for i, lc for lr, number of rows for number of columns.
  • The same element sits at 1005 in row-major order (00 01 02 10 11 12…) but at 1007 in column-major order (00 10 20 01 11 21 02 12…). Neither is wrong; it's the order that differs. Before solving, always check which order the question uses.

With rows lr…ur, columns lc…uc and element size w, let R = ur − lr + 1 (number of rows) and C = uc − lc + 1 (number of columns):

Row-major: LOC(A[i][j]) = BA + w × [ (i − lr) × C + (j − lc) ] Column-major: LOC(A[i][j]) = BA + w × [ (j − lc) × R + (i − lr) ] check [1][2], 3×3, BA 1000, w 1: row-major = 1000 + (1×3 + 2) = 1005 column-major = 1000 + (2×3 + 1) = 1007
➕ Added for exam Read the formula as a sentence. Row-major means skip (i − lr) full rows of C elements each, then move (j − lc) along the row. Column-major means skip (j − lc) full columns of R elements each, then move (i − lr) down the column. Total elements in a 2D array = R × C.
Which languages use which: C, C++, Java, Python (NumPy default) are row-major; FORTRAN, MATLAB and R are column-major.
Solved (added)A[1 … 10][1 … 15], base 100, w = 4 bytes. Find A[5][10].
R = 10, C = 15.
Row-major: 100 + 4 × [(5 − 1) × 15 + (10 − 1)] = 100 + 4 × 69 = 376.
Column-major: 100 + 4 × [(10 − 1) × 10 + (5 − 1)] = 100 + 4 × 94 = 476.
Solved (added) — negative boundsA[−2 … 2][3 … 7], base 500, w = 2. Find A[1][5].
R = 5, C = 5, total = 25 elements.
Row-major: 500 + 2 × [(1 + 2) × 5 + (5 − 3)] = 500 + 2 × 17 = 534.
Column-major: 500 + 2 × [(5 − 3) × 5 + (1 + 2)] = 500 + 2 × 13 = 526.
⚠️ Exam trap In row-major the multiplier is the number of columns; in column-major it is the number of rows. Students often swap these. Ask yourself: "how long is one full row (row-major) or one full column (column-major)?" If the order isn't stated, assume row-major, since C is row-major.
⚠️ Lecture slip While explaining column-major, the lecturer says "elements before the current row" a few times. The quantity is the elements in the columns before the current column. Also, the transcript is missing the row-major worked example itself, though it states the result (1005); it is filled in above.

2.7Array Traversal

🎓 From the lecture Traversing means visiting (touching, scanning) every element once, from start to end. Analogy: a plot of land with houses 1–5. You have good news and sweets (pede), so you go to house 1, then 2, 3, 4, 5. Once all five are visited you go home and the traversal is over. 
for (i = 0; i < n; i++)      /* n = 5 houses */
    printf("%d", arr[i]);
Notice from the picture: the plot was big but only five houses were built, so the rest of the land is unused. That is the fixed-size waste again: supply exceeded demand. The reverse can also happen: declare too small an array and you run out of space (demand exceeds supply).
➕ Added for exam Traversal is always O(n): every element is visited exactly once. Sums, averages, max/min, printing and counting are all traversals.

2.8Array Insertion (Cinema Queue Example)

🎓 From the lecture Insertion looks easy but isn't. You're in a cinema ticket line, second from the front (index 1). A friend arrives and you put him ahead of you, not at the back. Now the friend is at index 1 and you've moved to index 2. Everyone behind you also moves back one (index + 1). Their data can't be lost, so the elements after the insertion point are shifted right to make room, and their indexes change.

2.9Position vs Index and Insertion Best/Worst Case

🎓 From the lecture Position is the human count (1st, 2nd, 3rd…); index starts at 0. In [10, 20, 30], 10 is at position 1 but index 0.
position = index + 1 index = position − 1
🎓 From the lecture Insert 5 at index 1 of [10, 20, 30]: 30 moves right, then 20 moves right, then 5 goes into the gap, giving [10, 5, 20, 30].
  • Best case: insert at the end (e.g. 40 after 30). Nothing shifts.
  • Worst case: insert at index 0 (e.g. 1). Every element shifts right, giving [1, 10, 5, 20, 30].
/* insert x at index pos; n = current count, capacity must be > n */ for (i = n - 1; i >= pos; i--) a[i + 1] = a[i]; /* shift right, from the END backwards */ a[pos] = x; n++;
⚠️ Exam trap Shift from the last element backwards. Shifting forwards from pos overwrites the next value before it is copied, so every cell ends up holding a copy of the same element. Inserting at index pos moves n − pos elements; on average that's n/2, which is O(n).

2.10Array Deletion (Milk Queue Example)

🎓 From the lecture A line for milk. The person at index 1 (position 2) remembers some work and leaves. Everyone behind steps forward: left shift. Index 2 becomes 1, index 3 becomes 2… Insertion causes a right shift; deletion causes a left shift. Both are the overhead of arrays.
Delete index 1 from [10, 20, 30, 40, 50]: 20 leaves, then 30, 40 and 50 each move left, giving [10, 30, 40, 50].
  • Best case: delete the last element. Nothing moves.
  • Worst case: delete index 0. Every other element moves left.
Whether inserting or deleting, the end of the array is the best case and the beginning is the worst.
/* delete the element at index pos */ x = a[pos]; for (i = pos; i < n - 1; i++) a[i] = a[i + 1]; /* shift left, from pos FORWARDS */ n--;
➕ Added for exam Deleting index pos moves n − pos − 1 elements. If order doesn't matter, you can delete in O(1): copy the last element into the hole and decrease n.

2.11Array Searching (100-Floor Building Example)

🎓 From the lecture A 100-floor building: the floors are positions 1–100 (indexes 0–99). You eat dinner on the 100th floor and walk down the stairs to help digestion. Outside, your expensive watch is gone. You had it at dinner, so you search floor 1, then 2, then 3… up to 100. That is searching: start to end until found.
  • Best case: found on the first floor.
  • Worst case: found only on the 100th ("80 pe toh jaan chali gayi, 90 pe paani pila do").
  • Worst of the worst: not found at all, after scanning the whole array.
/* linear (sequential) search */ for (i = 0; i < n; i++) if (a[i] == key) return i; /* found */ return -1; /* not found */

2.12Binary Search, Complexity Table & Solved NumericalsADDED

➕ Added for exam If the array is sorted, binary search halves the range each step: compare with the middle element, then keep the left or the right half.
low = 0; high = n - 1; while (low <= high) { mid = (low + high) / 2; if (a[mid] == key) return mid; else if (a[mid] < key) low = mid + 1; else high = mid - 1; } return -1;
Tracea = [5, 12, 19, 26, 33, 40, 47], key = 40.
low 0, high 6 → mid 3 (26) < 40 → low 4.
low 4, high 6 → mid 5 (40) found in 2 comparisons. Linear search would take 6.

🎯 IBPS exam alert
  • Binary search needs a sorted array with random access. It's not efficient on a linked list.
  • Maximum comparisons for n = 1000: ⌊log₂ 1000⌋ + 1 = 9 + 1 = 10.
  • "Elements stored in consecutive memory locations" → array.
  • "Address of element = base + w(i − l)": asked as a direct numerical almost every year in some form.
Q1Array A[−3 … 12]: how many elements? → 12 − (−3) + 1 = 16.
Q2int A[20] (4 bytes each), base 3000, index from 0. Address of A[7]? → 3000 + 4 × 7 = 3028.
Q3Array of 50 elements: how many shifts to insert at position 1 (index 0)? → all 50. At position 50 (index 49)? → 1 (the old last element moves). Appending at index 50 needs 0.
Q4A[1…10][1…15], base 100, w 4: A[5][10] row-major = 376, column-major = 476 (worked in 2.6).
➕ Added for exam Beyond 2D: a 3D array A[l1…u1][l2…u2][l3…u3] in row-major order gives LOC = BA + w × [(i − l1) × D2 × D3 + (j − l2) × D3 + (k − l3)], where Dk = uk − lk + 1. A sparse matrix (mostly zeros) is better stored as (row, col, value) triplets or linked lists. Dynamic arrays (C++ vector, Java ArrayList, Python list) remove the fixed-size problem by doubling capacity when full, which makes appending O(1) amortised.

⚡ Rapid Revision

  • Array = same type, contiguous memory, indexed. Linear and static. Lecture: classroom, benches = addresses, roll numbers = indexes.
  • int arr[10]; → type, name, size. a[i] = *(a + i); C indexes start at 0; no bounds checking in C.
  • Pros: O(1) random access, simple. Cons: fixed size (waste or overflow), O(n) insert/delete.
  • Size = u − l + 1 (true for any starting index; watch negative bounds).
  • LOC = BA + w(i − l). Lecture: BA 1000, w 1 → A[1] = 1001, A[8] = 1008.
  • Row-major: BA + w[(i − lr)·C + (j − lc)]. Column-major: BA + w[(j − lc)·R + (i − lr)]. 3×3, [1][2] → 1005 vs 1007. C is row-major; FORTRAN is column-major.
  • Insert: shift right from the end; best at end O(1), worst at index 0 O(n). Delete: shift left; best last, worst index 0.
  • Position = index + 1.
  • Linear search: best 1, average (n+1)/2, worst n (or not found). Binary search (sorted): O(log n), ≤ ⌊log₂ n⌋ + 1 comparisons.
