Chapter 4

Singly Linked List

A singly linked list is a chain of nodes. Each node holds one piece of data and the address of the next node, and the chain runs in one direction only. Every operation in this chapter is the same game: change a few pointers in the right order, and never lose your grip on the rest of the list.

4.1What is a Linked List (Data Field, Link Field, Head)

🎓 From the lecture A linked list is "a list of elements which are linked to each other", because they sit in non-contiguous memory locations: one element here, the next somewhere else, the third somewhere else again, yet all connected.
In a singly linked list every node has two parts:
  • data field: the value;
  • link field: the address of the next node.
The head contains the address of the first node. If the first node is at address 10, head holds 10, i.e. head points to the first node.
Singly linked list: a linear collection of nodes, each holding data and a pointer to the next node; the head pointer gives the first node and the last node's pointer is NULL. An empty list is simply head == NULL.

4.2Node Structure and Dynamic Allocation (malloc)

🎓 From the lecture A node is defined with a structure named node. It has an integer data field and a struct node * link: the link points to another node of the same structure, which is why the struct refers to itself.
Because a linked list is dynamic, a node is created with dynamic memory allocation using malloc, passing the size of a node. malloc returns the address of the new node, and that address is caught in the head pointer.
Example: the new node gets address 10, so head = 10. The node is empty at first, so we write 5 into the data of the node head points to, and put NULL in its link, because a brand-new node has no next node yet.
struct node { int data; struct node *link; /* self-referential: points to a node */ }; struct node *head; head = (struct node *) malloc(sizeof(struct node)); head->data = 5; head->link = NULL;
➕ Added for exam
  • A struct that contains a pointer to its own type is a self-referential structure; that is the textbook name for a linked-list node.
  • malloc takes memory from the heap and returns void * (cast to struct node *). It returns NULL if no memory is available; that condition is called overflow for a linked list.
  • free(p) gives the memory back. Forgetting it causes a memory leak; using p after freeing it is a dangling pointer.
  • -> is shorthand: p->data is the same as (*p).data.

4.3Reading Pointer Expressions

🎓 From the lecture If you can read these expressions on the example list, the rest of the chapter becomes easy. Read each arrow as "go to the node this address points to":
  • head->data: the data of the node head points to → 1.
  • head->link → 20.
  • head->link->data: follow head's link (20) to the second node, read its data → 2. Read the other way, head->link->data = 2 writes 2 into that field.
  • head->link->link → 30.
  • head->link->link->data → 3.
  • head->link->link->link → NULL: the end of the list.
All of this uses only the one head pointer.

4.4Traversal

🎓 From the lecture Traversal is the most basic operation, and it is sequential: one node after another.
  • Copy head into a second pointer, current, so head keeps pointing to the first node.
  • Loop while current != NULL: print current->data, then move ahead with current = current->next.
  • "Next" and "link" are the same field; both names are common. A doubly linked list has two links, prev and next.
On 1 → 2 → 3 → 4 it prints 1, 2, 3, 4. After the last node, current becomes NULL and the loop stops: "the entire list has been traversed". This snippet is the base of almost every later operation.
void traverse(struct node *head) { struct node *current = head; while (current != NULL) { printf("%d ", current->data); current = current->next; } }
⚠️ Exam trap
  • while (current != NULL) visits every node.
  • while (current->next != NULL) stops at the last node without processing it, so it prints one fewer. It also crashes on an empty list.
  • That second form is exactly what you want when you need a pointer to the last node (insert at end, 4.8).
In the lecture, "until current's next is NULL" is said aloud, but the code uses current != NULL; go by the code.
⚠️ Exam trap Never traverse by moving head itself (head = head->next). After the loop, head is NULL and the whole list is lost (leaked). That is why a separate current pointer is used.

4.5Searching

🎓 From the lecture Search is the traversal snippet with one if block added. Search is given a key, and at each node we check whether current->data == key:
  • if it matches, return "found";
  • if not, move on with current = current->link;
  • if the loop ends at NULL without a match, return "not found".
Best case: the key is in the first node. Worst case: it is in the last node, or absent, so all n nodes are visited: O(n), because access is sequential.
One improvement is to keep a tail pointer as well as head, so you don't have to traverse as much. The traditional list keeps only the head pointer, and the lecture continues with that.
int search(struct node *head, int key) { struct node *current = head; while (current != NULL) { if (current->data == key) return 1; /* found */ current = current->link; } return 0; /* not found */ }
➕ Added for exam Search is O(n) even if the list is sorted. Binary search needs the middle element in O(1), which a linked list can't give (chapter 3). A sorted list only lets you stop early once you pass the key; the worst case is still O(n).

4.6Insert at Beginning

🎓 From the lecture Insertion has three important variations: at the beginning, after a node and at the end. All three are asked in exams.
List: head = 10 → nodes 10, 20, 30. The new node is at address 5, and it should become the first node.
  1. new->next = head; Head holds 10. Once the new node is first, the old first node becomes the second, so the new node's next must hold its address, 10. The new node's next is no longer NULL.
  2. head = new; The new pointer holds 5. Give 5 to head, and head now points to the new node.
The old first node has shifted to second place, but no node actually moved, unlike an array. Only pointers were exchanged, which is why linked-list insert and delete are fast.
new = (struct node *) malloc(sizeof(struct node)); new->data = x; new->next = head; /* step 1 */ head = new; /* step 2 */
⚠️ Exam trap The order matters. If you write head = new; first, the address 10 is overwritten and the rest of the list is lost. new->next = head would then make the new node point to itself. The rule for every insertion: connect the new node first, then redirect the old pointer.
➕ Added for exam Insert at beginning is O(1). It also works on an empty list: head is NULL, so new→next becomes NULL and head becomes new. It is the cheapest insertion, and it is how a stack is built on a linked list (push = insert at beginning).

4.7Insert After a Node

🎓 From the lecture Insert the new node right after a given node; call that node prev, because it will be just before the new one. Prev is at address 20, its next holds 30, and the new node is at 25.
  1. new->next = prev->next; After insertion the new node must point to node 30, and that address sits in prev's next, so copy it: the new node's link becomes 30.
  2. prev->next = new; Give the new node's address, 25, to prev's next. Now 20 → 25 → 30.
The connection is now 20 → 25 → 30, and the node is inserted.
⚠️ Exam trap Swap the two lines and you get prev->next = new; new->next = prev->next;. The second line now reads the new value, so new→next = new: a self-loop, and node 30 onwards is lost. MCQs love to ask "what is wrong with this code?" (In the lecture the old value in prev's next is said once as "35"; it is 30.)
➕ Added for exam With a pointer to prev, this is O(1). Inserting at a position k or after a value first needs a traversal to find prev: O(n). A singly list can insert after a node easily, but not before it: there is no back pointer to the previous node.

4.8Insert at End

🎓 From the lecture This one is simple. The list is 10 → 20 → 30, and the new node is at 35 with its link NULL.
  • To insert after 30 you must go all the way to the last node, traversing the whole list.
  • Give the new node's address to the last node's next: last->next = new. Node 30's link becomes 35 instead of NULL.
  • Nothing else is needed: the new node's link is already NULL, which marks it as the last node.
new->data = x; new->next = NULL; if (head == NULL) { /* empty list */ head = new; } else { struct node *last = head; while (last->next != NULL) /* stop AT the last node */ last = last->next; last->next = new; }
➕ Added for exam Insert at end costs O(n) with only a head pointer, because of the walk. With a tail pointer it is O(1): tail->next = new; tail = new;. That is how a queue is built on a linked list (enqueue at tail, dequeue at head).

4.9Delete at Beginning

🎓 From the lecture Deletion adds one fundamental step: keep a delete pointer (del) on the node being removed, so that its memory can be released with free(). "As the name, so the work": free it, it's of no use any more.
To delete the first node (head = 10):
  1. del = head; del also points to node 10.
  2. head = del->link; del's link holds 20, so head becomes 20 and now points to the second node.
  3. free(del); Nothing points to node 10 any more, so free it.
if (head != NULL) { struct node *del = head; head = del->link; /* head = 20 */ free(del); /* node 10 released */ }
⚠️ Exam trap Calling free(head) before head = head->link reads a freed node. That is undefined behaviour, even if it seems to work. Save the address, unlink, then free. Deleting from an empty list (head == NULL) is underflow.

4.10Delete After a Node

🎓 From the lecture To delete the node that comes after a given node prev:
  1. del = prev->link; Prev's link holds the address of the node to delete, 20. Give it to del (you can also call it temp).
  2. prev->link = del->link; del's link holds 30. Put 30 into prev's link, because once 20 is gone, prev must point to 30.
  3. free(del); The connection to node 20 is cut, so free it.
➕ Added for exam With prev in hand this is O(1). Deleting a node by value means walking with two pointers (prev and current) until current holds the key: O(n). The node to delete is unlinked through its predecessor; you need prev, not just the node itself.

4.11Delete at End

🎓 From the lecture To delete the last node, the node before it becomes "prev". Its link holds the address of the last node (say 30); replace it with NULL. The connection is cut, so free the last node.
"By simply playing with pointers you keep the structure intact while inserting and deleting, without taking extra load. That is the speciality of the linked list."
if (head->next == NULL) { /* only one node */ free(head); head = NULL; } else { struct node *prev = head; while (prev->next->next != NULL) /* stop at second-last */ prev = prev->next; free(prev->next); prev->next = NULL; }
⚠️ Exam trap Delete at end is O(n) even with a tail pointer. The tail pointer finds the last node instantly, but you must change the second-last node's link to NULL, and a singly list has no way back to it except walking from head. (A doubly linked list fixes this, in chapter 5.) Compare: insert at end with a tail pointer is O(1).

➕ Edge cases every operation must handle
  • Empty list (head == NULL): delete = underflow; insert at end must set head itself.
  • One node: deleting it must set head = NULL; the "second-last" loop would crash.
  • Operation at the first node: changes head, so a C function must receive struct node **head or return the new head.
  • Key not present: search returns not found; delete-by-value does nothing.

Reverse a singly linked list (the most asked coding question). Walk once, turning every arrow backwards with three pointers:

struct node *prev = NULL, *cur = head, *nxt; while (cur != NULL) { nxt = cur->next; /* save the rest */ cur->next = prev; /* reverse this arrow */ prev = cur; /* move prev ahead */ cur = nxt; /* move cur ahead */ } head = prev; /* old last node is the new head */

Find the middle in one pass: move slow one step and fast two steps. When fast reaches the end, slow is at the middle. On 10 → 20 → 30 → 40 → 50, slow stops at 30. The same slow/fast idea (Floyd's tortoise and hare) detects a loop: if the list has a cycle, fast eventually meets slow.

🎯 IBPS exam alert
  • "A node of a linked list is an example of a …" → self-referential structure.
  • "Which function allocates a node / releases it?" → malloc() / free(); memory comes from the heap.
  • "Cheapest insertion in a singly linked list?" → at the beginning, O(1).
  • "Which operation depends on list length even with head and tail pointers?" → deleting the last node.
  • "Linked list with no nodes" → head = NULL. "Delete from an empty list" → underflow. "malloc fails" → overflow.
  • Applications: implementing stacks and queues, polynomial representation, sparse matrices, adjacency lists of graphs, dynamic memory (free lists).
Q1On the lecture's list (head = 10; nodes 10, 20, 30 with data 1, 2, 3), what is head->link->link->data? → Two links take you to node 3 → 3.
Q2Which code correctly inserts node p after node q?
(a) q->next = p; p->next = q->next;
(b) p->next = q->next; q->next = p;
→ (b). Option (a) makes p point to itself and loses the rest of the list.
Q3What does this print for the list 1 → 2 → 3 → 4 → 5 → 6?
void fun(struct node *h) { if (h == NULL) return; printf("%d ", h->data); if (h->next != NULL) fun(h->next->next); printf("%d ", h->data); }
→ It prints on the way down, skipping every other node (1, 3, 5), then prints again while returning (5, 3, 1): 1 3 5 5 3 1.
Q4A singly linked list has n nodes, with pointers to the first and last node. Which of these takes O(n)? (a) insert at front (b) insert at end (c) delete front (d) delete last → (d): the second-last node must be found by walking from head.
Q5Minimum number of pointer fields changed to insert a node in the middle of a singly linked list? → 2: the new node's next and the predecessor's next.

⚡ Rapid Revision

  • Node = data + link (self-referential struct). head holds the first node's address; the last link is NULL; empty list ⇔ head == NULL.
  • Create with malloc(sizeof(struct node)) (heap) and release with free(). A new node's link starts as NULL.
  • Reading: k × ->link from head reaches node k+1. On the lecture list, head→link→link→data = 3, and three links reach NULL.
  • Traverse with a copy, cur = head; while (cur != NULL) cur = cur→next;. Never move head itself.
  • Search is O(n), best case the first node, even if the list is sorted.
  • Insert at beginning: new→next = head; head = new (O(1)). Insert after: new→next = prev→next; prev→next = new. Connect the new node first.
  • Insert at end: walk to the last node, last→next = new. O(n), or O(1) with a tail pointer.
  • Delete: keep del, unlink, then free(del). Beginning: head = del→next. After: prev→next = del→next. End: second-last→next = NULL, which is O(n) even with a tail.
  • Reverse with prev/cur/next in O(n) time and O(1) space. Slow/fast pointers find the middle and detect loops.
