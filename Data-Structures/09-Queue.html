Chapter 9

Queue

A queue is the stack's opposite twin. A stack has one door that is both entry and exit. A queue has two doors: you join at the rear and leave from the front, so whoever came first leaves first. Everything in this chapter is about keeping two indices, front and rear, moving correctly, and the circular queue is the fix for the space a straight array wastes.

9.1FIFO Concept (Water-Park Ride)

🎓 From the lecture A queue is the opposite of a stack. On a water-park slide that "spins you round and throws you straight into the water", the person who entered first falls into the water first. The next one in the line falls next, and so on.
This arrangement is a queue: First In First Out (FIFO), or equivalently Last In Last Out (LILO). "The dialogue 'the line starts where I stand' doesn't work here. This is a queue, get in line!"
Queue: a linear data structure in which insertion (enqueue) happens at one end, the rear, and deletion (dequeue) happens at the other end, the front. It follows FIFO.

9.2Front/Rear (Head/Tail), Enqueue and Dequeue

🎓 From the lecture
  • In a stack only one end was open. In a queue both ends are open. One end is called the head, the other the tail.
  • Insert = enqueue; delete = dequeue (for a stack these were push and pop).
  • The rule: insert from one end, delete from the other. Load from one side, unload from the other. This is the key difference from a stack, where you insert and delete at the same end.
  • Bus analogy: you board through one door and get off through the other; the boarding door isn't for getting off. The exit door is the front and the boarding door is the rear. Head/front and tail/rear are synonyms.
  • Initially the queue is empty, and front = rear = −1, like top = −1 for a stack.
⚠️ Exam trap Enqueue happens at the rear; dequeue happens at the front. The words sound reversed to many students, who think "front" is where you insert. Think of a ticket counter: people leave from the front of the line.

9.3Array Implementation: Overflow, First Insert, Underflow, Single Element

🎓 From the lecture Array of size n = 5 (indices 0–4), with f = r = −1 initially. The conditions to keep in mind:
  • Overflow (full): rear == n − 1. Each insert moves rear ahead. Once rear reaches 5 − 1 = 4, one more insert is overflow.
  • First element inserted: before it, f = r = −1 (empty). After it, f = r = 0. That is the one moment both point to 0.
  • Underflow (empty): f = r = −1. Deleting from an empty queue: "will you take the child's life?"
  • Only one element: front == rear.
  • Insert moves only rear (incremented); front doesn't budge. Delete moves front towards rear. With 1, 2, 3, 4, 5 in the queue, deleting 1 moves front to 2; delete again and front moves to 3, and so on. The element front points to is always the next one to leave.
  • When front and rear meet (one element) and that element is deleted, set f = r = −1 again: the queue is empty.
void enqueue(int x) { if (rear == n - 1) { printf("Overflow"); return; } if (front == -1) front = 0; /* first element */ rear = rear + 1; Q[rear] = x; } int dequeue() { if (front == -1) { printf("Underflow"); return -1; } int x = Q[front]; if (front == rear) /* last element leaves */ front = rear = -1; else front = front + 1; return x; }

9.4Limitation of the Linear Queue (Unused Space)

🎓 From the lecture Insert 1, 2, 3, 4, 5, so rear reaches index 4. Now dequeue 1 and 2: front moves to index 2 (element 3), and indices 0 and 1 are empty.
Try to insert: the full condition says rear == n − 1, so it's "full" and insert is not possible because of overflow, "however much space is lying empty". Memory utilisation in this linear queue is poor.
➕ Added for exam This is sometimes called false overflow. One fix is to shift all elements left after each dequeue, but that makes dequeue O(n). The standard fix is the circular queue, which keeps both operations O(1).

9.5Circular Queue ((p + 1) mod n)

🎓 From the lecture The solution: make the queue circular, so that after the last index it wraps round to the start and uses the free slots. "The circular queue was born precisely to solve this problem."
Let p stand for either pointer, rear or front. The old p++ becomes:
p = (p + 1) mod n
  • Rear wraps: rear = 4, n = 5 → (4 + 1) mod 5 = 5 mod 5 = 0, so the next insert goes into index 0.
  • Front wraps the same way: say 3 and 4 have left, front points to index 4 (element 5), and 1 and 2 have been inserted at indices 0 and 1, so rear = 1. Delete 5: front = (4 + 1) mod 5 = 0, so the next element to dequeue is the 1 at index 0.
(The lecture says the formula aloud once as "p + n mod n"; on the board it is (p + 1) mod n.)

9.6Queue Using a Linked List

🎓 From the lecture Same idea, played with pointers. front (head) points to the first node, and rear (tail) points to the last node, whose next is NULL. Insert at the rear, delete at the front, and no other node can be deleted.
  • Dequeue (nodes 10 → 20 → 30 → 40):
    1. temp = front; temp gets address 10.
    2. front = front->next; front changes from 10 to 20.
    3. free(temp);
  • Enqueue (rear holds 40; the new node is at 50 with next = NULL):
    1. rear->next = new; The NULL after 40 becomes 50, so the chain continues.
    2. rear = new; Rear changes from 40 to 50, because the new node is now the last.
⚠️ Exam trap
  • Enqueue into an empty linked queue must set both front and rear to the new node.
  • Dequeuing the last node must set rear = NULL as well, or rear is left pointing at freed memory.
  • Do it the other way round (insert at head, delete at tail) and dequeue becomes O(n). A singly list can't delete its tail in O(1) (chapter 4).

⚠️ Exam trap: the other convention Many textbooks start with front = rear = 0 and keep one slot always empty:
  • empty ⇔ front == rear;
  • full ⇔ (rear + 1) mod n == front;
  • so a circular queue of size n then holds at most n − 1 elements.
If an MCQ says "array of size n, maximum elements?", check which convention it uses (often n − 1).

➕ Deque (double-ended queue) Insert and delete at both ends: insertFront, insertRear, deleteFront, deleteRear.
  • Input-restricted deque: insert at one end only, delete at both.
  • Output-restricted deque: delete at one end only, insert at both.
  • A deque can act as a stack (one end only) or as a queue. It is best implemented with a circular array or a doubly linked list.
➕ Priority queue Each element has a priority, and the highest-priority element leaves first; ties are broken FIFO.
  • Ascending (min) and descending (max) priority queues.
  • Implementation cost (insert / delete-max): unsorted array O(1) / O(n); sorted list O(n) / O(1); binary heap O(log n) / O(log n) (chapter 14).
  • Uses: CPU scheduling by priority, Dijkstra's and Prim's algorithms, Huffman coding, event simulation.

➕ Queue using two stacks Enqueue = push onto S1. Dequeue = if S2 is empty, pop everything from S1 and push it onto S2, then pop S2. Each element moves at most twice, so this is amortised O(1). Conversely, a stack can be built from two queues.
🎯 IBPS exam alert
  • Queue = FIFO. Insert at the rear, delete at the front.
  • "Which data structure is used for BFS / CPU scheduling / printer spooling / buffering?" → queue. "Round-robin?" → circular queue.
  • "Disadvantage of a linear array queue?" → unused space at the front after deletions (false overflow).
  • Circular queue full: (rear + 1) % n == front.
  • "Elements are removed according to priority" → priority queue, best implemented with a heap.
Q1Empty queue: enqueue A, B, C, dequeue, enqueue D, dequeue. What is at the front? → Removed A, then B, so the queue is C D and the front is C.
Q2Circular queue, n = 8, front = 6, rear = 2 (wrapped). Number of elements? → (2 − 6 + 8) mod 8 + 1 = 4 + 1 = 5 (indices 6, 7, 0, 1, 2).
Q3Circular queue, n = 6, rear = 5. Where does the next element go? → (5 + 1) mod 6 = index 0, provided front ≠ 0.
Q4Linear queue of size 5: after 5 inserts and 3 deletes, can a new element be inserted? → No. rear = 4 = n − 1, so it overflows, even though 3 slots are free. That is why the circular queue is used.
Q5Which deque allows insertion at both ends but deletion at only one? → Output-restricted deque.

⚡ Rapid Revision

  • Queue = FIFO / LILO (water-park slide, bus doors). Two open ends: insert (enqueue) at the rear, delete (dequeue) at the front.
  • Array queue: start with f = r = −1. The first insert makes f = r = 0. Insert moves only rear, delete moves only front.
  • Conditions: full rear == n−1; empty f = r = −1; one element f == r; deleting the last element resets both to −1.
  • Linear queue limitation: freed front slots can't be reused (false overflow).
  • Circular queue: p = (p + 1) mod n for both pointers (4 → 0 when n = 5). Full: (rear+1) mod n == front. Count = (r − f + n) mod n + 1.
  • Linked queue: dequeue temp = front; front = front→next; free(temp); enqueue rear→next = new; rear = new. Watch the empty and last-node cases.
  • Deque: both ends (input-/output-restricted). Priority queue: highest priority leaves first, using a heap (O(log n)).
  • Stack ↔ DFS, recursion. Queue ↔ BFS, scheduling, spooling, buffers.
