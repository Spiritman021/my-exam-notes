Chapter 7

Stack

A stack is a linear list with one rule: you may touch only the top. Every insertion lands on top, and every removal takes the top. That single restriction makes it the structure behind function calls, undo, expression evaluation (chapter 8) and depth-first search. The lecture calls it "very important, very fundamental".

7.1LIFO / FILO Concept (Biscuits and Rotis)

🎓 From the lecture We see a stack implemented every day.
  • Biscuits with morning tea: the manufacturer put the bottom biscuit in first and the top one last. While eating, the top biscuit is eaten first and the bottom one last. What went in first comes out last: First In Last Out (FILO). Equivalently, what went in last comes out first.
  • Rotis at lunch: mummy puts the latest roti on top of the earlier ones. We take the top roti first, then the one below it, and so on: Last In First Out (LIFO).
This nature is a stack, and a stack is a linear data structure.
Stack: a linear data structure in which insertion (push) and deletion (pop) happen at only one end, called the top. It follows LIFO, which is the same as FILO.

7.2One-End Access, Top of Stack and Implementation

🎓 From the lecture
  • Insert and delete, called push and pop, happen from one end only. You open a biscuit packet from one end; open it from both and "all the biscuits will fall". The roti case also opens from one end only.
  • So we interact only with the element on top: the Top Of Stack (TOS). It is the only access point. Pull a biscuit from the middle and it breaks; for an unbroken biscuit only the top is visible and accessible. Treat the elements below as if you don't even know they're there.
  • You push onto it (the pushed element becomes the new TOS), and you pop it.
  • A stack can be implemented with an array (static) or a linked list (dynamic), the same static vs dynamic nature as in chapter 3.
  • Either way, fix one end. In an array, decide one end, and only that end inserts and deletes. In a linked list, use the head (starting) end for both insert and delete, and don't even look at the other end.
➕ Added for exam A stack is an Abstract Data Type (ADT). It is defined by its operations, not by how it is stored:
  • push(x), pop();
  • peek()/top(), which reads TOS without removing it;
  • isEmpty(), and isFull() for arrays only.
All of them are O(1). Searching for an arbitrary element is not a stack operation.

7.3Push and Pop: Basic Idea

🎓 From the lecture Push = insert into the stack; pop = delete from it. The code uses an array, the easiest way to see the stack's nature.
  • Push x, then y lands on x, then z lands on y.
  • Pop gives z first, then y, then x.

7.4Push Operation and Overflow (top == n − 1)

🎓 From the lecture The stack has room for n = 5 elements, at indices 0 to 4. x, y, z are pushed, so top = 2. Now push a:
  • Check first: if (top == n − 1), the top is at the last slot, so nothing more fits. With elements up to index 4, top = 4 = 5 − 1. This is stack overflow: print "stack full", and no push happens.
  • Here top is 2, so the condition is false and we continue.
  • A new element goes above the existing TOS. First top = top + 1 (2 + 1 = 3), moving to the empty slot. Then put a at stack[3].
void push(int x) { if (top == n - 1) { printf("Stack Overflow"); return; } top = top + 1; /* increment FIRST */ stack[top] = x; /* then store */ }
⚠️ Exam trap
  • The order is increment, then store (stack[++top] = x). Writing stack[top++] = x with top starting at −1 writes to stack[-1].
  • Some books start with top = 0 ("next free slot"). Then the full test is top == n, the empty test is top == 0, and push is stack[top++] = x. Read which convention a question uses; the lecture's (and IBPS's usual) one is top = −1.

7.5Pop Operation and Underflow (top == −1)

🎓 From the lecture
  • Initially, with no elements, we set top = −1, because there is no element to point to. top == −1 means the stack is empty. Popping from an empty stack is underflow: "what more will you take out of it?"
  • Example: size 4 (indices 0–3), elements x, y, z, top = 2. The top element is removed, z, not y or x:
    1. copy stack[top] (z) into a variable;
    2. decrement top: 2 − 1 = 1, so TOS is now y;
    3. return the popped element, so the caller knows what was popped.
  • Remember: push increments top, and pop decrements it.
int pop() { if (top == -1) { printf("Stack Underflow"); return -1; } int x = stack[top]; /* read FIRST */ top = top - 1; /* then decrement */ return x; }
➕ Added for exam Pop does not erase the value; z still sits in stack[2]. It is simply outside the stack, because only indices 0..top count, and the next push overwrites it. With top = −1 convention: number of elements = top + 1.

🎓 From the lecture The pop sequence is 3, 10, 10, 5, 1. If asked how many elements remain: zero, the stack is empty. Popping 1 from index 0 decremented top to −1, so one more pop would report "stack empty".
➕ Added for exam
  • Elements left after a sequence = number of pushes − number of successful pops.
  • Maximum stack height reached = the largest top + 1 during the run (here 4, after step 6). It is the "minimum array size needed" in MCQs.

7.7Linked Stack, Applications, Pop-Sequence Questions & Solved QuestionsADDED

Stack using a linked list: push = insert at beginning, pop = delete at beginning (chapter 4). Both are O(1), and the head pointer acts as top. There is no fixed size, so no overflow (until malloc fails), and an empty stack is top == NULL.

void push(int x) { struct node *n = malloc(sizeof *n); n->data = x; n->next = top; /* insert at head */ top = n; } int pop() { if (top == NULL) return -1; /* underflow */ struct node *t = top; int x = t->data; top = top->next; /* delete at head */ free(t); return x; }

⚠️ Exam trap A linked stack must push and pop at the head. Using the tail of a singly list makes pop O(n), because delete at end needs the second-last node (chapter 4).
➕ Applications of a stack
  • Function calls and recursion: the call stack holds activation records; too-deep recursion causes a stack overflow.
  • Expression conversion and evaluation: infix → postfix/prefix, evaluating postfix (chapter 8).
  • Balanced parentheses check: push on ( [ {, pop and match on ) ] }.
  • Undo in editors, browser back button, reversing a string or list.
  • Backtracking (mazes, N-queens) and DFS of graphs (chapter 16).
  • Tower of Hanoi, and converting decimal to binary (push the remainders, then pop them).

Which pop orders are possible? Push 1, 2, 3, …, n in this order, with pops allowed at any time. A sequence is possible if you can simulate it: before popping x, push everything up to x, and then x must be on top.

➕ Quick rule After popping some number x, all the numbers smaller than x that are still in the stack must come out in decreasing order. So with input 1, 2, 3, the only impossible output is 3, 1, 2: after 3, the 1 and 2 are still stacked with 2 on top. The number of valid orders for n elements is the Catalan number C(n) = (2n)! / ((n+1)! n!), which gives 1, 2, 5, 14, 42 for n = 1…5.
🎯 IBPS exam alert
  • Stack = LIFO (FILO); queue = FIFO (chapter 9).
  • Array stack with top = −1: overflow top == MAX − 1, underflow top == −1.
  • "Which data structure is used for recursion / function calls?" → stack.
  • "…for converting infix to postfix?" → stack. "…for BFS?" → queue. "…for DFS?" → stack.
  • Push, pop and peek are all O(1).
Q1Empty stack: push 5, push 8, pop, push 2, push 7, pop, pop, push 4. What is on top, and how many elements are there? → After the pops (8, 7, 2), the stack is 5, 4. Top = 4, 2 elements.
Q21, 2, 3, 4 are pushed in order (pops allowed in between). Which output is impossible? (a) 4 3 2 1 (b) 2 1 4 3 (c) 1 3 2 4 (d) 3 4 1 2 → (d). After popping 3 and 4, the stack holds 1, 2 with 2 on top, so 1 can't come before 2.
Q3An array stack has MAX = 10 and top = 9 (top starts at −1). What does push do? → top == MAX − 1, so overflow; no insertion.
Q4How many different pop sequences are possible when pushing 1, 2, 3, 4 in order? → Catalan C(4) = 8!/(5!·4!) = 14.
Q5For a string read character by character, which structure reverses it most simply? → Stack: push every character, then pop them all.

⚡ Rapid Revision

  • Stack = LIFO / FILO (biscuits, rotis); a linear structure with one open end, the top. TOS is the only access point.
  • Implement with an array (static) or a linked list (dynamic), always inserting and deleting at one end (the head for a list).
  • Push: if (top == n−1) overflow; top++; stack[top] = x;
  • Pop: if (top == −1) underflow; x = stack[top]; top--; return x;. Push increments, pop decrements.
  • Empty: top = −1 initially. Count = top + 1.
  • Lecture trace: push 1, 3, pop, push 5, 10, 10, pop ×4 gives 3 10 10 5 1, and the stack ends empty.
  • Linked stack: push = insert at head, pop = delete at head, both O(1), no overflow.
  • Pop-order rule: numbers below a popped x come out in decreasing order. For 1, 2, 3 the impossible order is 3 1 2. Count = Catalan (14 for n = 4).
  • Uses: recursion, expression conversion/evaluation, parentheses matching, undo, back button, DFS, backtracking.
