Chapter 17

Hashing

Every search so far has cost something that grows with n: O(n) for a list, O(log n) for a balanced tree. Hashing aims for O(1) on average. Instead of comparing the key with stored keys, it computes where the key should be. The rest of the chapter deals with what happens when two keys compute to the same place.

17.1What is Hashing: Key, Hash Function, Location and Hash Table

🎓 From the lecture Is hashing a data structure? No. It is a jugaad, an idea, a technique that makes searching fast. The price is more space: the usual time–space trade-off. Hashing chooses minimum time and accepts whatever space that needs.
The thief analogy:
  • A notorious thief runs from the police and hides in one of the many houses of a town.
  • Inspector "Singham" finds the thief's phone. From its call records and location he tracks the town, then the exact house, and the thief is caught. (Moral: "never do theft or cheating".)

Technically: give the key to the hash function, and it returns the location where the key is stored. The structure holding all the keys is the hash table.
key k ──► h(k) ──► index i ──► table[i] store: table[h(k)] = k search: look only at table[h(k)]

17.2Properties of a Good Hash Function

🎓 From the lecture
  1. Easy: not complicated, with no differentiation, integration, limits or series. It must not be computationally expensive.
  2. Fast: if it is easy it computes fast, and speed is the whole point of optimising search.
  3. Low collision rate: a collision is when the function sends a key to a location that is already occupied. It is like a hotel giving you the key to a room where guests are already staying.
The best hash function computes quickly, is easy to compute, and gives few collisions.
➕ Added for exam
  • A good hash function also spreads keys uniformly over the table, and is deterministic (the same key always gives the same index).
  • A function with no collisions for a known key set is a perfect hash function.

17.3Division Method (k mod n)

🎓 From the lecture The most popular hash function:
h(k) = k mod n n = table size → indices 0 … n − 1 variant: h(k) = (k mod n) + 1 → indices 1 … n (one extra slot of space)
With n = 10 (indices 0–9):
  • 10 mod 10 = 0, so 10 goes to index 0. To retrieve it later, put 10 through the same function and go straight to index 0: very little time.
  • 11 → 1, 12 → 2. With mod 10, the remainder is simply the last digit.
➕ Added for exam Choose the table size n as a prime not close to a power of 2 or 10. With n = 10 only the last digit matters, so 12, 42, 52, … all collide, as the next sections show.

17.4Mid-Square Method

🎓 From the lecture Square the key, then take the middle digit(s) as the index.
  • 12² = 144, so 12 goes to index 4.
  • 11² = 121, so 11 goes to index 2.
➕ Added for exam For bigger tables take as many middle digits as the table needs (e.g. 2 middle digits for 100 slots). The middle digits depend on all digits of the key, which spreads keys well.

17.5Folding Method

🎓 From the lecture For a big key, split it into parts and add the parts, then take mod n.
key 123456 → 123 + 456 = 579 → 579 mod 10 = 9 → index 9
➕ Added for exam This is shift folding. In boundary folding, every other part is reversed before adding: 123 + 654 = 777 → 7. Folding suits long keys such as phone or account numbers.

17.6Collision

🎓 From the lecture "The most important issue, with lots of questions." With h(k) = k mod 10:
  • 12 → index 2.
  • 42 → 42 mod 10 = 2 as well, but 12 is already there.
Each key should ideally have its own location; when two want the same slot, that is a collision. So pick a hash function with a low collision rate. Zero collisions would be the ideal case.
➕ Added for exam Collisions cannot be avoided in general. There are usually far more possible keys than slots (the pigeonhole principle), so every practical hash table needs a collision-resolution strategy.

17.7Collision Resolution: Open Hashing vs Closed Hashing

🎓 From the lecture A collision is a problem, but we don't stop at the problem; we resolve it. There are two broad categories:
  • Open hashing: chaining.
  • Closed hashing: linear probing, quadratic probing and double hashing. Double hashing combines a first and a second hash function when the first one collides.
⚠️ Exam trap: the names are confusing
  • Open hashing = separate chaining (keys live outside the table, in lists). It is also called closed addressing.
  • Closed hashing = open addressing (all keys stay inside the table; probing).
MCQs swap these words deliberately. Remember it with the lecture's picture: open hashing goes outside the house; closed hashing solves it inside the house.

17.8Separate Chaining (Open Hashing)

🎓 From the lecture "Open" because the problem is taken outside the hash table and solved there, with linked-list chaining.
  • With k mod 10, both 12 and 42 go to index 2. Instead of fighting over the slot, index 2 holds a pointer to a linked list of every key that belongs to index 2: 12 → 42 → 52 → NULL. 32, 62 and 72 would join the same list.
  • 55 and 35 share index 5. 16 and 26 share index 6.
The problem: a chain can grow very long. To find 96 you know to go to index 6, but then you hop link after link. We wanted to optimise searching, yet in the worst case it takes a lot of time. That is the big disadvantage of chaining.
➕ Added for exam
  • The table never "fills up": chaining allows a load factor α > 1.
  • Deletion is easy (it is just a linked-list delete).
  • Average successful search ≈ 1 + α/2 probes; unsuccessful ≈ 1 + α.
  • Worst case O(n), when all keys land in one chain.
  • Costs: extra pointer memory, and the chains have poor cache behaviour.

17.9Linear Probing and Primary Clustering

🎓 From the lecture "Why go outside? It's a problem of the house; solve it inside the house." On a collision, check the next slot, then the next, one by one, until an empty slot is found.
h(k, i) = (h(k) + i) mod n i = 0, 1, 2, … (i grows by 1 on every collision)
With h(k) = k mod 10, insert 12, 42, 33, 44, 45, 32:

17.10Quadratic Probing and Secondary Clustering

🎓 From the lecture Instead of adding i, add i². The step size grows, so you take "long jumps" instead of crawling to the next slot.
h(k, i) = (h(k) + i²) mod n
Insert 22, 26, 31, 43, 28, 37 with no collision (indices 2, 6, 1, 3, 8, 7). Then:
  • 46: 6 is taken. i = 1: 6 + 1 = 7, taken. i = 2: 6 + 4 = 10 mod 10 = 0, free. Placed at 0.
  • 52: "this one will eat your head". Only 4, 5 and 9 are empty. The probes go:
    • 2 (i = 0);
    • 3 (i = 1);
    • 6 (i = 2);
    • 11 → 1 (i = 3);
    • 18 → 8 (i = 4);
    • 27 → 7 (i = 5);
    • 38 → 8 (i = 6), …
    Every probe collides, and 52 may never find a place.
Index0123456789
Key46312243263728
🎓 From the lecture Secondary clustering: every key with the same home index (2 for 52, 32, …) follows the same probe sequence 2, 3, 6, 1, 8, 7 … and repeats the same collisions. Quadratic probing does not suffer from primary clustering, because it skips around instead of filling one block, but it does suffer from secondary clustering.
➕ Added for exam: why 52 really fails i² mod 10 only ever takes the values {0, 1, 4, 9, 6, 5}. So from home 2, quadratic probing can reach only {2, 3, 6, 1, 8, 7} and never 4, 5 or 9, even though those slots are free. Quadratic probing is guaranteed to find a free slot only if the table size is a prime and the table is at most half full.

17.11Double Hashing

🎓 From the lecture The last topic. It removes both primary and secondary clustering by combining two hash functions:
h(k, i) = (h1(k) + i · h2(k)) mod n h1(k) = k mod 13 h2(k) = 1 + (k mod 11) n = 13 (indices 0–12)
h2 isn't standardised; you can invent your own. If h1 doesn't collide, h1 alone is used. On a collision, use the combined formula, with i growing 1, 2, 3, …

🎓 From the lecture For 72: the first collision (i = 1) gives index 1, where 79 already sits. With i = 2 it lands at index 8. Problems that linear and quadratic probing struggle with are solved easily.
➕ Added for exam Two keys with the same h1 usually have different h2, so they follow different probe sequences; that is why secondary clustering disappears. h2(k) must never be 0 (hence the "1 +"), and h2 should be coprime with n, which is easiest when n is prime.

17.12Load Factor, Deletion, Rehashing, Comparison & Solved QuestionsADDED

➕ Load factor
α = (number of keys stored) / (table size)
  • Chaining: α can exceed 1, and the average cost is O(1 + α).
  • Open addressing: α ≤ 1 always. Performance drops sharply as α → 1: the expected probes for an unsuccessful search are about 1/(1 − α), so α = 0.9 gives about 10 probes.
  • Rehashing: when α crosses a threshold (≈ 0.7–0.75), build a table about twice as big (preferably prime) and re-insert every key with the new hash function. That one step is O(n), but the amortised cost per insert stays O(1).
⚠️ Exam trap: deleting in open addressing You can't simply empty a slot. A later search would stop at that hole and miss keys that probed past it. In the linear-probing table, deleting 42 at index 3 would make a search for 32 stop at 3 and report "not found". Mark it as deleted (a tombstone) instead: searches continue past it, and inserts may reuse it.

➕ Where hashing is used Dictionaries and maps (Python dict, Java HashMap), symbol tables in compilers, database hash indexes, caches, de-duplication, password storage (with cryptographic hashes such as SHA-256 or bcrypt, a different kind of hash function), checksums and digital signatures.
🎯 IBPS exam alert
  • Hashing gives O(1) average search; worst case O(n).
  • Two keys mapping to the same slot → collision.
  • Chaining = open hashing; probing = closed hashing (open addressing).
  • Linear probing → primary clustering. Quadratic → secondary clustering. Double hashing avoids both.
  • Load factor α = n / m. Table size should be a prime.
Q1Table size 10, h(k) = k mod 10, linear probing. Insert 43, 165, 62, 123, 142. Where does 142 go? → 43 → 3, 165 → 5, 62 → 2, 123 → 3 ✗ → 4, 142 → 2 ✗ 3 ✗ 4 ✗ 5 ✗ → 6. Final table: [_, _, 62, 43, 123, 165, 142, _, _, _].
Q2A hash table with 50 slots holds 35 keys. Load factor? → α = 35 / 50 = 0.7.
Q3Which collision technique can store more keys than the table has slots? → Separate chaining.
Q4Mid-square with 2-digit index: key 56 → 56² = 3136. Index? → Middle two digits 13.
Q5Quadratic probing, n = 10, home index 2. What are the first four probe positions? → 2, 3, 6, 1 (2 + 0, + 1, + 4, + 9, all mod 10).

⚡ Rapid Revision

  • Hashing is a technique, not a data structure: trade space for O(1) average search. Thief = key, phone = hash function, house = location, town = hash table.
  • A good h(k) is easy, fast and low-collision (and uniform).
  • Division k mod n (12 → 2). Mid-square 12² = 144 → 4, 11² = 121 → 2. Folding 123456 → 123 + 456 = 579 → 9.
  • Collision = the slot is already occupied (12 and 42 both → 2).
  • Open hashing = chaining (outside, in linked lists; long chains are slow). Closed hashing = probing (inside the table).
  • Linear (h + i): 12, 42, 33, 44, 45, 32 → 32 at index 7, causing primary clustering.
  • Quadratic (h + i²): 46 → 0, but 52 never fits (it only reaches 2, 3, 6, 1, 8, 7), causing secondary clustering.
  • Double (h1 + i·h2) mod 13 with h2 = 1 + k mod 11: 72 → 7 ✗, 1 ✗, then 8. No clustering.
  • α = keys / slots. Rehash when α ≈ 0.7. Delete in open addressing with tombstones. Use a prime table size.
