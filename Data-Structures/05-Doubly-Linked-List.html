Chapter 5

Doubly Linked List

A doubly linked list (DLL) is a singly linked list in which every node also remembers who came before it. That one extra pointer lets you walk backwards and delete a node without hunting for its predecessor. The price is more memory per node and more pointers to fix on every insert and delete.

5.1Node Structure (prev, data, next) and Two-Way Flexibility

🎓 From the lecture Each node maintains three things: a previous pointer, the data and a next pointer. You can remember the layout as "P-D-N": prev, data, next. Next holds the address of the following node, prev holds the address of the one before.
More pointers mean more complexity, and the code for some operations gets longer, but flexibility increases too.
  • A singly list is a one-way street: to make a U-turn you drive all the way to the junction and come back, which is hard work.
  • A doubly list is a two-way road: you can turn around at any point while walking it.
The first node's prev is NULL (nothing before it), and the last node's next is NULL.
struct node { struct node *prev; int data; struct node *next; };
➕ Added for exam For any middle node p, both p->next->prev == p and p->prev->next == p hold. Every insert and delete exists to keep these two identities true. If one is forgotten, forward and backward traversal give different lists.

5.2Insert at Beginning

🎓 From the lecture Head points to the first node. The new node starts with both ends NULL, and its address is 5.
  1. new->next = head; Give head's address to new's next, so the new node can point to what will be the second node.
  2. head->prev = new; The old first node's prev was NULL; now it gets 5, because the new node will sit before it. The two nodes now point to each other.
  3. head = new; Only head is left; give it the new node's address. "That's the whole game."
new->prev = NULL; new->next = head; if (head != NULL) /* list was not empty */ head->prev = new; head = new;
⚠️ Exam trap On an empty list, head is NULL, so head->prev = new crashes. Guard it with if (head != NULL). As in chapter 4, head = new must come last; otherwise head->prev = new would set the new node's prev to itself.

5.3Insert After a Node

🎓 From the lecture Put the address of the node we insert after into temp. In the example, temp is at 20, its next holds 30, and the new node is at 5.
  1. new->next = temp->next; New's next gets 30, establishing new → 30.
  2. temp->next->prev = new; Standing on temp, go to the next node and update its prev, which was 20, to the new node's address 5.
  3. temp->next = new; Temp's next was 30 and now becomes 5.
  4. new->prev = temp; "The last nail in the coffin": new's prev, which was NULL, becomes 20.
Now there is a full two-way connection on both sides of the new node.
⚠️ Exam trap
  • Step 2 must run before step 3. Once temp->next = new is done, temp->next->prev refers to the new node, and node 30 can no longer be reached from temp. Safe order: fill in the new node's own two pointers first, then fix the neighbours.
  • If temp is the last node, temp→next is NULL and step 2 crashes. Guard it with if (temp->next != NULL).
  • The lecture says the last step as "temp = new→prev", reading the slide backwards. The assignment is new->prev = temp.
➕ Added for exam Inserting in the middle of a DLL changes 4 pointer fields; a singly list needs only 2. A DLL can also insert before a given node p in O(1), using p->prev, which a singly list cannot.

5.4Insert at End

🎓 From the lecture The new node starts with prev and next both NULL.
  1. Traverse to the last node, then last->next = new;. The last node's next was NULL and now holds the new node's address.
  2. new->prev = last; New's prev gets the last node's address (30), so the new node can point backwards.
The new node's next stays NULL, because it is now the last node. The lecture corrects its own slide here: step 2 is new→prev, not new→next.
struct node *last = head; while (last->next != NULL) last = last->next; last->next = new; new->prev = last; new->next = NULL;
➕ Added for exam This costs O(n) with only head, and O(1) with a tail pointer: tail->next = new; new->prev = tail; tail = new;.

5.5Delete at Beginning

🎓 From the lecture List: nodes at 10, 20, 30, with links going both forward and backward. The first node's prev and the last node's next are NULL.
  1. temp = head; Keep the first node in temp so it can be freed later.
  2. head = head->next; Head now points to the next node (20).
  3. head->prev = NULL; The new first node's prev still pointed to the old node; set it to NULL. Now the old node's connection is completely cut.
  4. free(temp); "Let it go."
⚠️ Exam trap If the list had only one node, head becomes NULL after step 2, and step 3 (head->prev) crashes. Guard it with if (head != NULL) head->prev = NULL;.

5.6Delete a Given Node (p)

🎓 From the lecture Call the node to delete p (the lecture titles this "delete after a node"). Its neighbours, at 10 and 30, were only "distant relatives"; now we must make them close relatives:
  • node 10's next should hold 30;
  • node 30's prev should hold 10.
  1. p->prev->next = p->next; p's prev is node 10; its next field gets p's next, which is 30.
  2. p->next->prev = p->prev; p's next is node 30; its prev field gets p's prev, which is 10.
  3. free(p); Both relations are established, so free p. "No tension at all."
➕ Added for exam (the big DLL advantage) Given only a pointer to p, a DLL deletes it in O(1), because p→prev gives the predecessor directly. A singly list needs O(n) to find the predecessor. This is why DLLs are used in LRU caches: a hash map finds the node, and the DLL unlinks it instantly.
⚠️ Exam trap If p is the first node, p→prev is NULL. If p is the last node, p→next is NULL. Either line then crashes, so the full code checks both, and updates head when p is first:
if (p->prev != NULL) p->prev->next = p->next; else head = p->next; if (p->next != NULL) p->next->prev = p->prev; free(p);

5.7Delete at End

🎓 From the lecture Walk towards the last node but stop one before it; call that node p.
  1. temp = p->next; Temp now points to the last node.
  2. p->next = NULL; Cut the connection, so p is established as the new last node.
  3. free(temp); The last node is deleted.
"It sounds a bit complicated, but practise a little and it will be set."
➕ Added for exam The lecture's method walks to the second-last node: O(n), exactly like a singly list. A DLL does better: from the last node, last->prev is the second-last. With a tail pointer, delete at end is O(1):
temp = tail; tail = tail->prev; tail->next = NULL; /* guard: if tail != NULL */ free(temp);
That is the key difference from chapter 4, where delete at end stayed O(n) even with a tail.

➕ Where doubly linked lists are used
  • Browser back / forward history; music-player previous / next.
  • Editor undo / redo.
  • LRU cache (hash map + DLL); deque implementation.
  • OS process lists and memory free lists, where blocks are removed from the middle.
➕ XOR (memory-efficient) doubly linked list Each node stores a single field link = address(prev) XOR address(next) instead of two pointers. Knowing where you came from, next = link XOR prev. It gives two-way traversal with one pointer's worth of memory, but it can't be used with garbage collectors, and debugging is hard. It is a favourite "which list saves memory" option.
🎯 IBPS exam alert
  • "Which list can be traversed in both directions?" → doubly (and circular doubly).
  • "Main disadvantage of a DLL?" → extra memory for the prev pointer and more pointer updates.
  • "In a DLL, the prev of the first node and the next of the last node are…" → NULL.
  • "Deleting a node, given only a pointer to it, is O(1) in…" → doubly linked list.
  • "Pointers modified to insert a node between two nodes in a DLL?" → 4.
Q1Which statements remove node p from the middle of a doubly linked list?
(a) p->prev->next = p->next; p->next->prev = p->prev;
(b) p->prev = p->next; p->next = p->prev;
→ (a). Option (b) changes only p's own fields; the neighbours still point to p.
Q2A DLL has head and tail pointers and n nodes. Which operation is not O(1)? (a) insert at front (b) delete last (c) delete front (d) delete the node holding value x → (d): finding x is an O(n) search. Removing it, once found, is O(1).
Q3Memory to store 500 ints in a DLL (4-byte int, 8-byte pointer)? → 500 × (4 + 8 + 8) = 10,000 bytes. A singly list needs 6,000 B and an array 2,000 B.
Q4Code to insert node q at the front of a non-empty DLL, in a safe order? → q->prev = NULL; q->next = head; head->prev = q; head = q;
Q5Starting from tail, you print each node and move with t = t->prev until NULL, on the list 1 ⇄ 2 ⇄ 3 ⇄ 4. Output? → 4 3 2 1: a DLL prints in reverse without recursion or a stack.

⚡ Rapid Revision

  • Node = prev · data · next. First node's prev = NULL; last node's next = NULL. A "two-way road" vs the singly list's "one-way street".
  • Insert at beginning: new→next = head; head→prev = new; head = new. Guard the empty list.
  • Insert after temp: new→next = temp→next; temp→next→prev = new; temp→next = new; new→prev = temp. That is 4 pointer fields, and step 2 must come before step 3.
  • Insert at end: last→next = new; new→prev = last. It is prev, not next.
  • Delete at beginning: temp = head; head = head→next; head→prev = NULL; free(temp).
  • Delete node p: p→prev→next = p→next; p→next→prev = p→prev; free(p). That is O(1), the big advantage.
  • Delete at end: the lecture stops at the second-last node (O(n)). With a tail: tail = tail→prev; tail→next = NULL is O(1).
  • Cost: one more pointer per node (20 B vs 12 B per int). XOR list = one prev⊕next field.
  • Uses: back/forward navigation, undo/redo, LRU cache, deque.
