Chapter 1

Introduction to Data Structures

A program is only as fast as the way it keeps its data. The same million records can be found in one step, twenty steps or a million steps, depending on whether they sit in an array, a balanced tree or a hash table. Data structures are those ways of keeping data. This chapter defines the term and splits the subject into linear and non-linear structures. Every later chapter is one of these.

1.0Road Map of the Subject

🎓 From the lecture The one-shot covers the whole subject from scratch using handwritten notes, with diagrams, numericals and C code snippets. The topics run in this order: Introduction → Array → Linked List → Stack → Queue → Tree → Heap → Graph → Hash. These notes follow the same order across 17 chapters.

1.1What is a Data Structure (Refrigerator Analogy)

🎓 From the lecture To explain an unknown thing, start from a known one: the refrigerator at home. Its main job is to store items, and not just anywhere:
  • ice cream and ice cubes go in the freezer;
  • vegetables and rice go on the lower panels so they stay preserved, and fruits and vegetables go in the bottom drawer;
  • water, ketchup and mayonnaise bottles, and medicines that need cold storage, go in the side panel.
Things are stored in an organised fashion, by space and by type. Throw the sauce bottle in with the vegetables and "mummy ji" will scold you. Two more properties matter:
  • Easy access: open the fridge, take the item out, eat it ("khole, nikalo, kha lo").
  • Easy manipulation: put a glass of water in the freezer and a few days later it has become ice. The contents can change state.
A data structure is the same list of jobs with data in place of the items: it must store data, arrange it in an organised manner, give easy access, manage storage efficiently, and let you manipulate/update the data easily.
Data structure: a particular way of storing and organising data in memory so that it can be accessed and modified efficiently. It fixes both the layout of the data and the operations allowed on it.
➕ Added for exam Data structure vs algorithm: a data structure is how data is held; an algorithm is the step-by-step procedure that works on it. Niklaus Wirth's famous title sums it up: Algorithms + Data Structures = Programs. Choosing the structure usually decides the algorithm's speed. Searching a sorted array uses binary search, O(log n); searching a linked list, even a sorted one, needs a linear scan, O(n).

1.2Linear vs Non-Linear Data Structures

🎓 From the lecture Data structures fall into two broad categories, and "jaisa naam waise kaam" (the name says it):
  • Linear: items are attached adjacently, one after another, so the structure works on a single level. It looks like an array.
  • Non-linear: items are attached hierarchically, at multiple levels: one item, then items below it, then items below those.
The lecture then compares the two on four points:
  • Ease: linear structures are easy to understand and implement; non-linear ones are harder.
  • Runs: a linear structure is traversed from first to last element in a single run. A non-linear one needs multiple runs. Analogy: linear is like passing a nursery exam in one go; non-linear is like engineering placements, with many levels (aptitude, then group discussion…) and maybe several attempts.
  • Memory: in a linear structure such as an array, a lot of allocated space can sit empty and unused, so memory is used less efficiently. Non-linear structures such as trees and graphs are "memory friendly": nothing is wasted.
  • Relations: non-linear structures have relationships between items (parent, child, sibling in a tree). Linear structures (array, stack, linked list) have none.

⚠️ Exam trap The lecture's "linear = wastes memory, non-linear = memory friendly" is true of a static array, whose fixed size is reserved whether it is used or not. It is not a property of all linear structures. A linked list is linear and dynamic: it allocates exactly one node per element. In the other direction, every tree or graph node spends extra memory on pointers. If an exam asks which structure wastes memory, the answer is "array (static allocation)", not "linear structures".
⚠️ Exam trap "Linear" describes the logical order, not the memory layout. An array is linear and contiguous; a linked list is linear but non-contiguous. A heap is a non-linear tree even though it is usually stored in an array.

Abstract Data Type (ADT): a data type described only by what it stores and which operations it allows, not how they are implemented. Stack is an ADT (push, pop, peek, isEmpty); it can be implemented with an array or with a linked list. The ADT is the "what", the data structure the "how".
🎯 IBPS exam alert Frequently asked one-liners:
  • "Which is not a linear data structure?" → tree / graph / heap.
  • "Which is a non-primitive data structure?" → array (and anything else that is a collection). "char" and "int" are primitive.
  • Stack = LIFO, queue = FIFO (chapters 7 and 9).
  • BFS uses a queue, DFS uses a stack (chapter 16).
  • Recursion uses a stack internally (the call stack).

⚠️ Exam trap "Linked-list insertion is O(1)" assumes you already hold a pointer to the position. Inserting at the end of a singly linked list with only a head pointer is O(n), because you must walk to the last node first (the lecture shows this in chapter 4). With a tail pointer it becomes O(1).
➕ Added for exam Time–space trade-off: you can often buy speed with memory and vice versa. Hashing spends extra table space to get O(1) search (the lecture returns to this in chapter 17); a doubly linked list spends one extra pointer per node to allow backward movement.

1.5Solved Exam QuestionsADDED

Q1Which of the following is a non-linear data structure? (a) Stack (b) Queue (c) Linked list (d) Tree
Answer: (d) Tree. Its nodes sit at multiple levels (parent → children); the other three keep a single sequence.
Q2Which data structure allows access to any element in constant time using its index?
Answer: Array. Contiguous storage lets the address be computed directly: base + size × (i − lower) (chapter 2).
Q3An algorithm takes 10 steps for n = 1,024 and 11 steps for n = 2,048. What is its likely complexity?
Answer: O(log n). Doubling n adds just one step: log₂ 1024 = 10, log₂ 2048 = 11.
Q4Arrange in increasing order of growth: n log n, 2ⁿ, log n, n², n.
Answer: log n < n < n log n < n² < 2ⁿ.
Q5"A stack can be implemented using an array or a linked list." Which concept does this illustrate?
Answer: Abstract Data Type. The behaviour (LIFO, push/pop) is fixed; the implementation can vary.
Q6Which is a primitive data type in C? (a) Array (b) Structure (c) char (d) Union
Answer: (c) char. Arrays, structures and unions are derived / user-defined (non-primitive).

⚡ Rapid Revision

  • Data structure = a way to store, organise, access and manipulate data efficiently (lecture: the fridge with freezer, shelves, drawer and side panel).
  • Linear: adjacent, single level, one-pass traversal, easy (array, linked list, stack, queue). Non-linear: hierarchical, multiple levels, parent–child relations, harder (tree, graph, heap).
  • Lecture: linear wastes memory, non-linear is "memory friendly". This is true of the static array; a linked list is linear but dynamic.
  • Primitive (int, char, float, pointer) vs non-primitive (array, list, tree…). Static (array) vs dynamic (linked list).
  • ADT = what (operations) without how (implementation). Stack ADT → array or linked list.
  • Growth order: 1 < log n < n < n log n < n² < 2ⁿ < n!
  • Array access O(1); linked-list access O(n); balanced BST/AVL O(log n); hash average O(1).
