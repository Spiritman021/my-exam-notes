Expression Notation: Infix, Prefix and Postfix

An expression has operands (a, b, 5) and operators (+, ×, ^). The only difference between the three notations is where the operator sits. Humans read infix easily, but it needs precedence rules and brackets. Prefix and postfix need neither, so compilers convert to them and evaluate with a single stack. Expect at least one conversion or evaluation numerical in the exam.

8.1Infix, Prefix and Postfix: Operator Position

🎓 From the lecture An expression has two main components: the operator and the operand. The names describe the position of the operator:
  • Infix: the operator is in between the two operands: a + b.
  • Prefix: the operator comes first (pre), then the operands: + a b.
  • Postfix: the operands come first and the operator last (post): a b +.

⚠️ Exam trap Converting changes only the operator positions. The operands stay in the same left-to-right order in all three forms. If an option reorders the letters (e.g. b a + for a + b), eliminate it at once.

8.2Conversion Using an Expression Tree (First/Second/Last Visit)

🎓 From the lecture Infix makes sense to a human but is "senseless" to the system; the system finds sense in prefix and postfix. Conversion can be done with a tree, a stack or manually. The lecture recommends the tree, as the easiest.
Method: Traverse the tree top to bottom, left to right, going round each node, so you pass each node three times:
  • the 1st visit is on its left side;
  • the 2nd visit is underneath it (the middle);
  • the 3rd visit is on its right side.
Leaves have no children, so draw dummy branches under them so you can still count their three visits.
  • Write a node at its 2nd visit → infix: a + b * x + y. This checks that the tree is right.
  • Write a node at its 1st visit → prefix: + + a * b x y.
  • Write a node at its last visit → postfix: a b x * + y +.
These are the same ideas as inorder, preorder and postorder traversal of a tree, covered later.
Visit rule Traversal Result for a + b*x + y 1st (left side) preorder → + + a * b x y (prefix) 2nd (below) inorder → a + b * x + y (infix) 3rd (right side) postorder → a b x * + y + (postfix)

8.3Infix to Postfix Using a Stack (Precedence and Associativity)

🎓 From the lecture Most questions say "use a stack to convert this infix to postfix". The rules:
  • An operand goes straight to the output, never into the stack.
  • An operator goes into the stack, but first apply the pop rule.
  • Precedence: ^ (raise to power) is highest, then * /, then + − (lowest).
  • Associativity (when equal-precedence operators meet): * / and + − go left to right; ^ goes right to left.
  • Pop rule: if the operator on top is stronger, it "cannot bear the dominance of a weaker one sitting on it". It says "wait, I'll come out first, then you go in". Pop it to the output, then push the newcomer.

8.4Infix to Postfix: Manual Method

🎓 From the lecture Follow only precedence and associativity, and convert one operator at a time, highest priority first:
  1. a + b * x + y: * is highest, so b*x → b x *. This gives a + [b x *] + y.
  2. Two +'s: left-associative, so the left + goes first. a and [b x *] are its operands, so write them, then the operator: [a b x * +] + y.
  3. One + is left, with operands [a b x * +] and y: a b x * + y +.
"It's your choice, your faith": use whichever method you like. "My job is to put all the options before you."
➕ Added for exam (fastest manual trick) Fully parenthesise the expression according to precedence. Then move each operator to replace its own closing bracket (postfix) or opening bracket (prefix), and delete the brackets.
((a + (b * x)) + y) postfix: move each op to its ')' → a b x * + y + prefix: move each op to its '(' → + + a * b x y

8.5Building the Expression Tree (Weakest Operator as Root)

🎓 From the lecture The tree is built with the same rules in reverse: the weakest operator becomes the root, then you move from weak to strong. Everything to the operator's left becomes its left child, and everything to its right becomes its right child. Expression: a * b / c + d / e * f + g − h * i.
  1. − is the weakest, so it is the root. Left: a*b/c + d/e*f + g. Right: h*i, which becomes × with h and i.
  2. Left part: two +'s. With left-to-right associativity, the right one is evaluated last, so it is weaker and becomes the node. Left: a*b/c + d/e*f. Right: g.
  3. a*b/c + d/e*f: + is weakest. Left: a*b/c. Right: d/e*f.
  4. a*b/c: × and ÷ are equal, left-to-right, so the right one (÷) is weaker and becomes the node. Left: a*b. Right: c.
  5. d/e*f: the right one (×) is weaker. Left: d/e. Right: f.
Rule: go from low to high precedence, and break ties with associativity. (The lecture briefly calls × the weaker one in step 4 and then corrects itself to ÷.)
➕ Added for exam
  • From this tree, postfix = a b * c / d e / f * + g + h i * − and prefix = − + + / * a b c * / d e f g * h i.
  • For a left-associative tie, the rightmost operator becomes the root. For ^ (right-associative), the leftmost ^ does: a ^ b ^ c = a ^ (b ^ c).
  • In an expression tree, every leaf is an operand and every internal node is an operator. With binary operators, n operators give n + 1 leaves.

8.6Evaluating a Postfix Expression Using a Stack

🎓 From the lecture The expression is the same shape as before, with numbers in place of a, b, x, y: postfix 1 2 3 * + 5 + (infix 1 + 2 × 3 + 5).
  • Scan left to right.
  • Push every number into the stack, "without any condition".
  • On an operator, pop twice:
    • the first pop goes to the operator's right;
    • the second pop goes to its left.
  • Compute, and push the result back.

🎓 From the lecture Answer 12. On the board 5 was first written on the left; the lecture corrects it: 5 belongs on the right and 7 on the left. Check against the infix: 2 × 3 = 6, 6 + 1 = 7, 7 + 5 = 12.
⚠️ Exam trap The operand order only matters for − , ÷ and ^, which is exactly where MCQs trap you. In postfix the result is (second pop) op (first pop): with 8 2 /, 2 is popped first, so it is 8 ÷ 2 = 4, not 2 ÷ 8.

8.7Evaluating a Prefix Expression Using a Stack (Right-to-Left Scan)

🎓 From the lecture Prefix + + 1 * 2 3 5 (the same expression):
  • Scan right to left (postfix scanned left to right).
  • Push each number unconditionally.
  • On an operator the rule is reversed:
    • the first pop goes to the left of the operator;
    • the second pop goes to its right.

➕ Full infix → postfix algorithm (with brackets)
  1. Operand → append to output.
  2. '(' → push.
  3. ')' → pop to output until '(' is found, then discard the pair of brackets (brackets never appear in postfix).
  4. Operator op → while the top is an operator (not '(') and either
    • top precedence > op's, or
    • it is equal and op is left-associative,
    pop the top to output. Then push op. (For ^ meeting ^, don't pop.)
  5. End → pop everything left to output.

➕ Infix → prefix with a stack (reverse trick)
  1. Reverse the infix and swap '(' with ')'.
  2. Convert to postfix, except that equal precedence does not pop (^ excepted).
  3. Reverse the result.
In the exam, the tree or bracket method from 8.4 is usually faster.
⚠️ Exam trap: ^ and −
  • a ^ b ^ c = a ^ (b ^ c) → postfix a b c ^ ^, not a b ^ c ^. Numerically, 2 ^ 3 ^ 2 = 2⁹ = 512, not 8² = 64.
  • a − b − c = (a − b) − c → postfix a b − c −, prefix − − a b c.
  • A + B * C / D − E ^ F ^ G → postfix A B C * D / + E F G ^ ^ −.
🎯 IBPS exam alert
  • "Data structure used to convert infix to postfix / to evaluate postfix?" → stack (one stack is enough).
  • "Polish notation" = prefix; "Reverse Polish" = postfix.
  • "Which notation needs no parentheses?" → prefix and postfix.
  • In infix → postfix the stack holds operators. In postfix evaluation it holds operands / intermediate values.
  • An inorder/preorder/postorder traversal of an expression tree gives infix/prefix/postfix.

⚡ Rapid Revision

  • Infix a+b · prefix (Polish) +ab · postfix (Reverse Polish) ab+. The operand order never changes.
  • Tree method: write each node at its 1st visit → prefix, 2nd → infix, 3rd → postfix (pre-, in-, postorder).
  • Build the tree with the weakest operator as root; break ties by associativity (left-assoc → the rightmost operator).
  • Precedence: ^ > * / > + −. ^ is right → left; the others are left → right.
  • Stack conversion: operands → output; a stronger or equal (left-assoc) operator on top is popped before the newcomer is pushed; '(' is pushed; ')' pops until '('.
  • a + b*x + y → postfix a b x * + y +, prefix + + a * b x y.
  • Postfix evaluation: scan L→R, push numbers; on an operator, 2nd pop op 1st pop. 1 2 3 * + 5 + = 12.
  • Prefix evaluation: scan R→L; 1st pop op 2nd pop. + + 1 * 2 3 5 = 12.
  • Classic: 6 2 3 + − 3 8 2 / + * 2 ^ 3 + = 52. a^b^c → abc^^, and 2^3^2 = 512.
