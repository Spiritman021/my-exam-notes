Chapter 5

Functional Dependency

Chapter 4 ended with keys: attributes that identify a row uniquely. A functional dependency (FD) is the general idea behind that: knowing one attribute's value fixes another attribute's value. If you know a student's roll number you know their name, so RollNo → Name. FDs are the raw material for everything that follows: closure finds the keys (this chapter), minimal cover simplifies the FD set (chapter 6), and normalization uses FDs to split badly designed tables (chapters 7 and 8).

5.1Meaning of FD: Determinant and Dependent (Phone and Its Cover)

🎓 From the lecture

Example: a phone and its cover

Take two phone covers, each made for one particular phone. The cover tells you which phone will fit in it. A phone won't work in just any cover: if the camera is on one side and the cover's camera hole is on the other, you can't even use the camera. Which phone fits depends on whose cover it is.
  • Call the cover side A (or α) and the phone side B (or β). We say A determines B, written A → B or α → β. Both notations are popular.
  • A (α) is the determinant, because it determines.
  • B (β) is the dependent, because it depends on A.
➕ Added for exam
  • Bank examples: AccountNo → Balance, Branch; IFSC → Bank, Branch; PAN → Name. But Name → PAN does not hold, because two customers can share a name.
  • An FD is a statement about the schema (the meaning of the data), not about one snapshot of rows. It comes from business rules: "each account belongs to exactly one branch".
  • Both sides can be sets of attributes: {RollNo, SubjectID} → Marks.

5.2Tuple-Based Definition and Checking an FD on a Table

🎓 From the lecture Take a relation with two attributes A (α) and B (β). If A determines B, then every time the same A value appears, the same B value must appear with it.
  • Wherever A = 1 appears, B must be 5 — every single time.
  • A = 3 appears with B = 7 twice, but a third row has A = 3 with B = 6. For 3 we needed 7, so A → B does not hold. One such record is enough to break it.

The definition in terms of two records

Call two records t1 and t2. If t1's α value is the same as t2's α value (both 1 in our case), you must make sure their β values are also the same (both 5). For that α value, the same β value must be generated again and again.

🎓 From the lecture — first look at closure FDs tell you where you can "reach". In R(A, B, C) with A → B and B → C: if A is known you can reach B, and if B is known you can reach C. The closure of an attribute is everything you can reach from it:
  • A⁺: start with A. A → B adds B. Now with B, B → C adds C. A⁺ = {A, B, C}.
  • B⁺: start with B. B → C adds C. C is not on the left of any FD, so stop. B⁺ = {B, C}.
  • C⁺: C is on the left of no FD. C⁺ = {C}.
Closure is covered properly with solved problems in 5.5.
➕ Added for exam: checking an FD on a given table
  • Group the rows by the left side. Inside each group, the right side must have one value only. If any group shows two different values, the FD is violated.
  • If every value of the left side is unique in the table (no repeats), the FD is satisfied trivially, whatever the right side is.
  • A table instance can disprove an FD, but it can never prove that the FD holds for the schema. Exam wording: "Which FD is satisfied by the instance?" or "Which FD does not hold?"
  • Same right side for different left values is fine: A = 1 → 5 and A = 2 → 5 does not break A → B.
⚠️ Exam trap A → B does not mean B → A. In the table above, B = 5 only ever appears with A = 1, but that's a coincidence of this instance. Check each direction separately.

5.3Armstrong's Axioms: Reflexivity, Augmentation, Transitivity

🎓 From the lecture Armstrong's axioms are simple, basic properties that help you work with FDs. Questions on them come in university exams, so remember the examples.
  • Reflexivity: if B ⊆ A, then A → B. This is called the trivial property. If B is already inside A, then from A you can obviously reach B; "you're not telling me anything new."
  • Augmentation: if A → B, then AC → BC. Add the same attribute (column) to both sides, left and right; it makes no difference.
  • Transitivity: if A → B and B → C, then A → C. Just like "if a = b and b = c, then a = c".
➕ Added for exam
  • Armstrong's axioms are sound (they never produce an FD that doesn't really follow) and complete (every FD that follows can be derived with them). This pair of words is a favourite one-mark question.
  • All FDs that can be derived from a set F form the closure of F, written F⁺. Don't mix it up with the attribute closure X⁺ in 5.5.
  • Augmentation also works with only the left side growing: from A → B you get AC → B (augment to AC → BC, then BC → B by reflexivity, then transitivity).

5.4Secondary Rules: Union, Decomposition, Pseudo-Transitivity, Composition

🎓 From the lecture The three axioms are the basic (primary) rules. There are also some additional secondary rules; if asked, mention them.
  • Union: A → B and A → C give A → BC. Just combine the right-hand sides; the meaning doesn't change.
  • Decomposition: the reverse of union. A → BC can be split into A → B and A → C. But if AB → C, can you write A → C and B → C? No. You can't decompose the left-hand side this way; focus only on the right-hand side.
  • Pseudo-transitivity: from A → B and BC → D you can write AC → D. It's valid and the meaning doesn't change.
  • Composition: A → B and C → D give AC → BD. Combine both the left and right sides.
RuleGivenDeriveHow (from the axioms) ➕
UnionA → B, A → CA → BCAugment A → C with A: A → AC. Augment A → B with C: AC → BC. Transitivity.
DecompositionA → BCA → B, A → CBC → B by reflexivity, then transitivity.
Pseudo-transitivityA → B, BC → DAC → DAugment A → B with C: AC → BC. Then transitivity with BC → D.
CompositionA → B, C → DAC → BDAugment each and apply transitivity.
➕ Added for exam: a correction In the video, pseudo-transitivity is read out as "A → B and BC → D, so A → D". That last step is wrong: A alone does not give D, because D needs both B and C. The correct result is AC → D, as written above.
⚠️ Exam trap Only the right side can be split. A → BC ⇒ A → B ✅. But AB → C does not give A → C ❌. Example: {RollNo, SubjectID} → Marks is true, but RollNo → Marks is false, because a student has different marks in different subjects.

5.5Attribute Closure and Finding Candidate/Super Keys — Solved Problems

🎓 From the lecture

Problem 1: R(A, B, C, D) with A → B, B → C, C → D

To find the closure of an attribute, start with that attribute and then keep referring to the FDs: "from what I have now, where can I go next?"
  • A⁺: start with A. A → B adds B. B → C adds C. C → D adds D. A⁺ = {A, B, C, D}.
Now one important characteristic. When the closure of an attribute includes every attribute of the relation, you can say comfortably that it is a candidate key. Through A you reach B, C and D, so A is a candidate key.
  • B⁺: start with B. B → C adds C. C → D adds D. Can we go back to A? No FD gives A. B⁺ = {B, C, D}, so B cannot be a candidate key, because A is missing.

Closure of two attributes together: (AB)⁺

First write down the given attributes as they are: A, B. From A we reach B, from B we reach C, from C we reach D. Everything is included, so (AB)⁺ = {A, B, C, D}.
But AB is not a candidate key; it is a super key. "Sir, above you called A a candidate key when it reached everything; why is AB a super key?" Look at the difference: A is already a candidate key. B is a non-prime attribute (it's not in any candidate key). Adding a non-prime attribute to a candidate key gives a super key (chapter 4). This distinction is a core question in GATE and many competitive exams.

Problem 2: add one more FD, D → A

Can B become a candidate key now?
  • B⁺: B → C adds C. C → D adds D. Now D → A adds A. B⁺ = {A, B, C, D}, so B is now a candidate key. "D's role has become very big."
➕ Added for exam
  • The closure algorithm: result = X. Repeat: for every FD L → R, if L ⊆ result, add R to result. Stop when a full pass adds nothing.
  • X is a super key if X⁺ = all attributes. X is a candidate key if, in addition, no proper subset of X has that property (it's minimal).
  • So to check that AB is a candidate key, you must also check A⁺ and B⁺. If either reaches everything, AB is only a super key.
  • In Problem 2 (with D → A), every attribute reaches everything: A⁺ = B⁺ = C⁺ = D⁺ = ABCD. So A, B, C and D are all candidate keys, and every attribute is prime.
  • Closure also answers "does F imply X → Y?": compute X⁺ using F, and the answer is yes exactly when Y ⊆ X⁺. Chapter 6 uses this to find redundant FDs.
🎯 IBPS exam alert The typical question gives R and an FD set and asks "Which of these is a candidate key?" Don't compute everything. Compute the closure of each option and check two things: (1) does it reach all attributes, and (2) is it minimal?

TransitiveNon-prime → non-prime, reached through another attribute (breaks 3NF)RollNo → PinCode → City

Finding all candidate keys quickly

  1. Find the attributes that never appear on the right side of any FD. They can't be reached from anything, so they must be in every candidate key. Call this set E.
  2. Compute E⁺. If it covers everything, E is the only candidate key.
  3. Otherwise, add one more attribute at a time to E (then two, …), computing closures. Keep the minimal sets that reach everything.
  4. If a candidate key K contains X, and some FD Y → X exists, then (K − X) ∪ Y may be another candidate key. Check its closure and minimality.
Example: R(A, B, C, D, E) with A → B, BC → D, D → E. A and C never appear on the right, so both are in every key. (AC)⁺ = A, C, B (A → B), D (BC → D), E (D → E) = everything. So AC is the only candidate key.

5.7Solved Exam QuestionsADDED

Q1In A → B, A is called the: (a) dependent (b) determinant (c) prime attribute (d) super key
Answer: (b) Determinant. B is the dependent.
Q2Which of these is a trivial FD? (a) A → B (b) AB → C (c) AB → A (d) A → BC
Answer: (c) AB → A, because A ⊆ AB (reflexivity).
Q3Rows (A, B): (1, x), (2, y), (1, x), (3, y), (2, z). Does A → B hold? Does B → A hold?
Answer: A → B fails (A = 2 gives y and z). B → A fails (B = y gives 2 and 3).
Q4Armstrong's axioms are said to be:
Answer: Sound and complete.
Q5From A → B and BC → D, which follows? (a) A → D (b) AC → D (c) C → D (d) B → D
Answer: (b) AC → D (pseudo-transitivity).
Q6R(A, B, C, D, E), F = {A → BC, CD → E, B → D, E → A}. Find B⁺.
Answer: B⁺ = {B, D}. B → D adds D. No FD has B, D or BD alone on the left with everything satisfied (CD → E needs C). Stop.
Q7Same F as Q6. Find the candidate keys.
Answer: A, E, CD and BC. A⁺ = ABCDE. E → A, so E⁺ = ABCDE. CD → E, so CD⁺ = ABCDE. BC → D (via B → D), then CD → E, so BC⁺ = ABCDE. None of C, D or B alone reaches everything.
Q8R(A, B, C, D), F = {AB → C, C → D}. Is AB → D implied? Is A → C implied?
Answer: (AB)⁺ = ABCD, so AB → D is implied. A⁺ = {A}, so A → C is not.

⚡ Rapid Revision

  • FD A → B: A determines B. A (α) = determinant, B (β) = dependent (cover → phone).
  • Definition: if t1[A] = t2[A] then t1[B] = t2[B]. Same A value must always come with the same B value (1 → 5 every time; 3 with 7 and then 6 ⇒ fails). ➕ A table can disprove an FD but can't prove it.
  • Armstrong's axioms: reflexivity (B ⊆ A ⇒ A → B, trivial), augmentation (A → B ⇒ AC → BC), transitivity (A → B, B → C ⇒ A → C). ➕ Sound and complete.
  • Secondary rules: union (A → B, A → C ⇒ A → BC), decomposition (A → BC ⇒ A → B, A → C; only the right side), pseudo-transitivity (A → B, BC → D ⇒ AC → D), composition (A → B, C → D ⇒ AC → BD).
  • Closure X⁺: start with X, keep adding right sides of FDs whose left side you already have; stop when nothing changes.
  • X⁺ = all attributes ⇒ X is a super key; plus minimal ⇒ candidate key. A⁺ = ABCD ⇒ A is a CK; (AB)⁺ = ABCD but A alone works ⇒ AB is only a super key.
  • B⁺ = BCD (A missing) ⇒ not a key; add D → A and B⁺ = ABCD ⇒ B becomes a key.
  • ➕ Attributes never on any right side must be in every candidate key. Partial dependency breaks 2NF; transitive dependency breaks 3NF.
