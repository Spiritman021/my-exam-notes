13.1SELECT, WHERE, DISTINCT and Arithmetic (+10 for an Out-of-Syllabus Question)

🎓 Lecture topic (from outline)
SELECT columns FROM table WHERE condition;
  • Every column: SELECT * FROM Student;
  • Some columns: SELECT Name, Marks FROM Student; (this is π from chapter 10)
  • Some rows: SELECT * FROM Student WHERE State = 'Delhi'; → Asha, Neha (this is σ)
  • No repeats: SELECT DISTINCT State FROM Student; → Delhi, Bihar, Punjab. Without DISTINCT, Bihar appears 3 times.

Arithmetic: +10 grace marks for an out-of-syllabus question

One exam question was out of syllabus, so everyone gets 10 extra marks. You can show this without changing the stored data:
SELECT Name, Marks + 10 AS NewMarks FROM Student;
Asha 92, Ravi 75, Neha 84, Karan 55, Amit 101, Pooja NULL. AS gives the computed column a name (an alias). To change the stored marks permanently, you'd use UPDATE Student SET Marks = Marks + 10; (chapter 12).
⚠️ Exam trap Any arithmetic with NULL gives NULL: NULL + 10 = NULL, not 10. NULL means "unknown", and unknown plus 10 is still unknown.

13.2AND/OR, BETWEEN and NOT BETWEEN (Marks and Attendance)

🎓 Lecture topic (from outline)

AND / OR

  • Eligible for a prize: marks above 70 and attendance at least 75:
    WHERE Marks > 70 AND Attendance >= 75 → Asha, Neha, Amit
  • Needs counselling: marks below 50 or attendance below 75:
    WHERE Marks < 50 OR Attendance < 75 → Ravi (attendance 70), Karan (both)
  • AND binds tighter than OR. Use brackets when you mix them: WHERE State = 'Bihar' AND (Marks > 80 OR Attendance > 90) → Amit.

BETWEEN … AND … (inclusive)

WHERE Marks BETWEEN 65 AND 82 → Asha (82), Ravi (65), Neha (74). Both ends are included: it means Marks >= 65 AND Marks <= 82.

NOT BETWEEN

WHERE Marks NOT BETWEEN 65 AND 82 → Karan (45), Amit (91).
⚠️ Exam trap Pooja appears in neither BETWEEN nor NOT BETWEEN. A comparison with NULL is neither true nor false but unknown, and WHERE keeps only rows where the condition is true. BETWEEN 65 AND 82 plus NOT BETWEEN 65 AND 82 gives 5 rows, not 6. Also, BETWEEN 82 AND 65 (bounds reversed) returns nothing.

13.3LIKE with % and _ Wildcards

🎓 Lecture topic (from outline) LIKE matches text against a pattern:
  • % = any number of characters (including none)
  • _ = exactly one character
PatternMeansMatches
'A%'Starts with AAsha, Amit
'%a'Ends with aAsha, Neha, Pooja
'%ar%'Contains "ar"Karan
'_a%'Second letter is aRavi, Karan
'____'Exactly 4 charactersAsha, Ravi, Neha, Amit
'A___'A followed by exactly 3 charactersAsha, Amit
➕ Added for exam
  • NOT LIKE 'A%' = doesn't start with A.
  • To match a literal % or _, escape it: WHERE Code LIKE '%\_%' ESCAPE '\' finds codes containing an underscore.
  • Whether LIKE is case-sensitive depends on the DBMS: MySQL is not by default; PostgreSQL and Oracle are.
  • Use = for an exact match; LIKE without wildcards works but is unusual.

13.4UNION, INTERSECT, EXCEPT (and ALL)

🎓 Lecture topic (from outline) These are relational algebra's ∪, ∩ and − (chapter 10) in SQL. Using the Cricket(Roll, Name) = {1, 2, 3} and Hockey(Roll, Name) = {2, 4} tables:
  • SELECT Roll FROM Cricket UNION SELECT Roll FROM Hockey; → 1, 2, 3, 4
  • SELECT Roll FROM Cricket INTERSECT SELECT Roll FROM Hockey; → 2
  • SELECT Roll FROM Cricket EXCEPT SELECT Roll FROM Hockey; → 1, 3

With ALL

UNION, INTERSECT and EXCEPT remove duplicates. Add ALL to keep them: UNION ALL → 1, 2, 3, 2, 4 (Roll 2 twice). UNION ALL is also faster, because there's no duplicate check.
➕ Added for exam
  • Both SELECTs must have the same number of columns with compatible types (union compatibility). Column names come from the first SELECT.
  • Oracle calls EXCEPT MINUS.
  • ORDER BY may appear only once, at the very end, and sorts the combined result.

13.5Joins in SQL

🎓 Lecture topic (from outline) Chapter 9's joins, written in SQL, on Student(Roll, Name, City) and Centre(CentreID, City):
JoinSQL
Inner (equi)SELECT * FROM Student S INNER JOIN Centre C ON S.City = C.City;
Same, old styleSELECT * FROM Student S, Centre C WHERE S.City = C.City;
NaturalSELECT * FROM Student NATURAL JOIN Centre;
Left outer… FROM Student S LEFT JOIN Centre C ON S.City = C.City;
Right outer… FROM Student S RIGHT JOIN Centre C ON S.City = C.City;
Full outer… FROM Student S FULL OUTER JOIN Centre C ON S.City = C.City;
CrossSELECT * FROM Student CROSS JOIN Centre;
Self… FROM Enrol E1 JOIN Enrol E2 ON E1.Roll = E2.Roll AND E1.Subject <> E2.Subject;
➕ Added for exam
  • JOIN on its own means INNER JOIN; LEFT JOIN means LEFT OUTER JOIN.
  • USING (City) is shorthand for ON S.City = C.City and keeps one City column.
  • Students with no centre: … LEFT JOIN Centre C ON S.City = C.City WHERE C.CentreID IS NULL;

13.6Aggregate Functions, ORDER BY and GROUP BY (WhatsApp Group per State)

🎓 Lecture topic (from outline)

Aggregate functions: many rows in, one value out

QueryResultWhy
COUNT(*)6Counts rows, NULLs included
COUNT(Marks)5Skips Pooja's NULL
COUNT(DISTINCT State)3Delhi, Bihar, Punjab
SUM(Marks)35782 + 65 + 74 + 45 + 91
AVG(Marks)71.4357 ÷ 5, not ÷ 6
MAX(Marks) / MIN(Marks)91 / 45NULL ignored
🎓 Lecture topic (from outline)

ORDER BY: sort the result

SELECT Name, Marks FROM Student ORDER BY Marks DESC; → Amit 91, Asha 82, Neha 74, Ravi 65, Karan 45 (and Pooja, whose NULL sorts first or last depending on the DBMS). ASC (ascending) is the default. Sort on several columns: ORDER BY State ASC, Marks DESC.

GROUP BY: one WhatsApp group per state

Imagine putting every student into a WhatsApp group for their state. GROUP BY does that: it collects rows with the same State into one group, and an aggregate then gives one answer per group.
SELECT State, COUNT(*) AS Members, AVG(Marks) AS AvgMarks FROM Student GROUP BY State;
StateMembersAvgMarks
Delhi278 (82, 74)
Bihar378 (65, 91; Pooja's NULL skipped)
Punjab145
🎓 Lecture topic (from outline)

HAVING: filter the groups

… GROUP BY State HAVING COUNT(*) >= 2; → Delhi, Bihar. WHERE filters rows before grouping; HAVING filters groups after grouping, so only HAVING can use aggregates.
⚠️ Exam trap
  • SELECT Name, State, COUNT(*) FROM Student GROUP BY State; is an error in standard SQL: a group has many names, so which one would it show? Every column in SELECT must be in GROUP BY or inside an aggregate.
  • WHERE AVG(Marks) > 70 is an error; use HAVING.
  • AVG skips NULLs: AVG(Marks) = 71.4, but SUM(Marks)/COUNT(*) = 59.5.

13.7Views (Student, Teacher and Admin Views)

🎓 Lecture topic (from outline) A view is a saved query that behaves like a table. It's a virtual table: it stores the query, not the data, and runs the query each time it is used. It's the external level of the three-schema architecture (chapter 2.4): different users see different views of the same data.
  • Student view (marks only, attendance hidden): CREATE VIEW StudentView AS SELECT Roll, Name, Marks FROM Student;
  • Teacher view (marks and attendance, for teaching): CREATE VIEW TeacherView AS SELECT Roll, Name, Marks, Attendance FROM Student;
  • Admin: works on the base table Student and sees everything.
Use a view like a table: SELECT * FROM TeacherView WHERE Attendance < 75; Remove it with DROP VIEW TeacherView; (the base table is untouched).

Why views

  • Security: grant users access to the view only (chapter 12.5), and they can't see the hidden columns or rows.
  • Simplicity: a complex join is written once and reused by name.
  • Logical data independence: if the base table changes, the view can be redefined so users' queries keep working.
➕ Added for exam
  • A view is generally updatable (you can INSERT/UPDATE/DELETE through it) only if it's built on one table with no DISTINCT, GROUP BY, HAVING, aggregates, UNION or joins, and includes every NOT NULL column without a default.
  • WITH CHECK OPTION stops updates through a view that would create rows the view itself can't see.
  • A materialized view does store its result physically and is refreshed periodically. It's used for fast reporting.
  • CREATE OR REPLACE VIEW redefines an existing view.

13.8Subqueries and Nested Subqueries (Inception; an Investigation)

🎓 Lecture topic (from outline) A subquery is a query inside another query, like a dream inside a dream in Inception. The innermost one runs first, and its answer feeds the level above it.

An investigation, one clue at a time

Clue 1: who scored the highest marks? You can't write WHERE Marks = MAX(Marks), so first find the highest marks, then find who has them:
SELECT Name FROM Student WHERE Marks = (SELECT MAX(Marks) FROM Student);
Inner query → 91. Outer query → Amit.

Clue 2: the second-highest marks: the highest of the marks below the highest.
SELECT MAX(Marks) FROM Student WHERE Marks < (SELECT MAX(Marks) FROM Student);
→ 82 (Asha).

Clue 3 (nested two deep): everyone from the same state as the topper.
SELECT Name FROM Student WHERE State = (SELECT State FROM Student WHERE Marks = (SELECT MAX(Marks) FROM Student));
Innermost → 91. Middle → Bihar. Outer → Ravi, Amit, Pooja.
➕ Added for exam: correlated subquery A correlated subquery refers to the outer row, so it runs once per outer row instead of once in total. Students who beat their own state's average:
SELECT Name FROM Student S WHERE Marks > (SELECT AVG(Marks) FROM Student T WHERE T.State = S.State);
Delhi average 78 → Asha (82) ✅, Neha (74) ❌. Bihar average 78 → Amit (91) ✅, Ravi ❌. Punjab average 45 → Karan (45) ❌ (not greater). Answer: Asha, Amit.
⚠️ Exam trap WHERE Marks = (subquery) needs the subquery to return one value. If it can return several rows, use IN, ANY or ALL instead, or the query fails with "subquery returns more than one row".

13.9Order of Execution, NULLs, IN / EXISTS / ANY / ALLADDED

➕ Added for exam: the order SQL actually runs a query
➕ Added for exam

NULL

  • Test with IS NULL / IS NOT NULL. WHERE Marks = NULL returns nothing, even for Pooja.
  • COALESCE(Marks, 0) (or IFNULL / NVL) replaces NULL with 0.

Subquery operators

  • IN: WHERE State IN ('Delhi', 'Punjab') or IN (subquery), equal to any value in the list.
  • EXISTS: true if the subquery returns at least one row. Usually correlated.
  • > ANY (or SOME): greater than at least one value, i.e. greater than the minimum.
  • > ALL: greater than every value, i.e. greater than the maximum.
⚠️ Exam trap WHERE x NOT IN (subquery) returns no rows at all if the subquery's result contains a NULL, because "x ≠ NULL" is unknown. NOT EXISTS doesn't have this problem.
🎯 IBPS exam alert Favourites: the second-highest salary query, WHERE vs HAVING, COUNT(*) vs COUNT(column), the result of BETWEEN at its edges, LIKE patterns with _ and %, UNION vs UNION ALL, and "a view stores no data".

13.10Solved Exam QuestionsADDED

Q1Which keyword removes duplicate rows from a SELECT result?
Answer: DISTINCT.
Q2Names with 'a' as the second letter: which pattern?
Answer: LIKE '_a%'.
Q3Marks BETWEEN 40 AND 60 includes 40 and 60. True or false?
Answer: True. BETWEEN is inclusive at both ends.
Q4Which clause filters groups created by GROUP BY?
Answer: HAVING.
Q5A table has 10 rows; 3 have NULL in Salary. COUNT(*) and COUNT(Salary)?
Answer: 10 and 7.
Q6Which set operator keeps duplicates? (a) UNION (b) UNION ALL (c) INTERSECT (d) EXCEPT
Answer: (b) UNION ALL.
Q7Write a query for the second-highest salary in Emp(Name, Salary).
Answer: SELECT MAX(Salary) FROM Emp WHERE Salary < (SELECT MAX(Salary) FROM Emp);
Q8A view is:
Answer: a virtual table, defined by a stored query, with no data of its own (unless materialized).
Q9A subquery that uses a column of the outer query is called:
Answer: a correlated subquery. It's evaluated once per outer row.
Q10"Salary > ALL (SELECT Salary FROM Emp WHERE Dept = 'IT')" means:
Answer: salary greater than the highest IT salary.

⚡ Rapid Revision

  • SELECT (columns, π) FROM (tables) WHERE (rows, σ). DISTINCT removes duplicates. Marks + 10 AS NewMarks computes without storing. NULL + 10 = NULL.
  • AND binds tighter than OR; use brackets. BETWEEN is inclusive. NULL passes neither BETWEEN nor NOT BETWEEN.
  • LIKE: % = any number of characters, _ = exactly one. '_a%' = second letter a.
  • UNION / INTERSECT / EXCEPT remove duplicates; ALL keeps them. Oracle: MINUS.
  • Joins: INNER JOIN … ON, NATURAL JOIN, LEFT / RIGHT / FULL OUTER JOIN, CROSS JOIN, self join with aliases.
  • Aggregates ignore NULL except COUNT(*). AVG = SUM ÷ non-NULL count.
  • GROUP BY = one WhatsApp group per state, one result row per group. Non-aggregated SELECT columns must be in GROUP BY. WHERE filters rows before; HAVING filters groups after.
  • ORDER BY ASC (default) / DESC; runs almost last.
  • View = virtual table (stored query): student, teacher and admin each see what they need. Security, simplicity, data independence. ➕ Materialized view stores data.
  • Subquery = Inception: innermost first. Topper: WHERE Marks = (SELECT MAX…). Second highest: MAX where Marks < MAX. ➕ Correlated = runs once per outer row.
  • ➕ Logical order: FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. Use IS NULL, never = NULL. NOT IN with a NULL returns nothing.
