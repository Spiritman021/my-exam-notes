Chapter 11

Relational Calculus

Relational algebra (chapter 10) says how to compute an answer, step by step. Relational calculus only describes the answer: "the set of all t such that t satisfies this condition". It is non-procedural, and it's the idea SQL's WHERE clause is built on. There are two forms: tuple calculus, whose variables stand for whole rows, and domain calculus, whose variables stand for single column values.

Tables used throughout: Student(Roll, Name, City, Marks), Enrol(Roll, Course), Course(Course).

11.1Tuple Relational Calculus: Syntax and Connectors (∃, ∀)

🎓 Lecture topic (from outline)
{ t | P(t) } — the set of all tuples t for which the condition P(t) is true

Building blocks

  • Tuple variable: t ranges over rows. t ∈ Student says t is a row of Student.
  • Attribute access: t.Marks is the Marks value of row t.
  • Comparisons: =, ≠, <, ≤, >, ≥ between attributes and constants.
  • Connectors: ∧ (and), ∨ (or), ¬ (not), ⇒ (implies).
  • Quantifiers: ∃ s ∈ R (P) = "there exists a row s in R for which P holds". ∀ s ∈ R (P) = "for every row s in R, P holds".

Examples

  • Students with marks above 70 (whole rows):
    { t | t ∈ Student ∧ t.Marks > 70 } (like σMarks>70(Student))
  • Only their names:
    { t.Name | t ∈ Student ∧ t.Marks > 70 } (like πName(σMarks>70(Student)))
  • Names of students enrolled in DBMS (needs ∃ to reach into Enrol):
    { t.Name | t ∈ Student ∧ ∃ e ∈ Enrol (e.Roll = t.Roll ∧ e.Course = 'DBMS') }
  • Students enrolled in every course (needs ∀, like division):
    { t.Roll | t ∈ Student ∧ ∀ c ∈ Course ( ∃ e ∈ Enrol (e.Roll = t.Roll ∧ e.Course = c.Course) ) }
➕ Added for exam
  • Free variable: not bound by a quantifier; it's what the result is built from (t above). Bound variable: introduced by ∃ or ∀ (e, c above). Only free variables may appear left of the bar.
  • ∀ can always be rewritten with ∃: ∀ x (P) ≡ ¬∃ x (¬P). "Every course is taken" = "there is no course that isn't taken". That's exactly how SQL writes division, with NOT EXISTS … NOT EXISTS.
  • P ⇒ Q ≡ ¬P ∨ Q.
⚠️ Exam trap "Students not enrolled in any course" uses ¬∃: { t | t ∈ Student ∧ ¬∃ e ∈ Enrol (e.Roll = t.Roll) }. Writing ∃ e ∈ Enrol (e.Roll ≠ t.Roll) is wrong: it's true for almost every student, because some other enrolment row will always have a different Roll.

11.2Unsafe Expressions

🎓 Lecture topic (from outline) Calculus describes a set, and some descriptions describe an infinite set:
{ t | ¬(t ∈ Student) } — every tuple in the universe that is not a student
That includes every possible combination of every possible value: infinitely many rows. No database can return it. Such an expression is unsafe.

Safe expression

An expression is safe if every value in its result comes from the domain of the expression: values that appear in the relations it mentions, plus the constants written in it. A safe expression always gives a finite answer.
  • Unsafe: { t | ¬(t ∈ Student) }
  • Safe: { t | t ∈ Student ∧ ¬(t.City = 'Delhi') }. The ¬ only filters rows that are already tied to Student.
➕ Added for exam
  • Rule of thumb: every free variable must be tied to a relation with a positive "t ∈ R" before ¬ is applied to it.
  • Relational algebra can never be unsafe: every operator takes finite relations and returns a finite relation. Unsafety is a problem only for calculus.

11.3Domain Relational Calculus

🎓 Lecture topic (from outline) In DRC the variables range over attribute values (domains), not whole rows. You list one variable per column.
{ <x1, x2, …, xn> | P(x1, x2, …, xn) }
<r, n, c, m> ∈ Student means "there is a Student row with Roll r, Name n, City c and Marks m". The variables follow the column order.

The same queries in DRC

  • Names of students with marks above 70:
    { <n> | ∃ r, c, m ( <r, n, c, m> ∈ Student ∧ m > 70 ) }
  • Names of students enrolled in DBMS:
    { <n> | ∃ r, c, m ( <r, n, c, m> ∈ Student ∧ <r, 'DBMS'> ∈ Enrol ) }
    The shared variable r does the joining: the same r in both relations.
  • Rolls of students in every course:
    { <r> | ∃ n, c, m ( <r, n, c, m> ∈ Student ) ∧ ∀ k ( <k> ∈ Course ⇒ <r, k> ∈ Enrol ) }

11.4Algebra vs TRC vs DRC; Relational CompletenessADDED

➕ Added for exam
  • Codd's theorem: relational algebra, safe TRC and safe DRC have exactly the same expressive power. Any query written in one can be written in the other two.
  • A query language is relationally complete if it can express every relational algebra query. SQL is relationally complete (and goes further, with aggregates, sorting and grouping that basic algebra lacks).
  • Neither basic algebra nor calculus has aggregates (SUM, COUNT…) or recursion.

11.5Solved Exam QuestionsADDED

Q1Relational calculus is:
Answer: non-procedural (declarative). It says what to retrieve, not how.
Q2In tuple relational calculus, variables range over:
Answer: tuples (rows) of a relation. In DRC, they range over attribute domains.
Q3Which expression is unsafe? (a) { t | t ∈ R ∧ t.A > 5 } (b) { t | ¬(t ∈ R) } (c) { t | t ∈ R ∨ t ∈ S } with R, S compatible (d) { t | t ∈ R ∧ ¬(t ∈ S) }
Answer: (b). It describes everything outside R, an infinite set.
Q4Query By Example (QBE) is based on:
Answer: domain relational calculus.
Q5Which quantifier corresponds to relational algebra's division?
Answer: ∀ (universal quantifier).
Q6Relational algebra, safe TRC and safe DRC are:
Answer: equivalent in expressive power (Codd's theorem).
Q7∀ x P(x) is equivalent to:
Answer: ¬∃ x ¬P(x).

⚡ Rapid Revision

  • Relational calculus = non-procedural: describe the result, not the steps.
  • TRC: { t | P(t) }, t ranges over rows; t ∈ Student, t.Marks > 70. Connectors ∧ ∨ ¬ ⇒.
  • ∃ = there exists (used for joins). ∀ = for all (used for division). ∀x P ≡ ¬∃x ¬P.
  • Free variable = in the result; bound variable = introduced by ∃ or ∀.
  • Unsafe expression = infinite result, e.g. { t | ¬(t ∈ Student) }. Safe = values only from the relations and constants used.
  • DRC: { <x1…xn> | P }, variables range over column values; a shared variable joins relations. Basis of QBE.
  • ➕ Codd's theorem: algebra = safe TRC = safe DRC in power. SQL is relationally complete (and has more, like aggregates).
