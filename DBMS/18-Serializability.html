Chapter 18

Serializability

Serial schedules are always correct but slow; interleaved schedules are fast but sometimes wrong (chapter 17). Serializability is the test that tells them apart: an interleaved schedule is acceptable if it gives the same result as some serial schedule. Schedules are written compactly: R1(A) means "T1 reads A", W2(B) means "T2 writes B", read left to right in time order.

18.1Serializability; Conflicting vs Non-Conflicting Pairs

🎓 Lecture topic (from outline) A schedule is serializable if it's equivalent to some serial schedule of the same transactions. There are two ways to define "equivalent": conflict equivalence (18.2–18.3) and view equivalence (18.4).

Conflicting operations

Two operations conflict if all three hold:
  1. they belong to different transactions,
  2. they act on the same data item, and
  3. at least one of them is a write.
The order of two conflicting operations affects the result, so it can't be changed. The order of non-conflicting operations doesn't matter.
Pair (T1 then T2)Same item?Conflict?Why
R1(A), R2(A)YesNoTwo reads never interfere
R1(A), W2(A)YesYes (R–W)T1 sees the old value only if it reads first
W1(A), R2(A)YesYes (W–R)T2 sees T1's value only if T1 writes first
W1(A), W2(A)YesYes (W–W)The later write is the one that survives
W1(A), W2(B)NoNoDifferent items
R1(A), W1(A)YesNoSame transaction: its own order is fixed anyway

18.2Conflict Equivalence by Swapping Operations

🎓 Lecture topic (from outline) Two schedules are conflict equivalent if one can be turned into the other by repeatedly swapping adjacent non-conflicting operations. A schedule is conflict serializable if it's conflict equivalent to a serial schedule.

Solved: S = R1(A) W1(A) R2(A) W2(A) R1(B) W1(B) R2(B) W2(B)

Goal: move T1's B operations ahead of T2's A operations.
  • R1(B) is next to W2(A): different items → swap. Then next to R2(A): different items → swap. R1(B) is now right after W1(A).
  • Do the same with W1(B): it passes W2(A) and R2(A) (different items).
Result: R1(A) W1(A) R1(B) W1(B) R2(A) W2(A) R2(B) W2(B) = T1 then T2, a serial schedule. So S is conflict serializable, equivalent to T1 → T2.

When swapping gets stuck

S = R1(A) R2(A) W1(A) W2(A). To make it T1 → T2, W1(A) must move ahead of R2(A), but they conflict (W–R on A). To make it T2 → T1, W2(A) must move ahead of R1(A)… also a conflict. Neither serial order is reachable → not conflict serializable. (This is chapter 17's lost update.)
➕ Added for exam Swapping works for small schedules but gets tedious. The precedence graph (18.3) gives the same answer mechanically, and is the method to use in exams.

18.3Precedence Graph Test — Solved (Without and With a Cycle)

🎓 Lecture topic (from outline)

How to build it

  1. Draw one node per transaction.
  2. For every pair of conflicting operations where Ti's operation comes before Tj's, draw an edge Ti → Tj.
  3. No cycle → conflict serializable. An equivalent serial order is any topological order of the graph (follow the arrows).
  4. Cycle → not conflict serializable.

Solved 1 (no cycle): S = R1(A) W1(A) R2(A) R3(B) W2(A) W3(B) R1(B)

Check every pair that touches the same item, with at least one write:
  • A: W1(A) before R2(A) → T1 → T2. (R1(A), W1(A) before W2(A) give the same edge.)
  • B: W3(B) before R1(B) → T3 → T1. (R3(B) and R1(B) are both reads: no edge.)
Graph: T3 → T1 → T2. No cycle → conflict serializable, equivalent to the serial order T3, T1, T2.
🎓 Lecture topic (from outline)

Solved 2 (cycle): S = R1(A) R2(A) W1(A) W2(A)

  • R1(A) before W2(A) → T1 → T2.
  • R2(A) before W1(A) → T2 → T1.
  • W1(A) before W2(A) → T1 → T2 (already there).
T1 → T2 → T1 is a cycle → not conflict serializable. Each transaction must come before the other, which is impossible in any serial order.
⚠️ Exam trap
  • Look at every pair, not just neighbours. In Solved 1, W1(A) and R2(A) are adjacent, but W3(B) and R1(B) are far apart and still create an edge.
  • Don't draw edges for read–read pairs or for operations of the same transaction.
  • "Not conflict serializable" doesn't mean "not serializable": it may still be view serializable (18.4).

18.4View Serializability: Initial Read and Final Write — Solved

🎓 Lecture topic (from outline) Two schedules S and S′ are view equivalent if, for every data item:
  1. Initial read: the transaction that reads the item's original value in S does so in S′ too.
  2. Read-from (updated read): if Ti reads a value written by Tj in S, it reads the value written by Tj in S′ too.
  3. Final write: the transaction that does the last write of the item in S does so in S′ too.
Every transaction then sees the same values and leaves the same final database, so the result is the same. A schedule is view serializable if it's view equivalent to some serial schedule.

Solved: S = R1(A) W2(A) W1(A) W3(A)

Conflict test first: R1(A) → W2(A) gives T1 → T2; W2(A) → W1(A) gives T2 → T1. Cycle → not conflict serializable.

View test:
  • Initial read of A: T1 (reads the original A).
  • Read-from: none (no one reads a value another transaction wrote).
  • Final write of A: T3.
So the serial order must have T1 reading A before anyone writes it (T1 first) and T3 writing last (T3 last). Try T1, T2, T3 = R1(A) W1(A) W2(A) W3(A): initial read T1 ✅, final write T3 ✅, no read-from ✅. View equivalent → S is view serializable.
🎓 Lecture topic (from outline)

Why it passed: blind writes

W2(A) and W3(A) are blind writes: writes without a prior read of the item in that transaction. T2's write is overwritten before anyone reads it, so its position doesn't matter to anyone. Conflict serializability is too strict to notice that; view serializability does.

18.5Conflict vs View Serializability; Counting Serial OrdersADDED

➕ Added for exam
  • Every conflict-serializable schedule is view serializable, but not the other way round (18.4's example).
  • If a schedule is view serializable but not conflict serializable, it must contain a blind write. No blind writes → the two tests agree.
  • Testing conflict serializability is fast (build the graph, look for a cycle). Testing view serializability is NP-complete, which is why real DBMSs enforce conflict serializability (chapter 19's protocols).
  • Serializability and recoverability (chapter 17) are separate questions: a schedule can be serializable and still irrecoverable.
➕ Added for exam: how many serial schedules is it equivalent to? A conflict-serializable schedule is equivalent to every topological order of its precedence graph. If the graph has edges T1 → T2 and T1 → T3 only, the orders are T1 T2 T3 and T1 T3 T2: 2 equivalent serial schedules. A chain T3 → T1 → T2 has exactly 1.
🎯 IBPS exam alert Expect: "which pairs conflict?", "draw the precedence graph / is it conflict serializable?", "equivalent serial order?", and "a schedule that is view serializable but not conflict serializable must have ___" (blind writes).

18.6Solved Exam QuestionsADDED

Q1Which pair is non-conflicting? (a) R1(X), W2(X) (b) W1(X), W2(X) (c) R1(X), R2(X) (d) W1(X), R2(X)
Answer: (c). Two reads never conflict.
Q2A schedule is conflict serializable if its precedence graph:
Answer: has no cycle.
Q3S = R1(A) W1(A) R2(A) W2(A). Conflict serializable? Equivalent serial order?
Answer: Yes; T1 → T2. The only edge is T1 → T2.
Q4S = R1(A) R2(B) W1(B) W2(A). Conflict serializable?
Answer: No. R1(A) before W2(A) gives T1 → T2; R2(B) before W1(B) gives T2 → T1; cycle.
Q5A view-serializable schedule that isn't conflict serializable must contain:
Answer: a blind write.
Q6Which three conditions define view equivalence?
Answer: same initial reads, same read-from (updated reads), same final writes.
Q7Every view-serializable schedule is conflict serializable. True or false?
Answer: False. The converse is true.
Q8A precedence graph has edges T2 → T1 and T2 → T3. How many equivalent serial schedules?
Answer: 2 (T2 T1 T3 and T2 T3 T1).

⚡ Rapid Revision

  • Serializable = equivalent to some serial schedule.
  • Conflict = different transactions + same item + at least one write (R–W, W–R, W–W). R–R never conflicts.
  • Conflict serializable = reach a serial schedule by swapping adjacent non-conflicting operations.
  • Precedence graph: node per transaction; Ti → Tj if Ti's conflicting operation comes first. No cycle ⇒ conflict serializable; serial order = topological order. Cycle ⇒ not.
  • R1(A) W1(A) R2(A) R3(B) W2(A) W3(B) R1(B) → T3 → T1 → T2 ✅. R1(A) R2(A) W1(A) W2(A) → cycle ❌ (lost update).
  • View equivalent: same initial read, same read-from, same final write.
  • R1(A) W2(A) W1(A) W3(A): not conflict serializable, but view serializable (≡ T1 T2 T3) thanks to blind writes.
  • ➕ Serial ⊂ Conflict ⊂ View ⊂ All. View-not-conflict ⇒ blind write. View test is NP-complete, so DBMSs enforce conflict serializability.
