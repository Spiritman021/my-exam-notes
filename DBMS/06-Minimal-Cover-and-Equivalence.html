Chapter 6

Minimal Cover and Equivalence of FDs

An FD set given in a question often says the same thing more than once. Some FDs can be worked out from the others, and some left sides carry attributes that aren't needed. The minimal cover strips all of that away and keeps the smallest set that still means exactly the same thing. Equivalence asks the related question: do two different-looking FD sets mean the same thing? Both are answered with one tool you already know from chapter 5: attribute closure.

6.1Minimal (Canonical) Cover: Purpose (Two Routes to the Same Destination)

🎓 From the lecture Why do we use a minimal cover? Just to remove redundancy. Say we're given many FDs, like A → B, C → B, D → ABC, AC → D. Can we remove the redundancy in them and generate a minimal cover?

When is an FD redundant?

Suppose A → B is one of my FDs. It is redundant if, after removing it, I can still reach B from A using the other FDs.

Example: two roads

Here is my source and here is my destination. I have one road to get there and a second road too. When do I call one road redundant? When, even with that road cut, I can still get from the source to the destination by the other road. Then the road I just cut was redundant, and it's right to remove it. An FD is a road from its left side to its right side.
➕ Added for exam
  • A minimal cover (also called canonical cover or irreducible set), written Fc or Fmin, is a set equivalent to F such that: (1) every right side is a single attribute, (2) no left side has an extraneous attribute, and (3) no FD is redundant.
  • "Equivalent" means Fc and F imply exactly the same FDs: Fc⁺ = F⁺.
  • Why bother? Fewer FDs mean less checking on every insert and update, and the minimal cover is the starting point of the 3NF synthesis algorithm (chapter 8).

6.2Three Steps of Minimal Cover — Solved (A→B, C→B, D→ABC, AC→D)

🎓 From the lecture

Step 1: split the right-hand sides

If any FD has more than one attribute on the right, decompose it (the decomposition rule from chapter 5). D → ABC becomes D → A, D → B, D → C. Same meaning.

Step 2: remove redundant FDs, one at a time

Take each FD, pretend it isn't there, and find the closure of its left side using the remaining FDs. If the right side still shows up, the FD is redundant. "It may look lengthy because I'm explaining; when you do it yourself it's quick."
  • A → B: without it, A⁺ = {A}. A appears on the left of no other FD (it's inside AC, but that needs C too, so it's no use). No other way to B → keep.
  • C → B: without it, C⁺ = {C}. C alone is on the left of nothing → keep.
  • D → A: without it, D⁺ = D, then B (D → B), then C (D → C); from C we reach B, already there. D⁺ = {D, B, C}: no A → keep.
  • D → B: without it, D⁺ = D, A (D → A), B (A → B), C (D → C). B is reached: there's an alternate path from source to destination → remove.
  • D → C: without it, D⁺ = D, A, B. Can't reach C → keep.
  • AC → D: without it, (AC)⁺ = A, C, B (A → B, C → B). D can't be reached; no FD gives D without this one → keep.

Step 3: reduce the left-hand sides

Step 1 dealt with more than one attribute on the right; step 3 deals with FDs that have more than one attribute on the left. Here that's AC → D. Can we drop A or C? Only if one can reach the other through some FD.
  • A⁺ = {A, B}: no C. C⁺ = {C, B}: no A.
  • No way to go from A to C or from C to A, so we can remove neither A nor C. Both stay.

➕ Added for exam: the textbook step order The lecture removes redundant FDs first and reduces left sides last. Most textbooks (and GATE solutions) do it the other way round: 1. split right sides → 2. remove extraneous left-side attributes → 3. remove redundant FDs. The safe order is left-side reduction before redundancy removal, because shrinking a left side can make another FD redundant that wasn't before. In this example, no left side can be reduced, so both orders give the same answer. 6.4 works a second example in the textbook order.
⚠️ Exam trap When you test an FD, compute the closure without that FD but with every FD you've kept so far, including the split pieces. Once an FD is removed, it stays removed for the later checks. (D → C was checked after D → B had already gone.)

6.3Equivalence of FD Sets — Solved Problems

🎓 From the lecture Two FD sets are given; are they equivalent? Students get confused here, but it's simple. The condition: if FD1 covers FD2 and FD2 covers FD1, then FD1 = FD2.
  1. Does FD1 cover FD2? If no, stop: not equivalent.
  2. If yes, does FD2 cover FD1?
  3. Both yes → equivalent.

What does "FD1 covers FD2" mean?

Can FD1 produce every FD in FD2? Take each FD of FD2 and find the closure of its left side, but by referring to FD1. "Here it's the other way round": the FD belongs to FD2, yet we use FD1 to compute the closure, because we want to know whether FD1 can make that journey.

Solved example: FD1 = {A → B, B → C}, FD2 = {A → B, B → C, A → C}

Does FD1 cover FD2? (closures computed with FD1)
  • A⁺ = A, B (A → B), C (B → C) = {A, B, C}. So A → B ✅ and A → C ✅ are both covered.
  • B⁺ = B, C (B → C) = {B, C}. So B → C ✅ is covered.
  • FD1 covers FD2: yes.
Does FD2 cover FD1? (closures computed with FD2)
  • A⁺ = {A, B, C} (A → B, A → C). A → B ✅. "C also comes, but we're not interested in C right now."
  • B⁺ = {B, C} (B → C). B → C ✅.
  • FD2 covers FD1: yes.
Both yes, so FD1 = FD2: the two sets are equivalent.

Modified example: remove B → C from FD1

Now FD1 = {A → B}. Does FD1 cover FD2? From A you only reach B. B → C can't be covered under any circumstances. The answer is no, so the two sets are not equivalent.
➕ Added for exam
  • The lecture's "FD1 ⊆ FD2" is shorthand. Strictly, "F covers G" means G ⊆ F⁺: every FD in G can be derived from F. F and G are equivalent when F⁺ = G⁺, written F ≡ G.
  • Equivalent sets can look very different and have different numbers of FDs. FD1 above has 2 FDs, FD2 has 3.
  • Every FD set is equivalent to its minimal cover. That's what makes the minimal cover a valid replacement.
  • Exam options are often "F covers G", "G covers F", "both" or "neither". Check each direction separately and pick the matching option.
⚠️ Exam trap Use the other set when computing closures. To check whether FD1 covers FD2, take FD2's left sides but compute their closures with FD1's FDs. Using the set the FD came from always gives "yes" and proves nothing.

6.4Extraneous Attributes, Step Order and a Second Worked ExampleADDED

➕ Added for exam

Extraneous attribute on the left side

In XY → Z, the attribute Y is extraneous if X → Z already follows from F. Test: compute X⁺ using the full F (including XY → Z). If Z ∈ X⁺, drop Y.

Worked example: F = {A → BC, B → C, A → B, AB → C}

  1. Split right sides: A → B, A → C, B → C, A → B (duplicate, keep one), AB → C. Now {A → B, A → C, B → C, AB → C}.
  2. Reduce left sides: AB → C. A⁺ = {A, B, C} contains C, so B is extraneous. AB → C becomes A → C, a duplicate. Now {A → B, A → C, B → C}.
  3. Remove redundant FDs:
    • A → B: without it, A⁺ = {A, C}. No B → keep.
    • A → C: without it, A⁺ = {A, B, C} (A → B → C). C reached → remove.
    • B → C: without it, B⁺ = {B}. Keep.
Fc = { A → B, B → C }

The minimal cover is not always unique

F = {A → B, B → A, A → C, B → C}. A → C is redundant (A → B → C), and so is B → C (B → A → C), but you can't remove both. Removing either one gives a valid minimal cover:
  • {A → B, B → A, B → C}, or
  • {A → B, B → A, A → C}.
Both are correct. The answer depends on the order in which you test the FDs.
🎯 IBPS exam alert The usual question is "Which of the following is the canonical cover of F?" The quick method: for each option, check that (1) every right side is a single attribute (or the option's FDs can be split that way), (2) the option is equivalent to F (6.3), and (3) nothing in it is redundant. Equivalence alone isn't enough; F itself is equivalent to F, but it isn't minimal.

6.5Solved Exam QuestionsADDED

Q1The main purpose of finding a minimal cover is to:
Answer: remove redundant FDs and extraneous attributes while keeping the set equivalent to the original.
Q2Find the minimal cover of F = {AB → C, A → B}.
Answer: {A → B, A → C}. A⁺ = {A, B, C}, so B is extraneous in AB → C, giving A → C. Neither A → B nor A → C is redundant.
Q3F = {A → B, B → C}, G = {A → B, A → C}. Which is true? (a) F covers G only (b) G covers F only (c) both (d) neither
Answer: (a). Using F: A⁺ = ABC, so both FDs of G hold. Using G: B⁺ = {B}, so B → C does not hold.
Q4F = {A → C, AC → D, E → AD, E → H}, G = {A → CD, E → AH}. Are they equivalent?
Answer: Yes. Using F: A⁺ = ACD (covers A → CD), E⁺ = EADHC (covers E → AH). Using G: A⁺ = ACD (covers A → C, AC → D), E⁺ = EAHCD (covers E → AD, E → H).
Q5In AB → C, B is extraneous if:
Answer: C ∈ A⁺, computed with the full FD set.
Q6Which property must every FD in a minimal cover have? (a) right side is a single attribute (b) left side is a single attribute (c) both sides are keys (d) it is trivial
Answer: (a). The left side may still have several attributes (like AC → D in 6.2), as long as none of them is extraneous.
Q7Is the minimal cover of an FD set always unique?
Answer: No. F = {A → B, B → A, A → C, B → C} has two minimal covers (6.4).

⚡ Rapid Revision

  • Minimal cover = the smallest FD set equivalent to F; its purpose is to remove redundancy. ➕ Also called the canonical cover (Fc).
  • Redundant FD = its right side is still reachable from its left side without it (two roads to one destination; cut one and you still get there).
  • Lecture steps: (1) split right sides (D → ABC ⇒ D → A, D → B, D → C); (2) drop each FD and check the closure of its left side using the rest; (3) try to shrink multi-attribute left sides.
  • Worked: A → B, C → B, D → ABC, AC → D ⇒ D → B is redundant (D → A → B); AC → D can't shrink (A⁺ = AB, C⁺ = CB) ⇒ {A → B, C → B, D → A, D → C, AC → D}.
  • ➕ Textbook order: split → remove extraneous left-side attributes → remove redundant FDs. Y in XY → Z is extraneous if Z ∈ X⁺.
  • Equivalence: FD1 ≡ FD2 if FD1 covers FD2 and FD2 covers FD1. To check "FD1 covers FD2", take each FD of FD2 and compute the closure of its left side using FD1.
  • {A → B, B → C} ≡ {A → B, B → C, A → C} ✅. {A → B} vs {A → B, B → C, A → C}: B → C not covered ⇒ not equivalent.
  • ➕ The minimal cover is not always unique, but it's always equivalent to F.
