Chapter 15

B-Tree and B+ Tree

Chapter 14 ended with the multi-level index: an index on an index, read one block per level. Its weakness is that it's static; inserts and deletes slowly unbalance it. A B-tree is a multi-level index that keeps itself balanced automatically: every leaf is always at the same depth, so every search costs the same few block reads. The B+ tree is the variant almost every real DBMS uses for its indexes.

15.1B-Tree Node Structure: Block Pointers, Keys, Data Pointers

🎓 Lecture topic (from outline) Each node of a B-tree is one disk block. Inside it, three kinds of item alternate:
  • Keys K1 < K2 < … < Kq−1, kept in sorted order.
  • Block (tree) pointers P1 … Pq: one more than the number of keys. Each points to a child node.
  • Data (record) pointers Pri: one next to each key, pointing to the record with that key in the data file.
< P1, (K1, Pr1), P2, (K2, Pr2), …, (Kq−1, Prq−1), Pq >
Search rule: everything under Pi lies between Ki−1 and Ki. So to find X, compare it with the keys in the node; if it matches, follow the data pointer; otherwise go down the block pointer between the two keys it falls between.

15.2Order of a B-Tree: Minimum and Maximum Keys

🎓 Lecture topic (from outline) The order p of a B-tree is the maximum number of children (block pointers) a node may have. Everything else follows from it:
NodeChildren (min – max)Keys (min – max)Order 4 example
Root (if not a leaf)2 – p1 – (p − 1)2–4 children, 1–3 keys
Internal (non-root)⌈p/2⌉ – p⌈p/2⌉ − 1 – (p − 1)2–4 children, 1–3 keys
Leaf (non-root)0⌈p/2⌉ − 1 – (p − 1)1–3 keys
🎓 Lecture topic (from outline) Rules that keep it balanced:
  • Every node except the root is at least half full.
  • All leaves are at the same level.
  • A node with k keys has exactly k + 1 children.
  • The tree grows upward: when a node overflows, it splits and pushes its middle key up. Only a root split adds a new level.
⚠️ Exam trap Books define "order" differently. Most (and IBPS-level questions) use p = maximum children, as here. Some (Cormen) use minimum degree t: each node has between t and 2t children, so max keys = 2t − 1. Read the question's definition. If it says "order p, max keys?" the answer is p − 1.

15.3Inserting 1 to 12 into a B-Tree of Order 4 — Solved

🎓 Lecture topic (from outline) Order 4 → a node holds at most 3 keys. Insertion rule:
  1. Search down to the correct leaf and insert the key there in sorted order.
  2. If the leaf now has 4 keys (overflow), split it: push a middle key up to the parent, and divide the rest into two nodes.
  3. If the parent overflows, split it the same way. If the root splits, a new root is made and the tree grows one level.
With 4 keys there are two middle keys. We'll push up the second one (left-biased): [a, b, c, d] → b goes up, [a] and [c, d] stay. Inserting 1, 2, …, 12 in order:

⚠️ Exam trap The answer depends on which middle key goes up. Pushing up the third key (right-biased: [a, b, c, d] → c up, [a, b] and [d] stay) gives a different tree for the same input: [3, 6, 9] / [1, 2] [4, 5] [7, 8] [10, 11, 12], only 2 levels. Both are valid B-trees. In an exam, follow the convention the question states; if none is stated, say which one you used.
➕ Added for exam: deletion in one paragraph Delete from a leaf; if that leaves it below the minimum, first try to borrow a key from a sibling (through the parent). If the sibling is also at the minimum, merge the two with the separating key from the parent. Merging can underflow the parent, and if the root loses its last key, the tree shrinks by one level. Deleting a key in an internal node first swaps it with its in-order predecessor or successor from a leaf.

15.4B+ Tree: Leaf vs Non-Leaf Nodes and Linked Leaves

🎓 Lecture topic (from outline) A B+ tree changes two things about the B-tree:
  1. Data pointers only in the leaves. Internal (non-leaf) nodes hold only keys and block pointers; they're a pure signpost. Every key appears in a leaf, and some keys are repeated in internal nodes as guides.
  2. Leaves are linked. Each leaf has a pointer to the next leaf, so the leaves form a sorted linked list of every key.

Two kinds of node

Internal (non-leaf) nodeLeaf node
HoldsKeys + block pointers to childrenKeys + data pointers to records
Extra pointerNoneOne "next leaf" pointer
PurposeRoute the searchPoint to the actual data
🎓 Lecture topic (from outline)

Why the change helps

  • Bigger fan-out: internal nodes have no data pointers, so more keys fit per block. A wider tree is a shorter tree, and fewer levels mean fewer block reads.
  • Range queries: for Marks BETWEEN 60 AND 80, find 60 once, then walk along the linked leaves until 80. A B-tree would have to keep going up and down.
  • Uniform search cost: every search goes all the way to a leaf, so every lookup costs the same.
➕ Added for exam: insertion difference When a B+ tree leaf splits, the middle key is copied up (it stays in the leaf too, because leaves must hold every key). When an internal node splits, the middle key is moved up, exactly as in a B-tree.

15.5Finding the Order of B-Tree and B+ Tree Nodes — Solved Numericals

🎓 Lecture topic (from outline) A node is one block, so its contents must fit in the block size B. With order p, key size K, block pointer P and data (record) pointer Pr:
NodeContentsInequality
B-tree nodep block pointers, p − 1 keys, p − 1 data pointersp·P + (p − 1)(K + Pr) ≤ B
B+ internal nodep block pointers, p − 1 keysp·P + (p − 1)·K ≤ B
B+ leaf nodem (key, data pointer) pairs + 1 next-leaf pointerm(K + Pr) + P ≤ B
SolvedBlock size B = 1024 bytes, key K = 9 bytes, block pointer P = 6 bytes, data pointer Pr = 7 bytes. Find the orders.

B-tree: 6p + 16(p − 1) ≤ 1024 → 22p ≤ 1040 → p ≤ 47.27 → p = 47 (46 keys per node).
B+ internal: 6p + 9(p − 1) ≤ 1024 → 15p ≤ 1033 → p ≤ 68.87 → p = 68.
B+ leaf: 16m + 6 ≤ 1024 → m ≤ 63.6 → m = 63 keys per leaf.

The B+ internal node holds 68 children against the B-tree's 47: that's the bigger fan-out from 15.4, in numbers.
⚠️ Exam trap Always round the order down (a node can't hold a fraction of a pointer, and it must fit in the block). Check by substituting: p = 47 → 6·47 + 16·46 = 282 + 736 = 1018 ≤ 1024 ✅; p = 48 → 288 + 752 = 1040 > 1024 ❌.

➕ Added for exam: how much a few levels can hold With the B+ tree from 15.5 (internal fan-out 68, 63 keys per leaf), if every node is full:
  • Root: 68 children. Level 2: 68 × 68 = 4,624 children. Level 3 (leaves): 4,624 × 63 = 2,91,312 keys.
  • So about 3 lakh records can be found in 3 index block reads + 1 data block read. One more level takes it to about 2 crore.
That's why B+ trees are rarely more than 3–4 levels deep, even for huge tables.
🎯 IBPS exam alert Expect: "max keys in a B-tree node of order p" (p − 1), "min children of a non-root internal node" (⌈p/2⌉), "in which tree are all records at the leaf level?" (B+), "which supports range queries better?" (B+), and the node-order numerical from 15.5.

15.7Solved Exam QuestionsADDED

Q1A B-tree of order 5: maximum and minimum keys in a non-root node?
Answer: max 4, min 2 (⌈5/2⌉ − 1 = 2).
Q2Minimum number of children of the root of a B-tree (when it isn't a leaf)?
Answer: 2.
Q3In a B+ tree, data pointers are stored in:
Answer: leaf nodes only.
Q4Which property is common to B-trees and B+ trees? (a) linked leaves (b) all leaves at the same level (c) data in leaves only (d) keys repeated
Answer: (b). Both are balanced.
Q5B = 512 bytes, K = 10, P = 6. Order of a B+ tree internal node?
Answer: 32. 6p + 10(p − 1) ≤ 512 → 16p ≤ 522 → p ≤ 32.6.
Q6A B-tree grows in height when:
Answer: the root splits. B-trees grow upward, from the root.
Q7Why does a B+ tree usually have fewer levels than a B-tree for the same data?
Answer: its internal nodes have no data pointers, so they hold more keys (higher fan-out).

⚡ Rapid Revision

  • B-tree = self-balancing multi-level index; one node = one block; all leaves at the same level; grows upward via root splits.
  • Node: block pointers P, sorted keys K, data pointers Pr. q block pointers around q − 1 keys.
  • Order p = max children. Max keys p − 1. Non-root: min children ⌈p/2⌉, min keys ⌈p/2⌉ − 1. Root: min 2 children, min 1 key.
  • Order 4, insert 1–12 (left-biased split): splits at 4, 6, 8, 10 (root splits twice: at 4 and at 10), 12 → [4] / [2] [6,8,10] / [1] [3] [5] [7] [9] [11,12]. Right-biased gives [3,6,9] / [1,2] [4,5] [7,8] [10,11,12].
  • B+ tree: data pointers only in leaves, leaves linked, internal keys repeated in leaves. Higher fan-out, fast range queries. Leaf split copies the key up; internal split moves it.
  • Node orders: B-tree p·P + (p−1)(K+Pr) ≤ B; B+ internal p·P + (p−1)K ≤ B; B+ leaf m(K+Pr) + P ≤ B. Round down.
  • B = 1024, K = 9, P = 6, Pr = 7 → B-tree 47, B+ internal 68, B+ leaf 63.
  • ➕ 3 B+ levels at fan-out 68 hold ~3 lakh keys. B+ trees are the standard DBMS index.
