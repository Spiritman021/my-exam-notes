Chapter 10

Relational Algebra

Relational algebra is the formal query language behind SQL. Each operator takes one or two relations and returns a new relation, so operators can be chained like arithmetic. The joins of chapter 9 are just combinations of these operators. SQL queries are translated into relational algebra before the database runs them.

10.1Procedural vs Non-Procedural Languages; Basic and Derived Operators

🎓 Lecture topic (from outline)
  • Procedural: you say what you want and how to get it, as a sequence of steps. Relational algebra is procedural: the order of operators is the plan.
  • Non-procedural (declarative): you say only what you want; the system works out how. Relational calculus (chapter 11) is non-procedural, and so is SQL.

Basic (fundamental) operators: six

These can't be built from each other:

🎓 Lecture topic (from outline)

Derived operators

Built from the basic six, kept because they're convenient:
  • Intersection: R ∩ S = R − (R − S)
  • Joins (⋈, ⋈θ, outer joins): R ⋈θ S = σθ(R × S)
  • Division (÷): built in 10.5
  • Assignment (←): stores an intermediate result under a name
⚠️ Exam trap Intersection and join are not basic operators, even though they're used everywhere. If asked "which of these is not a fundamental operator?", the answer is usually ∩, ⋈ or ÷.

10.2Projection (π) and Selection (σ)

🎓 Lecture topic (from outline) Example table Student(Roll, Name, City, Marks): (1, Asha, Delhi, 82), (2, Ravi, Pune, 65), (3, Neha, Delhi, 74).

Selection σ: pick rows (horizontal)

σCity = 'Delhi'(Student) → rows 1 and 3, all four columns
  • The condition can use =, ≠, <, ≤, >, ≥ and combine with ∧ (and), ∨ (or), ¬ (not): σCity='Delhi' ∧ Marks>80(Student) → row 1.
  • Degree (columns) stays the same; cardinality (rows) can only stay the same or shrink.

Projection π: pick columns (vertical)

πCity(Student) → {Delhi, Pune}: 2 rows, not 3
  • Relational algebra works on sets, so projection removes duplicate rows. Delhi appears once.
  • Combine them: names of students from Delhi = πName(σCity='Delhi'(Student)) → {Asha, Neha}.
⚠️ Exam trap
  • π removes duplicates, but SQL's SELECT City FROM Student does not (it returns Delhi twice). π matches SELECT DISTINCT.
  • Don't mix up the symbols: σ (sigma) = selection = rows; π (pi) = projection = columns. SQL's SELECT clause is really π, and its WHERE clause is σ.
  • Order matters with π: πName(σCity='Delhi'(Student)) works, but σCity='Delhi'(πName(Student)) fails, because City is already gone.

10.3Union and Set Difference (Cricket and Hockey Tables)

🎓 Lecture topic (from outline) Two tables list the students in the cricket team and the hockey team:
CricketHockey
RollNameRollName
1Asha2Ravi
2Ravi4Karan
3Neha
🎓 Lecture topic (from outline)
  • Cricket ∪ Hockey = students who play at least one game → 1, 2, 3, 4. Ravi appears once (duplicates removed).
  • Cricket − Hockey = cricket but not hockey → 1, 3.
  • Hockey − Cricket = hockey but not cricket → 4. Difference is not commutative.
  • Cricket ∩ Hockey (derived) = both games → 2. Check: Cricket − (Cricket − Hockey) = {1,2,3} − {1,3} = {2} ✅

Union compatibility

∪, − and ∩ only work when the two relations are union compatible:
  1. the same number of attributes (same degree), and
  2. the i-th attribute of each has the same domain.
Cricket(Roll, Name) and Hockey(Roll, Name) qualify. Cricket(Roll, Name) and Fees(Roll, Amount) don't: Name and Amount have different domains.

R ∪ Smax(m, n)m + n
R ∩ S0min(m, n)
R − S0m

10.4Cross Product and Rename (ρ) (Student → Alumni)

🎓 Lecture topic (from outline)

Cross product ×

Same as chapter 9: R × S pairs every row of R with every row of S. Rows multiply (m × n), columns add. The two relations do not need to be union compatible.

Rename ρ

ρ gives a relation, or its attributes, a new name. It changes no data.
  • ρAlumni(Student): the same table, now called Alumni.
  • ρAlumni(R, N, C, M)(Student): renames the table and all four attributes.
Why we need it: when a table is combined with itself (a self join), both copies would have identical column names. Renaming one copy lets you tell Student.Marks from Alumni.Marks.
➕ Added for exam: highest marks with no MAX function Relational algebra has no aggregate functions in its basic form, but rename makes "highest" possible:
  1. T = ρT(Roll2, Marks2)(πRoll, Marks(Student))
  2. Marks that are beaten by someone: Lower = πMarks(σMarks < Marks2(Student × T))
  3. Highest = πMarks(Student) − Lower
With marks 82, 65, 74: Lower = {65, 74}, so Highest = {82} ✅. This "find the losers, subtract them" pattern is a favourite exam question.

10.5Division and Building It from Basic Operators — Solved

🎓 Lecture topic (from outline) Division answers "for all" questions: which students have taken every course? For R(A, B) ÷ S(B), the result is the A values that are paired in R with every B value in S.

Example: Enrol ÷ Course

Enrol(Roll, Course)Course
1DBMSDBMS
1OSOS
2DBMS
3DBMS
3OS
3CN
🎓 Lecture topic (from outline) Roll 1 has DBMS and OS ✅. Roll 2 is missing OS ❌. Roll 3 has both, and an extra CN that doesn't matter ✅. Enrol ÷ Course = {1, 3}.

Building ÷ from the basic operators

Idea: work out every pair that should exist, find the ones that are missing, and remove the students who have a missing pair.
  1. All students: πRoll(Enrol) = {1, 2, 3}
  2. Every pair that should exist: πRoll(Enrol) × Course = (1,DBMS), (1,OS), (2,DBMS), (2,OS), (3,DBMS), (3,OS)
  3. Missing pairs: step 2 − Enrol = {(2, OS)}
  4. Students with a missing pair: πRoll(step 3) = {2}
  5. Answer: step 1 − step 4 = {1, 3} ✅
R ÷ S = πA(R) − πA( (πA(R) × S) − R )
➕ Added for exam
  • Keywords "all", "every" or "each" in a query point to division.
  • Result attributes = attributes of R that are not in S. Degree of R ÷ S = degree(R) − degree(S).
  • SQL has no division operator; it's written with a double NOT EXISTS ("there is no course this student hasn't taken").

10.6Equivalence Rules and Writing QueriesADDED

➕ Added for exam The query optimizer rewrites algebra into an equivalent, cheaper form. The rules you're most likely to be asked about:
  • Cascade of σ: σc1 ∧ c2(R) = σc1(σc2(R))
  • σ is commutative: σc1(σc2(R)) = σc2(σc1(R))
  • Cascade of π: πA(πA,B(R)) = πA(R). Only the outermost projection matters.
  • ∪, ∩, × and ⋈ are commutative and associative; − is neither.
  • Push selections down: σc(R ⋈ S) = σc(R) ⋈ S when c uses only R's attributes. Filtering early makes the join smaller.

Names of students enrolled in DBMSπName(Student ⋈ σCourse='DBMS'(Enrol))
Rolls in DBMS but not OSπRoll(σCourse='DBMS'(Enrol)) − πRoll(σCourse='OS'(Enrol))
Rolls enrolled in every courseEnrol ÷ Course
🎯 IBPS exam alert Expect: matching a symbol to its operator (σ, π, ρ, ÷), "which is a unary operator?" (σ, π, ρ), "which needs union compatibility?" (∪, −, ∩), counting rows/columns of a result, and "which query does this expression answer?".

10.7Solved Exam QuestionsADDED

Q1Relational algebra is a ____ language.
Answer: procedural. Relational calculus is non-procedural.
Q2Which is not a fundamental operator? (a) σ (b) ρ (c) ∩ (d) ×
Answer: (c) ∩. It's derived: R ∩ S = R − (R − S).
Q3Which operator selects columns? (a) σ (b) π (c) ρ (d) ×
Answer: (b) π (projection).
Q4R has 5 rows, S has 3 rows, and they are union compatible. Max rows in R ∪ S and R ∩ S?
Answer: 8 and 3.
Q5R(A, B, C) ÷ S(C) has which attributes?
Answer: A, B (R's attributes not in S).
Q6Which operator is needed to join a relation with itself?
Answer: rename (ρ), so the two copies have distinct names.
Q7"Find the suppliers who supply all parts" uses which operator?
Answer: division (÷).
Q8Is R − S = S − R?
Answer: No, set difference is not commutative (Cricket − Hockey = {1, 3}, Hockey − Cricket = {4}).

⚡ Rapid Revision

  • Relational algebra = procedural (what + how). Relational calculus and SQL = non-procedural (what only).
  • Six basic operators: σ, π, ρ (unary) and ∪, −, × (binary). Derived: ∩, ⋈, ÷, ←.
  • σ picks rows (SQL WHERE); π picks columns and removes duplicates (SQL SELECT DISTINCT).
  • ∪, −, ∩ need union compatibility: same degree, matching domains. Cricket ∪ Hockey = 1,2,3,4; Cricket − Hockey = 1,3; ∩ = 2.
  • R ∩ S = R − (R − S). Difference is not commutative.
  • ×: rows multiply, columns add. ρ renames (Student → Alumni), needed for self joins.
  • ➕ Highest value without MAX: π(R) − π(values beaten in R × ρ(R)).
  • ÷ = "for all": Enrol ÷ Course = students in every course. R ÷ S = πA(R) − πA((πA(R) × S) − R).
  • ➕ Optimizer rules: cascade σ and π, push selections below joins; ∪, ∩, ×, ⋈ commute, − doesn't.
