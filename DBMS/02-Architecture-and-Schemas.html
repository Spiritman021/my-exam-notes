Chapter 2

DBMS Architecture and Schemas

A database is useless if nobody can reach it, and dangerous if everybody can reach all of it. This chapter looks at the structure around the data from two angles. The tier architecture is about the network: how many layers sit between the user's machine and the database server. The three-schema architecture is about abstraction: how the same data is described for end users, for the database designer and for the disk, so that a change at one level does not break the others.

2.12-Tier Client-Server Architecture (Bag of Gold Left on the Road)

🎓 From the lecture University exams ask for these architectures with a diagram, so know what to draw, which points to write and how to explain each one.
  • The 2-tier architecture is also called the client-server architecture. It has two tiers: the client tier with client machines C1, C2, C3…, and the data tier with the database server.
  • Working: each client machine has a basic interface. The client sends a query for the data it needs, and it is directly connected to the DB server. The server accepts the query, processes it (to understand what the client is asking for), then sends the data back as a response. It does the same for C1, C2, C3 and every other client; nobody gets special treatment.
  • Problem 1, slow: with 2–5 clients it works fine. At a large scale, many clients send requests at the same time, and the server must process each, respond, then take the next. That introduces a delay factor, and users experience slowness.
  • Problem 2, weak security: the client is in direct contact with the database. It is like leaving a 1-ton bag of gold on the road in public. Not everyone will steal it, but someone surely will take advantage. Data is "no less than gold", and any machine can exploit that direct connection.
➕ Added for exam
  • 1-tier architecture: the user works directly on the DBMS on the same machine, e.g. a developer running MySQL locally or an MS Access file on a desktop. No network is involved.
  • In 2-tier, the client talks to the database through APIs such as ODBC (Open Database Connectivity) and JDBC (Java Database Connectivity). The application logic sits on the client, which is called a fat (thick) client.
  • 2-tier advantages: simple, easy to build and maintain, fast for a small number of users. Typical use: a small office application on a LAN.

2.23-Tier Architecture: Client, Business Logic and Data Tiers

🎓 From the lecture The 3-tier architecture removes both disadvantages by adding a middle layer:
  • Client tier: client machines (your laptop, a web application).
  • Business tier, also called the middleware or logic tier.
  • Data tier: the database server.
Working: the client is not in direct contact with the database at all. You open a web app on your laptop and request some data. The query goes to the business layer, which has "taken the contract" for processing. It understands and processes the query, then puts a plain, straightforward request to the DB: "please give us this". The DB server returns the data to the business layer, which sends it to client C1 in the form C1 expects.
  • In 2-tier, the DB did the processing. In 3-tier, the DB is freed from it and only serves data.
  • However many client machines you add, the business layer handles them; the load is not on the DB server. So it is faster.
  • No direct contact also makes it more secure.

➕ Added for exam In web terms, the three tiers are the presentation tier (browser/UI), the application tier (web or application server running business logic, e.g. Java, Python, Node.js) and the data tier (RDBMS). 3-tier disadvantages: more complex to build, more components to maintain, and a little extra latency from the extra hop. Splitting further gives n-tier architecture.
⚠️ Exam trap "Client-server architecture" in DBMS questions means the 2-tier architecture. In 3-tier the end user does not know the database exists; the application server is what the client talks to.

2.3Schema vs Instance

🎓 From the lecture
  • Schema: the logical representation of your data; in other words, the blueprint of your database: its framework (dhaancha), structure, skeleton. It answers many questions: how the data is organised and arranged, which tables (relations) exist, which columns they have, their names, their types and the constraints imposed on them. To implement a schema you use SQL (Structured Query Language). This applies to relational DBMS, where there are relations (tables) and relationships between them.
  • Instance: the information present in the database at a given moment. Whatever data is currently stored right now is the instance.
  • The difference between schema and instance is asked very often.

MeaningLogical structure / blueprint of the databaseData stored at a particular moment

Analogy ➕Variable declaration in a program (int x;)Value of the variable at a moment (x = 5)
➕ Added for exam Schemas exist at three levels, matching the three-schema architecture below: physical schema (internal), logical schema (conceptual) and view schema / subschema (external). A database has one physical and one logical schema but can have many subschemas (views). The schema description is stored in the data dictionary as metadata.
⚠️ Exam trap Schema = intension; instance = extension. Memory hook: intension is like the int declaration (structure), extension is the data that exists right now.

2.4Three-Schema Architecture: External, Conceptual, Internal (School Records Views)

🎓 From the lecture Three schemas, i.e. three layers:
  1. External schema / external layer: the place of views. Different users should see the same data differently (as with the file-system security problem in chapter 1).

    Example: school records

    • A student sees their own profile data: name, surname, mobile number, hobbies, class, percentage, pass or fail.
    • Teachers also get write access to students' academic records, to enter marks. Give that same access to a student and they would enter "100, 100, 100…" and pass everything. That is why views are generated in the external layer.
    • The administration sees its own view, and the admin can access all the data.
    So View 1 is for User 1, View 2 for User 2, View 3 for User 3.
  2. Conceptual schema / conceptual layer: sits between the external and internal layers. This is where the ER diagram belongs: how the database is designed, what goes in and what does not, which relations and tables exist, how many columns, their data types, and which constraints and restrictions apply.
  3. Internal schema / internal layer: the back-end layer, in direct connection with the database. It describes how the data is physically stored in the database.

Who owns each layer

  • External layer (application interface): developers.
  • Conceptual layer: the database designer, who decides the tables, columns, types and constraints.
  • Internal layer: the database administrator (DBA), closest to the database with the most control. The DBA decides which methods and protocols are used to store the actual data.
➕ Added for exam
  • This is the ANSI/SPARC architecture (proposed 1975). Its levels are also called the view level (external), logical level (conceptual) and physical level (internal).
  • The DBMS translates requests between levels through mappings: external/conceptual mapping and conceptual/internal mapping. Data independence comes from these mappings: when a lower level changes, only the mapping is updated.
  • Number of schemas: many external schemas, exactly one conceptual schema and exactly one internal schema per database.
  • The internal level deals with storage space allocation, record placement, access paths (indexes, hashing), compression and encryption.
  • The main objective of the architecture is to separate each user's view from the way the data is physically stored.
⚠️ Exam trap The DBA is formally responsible for the whole database (schema definition, storage structures, access permissions, backup and recovery), but in the layer-ownership picture the DBA is tied to the internal level. Views (and security through views) belong to the external level; table design (ER) belongs to the conceptual level.

2.5Data Independence: Physical and Logical

🎓 From the lecture Data independence means layer-wise independence: if I change something in a lower layer, the higher layers should feel no impact. They should keep working as before, without any error, problem or obstacle. The change stays confined to that layer. There are two types:
  • Physical (internal) data independence: works between the internal and conceptual layers. Changes in the internal schema should not propagate up to the conceptual layer; it should not even "get a hint" (bhanak) of them.
  • Logical (conceptual) data independence: works between the conceptual and external layers. If you change the design (a table, a column, a type) in the conceptual layer, the impact should not show in the views, to the users, or in the application interface and programs.

➕ Added for exam Data independence is the capacity to change the schema at one level without changing the schema at the next higher level. It is the biggest advantage of DBMS over the file system, where programs depend on the exact file format (data dependence). Not every logical change can be hidden: dropping a column that a view uses will still break that view.
🎯 IBPS exam alert Two classic one-liners: "Adding an index without changing application programs is an example of physical data independence." "Adding a new attribute to a table without rewriting existing programs is an example of logical data independence." And: "Which data independence is harder to achieve?" → Logical.

2.6Solved Exam QuestionsADDED

Q1In which architecture does the client communicate directly with the database server? (a) 1-tier (b) 2-tier (c) 3-tier (d) n-tier
Answer: (b) 2-tier (client-server).
Q2In a 3-tier architecture, business rules are placed in the: (a) client tier (b) application/middle tier (c) data tier (d) storage tier
Answer: (b) Application (middle) tier.
Q3The overall design of a database is called the ____, and the data in it at a given moment is called the ____.
Answer: schema; instance.
Q4Which level of the three-schema architecture describes how data is actually stored? (a) External (b) Conceptual (c) Internal (d) View
Answer: (c) Internal (physical level).
Q5How many conceptual schemas can a database have?
Answer: Exactly one. It can have many external schemas (views).
Q6The DBA moves a table to a faster disk and builds a new index; no query or program needs changing. This shows:
Answer: Physical data independence.
Q7A column "email" is added to CUSTOMER; old reports keep working. This shows:
Answer: Logical data independence.
Q8Schema is also known as: (a) extension (b) intension (c) snapshot (d) state
Answer: (b) Intension. The other three describe an instance.

⚡ Rapid Revision

  • 2-tier = client-server; client tier (C1, C2, C3) directly connected to the DB server; DB processes every query. Slow at scale (delay factor) and insecure (1-ton bag of gold on the road).
  • 3-tier = client + business/middleware/logic + data. Business tier processes queries; DB only serves data. No direct contact → faster and more secure.
  • ➕ 1-tier = DBMS on the same machine. 2-tier uses ODBC/JDBC, fat client. 3-tier = thin client (browser), e.g. net banking.
  • Schema = logical representation / blueprint (tables, columns, types, constraints), implemented with SQL; ➕ intension, rarely changes. Instance = data at a given moment; ➕ extension / state / snapshot.
  • Three-schema: External (views per user; school: student, teacher, admin; owned by developers) → Conceptual (design, ER; DB designer) → Internal (physical storage; DBA). ➕ ANSI/SPARC; one conceptual + one internal, many external.
  • Data independence: change at a lower layer must not affect higher layers. Physical = internal → conceptual (new index, new disk). Logical = conceptual → external (new column, split table); ➕ harder to achieve.
