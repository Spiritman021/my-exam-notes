Chapter 12

File Systems

Chapter 11 showed the disk as raw tracks and sectors. Users never see sectors; they see files (documents, songs, videos, images). The file system is the OS layer that turns files into sectors and back: it decides where each piece of a file goes on disk, how to find it again quickly, and how to avoid wasting space.

12.1Introduction to File Systems and Block-Sector Mapping

File: a named collection of related information stored on secondary storage. It is the smallest unit of logical storage from the user's point of view.
File system: the part of the OS that organises, stores, retrieves, names and protects files on a storage device.
🎓 From the lecture The file system is an integral part of every OS. For a user, everything appears as a file: a doc, audio, video or image. Internally, the file's data is divided into blocks (block 1, 2, 3 …) and each block is mapped onto disk sectors, where the data actually resides. This is block–sector mapping. To store, write into those sectors; to fetch, access the same sectors.
➕ File-system layers (Galvin) Application programs → logical file system (metadata, directories, the FCB, protection) → file-organisation module (logical block → physical block, free-space manager) → basic file system (generic block reads and writes, buffers) → I/O control (device drivers, interrupts) → devices.
File Control Block (FCB): the per-file structure holding its attributes and block locations. In UNIX it is the inode; in NTFS it is an entry in the MFT (Master File Table).

🎓 Truncate and Reposition (lecture) Truncate: the old data is "udaa diya" (wiped). The file now looks empty, but you can still write new data into it. Reposition: the read/write pointer is at byte x of the data x, y, z…; reposition it to z so that reading starts from there.
⚠️ Exam trap Truncate keeps the file's attributes (name, permissions, creation time). Only the length becomes 0. Delete removes the file entirely. The lecture's wording blurs the two at one point. Also, the OS keeps per-process and system-wide open-file tables, with a file pointer, an open count, the disk location and access rights.

12.4File Allocation Methods: Contiguous vs Non-Contiguous

Allocation method: how the blocks of a file are placed onto disk blocks or sectors. The three methods are contiguous, linked and indexed.
🎓 From the lecture A file is split into blocks 0, 1 and 2. In contiguous allocation they go to adjacent sectors (0, 1, 2). In non-contiguous allocation each block can go anywhere. Any method has two goals:
  1. Good disk utilisation: don't waste space. Avoid external fragmentation, where space is available but can't be used.
  2. Fast access: "fast & furious" storing and fetching.

12.5Contiguous Allocation

Contiguous allocation: each file occupies a set of consecutive blocks. The directory entry stores only (start block, length).
Directory: fileStartLengthBlocks
X050–4
Y101010–19
Z20520–24
🎓 From the lecture Only the start and the length are needed, because the rest follows in sequence. It is easy and fast:
  • Sequential access: start at block 0 and read 0 → 4 in order.
  • Direct / random access: block 2 of X = start + 2 = disk block 2. Jump straight there.
Formula (added)
Physical block of logical block i = start + i (valid if i < length)
X: logical block 3 → 0 + 3 = block 3. Y: logical block 7 → 10 + 7 = block 17. Each takes one disk access.

12.6External Fragmentation in Contiguous Allocation

🎓 From the lecture A new file A must start at block 7 with length 5. Blocks 7, 8 and 9 are free, but block 10 belongs to Y. The remaining 2 blocks can't be placed in the free region at 25–28, because "you can't break and place; it's contiguous." Space is available but the file can't be stored: external fragmentation. If A had been allowed to start at block 5, blocks 5–9 would have fit.
➕ Other problems of contiguous allocation
  • File growth: if a file needs to grow but the next block is taken, it must be moved, or space must be over-allocated in advance (internal waste).
  • Size must be known at creation time.
  • Placement uses first fit, best fit or worst fit (Chapter 9), and compaction (defragmentation) fixes fragmentation but is slow.
  • Extents (used by ext4 and NTFS): a modified contiguous scheme in which a file is a list of contiguous chunks.
  • CD-ROMs and DVDs use contiguous allocation (the files never change).

12.7Linked List Allocation

Linked allocation: each file is a linked list of disk blocks that may be scattered anywhere. Each block holds a pointer to the next block. The directory stores the start and end blocks.
🎓 From the lecture Directory: X, start = 5, end = 24. Block 5 holds the first block of X and says "next is 11". Then 11 → 15 → 12 → 18 → 24. At 24 the file ends. The list itself is the "hero": each block tells you where the next one is.
  • ✔ No external fragmentation, because any free block can be used.
  • ✗ High seek time: the blocks are scattered across tracks, so the read/write head gets a lot of "exercise". To avoid external fragmentation you compromise on seek time.
➕ More disadvantages, and FAT
  • No direct (random) access: to reach block i you must follow i pointers from the start. Only sequential access is efficient.
  • Pointer overhead: e.g. 4 bytes of each 512-byte block (0.78%) is spent on pointers. Clusters (groups of blocks) reduce it.
  • Reliability: one damaged pointer loses the rest of the file.
  • FAT (File Allocation Table): the pointers are kept in a table at the start of the partition, with one entry per block, instead of inside the blocks. The table can be cached in memory, which makes random access faster. Used by MS-DOS, FAT16/FAT32, USB drives.
Numerical (added) The disk block is 1 KB and a pointer is 4 B, so usable data per block = 1020 B.
A file of 10,200 B needs 10,200 / 1020 = 10 blocks.
To read byte 5000: 5000 / 1020 = logical block 4 (0-based), so 5 block reads are needed to follow the chain. Contiguous allocation would need just 1.

12.8Indexed Allocation

Indexed allocation: all of a file's block pointers are gathered into one index block. Entry i of the index block points to the file's i-th block. The directory stores the index-block address.
🎓 From the lecture Directory: X → index block 5. Block 5 doesn't hold data; it lists where every block of X is: 1, 7, 30, 11, 16.
  • ✔ No external fragmentation (non-contiguous).
  • ✔ Easy random access: the index tells you exactly where each block is, so jump straight there.
➕ Disadvantages and remedies
  • Index-block overhead: even a 2-block file needs a whole index block, which is wasted space for small files.
  • The size of the index block limits the file size. Remedies: a linked scheme (chain index blocks together), a multilevel index (an index of index blocks), or the combined scheme (UNIX inode, next section).
  • Access costs one extra read for the index block, unless it is cached.

12.8AMultilevel Index & UNIX inode ADDED

Numerical: maximum file size with an inode Block size = 4 KB, pointer = 4 B, so each index block holds 4 KB / 4 B = 1024 pointers.
Direct: 12 × 4 KB = 48 KB.
Single indirect: 1024 × 4 KB = 4 MB.
Double indirect: 1024² × 4 KB = 4 GB.
Triple indirect: 1024³ × 4 KB = 4 TB.
Maximum file size ≈ 48 KB + 4 MB + 4 GB + 4 TB ≈ 4 TB.
Conclusion: small files are reached quickly through the direct pointers, and huge files are still possible through the indirect levels.
Variant (practice) Block = 1 KB, pointer = 4 B, so 256 pointers per block. With 10 direct pointers plus single and double indirect: 10 KB + 256 KB + 64 MB ≈ 64.26 MB.

12.10Free-Space Management ADDED

MethodHowNote

Numerical: bitmap size Disk = 1 TB, block = 4 KB, so blocks = 2⁴⁰ / 2¹² = 2²⁸.
The bitmap needs 2²⁸ bits = 2²⁵ bytes = 32 MB.
Example: blocks 2, 3, 4, 5, 8, 9, 10 are free in a 12-block disk, so the bitmap (blocks 0–11) is 0011 1100 1110.

12.11Protection, Links, Mounting & Real File Systems ADDED

UNIX file protection (rwx)

Three classes, owner (u), group (g), others (o), each with read (4), write (2), execute (1) permissions.

Numerical: chmod chmod 754 file → owner 7 = rwx (4+2+1), group 5 = r-x (4+1), others 4 = r-- → rwxr-xr--.
chmod 644 → rw-r--r-- (typical for files). chmod 755 → rwxr-xr-x (typical for programs and directories).
Other mechanisms: access-control lists (ACLs) per file and per user, and passwords.

🎯 IBPS exam alert (one-liners)
  • Contiguous allocation causes external fragmentation but has the best seek time and direct access. Linked allocation has no random access; FAT is its table form. Indexed allocation supports random access and is used by the UNIX inode.
  • Maximum file size in FAT32 = 4 GB. A journaling file system (NTFS, ext3/4) logs changes first, which makes recovery after a crash fast.
  • The default permissions of a new file come from the umask (e.g. 022 gives 644 for files).

12.12Protection Domains & the Access Matrix (ACL vs Capability List) ADDED

Principle of Least Privilege: a process, user or program is given exactly the privileges it needs to do its task, and nothing more. A bug or attack can then do only limited damage.
  • A system is a set of processes (subjects) and objects (files, printers, memory segments).
  • Access right = an ordered pair <object, {rights}>, e.g. <File X, {read, write}>.
  • Domain = a set of access rights. It specifies exactly which objects a process may touch and how. A domain can be a user, a process or a procedure.

Access matrix

Conceptually the OS keeps one global matrix: rows = domains (users / processes), columns = objects, and cell (i, j) = the rights domain i has on object j.

Domain ↓ / Object →File 1File 2Printer 1
D1 (User A)read, writeread—
D2 (User B)—read, write, executeprint
D3 (Admin)read, write, deleteread, write, deleteprint, config

The full matrix is huge and mostly empty, so it is never stored as-is. It is sliced by column or by row:

BasisAccess Control List (ACL)Capability List
Slice of the matrixColumn (one per object)Row (one per domain)
Attached toThe object (file): "who may access me?"The domain / process: "what may I access?"
AnalogyGuest list at the doorKeyring held by the user
Revoking a rightEasy: edit the object's listHard: capabilities are scattered across domains

🎯 IBPS exam alert Column-wise = ACL (stored with the object). Row-wise = Capability list (stored with the domain). The rule "give only the minimum rights needed" is the Principle of Least Privilege.

⚡ Rapid Revision — Chapter 12

  • File system: maps a file's blocks → disk sectors (block–sector mapping) for storing and fetching. The FCB holds the metadata (the UNIX inode).
  • Operations: create, read, write, truncate (empty the contents, keep the file), reposition (move the pointer x → z), delete, open, close.
  • Attributes: name, identifier, type, location, size, protection, time and date (from "Get Info").
  • Access methods: sequential, direct, indexed (ISAM).
  • Contiguous: directory = (start, length). X(0, 5), Y(10, 10), Z(20, 5). Fast sequential and direct access (start + i). External fragmentation: file A(7, 5) can't fit even though blocks 25–28 are free.
  • Linked: directory = (start, end). X: 5 → 11 → 15 → 12 → 18 → 24. No external fragmentation, but high seek time, no random access, pointer overhead. FAT keeps the pointers in a table.
  • Indexed: directory = index block (5) → [1, 7, 30, 11, 16]. No external fragmentation, easy random access; index-block overhead. The UNIX inode has 12 direct + single, double and triple indirect pointers (4 KB blocks give about 4 TB maximum).
  • Directories: single-level → two-level → tree → acyclic graph → general graph. Free space: bitmap (1 TB / 4 KB → 32 MB), linked list, grouping, counting.
  • Protection: rwx = 4/2/1 (754 = rwxr-xr--). Hard link = same inode; soft link = a path (can dangle). FAT32 has a 4 GB limit; NTFS and ext4 use journaling.
  • Access matrix: rows = domains, columns = objects. Column slice = ACL (with the file); row slice = capability list (with the process, a "keyring"). Least privilege = only the minimum rights needed.
