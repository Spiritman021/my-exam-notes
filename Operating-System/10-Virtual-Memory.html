Chapter 10

Virtual Memory

Chapter 9 ended with demand paging: load a page only when it is needed, and if it is missing, take a page fault and fetch it. This chapter builds on that idea. If only part of a process needs to be in RAM, a process can be bigger than RAM, and many more processes can share RAM. That raises three questions: how many frames each process gets, which page to evict when RAM is full, and what happens when we overdo it (thrashing).

10.1Concept of Virtual Memory (Real-Life Example)

Virtual memory: a technique that lets a process execute without being completely in main memory. Only the needed pages are loaded; the rest stay on disk. It gives the user the illusion of a memory much larger than the physical RAM.
🎓 From the lecture — The 80 kg feast You are very hungry and in front of you lie 10 kg gulab jamun, 10 kg rasgulla, 10 kg kaju katli and 50 kg of samosa and vada pav: 80 kg in all. Your stomach (RAM) holds maybe 2–3 kg. You can't eat it all at once, so you take a few pieces of each now, a few more tomorrow, and so on, as per your need. Later you tell everyone "I ate all of it!" That is an illusion. That is virtual memory.

In OS terms: a huge process (the 80 kg), small RAM (the stomach). Load only pages 0, 3, 6 and 9 into frames 1, 2, 3 and 4. In the page table, those entries have present bit = 1; all the others have 0 (on disk). The user believes the whole process is in memory.

➕ Benefits and implementation
  • Programs can be larger than physical memory, and programmers needn't worry about memory limits.
  • More processes fit in RAM, so CPU utilisation and throughput rise.
  • Less I/O for loading and swapping, because only the needed pages move.
  • Easy sharing of libraries and memory, and fast process creation through copy-on-write.
  • Implemented by demand paging (most common) or demand segmentation. The virtual address space is managed by the OS together with the MMU.

10.2Virtual Memory and Degree of Multiprogramming

🎓 From the lecture There are 100 processes, each with 10 pages, so 1000 pages in all, but RAM has only 100 frames. Without virtual memory, only about 10 whole processes fit. With virtual memory, load one page of each process: all 100 processes are in memory at once. The degree of multiprogramming rises, and so does CPU utilisation. But this also brings problems, which leads to thrashing (10.12).

10.3Page Fault Handling, Victim Page and Dirty Bit

🎓 From the lecture
  1. The CPU wants page 2, but its present bit = 0, so there is a page fault.
  2. Control goes to the OS, which fetches page 2 from secondary memory.
  3. If a free frame exists, put it there.
  4. If no frame is free (pages 0, 1, 2 occupy everything and page 3 must come in), pick a victim page to evict.
  5. Check the victim's dirty bit:
    • Dirty = 0: the page was not modified, so just discard it. Its copy on disk is still valid.
    • Dirty = 1: it was modified ("khilwaad hua hai"), so write it back to disk first. Otherwise consistency is ruined.
➕ Why the dirty bit matters Without it, every replacement would need two disk transfers (one out, one in). With it, clean pages need only one, which halves the page-fault service time for clean victims. Read-only code pages are never dirty.

10.4Frame Allocation (Minimum and Maximum Pages)

Frame allocation: deciding how many frames (pages in RAM) each process gets.
🎓 From the lecture — two extremes
  • Minimum: the number of pages needed to execute a single instruction. If instruction i1 needs pages P1 and P2 (e.g. the operand is in another page), both must be in RAM, because an instruction is atomic and can't run half-way.
  • Maximum: all the pages of the process (the whole process in RAM).
➕ Why there is a minimum The minimum is defined by the instruction-set architecture. Example: a memory-to-memory MOVE whose operands straddle page boundaries may need up to 6 frames. With fewer frames than the minimum, the process faults forever and never finishes the instruction. The maximum is bounded by the total frames available.

10.5Equal Frame Allocation

Formula and numerical (lecture)
Frames per process = m / n (m = total frames, n = number of processes)
m = 60 frames. P1 = 20 pages, P2 = 100 pages, P3 = 100 pages.
Each gets 60 / 3 = 20 frames.
Result: P1 is 100% loaded (all 20 pages), but P2 and P3 get only 20% of their pages.
Conclusion: equal allocation is simple but shows "partiality" (unfairness): small processes get too much and big ones too little.

10.6Weighted (Proportional) Frame Allocation

Formula and numerical (lecture)
aᵢ = (sᵢ / S) × m (sᵢ = pages of process i, S = Σ sᵢ, m = total frames)
m = 10 frames. P1 = 30, P2 = 40, P3 = 30 pages, so S = 100.
P1 = 30/100 × 10 = 3 · P2 = 40/100 × 10 = 4 · P3 = 30/100 × 10 = 3. Total 3 + 4 + 3 = 10 ✔.
Conclusion: each process gets frames in proportion to its size.
Numerical (added, Galvin) m = 62 frames; P1 = 10 pages, P2 = 127 pages, so S = 137.
a₁ = 10/137 × 62 ≈ 4, a₂ = 127/137 × 62 ≈ 57 (round down; leftover frames go to a free pool).
Equal allocation would give 31 each, so P1 would waste 21 frames.
➕ Priority allocation Allocate in proportion to priority (or size and priority combined). A high-priority process that faults may take frames from lower-priority processes.

10.7Page Replacement Algorithms: FIFO

Page replacement: when a page fault occurs and no frame is free, choose a victim page to evict. The goal is the lowest page-fault rate.

FIFO (First-In First-Out): replace the page that was brought into memory earliest, the oldest page. Implemented with a FIFO queue.
🎓 From the lecture "Whoever came first goes out first." The page that entered first is replaced so a new page can be placed. The first few references always fault because the frames start empty (compulsory or cold-start misses).

10.9Belady's Anomaly

Belady's anomaly: for some reference strings, increasing the number of frames increases the number of page faults. It occurs with FIFO.
🎓 From the lecture Normally we expect "more frames → fewer page faults" (3 → 10 → 100 frames). But with FIFO there is a possibility that adding frames makes the page-fault count go up. It doesn't happen every time, but it can.

➕ Who suffers, who doesn't Stack algorithms never show Belady's anomaly. In a stack algorithm, the set of pages in memory with n frames is always a subset of the set with n + 1 frames. LRU and Optimal are stack algorithms, so they are immune. FIFO (and Second-Chance, which is FIFO-based) is not.

10.10Optimal Page Replacement

Optimal (OPT / MIN) algorithm: replace the page that will not be used for the longest time in the future. It gives the lowest possible page-fault rate for a fixed number of frames.
🎓 From the lecture — "Think of the future" At the fault on 1, look ahead: 7 and 6 will be needed soon, but 4 never appears again, so evict 4. At the fault on 2, look ahead: 7 comes next, so keep it. Neither 1 nor 6 appears again, so evict either one; the lecture evicts 1.

⚠️ Exam trap Optimal is impossible to implement in a real OS, because the future reference string is unknown. It is used as a benchmark to measure how good other algorithms are. Like SJF in CPU scheduling, it is optimal but impractical.

10.11LRU Page Replacement

LRU (Least Recently Used): replace the page that has not been used for the longest time in the past. It uses the recent past as a predictor of the near future (locality).
🎓 From the lecture — "Look at the past" At the fault on 1, look back: 6 was used most recently, 7 before it, and 4 longest ago, so evict 4. At the fault on 2: 1 is the most recent, then 6, and 7 the oldest, so evict 7. But 7 is needed immediately afterwards ("if we had looked ahead…"), so it faults again. Then 2 is the most recent, 1 is older and 6 the oldest, so evict 6. The reference bit of the PTE helps track recent use.

➕ How LRU is implemented (both need hardware)
  • Counters / time-stamps: each PTE stores the time of last use, and the page with the smallest time is replaced. Finding it requires a search.
  • Stack: keep a doubly-linked stack of page numbers. A referenced page moves to the top, so the bottom is the LRU page. No search is needed, but every reference updates the stack.
Because exact LRU is costly, OSs use LRU approximations (next section).

10.11ALRU Approximations, LFU, MFU & Comparison ADDED

AlgorithmIdea
Reference-bit algorithmHardware sets R = 1 on access; the OS periodically clears it. Replace a page with R = 0. With extra history bits (shift registers), this is the "additional reference bits" algorithm.
Second-Chance (Clock)FIFO plus the reference bit. The pages form a circular queue with a "clock hand". If the hand's page has R = 1, clear it to 0 (give it a second chance) and move on. Replace the first page with R = 0. If all bits are 1, it degenerates to FIFO.
Enhanced Second-Chance (NRU)Uses the pair (reference, dirty). Order of preference for the victim: (0,0) not used and clean → (0,1) → (1,0) → (1,1) used and dirty.
LFU (Least Frequently Used)Replace the page with the smallest use count. Problem: a page heavily used early on stays forever. Fix by decaying the counts.
MFU (Most Frequently Used)Replace the page with the largest count, on the argument that a small count means the page was just brought in. Rarely used.
Page bufferingKeep a pool of free frames, so the faulting page is read in before the victim is written out.

10.12Thrashing

Thrashing: a state in which the system spends more time paging (swapping pages in and out) than executing. Page faults occur so often that CPU utilisation collapses.
🎓 From the lecture Raising the degree of multiprogramming (DoM) improves CPU utilisation, but each process then gets only a few pages, so the chance of page faults rises. After a certain peak, CPU utilisation starts falling: that is thrashing.

Example: 4 processes P1 to P4 and 4 frames. To maximise DoM, load page 1 of each process. Now the CPU wants P1's page 2: fault. P2's page 2: fault. P3's page 3: fault. "Page fault after page fault after page fault." The CPU sits idle while the disk works.

Lecture's remedy: look at the past requests the CPU made for each process, and keep those pages in memory. (This is the idea behind the working-set model, below.)

➕ The vicious cycle (Galvin) Faults rise, so processes wait on the paging disk, so CPU utilisation drops. The long-term scheduler sees low utilisation and admits more processes, which steal even more frames, so there are even more faults. Utilisation collapses.
Root cause: the total size of all processes' current localities exceeds the total memory (Σ localities > m).
Fixes: reduce the degree of multiprogramming (suspend or swap out processes through the medium-term scheduler), use local replacement, the working-set model, page-fault frequency control, or add RAM.

10.12AWorking Set & Page-Fault Frequency ADDED

Locality model: a process moves from one locality (a set of pages actively used together, such as a function and its data) to another. To avoid thrashing, give each process enough frames for its current locality.

Working set WS(t, Δ): the set of distinct pages referenced in the most recent Δ references (the working-set window).
Numerical: working set Reference string ending at time t₁: … 2 6 1 5 7 7 7 7 5 1, with Δ = 10.
WS(t₁) = distinct pages among the last 10 = {1, 2, 5, 6, 7}, so WSS = 5.
Later the references are … 3 4 4 4 3 4 3 4 4 4, so WS(t₂) = {3, 4} and WSS = 2. The process has moved to a new locality.
Essential formula: working-set strategy
D = Σ WSSᵢ (total demand for frames) if D > m (available frames) → thrashing will occur → SUSPEND a process if D < m → safe; another process may be admitted
Choosing Δ: too small and it misses the whole locality; too large and it overlaps several localities; Δ = ∞ means the whole program.

Page-Fault Frequency (PFF) is a more direct approach: measure each process's fault rate. If it is above an upper bound, give the process more frames. If it is below a lower bound, take frames away. If no free frames are available, suspend a process.

🎯 IBPS exam alert
  • Thrashing means high paging activity with low CPU utilisation. It is caused by too high a degree of multiprogramming, or too few frames per process.
  • Remedy: decrease the degree of multiprogramming, using the working-set model or page-fault frequency.
  • The working-set model is based on the locality of reference.

⚡ Rapid Revision — Chapter 10

  • Virtual memory: run a process that is only partly in RAM, giving the illusion of large memory. Like eating an 80 kg feast a little at a time. Pages 0, 3, 6, 9 in frames 1–4 have present = 1; the rest are on disk.
  • VM increases the degree of multiprogramming: 100 processes × 10 pages with 100 frames, so one page each lets all 100 be in memory.
  • Page fault → OS fetches the page → if no free frame, pick a victim. Dirty = 1 → write back first; dirty = 0 → just discard.
  • Frame allocation: the minimum is set by an instruction's needs; the maximum is all pages. Equal: m/n (60/3 = 20 each, unfair to big processes). Proportional: sᵢ/S × m (30, 40, 30 of 100 with 10 frames → 3, 4, 3). Also priority allocation, and global vs local replacement.
  • FIFO: evict the oldest. Lecture string 4 7 6 1 7 6 1 2 7 2 with 3 frames → 6 faults. It evicted 7 just before 7 was needed.
  • Belady's anomaly: more frames give more faults, FIFO only. 1 2 3 4 1 2 5 1 2 3 4 5 gives 9 faults with 3 frames and 10 with 4. LRU and OPT (stack algorithms) are immune.
  • Optimal: evict the page used farthest in the future. Lecture → 5 faults. Best possible, not implementable, a benchmark.
  • LRU: evict the page least recently used in the past. Lecture → 6 faults. Galvin's string: FIFO 15, LRU 12, OPT 9. Implemented with counters or a stack; approximated by Second-Chance (clock) using the reference bit.
  • Thrashing: too high a degree of multiprogramming means fault after fault and CPU utilisation collapses (4 processes, 4 frames, one page each). Fix: lower the degree of multiprogramming, working set (D = ΣWSS > m → suspend), or PFF bounds.
