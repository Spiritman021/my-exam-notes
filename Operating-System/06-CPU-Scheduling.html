Chapter 6

CPU Scheduling

Chapter 5 introduced the short-term (CPU) scheduler, which picks a process from the ready queue and gives it the CPU. This chapter covers how it picks: the scheduling algorithms. It is the most numerical-heavy topic in OS. For each algorithm, master the Gantt chart and the CT → TAT → WT → RT table.

6.1Preemptive vs Non-Preemptive Scheduling Algorithms

🎓 From the lecture
  • Preemptive: a process can be forcibly stopped after a particular time unit, and another process is scheduled (remember the "5 selfies per turn" analogy).
  • Non-preemptive: no force. "We want to run your whole process. If you go off for I/O on your own, that's not our fault; we'll schedule another process."

6.2Scheduling Terminology: Time Quantum, Arrival, Burst, Turnaround, Waiting and Response Time

🎓 From the lecture — Point of time vs duration
  • Time Quantum (TQ): the fixed time unit each process gets in preemptive scheduling before it is preempted. It does not apply to non-preemptive algorithms.
  • Arrival Time (AT): the point of time when the process enters the ready state (main memory), like "I came home at 11:00".
  • Burst Time (BT): the duration of CPU time the process needs to finish. "My preparation for tomorrow's exam will take 2 hours": the 2 hours is a duration, not a point of time.
  • Completion Time (CT): the point of time when the process finishes execution ("my study finished at 2 o'clock").
  • Turnaround Time (TAT) = CT − AT: the total time from arrival to completion.
  • Waiting Time (WT) = TAT − BT: total time minus the time actually executing leaves the time it was waiting.
  • Response Time (RT) = time it first gets the CPU − AT. Arrived at 1:00 and first got the CPU at 2:00 → RT = 1 hour. Arrived at 1:00 and got the CPU at 1:00 → RT = 0.
Essential formulas
TAT = CT − AT WT = TAT − BT = CT − AT − BT RT = (first time on CPU) − AT Average X = (sum of X over all processes) / n Throughput = number of processes completed / total time For non-preemptive algorithms: RT = WT (the process runs once, without interruption)
🎯 Gantt-chart reading tricks (from the lecture)
  • Completion time: scan the chart right → left. The right edge of a process's last block is its CT.
  • Response time: scan the chart left → right. The left edge of a process's first block, minus its AT, is its RT.
  • Sanity check: if the CPU is never idle, the chart ends at first AT + sum of all BTs (e.g. 3+4+2+1 = 10). Every algorithm on the same data should end at the same point.

6.2AScheduling Criteria & When Scheduling Happens ADDED

CriterionGoalMeaning
CPU utilisationMaximiseKeep the CPU as busy as possible (40% to 90% in real systems)
ThroughputMaximiseProcesses completed per unit time
Turnaround timeMinimiseSubmission to completion
Waiting timeMinimiseTime spent in the ready queue. The scheduling algorithm affects only this.
Response timeMinimiseSubmission to first response; key for interactive systems

Memory aid: maximise U and T (Utilisation, Throughput); minimise T, W, R (Turnaround, Waiting, Response).

Four moments when the CPU scheduler runs (Galvin)

  1. A process moves Running → Waiting (I/O request or wait()): non-preemptive.
  2. A process moves Running → Ready (interrupt or time-out): preemptive.
  3. A process moves Waiting → Ready (I/O completes): preemptive, because the new arrival may beat the current process.
  4. A process terminates: non-preemptive.

If scheduling happens only in cases 1 and 4, the scheme is non-preemptive (cooperative). Otherwise it is preemptive.

⚠️ Exam trap Textbooks say FCFS is starvation-free, since every process eventually gets the CPU. The lecture's "starvation" here means the long wait of late arrivals (the convoy effect). In MCQs: "Which algorithm can never cause starvation?" → FCFS (and Round Robin).

6.4Shortest Job First (SJF) with Numerical Example

SJF (Shortest Job First), also called Shortest Process Next: among the arrived processes, pick the one with the smallest burst time. It is non-preemptive. Ties are broken by FCFS (earlier arrival).
🎓 Lecture analogy "In my daily routine, I finish what takes the least time first. In engineering exams too, solve the quickest question first and do the longest one calmly at the end."

Steps: at t = 0 there is no choice, so P1 runs 0→3. At t = 3, P2 (4), P3 (2) and P4 (1) are waiting, and the shortest is P4 (3→4). Then P3 (2) runs 4→6 and P2 (4) runs 6→10.
Conclusion: total WT is 7 vs 13 in FCFS, and two processes didn't wait at all. Much less waiting.
➕ Added for exam — Properties and burst prediction
  • SJF is provably optimal: it gives the minimum average waiting time for a given set of processes (non-preemptive case; SRTF is optimal among preemptive algorithms).
  • Problem 1: starvation. A long job may never run if short jobs keep arriving.
  • Problem 2: burst time is unknown in advance. The OS predicts the next CPU burst using exponential averaging:
τ(n+1) = α · t(n) + (1 − α) · τ(n) t(n) = actual length of the nth burst, τ(n) = predicted value, 0 ≤ α ≤ 1 (usually α = ½) α = 0 → recent history ignored · α = 1 → only the last burst counts
Numerical: predicting the next CPU burst α = 0.5, initial guess τ₀ = 10, actual bursts 6, 4, 6.
τ₁ = 0.5×6 + 0.5×10 = 8 · τ₂ = 0.5×4 + 0.5×8 = 6 · τ₃ = 0.5×6 + 0.5×6 = 6.
Conclusion: the next predicted burst is 6 units.

6.6Highest Response Ratio Next (HRRN) Scheduling

HRRN: a non-preemptive algorithm. Whenever the CPU becomes free, compute the response ratio for every waiting process and run the one with the highest ratio.
Essential formula: response ratio
Response Ratio (RR) = (W + S) / S = 1 + W/S W = waiting time so far = current time − AT S = service (burst) time
➕ Why HRRN is clever
  • Short jobs (small S) get a high ratio quickly, so it behaves like SJF.
  • Long jobs keep waiting, W grows, and their ratio rises over time, so they cannot starve. This is built-in aging.
  • It is a balance between SJF and FCFS. Like SJF, it still needs to know burst times.

6.9Preemptive Scheduling Algorithms: Introduction

🎓 From the lecture In preemptive algorithms we stop after every time unit ("every hour") and re-check which process to run now. We have the authority to preempt, so we can forcibly stop any process.

Exam method for SRTF, LRTF and Priority (P): re-evaluate at every arrival and every completion. Between such events nothing changes, so you can jump ahead instead of going one unit at a time. The lecture does the same once only two processes remain ("why waste time going one unit at a time?").

6.11Calculating Response Time from the Gantt Chart

🎓 From the lecture — scan left → right For each process, find the first time it appears in the chart and read the time at its left edge. RT = that time − AT.
  • P1: first appears at 0, AT 0 → RT 0 (the only option, scheduled immediately).
  • P2: first appears at 1, AT 1 → RT 0 (scheduled as soon as it arrived).
  • P3: first appears at 12, AT 2 → RT 10.
  • P4: first appears at 5, AT 4 → RT 1 ("you took an hour to respond to it").
⚠️ Exam trap In preemptive algorithms, RT ≤ WT (often RT < WT), because a process can start, be preempted and wait again. Here P1 has RT 0 but WT 6. In non-preemptive algorithms RT = WT always.

6.14Round Robin Scheduling and Time Quantum

Round Robin (RR): preemptive FCFS with a time quantum. Processes are taken from a FIFO ready queue in arrival order. Each runs for min(remaining BT, TQ). If it is not finished, it goes to the tail of the queue.
🎓 From the lecture — The golden rule RR looks at two conditions: arrival time (queue order) and the time quantum. The rule "close to RR's heart" is: run for min(burst remaining, TQ).
  • BT 5, TQ 2 → run 2, then preempt.
  • BT 1, TQ 2 → run only 1 and finish. "Why give it 2 when it needs only 1?"
➕ Effect of the time-quantum size
  • TQ very large (≥ the largest burst) → RR becomes FCFS.
  • TQ very small → too many context switches, so overhead dominates. With q = 10 and switch = 1, efficiency is about 91% (Chapter 5.3A).
  • Rule of thumb: 80% of CPU bursts should be shorter than q. Typically q = 10 to 100 ms, while a context switch takes under 10 µs.
  • With n processes and quantum q, no process waits more than (n − 1) × q before its next turn. This is why RR has good response time and suits time-sharing.
  • RR has no starvation. Its average WT is often higher than SJF's, but its response time is better.

6.16Counting Context Switches in Round Robin

🎓 From the lecture Count the boundaries between different processes in the Gantt chart. P1|P2|P3|P1|P4|P2 has 5 boundaries, so there are 5 context switches. The end of the chart is a completion, not a switch, because nothing is scheduled after it.
⚠️ Exam trap (Read the question's convention)
  • A boundary between two slots of the same process (P1 | P1, preempted but rescheduled immediately because it is alone) is not a context switch.
  • Some questions count the initial dispatch at t = 0 and/or the final exit as switches. Then the answer is 6 or 7. The lecture's (and the most common) convention is switches between processes only = 5.
  • Context switches can also be asked for SRTF and Priority (P). For the SRTF chart above, P1|P2|P4|P1|P3 gives 4.

6.17Priority Scheduling (Preemptive) with Numerical Example

Priority scheduling: each process has a priority number (stored in its PCB), and the CPU goes to the highest-priority ready process. In the preemptive version, a newly arrived process with higher priority preempts the running one.
🎓 Lecture convention "Greater the number, greater the priority; lower the number, lower the priority." Priorities used: P1 = 2, P2 = 4, P3 = 6, P4 = 8.

➕ Starvation and aging
  • Starvation (indefinite blocking): a low-priority process may never run if higher-priority processes keep arriving. A famous story: when MIT's IBM 7094 was shut down in 1973, a low-priority job submitted in 1967 was found still waiting.
  • Aging is the fix: gradually increase the priority of processes that wait a long time (e.g. +1 every 15 minutes), so eventually they get the CPU.
  • Priorities can be internal (memory needs, time limits, I/O-to-CPU burst ratio) or external (importance, money paid, department).
  • SJF is a special case of priority scheduling where priority = 1 / (predicted next burst).
⚠️ Exam trap (Priority convention) The lecture uses higher number = higher priority. Many textbooks (Galvin) and exam questions use lower number = higher priority (0 = highest, as in UNIX). Always read the question; if it is not stated, assume the textbook convention (low number = high priority) and say so.

6.19Multilevel Queue Scheduling

Multilevel Queue (MLQ): the ready queue is split into several separate queues by process type. Each queue has its own scheduling algorithm, and there is scheduling between the queues (usually fixed priority). A process is permanently assigned to one queue.
🎓 From the lecture So far all processes sat in one ready queue. But processes are not all alike, so putting them in one queue is "naainsaafi" (injustice):
  • System processes get the highest priority (e.g. a priority-based algorithm).
  • Interactive / application processes get medium priority (e.g. Round Robin).
  • Batch / background processes get the lowest priority (e.g. FCFS or SJF).
Each queue applies its own algorithm, and the chosen process goes to the CPU.
➕ Scheduling between the queues
  • Fixed-priority preemptive: a lower queue runs only when all higher queues are empty. A process arriving in a higher queue preempts a lower one.
  • Time slicing among queues: e.g. 80% of CPU time to the foreground (RR) and 20% to the background (FCFS). This reduces starvation.
  • Galvin's 5-level example: System → Interactive → Interactive editing → Batch → Student processes.

6.20Starvation Problem in Multilevel Queue Scheduling

🎓 From the lecture
  • High-priority system processes get the CPU again and again. Interactive processes get some chances, but batch processes starve.
  • Even when the system queue empties and a batch process is about to run, a new system process arrives and snatches the CPU again, so "who knows when their turn will come."
  • Root cause: each process is confined to its queue. There is no promotion or demotion and no movement ("aavan-jaavan") between queues.

6.21Multilevel Feedback Queue Scheduling

Multilevel Feedback Queue (MLFQ): like MLQ, but processes can move between queues. They can be demoted (high → low) if they use too much CPU, and promoted (low → high) if they wait too long. This is aging, and it greatly reduces starvation.
🎓 From the lecture — "Singing in chorus" In MLQ, each queue "sings its own tune" and won't join a chorus. In MLFQ, "we'll sing in chorus; no problem."
  • Demotion: the top queue has TQ = 10 minutes. A process wanting 15 minutes gets only 10, then moves down to the next queue, so it can't hog the CPU and others don't starve.
  • Promotion: a process that has waited a long time in a lower queue is moved up to a higher-priority queue, so it gets the CPU.
  • Each queue can still use its own algorithm (Priority, RR, FCFS, SJF, LJF).
Numerical: a job's path through the MLFQ above A process with CPU burst = 30 ms enters Q0.
Step 1: Q0 gives 8 ms, leaving 22, so it is demoted to Q1.
Step 2: Q1 gives 16 ms, leaving 6, so it is demoted to Q2.
Step 3: Q2 (FCFS) runs the remaining 6 ms to completion.
Conclusion: a job with a burst ≤ 8 ms (I/O-bound or interactive) finishes in Q0 with top priority. Long CPU-bound jobs sink to the bottom. MLFQ automatically favours short and interactive jobs without knowing burst times in advance.
➕ MLFQ is defined by five parameters (Galvin) (1) the number of queues · (2) the scheduling algorithm of each queue · (3) the method to upgrade (promote) a process · (4) the method to demote a process · (5) the method to choose which queue a new process enters. It is the most general and most complex CPU-scheduling algorithm. Variants are used in Windows, macOS, Solaris and older Linux schedulers. (Modern Linux uses CFS, the Completely Fair Scheduler, built on a red-black tree.)

🎯 IBPS exam alert (one-liners)
  • Minimum average waiting time → SJF (NP) / SRTF (P). Best for time-sharing → Round Robin. Simplest → FCFS.
  • RR with a very large quantum → FCFS. Starvation in priority scheduling → fix with aging.
  • Convoy effect → FCFS. Starvation-free → FCFS, RR, HRRN.
  • Throughput = processes completed / time. For the FCFS data: 4 processes in 10 units = 0.4 processes per unit.
  • CPU idle time: if the next process arrives after the CPU finishes, the Gantt chart has an idle gap. Don't forget it when computing CT.

⚡ Rapid Revision — Chapter 6

  • Non-preemptive: FCFS, SJF, LJF, HRRN (+ Priority-NP). Preemptive: SRTF, LRTF, RR, Priority-P, MLFQ.
  • AT = point of arrival; BT = duration of CPU need; CT = point of finish. TAT = CT − AT; WT = TAT − BT; RT = first CPU − AT. For NP algorithms, RT = WT.
  • Gantt chart: CT from right → left, RT from left → right. The chart should end at the sum of the BTs (if there is no idle gap).
  • Criteria: maximise CPU utilisation and throughput; minimise TAT, WT and RT.
  • FCFS: arrival order; convoy effect (24,3,3 → avg WT 17 vs 3). Lecture data: avg WT 3.25.
  • SJF: shortest BT first; optimal avg WT (lecture data: 1.75); starvation possible; predict with τ(n+1) = α·t(n) + (1−α)·τ(n).
  • LJF: longest first; poor.
  • HRRN: RR = (W+S)/S. At t=9: P3 2.25 > P4 1.6 > P5 1.5. At t=13: P5 3.5 > P4 2.4. Order: P1 P2 P3 P5 P4. No starvation.
  • SRTF: preemptive SJF; ties go to the earlier AT. Lecture: P1 0–1, P2 1–5, P4 5–7, P1 7–12, P3 12–17; RT = 0, 0, 10, 1.
  • LRTF: preemptive LJF; everyone finishes near the end (CT 14, 15, 16, 17).
  • RR: run min(BT left, TQ); new arrivals enter the queue before the preempted process. Lecture (q=2): P1 P2 P3 P1 P4 P2, with 5 context switches. A large q gives FCFS; a small q gives too much overhead.
  • Priority: the lecture uses a higher number for higher priority (the textbook often the reverse). P: P1 P2 P3 P4 P3 P2 P1 (RT all 0). NP: P1 P4 P3 P2. Starvation is fixed by aging.
  • MLQ: separate queues (system, interactive, batch), each with its own algorithm, fixed membership, and starvation of low queues. MLFQ: promotion and demotion ("singing in chorus"), e.g. Q0 RR 8 → Q1 RR 16 → Q2 FCFS.
