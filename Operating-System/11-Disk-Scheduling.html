Chapter 11

Disk Management and Disk Scheduling

Virtual memory (Chapter 10) keeps most pages on disk, and every page fault and file read hits the disk, the slowest part of the hierarchy. This chapter covers how a hard disk is built, how to calculate its capacity and access time, and how the OS orders pending requests (disk scheduling) to minimise the seek time, the biggest component of that access time.

11.1Disk Architecture: Platters, Surfaces, Tracks, Sectors

🎓 From the lecture
  • Platter: one disk "plate" (like a CD). Each platter has 2 surfaces, upper and lower. A disk can have many platters.
  • Spindle: the rod that holds all the platters together and rotates them.
  • Track: a concentric circular ring on a surface. Outer tracks are bigger, and tracks get smaller towards the centre.
  • Sector: each track is divided into blocks or sections called sectors. This is where the data actually lives.
  • Read/write head: one per surface (upper and lower). All heads are held by the actuator arm. The heads move back and forth (in/out), never in a circle; the platter rotates.
  • Hierarchy: platter → 2 surfaces → tracks → sectors → data.
➕ More terms Cylinder: the set of tracks at the same arm position on all surfaces. Moving within a cylinder needs no seek. Typical sector size is 512 B (now 4 KB "Advanced Format"). CAV (constant angular velocity) keeps the same number of sectors per track, so bit density is higher on inner tracks. CLV (constant linear velocity, CDs and DVDs) puts more sectors on outer tracks. Head crash: the head touches the platter surface, which usually destroys data.

11.2Numerical Example: Disk Capacity

Essential formula
Disk capacity = platters × 2 (surfaces) × tracks/surface × sectors/track × bytes/sector = surfaces × tracks × sectors × sector size
Numerical (lecture) 8 platters, 2 surfaces each, 256 tracks per surface, 512 sectors per track, 512 B per sector.
Step 1: write each as a power of 2: 2³ × 2¹ × 2⁸ × 2⁹ × 2⁹.
Step 2: add the exponents: 3 + 1 + 8 + 9 + 9 = 30, so 2³⁰ bytes.
Conclusion: capacity = 2³⁰ B = 1 GB.
⚠️ Exam trap The lecture says "2³⁰ = 1 MB" here. That is a slip: 2³⁰ B = 1 GB (2²⁰ = 1 MB). Remember: 2¹⁰ K, 2²⁰ M, 2³⁰ G, 2⁴⁰ T.

11.3Disk Access Time

Disk access time: the total time to read or write a particular piece of data on the disk.
Essential formula
Disk access time = Seek time + Rotational latency + Transfer time (+ controller overhead + queuing delay, if given)

11.4Seek Time

Seek time: the time for the read/write head (arm) to move from its current track to the target track.
🎓 From the lecture The head moves back and forth across tracks. If it is on an outer track and the target is an inner one, the time to get there is the seek time.
Seek time = n × s (n = number of tracks crossed, s = time to cross one track)
➕ Average seek time Manufacturers quote the average seek time (typically 3 to 12 ms), roughly the time to move across one-third of the tracks. If a question gives "average seek time", use it directly. Seek time is the largest component of access time, which is why disk scheduling targets it.

11.5Rotational Latency

Rotational latency: once on the right track, the time for the platter to rotate the desired sector under the head.
🎓 From the lecture The head can't rotate; it only moves in and out. So if it is at sector 0 and the data is in sector 2, the disk must rotate sector 2 under the head.
Rotational latency = θ / f (θ = angle between current and target sector, f = rotational frequency) Average rotational latency = ½ × time for one rotation
Numerical (added) The disk spins at 7200 RPM.
Rotations per second = 7200 / 60 = 120, so one rotation = 1/120 s = 8.33 ms.
Average rotational latency = 8.33 / 2 = 4.17 ms.
(At 3600 RPM: one rotation = 16.67 ms, average latency = 8.33 ms. At 15,000 RPM: 4 ms and 2 ms.)

11.6Transfer Time and Data Transfer Rate

Transfer time: once the head is over the right sector, the time to actually read or write the data.
Essential formulas (lecture)
Transfer time = data size / data transfer rate Data transfer rate = number of heads (surfaces) × capacity of one track × rotations per second
➕ Single-head form Many questions assume one head reads at a time. Then the transfer rate = track capacity × rotations per second, and the transfer time for one sector = one rotation ÷ sectors per track. Read whether the question says the heads transfer in parallel, as the lecture's formula assumes.

11.7Numerical Example: Capacity, Sector Addressing and Transfer Rate

Numerical (lecture) Given: 16 surfaces, 128 tracks per surface, 256 sectors per track, 512 B per sector, 3600 RPM.

(a) Capacity = 2⁴ × 2⁷ × 2⁸ × 2⁹ = 2²⁸ B = 2⁸ × 2²⁰ = 256 MB.

(b) Bits to address a sector: total sectors = surfaces × tracks × sectors = 2⁴ × 2⁷ × 2⁸ = 2¹⁹, so 19 bits.

(c) Data transfer rate = heads × track capacity × rotations per second.
Track capacity = 256 × 512 = 2⁸ × 2⁹ = 2¹⁷ B = 128 KB. Rotations per second = 3600 / 60 = 60.
Rate = 2⁴ × 2¹⁷ × 60 = 2²¹ × 60 = 2 MB × 60 = 120 MB/s.

11.7AAccess-Time Numericals ADDED

Numerical 1: time to read one sector Average seek = 4 ms; 7200 RPM; 400 sectors per track; sector = 512 B.
One rotation = 60/7200 s = 8.33 ms, so average rotational latency = 4.17 ms.
Transfer one sector = 8.33 / 400 = 0.021 ms.
Access time = 4 + 4.17 + 0.021 ≈ 8.19 ms.
Conclusion: transfer is tiny. Seek and rotation dominate, so reading sectors sequentially on the same track or cylinder is far faster than random reads.
Numerical 2: seek from a track count The head is at track 20, the target is track 70, and crossing one track takes 0.1 ms.
Seek = |70 − 20| × 0.1 = 50 × 0.1 = 5 ms.
Numerical 3: total seek from disk scheduling If a schedule moves the head a total of 85 tracks (SSTF below) and crossing one track takes 1 ms, then total seek time = 85 ms.

11.8Disk Scheduling Algorithms Overview

Disk scheduling: the OS orders the pending I/O requests (track numbers in the request queue) so that the total head movement, and therefore total seek time, is minimised.
🎓 From the lecture There are several algorithms: FCFS, SSTF, SCAN, LOOK, C-SCAN and C-LOOK, all applied to one example.
Common problem used for all six (lecture) Tracks 0 to 99 (100 tracks). Request queue: 80, 30, 90, 95, 45. Head currently at 50. Direction for SCAN-family algorithms: towards larger track numbers.
🎓 Counting shortcut (lecture) Total head movement = sum of |differences| between consecutive positions. If the head keeps moving in one direction through several stops, just subtract the two extreme ends of that run: 95 − 30 instead of (90 − 30) + (95 − 90). The answer is the same with fewer steps.

11.9FCFS Disk Scheduling

FCFS (First Come First Serve): serve the requests in the order they arrive.
Calculation (80−50) + (80−30) + (90−30) + (95−90) + (95−45) = 30 + 50 + 60 + 5 + 50 = 195 tracks.
Using the shortcut: 30 + 50 + (95 − 30) + 50 = 195.
➕ Properties Fair, with no starvation, and simple. But it causes wild swings across the disk, so the total seek is high. It is fine under a light load.

11.10SSTF (Shortest Seek Time First)

SSTF: from the current head position, serve the closest pending request next (the one with the minimum seek distance).
🎓 From the lecture At 50, the nearest requests are 45 (distance 5) and 80 (distance 30), so go to 45. From 45 the nearest is 30. From 30 the nearest left is 80, then 90, then 95.
Calculation (50 − 30) + (95 − 30) = 20 + 65 = 85 tracks, compared with 195 for FCFS.
⚠️ Exam trap SSTF is like SJF for disks. It gives a good average but is not optimal in general, and it can cause starvation: requests far from the head may wait forever if new nearby requests keep arriving. It also favours middle tracks.

11.11SCAN (Elevator) Algorithm

SCAN: the head moves in one direction serving every request on the way all the way to the end of the disk (track 99 or 0), then reverses and serves requests on the way back. It works like an elevator.
🎓 From the lecture Going towards higher tracks: 50 → 80 → 90 → 95 → 99 (the extreme end, even though 99 is not requested; that is the disadvantage) → back to 45 → 30.
Calculation (99 − 50) + (99 − 30) = 49 + 69 = 118 tracks. The trip from 95 to 99 and back is wasted overhead (4 + 4 = 8).
➕ Properties No starvation, and a lower variance in response time than SSTF. But requests at the far end that just missed the head must wait for a full round trip, and the middle tracks are served twice as often as the ends.

11.12LOOK Algorithm

LOOK: like SCAN, but the head goes only as far as the last request in each direction (it "looks" ahead), then reverses. It does not touch the disk's extreme end.
Calculation (95 − 50) + (95 − 30) = 45 + 65 = 110 tracks.
🎓 Why 110 and not 114? (lecture) SCAN = 118 and LOOK = 110, a difference of 8, not 4. The 95 → 99 stretch is counted twice in SCAN, once going out and once coming back, so LOOK saves 4 + 4 = 8.

11.13C-SCAN Algorithm

C-SCAN (Circular SCAN): the head moves in one direction serving requests up to the end of the disk. Then it jumps straight back to the other end (track 0) without serving anything on the way, and continues serving in the same direction. The disk is treated as circular.
🎓 From the lecture 50 → 80 → 90 → 95 → 99 → jump to 0 → 30 → 45. Touching 0 is extra overhead.
Calculation (99 − 50) + (99 − 0) + (45 − 0) = 49 + 99 + 45 = 193 tracks (counting the return jump).
➕ Why use C-SCAN? It gives a more uniform waiting time than SCAN: every request waits at most about one sweep. That makes it good for heavily loaded systems. The return jump is fast (the head isn't reading), and some books don't count it: 49 + 45 = 94. Always state your convention.

11.14C-LOOK Algorithm

C-LOOK: the circular version of LOOK. The head serves requests in one direction up to the highest request, then jumps to the lowest pending request (not track 0) and continues in the same direction.
🎓 From the lecture 50 → 80 → 90 → 95 (highest request) → jump to 30 (lowest request) → 45.
Calculation (95 − 50) + (95 − 30) + (45 − 30) = 45 + 65 + 15 = 125 tracks (counting the jump). Without the jump: 45 + 15 = 60.
⚠️ Exam trap The lecture writes the C-LOOK total as "120" (and "129" in the summary). The correct sum is 45 + 65 + 15 = 125. Always redo the arithmetic yourself.

🎯 IBPS exam alert
  • "Elevator algorithm" = SCAN. Starvation is possible in SSTF. The fairest and simplest is FCFS. The most uniform waiting time comes from C-SCAN / C-LOOK.
  • SCAN and C-SCAN go to the disk ends (0 / 99); LOOK and C-LOOK stop at the last request.
  • Heavily loaded systems prefer SCAN / C-SCAN / LOOK. SSTF or LOOK is a common default. Modern SSDs have no seek, so a simple FCFS/NOOP scheduler is used.
  • Always check: the direction (towards larger or smaller), whether the return jump counts, and the disk range (0 to n−1).

11.16Disk Formatting, Swap Space, RAID & SSD ADDED

Disk management tasks

  • Low-level (physical) formatting: divides the disk into sectors, each with a header, a data area (usually 512 B) and a trailer (ECC, the error-correcting code). It is done at the factory.
  • Partitioning: splits the disk into one or more groups of cylinders (logical disks, e.g. C:, D:). Logical formatting: creates a file system (FAT, NTFS, ext4).
  • Boot block: holds the bootstrap loader; the MBR is in sector 0 (Chapter 1). Bad blocks are handled by sector sparing (remapping to spare sectors) or sector slipping.
  • Swap space: the disk area used by virtual memory (Chapter 10). It can be a separate raw partition (faster) or a file in the file system (e.g. pagefile.sys in Windows).

  • Disk: platters (2 surfaces each) on a spindle; tracks (concentric rings, the outer ones bigger) divided into sectors (the data). One read/write head per surface on the actuator arm; heads move in/out while platters rotate. Cylinder = the same track on every surface.
  • Capacity = surfaces × tracks × sectors × sector size. Lecture: 8 × 2 × 256 × 512 × 512 = 2³⁰ = 1 GB (the lecture slips to "1 MB"). 16 × 128 × 256 × 512 = 2²⁸ = 256 MB; 2¹⁹ sectors → 19 bits to address.

  • Transfer rate = heads × track capacity × rotations per second. Lecture: 16 × 128 KB × 60 = 120 MB/s. Transfer time = data size / rate.
  • Scheduling (head 50; queue 80, 30, 90, 95, 45; tracks 0–99; towards higher): FCFS 195 · SSTF 85 (best here; starvation possible) · SCAN 118 (elevator, to 99) · LOOK 110 (to the last request) · C-SCAN 193 (99 → jump to 0) · C-LOOK 125 (95 → jump to 30).
