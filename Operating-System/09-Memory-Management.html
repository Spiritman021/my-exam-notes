Chapter 9

Memory Management

Chapters 5 to 8 were about processes. But a process can run only when it is in main memory, which is limited. This chapter covers how the OS divides RAM among processes, first contiguously (partitions) and then non-contiguously (paging and segmentation), and how every address a program uses is translated into a real RAM location.

9.0Why Memory Management?

Memory management: the OS function that keeps track of every byte of main memory and decides which process gets which part, and when. It allocates and deallocates memory, protects processes from each other, and swaps processes between RAM and disk, all for the efficient, optimal use of memory and good multiprogramming.
🎓 From the lecture The CPU is not directly connected to secondary memory. A process must be swapped in from disk to main memory (RAM) before the CPU can run it, and it can be swapped out again. RAM is volatile: its contents vanish ("chhoomantar") without power. Secondary memory is non-volatile and keeps data for a long time. Memory management is the "jugalbandi" (duet) between the two.

9.1Memory Hierarchy

🎓 From the lecture Registers are closest to the CPU, then cache, then main memory, and secondary memory is farthest. Access time: least for registers and most for secondary. Capacity: the reverse, least for registers and most for secondary. The nearer the memory, the faster it is to access.
➕ Typical figures and principles Registers under 1 ns · cache L1/L2/L3 about 1–10 ns · RAM about 50–100 ns · SSD about 0.1 ms · HDD about 5–10 ms. Cost per bit falls going down the pyramid. The hierarchy works because of locality of reference: temporal (recently used data is likely to be used again soon) and spatial (nearby addresses are likely to be used next).

9.2Degree of Multiprogramming and CPU Utilization

Essential formula
CPU utilisation = 1 − pⁿ p = fraction of time a process spends waiting for I/O n = number of processes in main memory (degree of multiprogramming)
Numerical (lecture): p = 0.6 (60% I/O, 40% CPU)

Conclusion: with one process, the CPU idles for the whole 60% I/O time because there is nothing else to run. With more processes in RAM, the chance that all of them are waiting for I/O at once falls, so CPU utilisation rises with the degree of multiprogramming. The aim of memory management is to fit as many processes into RAM as possible.
⚠️ Exam trap This is a simplified probabilistic model that assumes the I/O waits are independent. Utilisation does not rise forever: beyond a point, too many processes cause thrashing (Chapter 10).

9.3Contiguous vs Non-Contiguous Allocation

🎓 From the lecture — Classroom seating Contiguous: the teacher strictly says "sit by roll number": roll 1, then 2, then 3, side by side. Non-contiguous: "sit anywhere". The back-benchers spread out: roll 40 here, 2 there, 5 and 6 somewhere else.
ContiguousNon-contiguous

9.4Address Translation in Contiguous Allocation (Relocation Register)

Logical address: the address generated by the CPU (as seen by the program). Physical address: the actual location in main memory. Address translation maps logical to physical. In contiguous allocation it uses the relocation (base) register.
🎓 From the lecture The relocation register gives base = 1000. The CPU generates logical address 50. Physical = 50 + 1000 = 1050, the RAM location that is actually accessed.
➕ The limit register (protection) The lecture shows only the relocation register. Hardware also has a limit register holding the size of the process. Every logical address is first checked: LA < limit. Otherwise the hardware traps to the OS, which prevents a process reaching another's memory. Both registers are loaded by the dispatcher on each context switch, and loading them is privileged. The translation is done by the MMU (Memory Management Unit).

  • Swapping: a process is moved temporarily out to a backing store (disk) and back in (Chapter 5's medium-term scheduler).

9.5Fixed Partitioning

Fixed (static) partitioning: main memory is divided into a fixed number of partitions before processes arrive. Partitions can be equal-sized (e.g. every partition 2 MB) or unequal-sized. Each partition holds exactly one process.
🎓 From the lecture It is called "fixed" because the number of partitions is fixed; their sizes may be equal or unequal. Spanning is not allowed: a process must sit wholly inside one partition and can't be split across two.
➕ How processes are assigned Equal-size: any free partition will do. Unequal-size: put a process in the smallest partition it fits, using either one queue per partition or a single queue. Example: IBM OS/360 MFT (Multiprogramming with a Fixed number of Tasks).

9.6Internal Fragmentation and Size Limitation

Internal fragmentation: memory wasted inside an allocated partition, because the partition is bigger than the process placed in it. No other process can use that leftover space.
🎓 From the lecture
  • Partition = 10 MB, process = 8 MB, so 2 MB is wasted "for free". P3 can't sit in it. This is internal fragmentation.
  • Size limitation: the largest partition is 30 MB and a 50 MB process arrives. It can't run, because spanning (30 + 20 across two partitions) is not allowed.
  • So fewer processes fit in RAM, and the degree of multiprogramming is limited, along with CPU utilisation.

9.7External Fragmentation

External fragmentation: enough total free memory exists to satisfy a request, but it is scattered in non-adjacent pieces, so it can't be used because allocation must be contiguous.
🎓 From the lecture P0 to P3 occupy partitions, leaving a 1 MB free piece in one and 1 MB in another. A process needing 2 MB arrives. 1 + 1 = 2 MB is free, but it can't be allocated because the space is not contiguous. That is external fragmentation.
Internal fragmentationExternal fragmentation
Waste inside an allocated blockWaste between allocated blocks (free holes)
The allocated block is larger than the requestTotal free space is enough but not contiguous
Fixed partitioning, paging (last page)Variable partitioning, segmentation
Fix: smaller partitions or pages, best fitFix: compaction, paging, non-contiguous allocation

9.8Variable (Dynamic) Partitioning

Variable (dynamic) partitioning: there are no pre-made partitions. Each arriving process gets a partition exactly its size, carved out at run time.
🎓 From the lecture "You need 5 MB? Sit here in 5 MB. You need 2 MB? Take 2 MB. You need 10 MB? Here's 10 MB." So P1 = 5 MB, P2 = 2 MB and P3 = 10 MB, each in a perfectly sized block.
  • No internal fragmentation, because the block equals the process size.
  • No limit on process size, so the degree of multiprogramming is not hurt the way it is with fixed partitions.
  • But external fragmentation still happens (next section).
➕ Fixed vs variable
Fixed partitioningVariable partitioning
Number of partitions fixed in advancePartitions created on demand

9.9External Fragmentation in Variable Partitioning

🎓 From the lecture P1 (5 MB) and P3 (10 MB) finish, so 15 MB is free, but P2 (2 MB) sits between the two holes. P4 needs 15 MB and can't be placed: spanning is not allowed in contiguous allocation.
➕ The 50-percent rule (Galvin) Statistical analysis of first fit shows that for every N allocated blocks, about 0.5 N blocks are lost to fragmentation. So about one-third of memory may be unusable.

9.10Compaction

Compaction (the lecture also calls it "process shifting"): move all processes to one end of memory so that all the free holes merge into one big contiguous hole at the other end.
🎓 From the lecture Free regions are called holes. Shift the processes to one end and the holes to the other. The 5 MB and 10 MB holes become one 15 MB block, so P4 now fits. But compaction is very expensive.
➕ Why expensive, and when possible Every byte of every moved process must be copied, during which the CPU does no useful work. Compaction is possible only with dynamic (execution-time) relocation, because the base register can be updated after the move. It is impossible with compile-time or load-time binding.

9.11First Fit Allocation

When a process arrives in variable partitioning, which hole should it go into? There are four placement strategies. Lecture set-up: holes of 5 MB, 10 MB, 15 MB (top to bottom) between P1 to P4.

First fit: scan from the start of memory and allocate the first hole that is big enough.
🎓 From the lecture P5 = 4 MB. Scanning from the start, the first hole is 5 MB and 5 ≥ 4, so P5 goes there and a 1 MB hole remains.

9.12Next Fit Allocation

Next fit: like first fit, but the search starts from where the last allocation was made, not from the beginning. It wraps around if needed.
🎓 From the lecture P6 = 8 MB. The last allocation was P5, so search after P5. The 1 MB leftover is too small and P2 is occupied, so the next hole is 10 MB and P6 goes there (2 MB left). "Next fit plays a bit smartly": it doesn't rescan from the top every time.

9.13Best Fit Allocation

Best fit: search the entire list of holes and allocate the smallest hole that is big enough, which leaves the least leftover.
🎓 From the lecture P7 = 9 MB, holes of 10 MB and 15 MB. In 10 MB, 1 MB is wasted; in 15 MB, 6 MB would be wasted. Best fit picks 10 MB. An 8 MB hole can't be used (9 > 8). Given 10 and 12, it picks 10 (1 MB left vs 3 MB). The overhead is that it must search the whole memory every time.

9.14Worst Fit Allocation

Worst fit: search the entire list and allocate the largest hole.
🎓 From the lecture P8 = 9 MB, holes of 10 MB and 15 MB. Worst fit picks 15 MB, the place where the most space is left over (6 MB).
⚠️ Exam traps
  • The lecture calls the leftover "internal fragmentation". In variable partitioning, the leftover piece becomes a new free hole, so it is external fragmentation. Internal fragmentation belongs to fixed partitions and paging.
  • Worst fit isn't trying to waste memory. The idea is that the leftover hole stays large enough to be useful for another process, while best fit tends to leave tiny useless slivers.
  • Galvin: first fit and best fit are both better than worst fit in time and storage use. First fit is generally the fastest.

9.15Non-Contiguous Memory Allocation

Non-contiguous allocation: a process may be split into pieces placed in different, non-adjacent places in memory. Spanning is allowed, which removes external fragmentation.
🎓 From the lecture There are free holes of 3 MB and 3 MB, and P1 needs 6 MB. Contiguous allocation can't place it (external fragmentation). Non-contiguous allocation breaks P1 into 3 + 3 and puts one piece in each hole. The overhead: the OS must analyse the number and sizes of the holes first and split the process accordingly. With holes of 2 MB and 4 MB, the split would be 2 + 4.
➕ The practical fix Splitting processes to match holes of random sizes is messy. Paging solves this by cutting both the process and the memory into pieces of the same fixed size, so any piece fits any slot.

9.16Paging: Pages and Frames

Paging: the process (logical memory) is divided into fixed-size blocks called pages. Main memory (physical memory) is divided into blocks of the same size called frames. Any page can go into any free frame.
🎓 From the lecture — The book analogy Tear the process into pieces; each piece is a page, and the bundle of pages is a book called "Process". Tear main memory too; each piece is a frame, and the bundle is a book called "Main Memory". Page size = frame size, always: a whole page must sit in one frame. If the page is 2 MB, the frame must also be 2 MB.
Lecture example: process P1 = 16 B, page = 4 B, main memory = 32 B Number of pages = 16 / 4 = 4 (pages 0 to 3). Number of frames = 32 / 4 = 8 (frames 0 to 7).
Page 0 holds bytes 0–3, page 1 holds 4–7, page 2 holds 8–11, page 3 holds 12–15.
Placement: page 0 → frame 1, page 1 → frame 3, page 2 → frame 5, page 3 → frame 7.
🎓 Where is byte 5? The CPU wants byte 5 of P1. Byte 5 is in page 1 (bytes 4–7) at position 1 within the page. Page 1 is in frame 3, which starts at byte 12, so byte 5 is physical byte 12 + 1 = 13. The MMU does this translation using the page table.

9.17Logical and Physical Address Format (Page Number and Offset)

Logical address = [ page number (p) | page offset (d) ]. Physical address = [ frame number (f) | frame offset (d) ]. The offset is the same in both: byte 2 of a page is byte 2 of whichever frame holds that page.
Lecture example: bit widths
  • Page number: 4 pages need 2 bits (00, 01, 10, 11). One bit can only say 0 or 1.
  • Offset: 4 bytes per page need 2 bits (00 = 1st byte … 11 = 4th byte).
  • Frame number: 8 frames need 3 bits (000 … 111).
So the logical address is 2 + 2 = 4 bits (process = 16 B = 2⁴) and the physical address is 3 + 2 = 5 bits (memory = 32 B = 2⁵).
➕ The general rule
n bits can represent 2ⁿ things → to represent N things you need log₂N bits offset bits d = log₂(page size) page-number bits = log₂(number of pages) = LA bits − d frame-number bits = log₂(number of frames) = PA bits − d
(The lecture says "2 byte" and "3 byte" for these fields at one point; it means bits.)

9.18Address Translation using MMU and Page Table

Walkthrough (lecture)
  1. The CPU wants byte 5, so LA = page 01, offset 01 (0101₂ = 5).
  2. The MMU looks up page 1 in P1's page table and finds frame 3 = 011.
  3. PA = frame 011 followed by offset 01 = 01101₂ = 13.
  4. Go to frame 3 and fetch byte position 1. The CPU gets its byte.
Physical address = frame number × page size + offset = 3 × 4 + 1 = 13

9.19Page Table

Page table: a per-process data structure that maps each page number → frame number. It is used by the MMU for every memory access.
🎓 From the lecture
  • Every process has its own separate page table.
  • The page table is itself stored in main memory. That is an overhead, partly reduced by inverted paging.
  • Number of entries in a page table = number of pages of the process.
➕ Where the CPU finds it The PTBR (Page-Table Base Register) points to the current process's page table, and the PTLR (Page-Table Length Register) gives its size. On a context switch, only the PTBR is changed. The PTBR is saved in the PCB.

9.20Page Table Entry Size

🎓 From the lecture The page table of P1 has 4 entries (one per page). What is the size of one entry? It must hold a frame number. With 8 frames, that takes 3 bits. So each entry is 3 bits: page 0 → 001, page 1 → 011, page 2 → 101, page 3 → 111. More frames means a wider entry.
Essential formulas
PTE size (minimum) = frame-number bits = log₂(number of frames) [+ control bits, see 9.25] Page-table size = number of pages × PTE size
⚠️ Exam trap The entry width grows with log₂(frames), not in proportion: doubling the frames adds just 1 bit. Real PTEs also carry valid, protection, dirty and reference bits and are rounded up to whole bytes, typically 4 bytes on 32-bit systems.

9.21Drawbacks of Paging

🎓 From the lecture
  1. Two memory accesses per reference: one to read the page table (it lives in RAM) and one to read the actual data. Memory access becomes about twice as slow. The fix is the TLB (9.28).
  2. Page table storage: every page table occupies main memory.
  3. Address translation is complex.
➕ More pros and cons
  • Advantage: no external fragmentation, because any free frame can be used. Allocation is simple, and pages are easy to swap and share (e.g. many users running one editor share its read-only code pages).
  • Internal fragmentation: the last page of a process is usually partly empty. On average this wastes half a page per process. Example: process = 72,766 B, page = 2,048 B → 35 full pages + 1,086 B, so 36 frames are used and 2,048 − 1,086 = 962 B is wasted.
  • Page-size trade-off: small pages mean less internal fragmentation but a bigger page table. Large pages mean a smaller page table and faster I/O, but more internal fragmentation. Typical sizes are 4 KB, plus "huge pages" of 2 MB or 1 GB. The page size is always a power of 2.

9.22Logical Address Space and Physical Address Space

Logical Address Space (LAS): the size of the process's address range (2^(LA bits)). Physical Address Space (PAS): the size of main memory (2^(PA bits)).
🎓 From the lecture If an address has n bits, the address space is 2ⁿ. In the running example, LA = 4 bits gives LAS = 2⁴ = 16 B, and PA = 5 bits gives PAS = 2⁵ = 32 B.
Shortcuts to memorise
2¹⁰ = 1 K (kilo) 2²⁰ = 1 M (mega) 2³⁰ = 1 G (giga) 2⁴⁰ = 1 T (tera) e.g. 16 KB = 2⁴ × 2¹⁰ = 2¹⁴ 64 MB = 2⁶ × 2²⁰ = 2²⁶ 4 GB = 2² × 2³⁰ = 2³²

9.23Numerical Example: Address Bits from Address Space

Numerical (lecture): LAS = 16 GB, PAS = 32 GB, page size = 16 KB Step 1: LA bits: 16 GB = 2⁴ × 2³⁰ = 2³⁴, so 34 bits.
Step 2: PA bits: 32 GB = 2⁵ × 2³⁰ = 2³⁵, so 35 bits.
Step 3: Offset: 16 KB = 2⁴ × 2¹⁰ = 2¹⁴, so 14 bits. This is the same in LA and PA, because page size = frame size.
Step 4: Page-number bits = 34 − 14 = 20 bits.

9.24Numerical: Number of Pages and Frames from Address Bits

Continuing (lecture) Pages = 2^(page bits) = 2²⁰ = 1 M pages (also LAS / page size = 2³⁴ / 2¹⁴ = 2²⁰).
Frame bits = 35 − 14 = 21, so frames = 2²¹ = 2 M frames (also PAS / frame size = 2³⁵ / 2¹⁴). The lecture briefly says "20 bits" for frames; the correct value is 21.
Conclusion: go both ways, from space to bits and from bits to space, pages and frames.
Extension (added): page-table size for this numerical PTE needs ≥ 21 bits for the frame number, rounded up to 4 bytes with control bits.
Page-table size = 2²⁰ entries × 4 B = 4 MB per process. That is too big to store contiguously, which is why multilevel paging (9.26) exists.
Practice numerical (added) 32-bit logical address, page size 4 KB, PTE 4 B. Offset = 12 bits; pages = 2³² / 2¹² = 2²⁰. Page-table size = 2²⁰ × 4 B = 4 MB. With 1 GB of RAM: frames = 2³⁰ / 2¹² = 2¹⁸, so the frame number needs 18 bits.

9.26Multilevel Paging

Multilevel (hierarchical) paging: when a page table is too large to fit in one frame, the page table is itself paged, and an outer page table keeps track of where its pieces are. Repeat as many levels as needed.
🎓 From the lecture P's page table PT0 = 12 KB, but page/frame = 4 KB, so it doesn't fit in one frame. Split PT0 into 12/4 = 3 pages, stored in frames 8, 9 and 10. An outer table PT1 records PT0's page 0 → frame 8, page 1 → frame 9, page 2 → frame 10. If PT1 is also too big, page it again: "multi-level". Drawbacks: more memory overhead and more memory accesses (3, 4 … instead of 2).
Numerical (added, Galvin): 32-bit LA, 4 KB pages, 4 B PTE Offset = 12 bits, so the page number = 20 bits.
One page holds 4 KB / 4 B = 1024 = 2¹⁰ entries, so the inner index p2 = 10 bits and the outer index p1 = 20 − 10 = 10 bits.
LA = [p1 = 10 | p2 = 10 | d = 12]. The outer table has 2¹⁰ entries × 4 B = 4 KB, which fits in one frame ✔.
Memory accesses without a TLB: 2-level = 3 (2 tables + data); k-level = k + 1.
➕ Rule for the number of levels Keep splitting the page-number bits into chunks of log₂(PTEs per page) until the top table fits in one page.
Example: 64-bit addresses with 4 KB pages would need about 6 or 7 levels, so 64-bit systems use hashed or inverted page tables, or limit the address to 48 bits with 4 levels (x86-64).

9.27Inverted Paging (Global Page Table)

Inverted page table: one global table for the whole system with one entry per physical frame. Each entry holds the <process ID, page number> stored in that frame. There are no per-process page tables.
🎓 From the lecture
  • With 1000 processes there are 1000 page tables in RAM, even if only one page of each process is loaded: a huge overhead.
  • Inverted: indexed by frame instead of page. Number of entries = number of frames (1000 frames → 1000 entries).
  • The logical address must now carry the PID, because "page 1" could belong to P1 or P3: LA = <pid, p, d>.
  • Example: find pid 1, page 1, offset 1. Search the table for (P1, page 1), which is found at frame 1, so PA = <frame 1, offset 1>.
  • Disadvantage: search overhead. In the worst case all 1000 entries are scanned.
Normal page tableInverted page table
One per processOne for the whole system
Entries = number of pagesEntries = number of frames
Indexed by page number: direct lookup, fastMust be searched by (pid, page): slow
Total memory grows with the number of processesFixed size, proportional to RAM: saves memory
Easy page sharingSharing pages is difficult (one entry per frame)
➕ Speed-up Use a hash table on (pid, page) to find the entry quickly, plus the TLB. Used by IBM PowerPC and UltraSPARC. A hashed page table (hash of the virtual page number → chain of entries) is a related technique for 64-bit address spaces.

9.28Translation Lookaside Buffer (TLB)

TLB: a small, very fast associative memory (hardware cache) near the CPU that stores recently used page → frame translations. On a hit, the page table in RAM is not accessed at all.
🎓 From the lecture It fixes paging's 2-access problem (and multilevel paging's 3–4 accesses). Each TLB entry stores (process ID + page number) and the frame number. Example: (P1, page 2) → F3, found without touching the page table. But the TLB is expensive, so only a few crucial, frequently used entries are kept.
⚠️ Exam trap (key vs value) The lecture calls the frame-number field the "key". In Galvin, each TLB entry has a key (tag) = page number, which is searched in parallel, and a value = frame number. The stored PID is called the ASID (Address-Space Identifier), which lets the TLB hold entries of several processes. Without ASIDs, the TLB must be flushed on every context switch. Typical TLB size is 32 to 1024 entries.

9.29TLB Hit, TLB Miss and Effective Memory Access Time

🎓 From the lecture TLB hit (e.g. P1 page 2 found → F3): time = t + m (TLB search + one memory access for the data).
TLB miss (e.g. P3 page 2 not in the TLB): search the TLB, then read the page table, then the data: t + 2m.
With p = hit ratio and 1 − p = miss ratio:
Essential formula: EMAT
EMAT = p (t + m) + (1 − p)(t + 2m) = t + (2 − p)·m [lecture form] Galvin form (TLB time ignored): EAT = p·m + (1 − p)·2m k-level paging, miss cost: t + (k + 1)·m
Numerical 1 (added) TLB access t = 20 ns, memory m = 100 ns, hit ratio p = 0.8.
Hit = 20 + 100 = 120 ns. Miss = 20 + 200 = 220 ns.
EMAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = 140 ns (check: 20 + 1.2 × 100 = 140 ✔).
Conclusion: without a TLB every access costs 2m = 200 ns, so the TLB saves 30%.
Numerical 2 (Galvin, TLB time ignored) m = 100 ns, hit 80%: 0.8 × 100 + 0.2 × 200 = 120 ns. Hit 99%: 0.99 × 100 + 0.01 × 200 = 101 ns.
Numerical 3: find the hit ratio (reverse) t = 10 ns, m = 100 ns, required EMAT ≤ 130 ns.
10 + (2 − p) × 100 ≤ 130 → 2 − p ≤ 1.2 → p ≥ 0.8 (an 80% hit ratio is needed).
⚠️ Exam trap Read whether the question says the TLB and the page table are searched sequentially (lecture form, t added on a miss) or in parallel (miss = 2m only), or whether TLB time is negligible. After a miss, the new translation is inserted into the TLB, replacing one by LRU or randomly.

9.31Segmentation vs Paging

Segmentation: a memory-management scheme that supports the user's (programmer's) view of memory. A process is a collection of variable-sized logical segments such as main, functions, stack, heap, symbol table and arrays. A logical address is <segment number, offset>.
🎓 From the lecture Paging cuts a process into equal pages and is close to the OS's view, but far from the user's. Programmers think in modules (main, functions, stack, heap). Those modules are the segments, of variable size. Segmentation matches the user view.

9.33Segment Table and Address Translation in Segmentation

Segment table: one entry per segment, holding base (the starting physical address) and limit (the segment's length). The STBR (Segment-Table Base Register) points to the table and the STLR (Segment-Table Length Register) gives the number of segments.
🎓 From the lecture LA = <s, d>. Use the STBR + s to reach the segment's entry, then check the offset against the limit. If it exceeds the limit, an error occurs. If it is within, physical address = base + offset. Example: base of segment 1 = 1000, offset = 50, so PA = 1050.

9.34Segmentation with Paging

Segmented paging: a process is divided into segments, and each segment is divided into pages. Each segment has its own page table. LA = <segment no., page no., offset>.
🎓 From the lecture Process → segments 0, 1, 2. Segment 0 → pages 0, 1, 2, and so on. Translation: STBR + s gives the segment-table entry, which points to that segment's page table. Then page number gives the frame, and frame + the same offset gives the physical address. It needs a segment table, page tables and frames.
➕ Why combine? It keeps the user view and protection of segmentation and removes external fragmentation through paging. Used by MULTICS and Intel x86 (IA-32). Modern 64-bit OSs (Linux, Windows) set the segments to cover the full space ("flat model") and rely on paging.

9.35Demand Paging and Page Fault

Demand paging: a page is loaded into memory only when it is demanded (first referenced), not in advance. The pager is a "lazy swapper". Page fault: a reference to a page that is not in main memory (its valid / present bit = 0).
🎓 From the lecture
  1. The CPU requests a page. It is not in main memory, so a page fault occurs.
  2. Control switches from the user to the OS.
  3. The OS loads the page from secondary memory into main memory.
  4. Control returns to user mode.
  5. The CPU re-issues the request. Now the page is present, so there is no fault.
This leads into page replacement (Chapter 10).
➕ Textbook steps and the cost
  1. Check the process's internal table (in the PCB). If the reference is illegal, terminate the process. If it is legal but not in memory, page it in.
  2. Find a free frame. If there is none, page replacement chooses a victim (Chapter 10).
  3. Schedule a disk read. The process is blocked meanwhile, and the CPU may run another process.
  4. When the read completes, update the page table (valid bit = 1).
  5. Restart the instruction that caused the fault.
Pure demand paging starts a process with no pages in memory. Benefits: less I/O, less memory per process, more processes in memory, and programs larger than RAM can run (virtual memory).
Numerical (added): effective access time with page faults
EAT = (1 − p) × ma + p × page-fault service time
ma = 200 ns, fault service = 8 ms = 8,000,000 ns, p = 1/1000.
EAT = 0.999 × 200 + 0.001 × 8,000,000 = 199.8 + 8000 = 8199.8 ns ≈ 8.2 µs, which is about 40× slower.
For under 10% degradation (EAT < 220 ns): 200 + 7,999,800 p < 220 → p < 0.0000025, i.e. fewer than 1 fault per 400,000 accesses.
⚠️ Exam trap A page fault causes a trap (a mode switch to the kernel), not a context switch in itself. Replacement is needed only when no free frame exists, not on every fault. A page fault is not an error: it is a normal event in demand paging.

⚡ Rapid Revision — Chapter 9

  • The CPU can't touch the disk directly: a process must be in RAM (volatile). Hierarchy: registers → cache → RAM → disk, with speed falling and capacity rising.
  • CPU utilisation = 1 − pⁿ. Lecture with p = 0.6: n = 1 → 40%, n = 2 → 64%, n = 3 → 78.4%, n = 10 → 99.4%.
  • Contiguous (roll-number seating) vs non-contiguous (sit anywhere). Relocation: PA = base + LA (1000 + 50 = 1050). The limit register checks LA < limit, else trap.
  • Fixed partitioning: fixed number of partitions, no spanning → internal fragmentation (10 MB partition − 8 MB process = 2 MB) and a size limit (50 MB can't fit in a 30 MB maximum).
  • Variable partitioning: exact-size partitions → no internal fragmentation, but external fragmentation (5 + 10 MB free, 15 MB process can't fit). Compaction fixes it but is expensive.
  • Placement (holes 5, 10, 15): first fit 4 MB → 5; next fit 8 MB → 10 (after the last allocation); best fit 9 MB → 10; worst fit 9 MB → 15. First fit is fastest; worst fit is generally poorest.
  • Paging: page = frame size. Lecture: 16 B process, 4 B pages, 32 B RAM → 4 pages, 8 frames; PT = {0→1, 1→3, 2→5, 3→7}. Byte 5 = (p 01, d 01) → frame 011 → PA 01101 = 13.
  • LA = p | d; PA = f | d (the offset is unchanged). n bits ⇒ 2ⁿ. One page table per process, stored in RAM, entries = number of pages. PTBR points to it.
  • Numerical: LAS 16 GB → 34 bits; PAS 32 GB → 35 bits; page 16 KB → 14-bit offset; 20-bit page number → 1 M pages; 21-bit frame number → 2 M frames.
  • PTE fields: frame number (mandatory), valid/present, protection (R/W/X), reference, cache-disable, dirty (modified → write back before replacing).
  • Multilevel paging: page the page table (12 KB PT, 4 KB pages → 3 pages in frames 8, 9, 10 plus an outer table). 32-bit with 4 KB pages → 10 | 10 | 12.
  • Inverted PT: one global table, entries = frames, (pid, page) per entry; saves memory but needs searching (use hashing).
  • TLB: fast associative cache of page → frame. EMAT = p(t+m) + (1−p)(t+2m). Maggi dabba = TLB, kirana shop = RAM.
  • Segmentation: variable segments in the user view (thali made to taste). Table holds base + limit; PA = base + d if d < limit, else trap (1000 + 50 = 1050). External fragmentation.
  • Segmented paging: segment → page table → frame (x86, MULTICS). Demand paging: load a page on first use; a missing page causes a page fault, the OS loads it, and the instruction restarts.
