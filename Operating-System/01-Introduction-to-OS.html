Chapter 1

Introduction to Operating Systems

This chapter covers what an operating system is, where it sits in a computer, what it is expected to do and the main types of OS. It ends with the idea that the rest of the subject builds on: a program on disk becomes a process when it is loaded into memory.

1.1Computer System: Hardware and Software

A computer system has two complementary parts:

  • Hardware: the physical mechanical, electrical and electronic components, such as the CPU, RAM, hard disk/SSD, keyboard, monitor, printer and motherboard. You can touch them.
  • Software: a set of programs (instructions plus data) that tells the hardware what to do. You cannot touch it.

Hardware without software is useless, and software without hardware has nothing to run on.

🎓 From the lecture — The car & driver analogy Hardware is like a world-class car with premium tyres, bulletproof glass and a smooth steering wheel. If nobody drives it, it is just a piece of metal. Software is the driver.
  • A "noob" driver (poor software) presses the accelerator instead of the brake and cannot reverse. The hardware's potential is wasted.
  • A "pro" driver ("Fast & Furious") handles the car smoothly and takes it to its peak, optimal performance.
Good software, especially a good OS, gets the most out of the hardware.
➕ Added for exam — Components & related terms
  • Four components of a computer system (Galvin): Hardware → Operating System → Application programs → Users.
  • Basic hardware units: Input unit, Output unit, CPU (ALU + Control Unit + Registers), Memory (primary: RAM/ROM/cache; secondary: HDD/SSD).
  • Firmware: software permanently stored in ROM/flash on the hardware, such as BIOS/UEFI. It sits between hardware and software.
  • Liveware / Peopleware: the human users of the system.

1.2Application Software vs System Software

System software handles the operations of the system itself: managing hardware and providing a platform for other software. The best example is the Operating System.
Application software does an application-specific task for the user, such as a spreadsheet, a DBMS package, a browser or MS Word.
BasisSystem SoftwareApplication Software

⚠️ Exam trap (Translators & utilities) Compilers, interpreters, assemblers, linkers and loaders are system software, not application software. Antivirus and disk defragmenter are utility software, which is a sub-type of system software. Middleware (for example, database connectors and message queues) sits between the OS and applications.

1.3OS as an Interface between User and Hardware

Operating System: system software that acts as an interface (intermediary) between the user and the computer hardware. It manages all hardware resources and gives programs an environment to run in.
🎓 From the lecture — Why not talk to hardware directly? If the user interacted with the hardware directly, the work would be tedious, time-consuming and effort-heavy, and the result would still be poor. Instead, the user goes through someone: the OS. It sits exactly between the user and the system hardware, which is why it is called the interface or intermediary.
➕ Added for exam — Two views of an OS
  • User view: the OS should be easy to use. A PC is designed for convenience, a mainframe for resource utilisation, and a mobile for touch and battery life.
  • System view:
    • Resource allocator / manager: decides who gets the CPU, memory, files and I/O, and when, resolving conflicting requests fairly and efficiently.
    • Control program: controls the running of user programs to prevent errors and improper use of the computer.
  • The OS is also called a virtual machine / extended machine, because it hides messy hardware details behind a simpler abstraction (files instead of disk sectors).

1.3AKernel, Shell and Booting ADDED

The lecture covers kernel/user mode later, under System Calls. The basic terms below are asked often enough in the exam that they belong in the introduction.

TermMeaning
KernelThe core of the OS. It is loaded first and stays in main memory the whole time. It handles process, memory and device management and system calls, and runs in kernel (privileged) mode.
ShellThe outer layer / command interpreter that takes user commands and passes them to the kernel. It can be CLI (bash, cmd, PowerShell) or GUI (Windows Explorer, GNOME).

🎯 IBPS exam alert (Booting)
  • The program that loads the OS is the bootstrap loader. It is stored in ROM / firmware.
  • POST = Power-On Self-Test. BIOS = Basic Input/Output System. UEFI is its modern replacement and supports GPT disks larger than 2 TB and Secure Boot.
  • The MBR (Master Boot Record) is the first sector (512 bytes) of the disk.
  • The kernel is the first part of the OS loaded and stays resident in memory.

🎓 From the lecture — Primary & secondary objective
  • Primary objective: Convenience. The user should feel the task was easy and took no real effort. The OS should be easy to use / user-friendly.
  • Secondary objective: Efficiency. Jobs and processes should run efficiently, with all resources well utilised and in a reliable manner.

Other goals also listed: reliability, security/protection, resource sharing, fairness, minimum response time.

1.5Functions of an Operating System

🎓 From the lecture The OS performs several kinds of management: process management, memory management, file system management, I/O device management, disk management and security. For security it must keep the CIA parameters intact. Otherwise anyone could open any file and read it, which breaks confidentiality. Each management area is covered in its own later module.

1.6Types of Operating Systems

The lecture separates the core types that are asked in detail from the minor types that are rarely asked:

  • Core types (study in detail): Batch, Multiprogramming, Multitasking (Time-sharing), Multiprocessing, Real-Time.
  • Minor types (know with an example): Clustered, Distributed, Embedded.
  • Also asked in exams ADDED: Network OS, Mobile OS, Time-sharing OS (= multitasking), Multi-user vs Single-user OS.

1.7Clustered Operating System

Clustered system: two or more independent computers (nodes) joined by a local network (LAN) that share storage and work together as one powerful system. The OS that manages this cluster environment is the clustered OS.
🎓 From the lecture — "1 + 1 = 11" Connecting many systems unites their power, so "1 + 1 = 11". The cluster no longer behaves like a normal computer. It behaves like a supercomputer and can carry out very heavy, complex computations.
➕ Added for exam — Types & purpose
  • The main purpose is High Availability (HA): if one node fails, another takes over its work (failover). Nodes monitor each other with a heartbeat signal.
  • Asymmetric clustering: one node runs the applications while the other stays in hot-standby mode, only monitoring.
  • Symmetric clustering: all nodes run applications and monitor each other, so resources are used better.
  • Parallel clustering / HPC: many nodes run parts of the same job (e.g. Beowulf clusters, supercomputers).
  • Nodes are loosely coupled: each has its own CPU and memory.

1.8Distributed Operating System

Distributed OS: manages a collection of independent, geographically dispersed computers, each with its own CPU and memory, connected by a network. To the user they appear as a single coherent system.
🎓 From the lecture
  • One system may be in America, another in India, another in Africa, all connected through a network.
  • Load balancing is very efficient: if one system gets too much work, part of it is handed to another node.
  • No single point of failure: control is not centred at one point, so if one node fails, another takes over its work.
➕ Added for exam — Advantages, transparency, examples
  • Four advantages (Galvin): Resource sharing, Computation speed-up, Reliability and Communication.
  • Loosely coupled: no shared memory and no common clock. Nodes communicate by message passing.
  • Transparency: the user should not notice the distribution (access, location, migration, replication, failure transparency).
  • Disadvantages: complex software, network dependency, security risk, hard to keep data consistent.
  • Examples: Amoeba, LOCUS, Mach, Plan 9. Distributed applications include Google search and blockchain.
➕ Added for exam — Remote Procedure Call (RPC)

RPC lets a program on machine A call a function that lives on machine B as if it were a local call; the network details are hidden from the programmer.

  1. Client stub: the client calls a local stub, which marshals (packs/serialises) the parameters into a network message.
  2. Transport: the OS sends the message over the network (TCP/UDP).
  3. Server stub: unmarshals the parameters, converting them to the server's format (e.g. big- vs little-endian, using a standard representation such as XDR), and calls the real function.
  4. Return: the result is marshalled and sent back; the client stub unmarshals it and returns it to the caller.

The client finds the server's port through a binder / matchmaker (portmapper). Java's version is RMI.

1.9Embedded Operating System

Embedded OS: an OS built into a device to perform a specific, fixed, narrow-range set of functions. It does only the job it was designed for and nothing more.
🎓 From the lecture — AC vs washing machine An AC cools and a washing machine washes clothes. Tell the AC to wash clothes, or the washing machine to blow cold air, and neither can do it. You only get a headache. That restriction to a fixed, narrow task is what defines an embedded OS. Other examples: microwave oven, home appliances.
➕ Added for exam — Characteristics
  • Stored in ROM / flash; small footprint; works with limited memory, CPU and power.
  • Little or no user interface; often real-time (many embedded OSs are RTOSs).
  • Examples of devices: digital camera, ATM, car engine control unit, smart TV, smartwatch, IoT sensors, traffic lights.
  • Examples of OS: Embedded Linux, FreeRTOS, VxWorks, Windows IoT (earlier Windows CE), Zephyr.

1.10Batch Operating System

Batch OS: a very old technique. Users do not interact with the computer directly. They hand their jobs to an operator, who groups jobs with similar requirements into batches. The batches are given to the CPU one by one, and each job runs to completion before the next one starts.

Why the CPU sits idle: CPU burst and I/O burst

A job's execution time has two parts: CPU time (computation) and I/O time (reading/writing through I/O devices). In batch OS, when the running job goes off to do I/O, the CPU cannot pick another job, because only one job is allowed at a time. The CPU stays idle.

Numerical: CPU utilisation in batch OS (lecture example) Given: J1 uses the CPU for 1 h, does I/O for 2 h, uses the CPU for 1 h, then does I/O for 2 h.
Step 1: Total time = 1 + 2 + 1 + 2 = 6 h
Step 2: CPU busy time = 1 + 1 = 2 h; CPU idle = 4 h
Step 3: CPU utilisation = busy / total = 2 / 6 = 33.3%
Conclusion: The CPU is idle two-thirds of the time. In the lecturer's words, CPU utilisation "ki band baji padi hai" (is ruined). This is the problem multiprogramming solves.
AdvantagesDisadvantages
  • Good for large, repetitive jobs (payroll, bank statements, billing)
  • Less operator setup time, because similar jobs are grouped
  • Can run unattended, e.g. overnight
  • CPU idle during I/O → low CPU utilisation
  • No user interaction while the job runs
  • No guarantee when the job finishes; turnaround time is very long
  • A job stuck in an infinite loop can hold up the others
  • Hard to debug
➕ Added for exam — Batch-era terms
  • Job = program + data + control instructions, originally on punch cards.
  • JCL (Job Control Language): instructions telling the system how to run the job.
  • Resident monitor: the first rudimentary OS. A small program that stays in memory and automatically moves from one job to the next.
  • Examples: IBM OS/360-era systems, payroll and bank statement generation.

1.10ASpooling, Buffering, Caching & Device Drivers ADDED

SPOOL = Simultaneous Peripheral Operations On-Line. Data for a slow device (e.g. a printer) is first written to a fast disk (spool area/queue). The device then reads it from there at its own pace, so the CPU does not wait for the slow device.
  • Classic example: print spooling. Many documents queue on disk while the printer prints them one by one, and the user keeps working.
  • Spooling lets the I/O of one job overlap with the computation of another. It was an early step towards multiprogramming.

⚠️ Exam trap Driver = software in the kernel; controller = hardware. Spooling is used for devices that cannot interleave jobs (a printer cannot print one line from each of 5 users), so whole jobs are queued on disk.

1.11Multiprogramming and Multitasking (Non-Preemptive vs Preemptive)

Multiprogramming: more than one program is kept in main memory (the ready queue) at the same time. When the running process leaves the CPU, for example to do I/O, the CPU switches to another ready process instead of sitting idle. Goal: maximise CPU utilisation.

The lecture presents this with two "natures" of switching:

  • Non-preemptive (the lecture calls this multiprogramming): the process is never forcibly stopped. P1 runs, then goes to I/O on its own. While it is away, the CPU takes P2 from the ready queue.
  • Preemptive (the lecture calls this multitasking): preemption = forcibly stopping a process. P1 runs for a while and is stopped forcibly, whether it is half done or nearly done. Then P2 gets the CPU, is stopped after the same amount of time, then P3, and so on.
➕ Added for exam — Textbook definitions (use these in descriptive answers)
  • Multiprogramming (Galvin): keeps several jobs in memory and switches the CPU when the current job has to wait. Objective: maximum CPU utilisation. It needs memory management (several programs in RAM) and CPU scheduling (choosing which one runs).
  • Multitasking = Time-sharing: a logical extension of multiprogramming. The CPU switches between jobs so frequently (time slice / quantum of a few ms) that each user can interact with their program while it runs. Objective: minimum response time (interactivity). Example: Round Robin scheduling, UNIX, Windows. Early example: CTSS, MULTICS.
  • Degree of multiprogramming = the number of processes in main memory at the same time.
  • Context switch: saving the state of the current process and loading the state of the next one (details in Process Management).
Numerical: CPU utilisation with multiprogramming
CPU Utilisation = 1 − pn   (p = fraction of time a process waits for I/O, n = degree of multiprogramming)
Given: each process spends 80% of its time waiting for I/O (p = 0.8).
n = 1: 1 − 0.8 = 20%
n = 3: 1 − 0.8³ = 1 − 0.512 = 48.8%
n = 5: 1 − 0.8⁵ = 1 − 0.328 = 67.2%
Conclusion: Keeping more programs in memory lowers the chance that all of them wait for I/O at once, so CPU utilisation rises. Beyond a point, too many processes cause thrashing (covered in Virtual Memory).
⚠️ Exam trap (Lecture shortcut vs textbook) The lecture maps multiprogramming = non-preemptive and multitasking = preemptive. That is a useful intuition. In MCQs, though, remember the goals: multiprogramming → CPU utilisation; time-sharing/multitasking → response time. Every multitasking system is a multiprogramming system, but not the other way round. Neither needs more than one CPU; only multiprocessing does.

1.12Example: Selfie Analogy for Multiprogramming vs Multitasking

🎓 From the lecture — The superstar & selfies A superstar stands outside a cinema hall promoting the film "Selfie" and promises 10 selfies to every fan who bought a ticket. The fans wait in line, which is the ready queue.
  • Multiprogramming (non-preemptive): the star takes all 10 selfies with each person. If a fan's phone gets stuck (password, black camera, dust on the lens), which is an I/O problem, that fan steps aside on their own to fix it while the next fan comes forward. Once fixed, they return. No one is forcibly sent away; the star "respects the fans".
  • Multitasking (preemptive): the star says "only 5 selfies per turn". After 5 they move to the next person, whether or not you wanted 10. That is forcible stopping, or preemption. If you want more, rejoin the line (get rescheduled) for your remaining 5.

1.13Multiprocessing Operating System

Multiprocessing OS: runs on a system with more than one CPU (processor). The CPUs share the same memory and I/O devices, so we add extra processors, not extra memory or I/O. Different processes run on different CPUs at the same instant: true parallelism.
🎓 From the lecture — Benefits
  • Parallelism increases → processing is faster and results come sooner.
  • Improved efficiency.
  • Reliable and fault tolerant: if one CPU is overloaded or goes down, its work can be redirected to another CPU.
➕ Added for exam — SMP vs AMP and key terms
Symmetric Multiprocessing (SMP)Asymmetric Multiprocessing (AMP)
All CPUs are peers; each runs OS tasks and user processesMaster–slave: one master CPU runs the OS and assigns work to the slave CPUs
Better load balancing; more complex OSSimpler; the master is a bottleneck and a single point of failure
Windows, Linux, macOS (all modern OSs)Older systems, some embedded systems
  • Also called parallel systems or tightly coupled systems: shared memory, shared clock, shared bus.
  • Three advantages (Galvin): Increased throughput, Economy of scale (sharing peripherals, power and storage is cheaper than multiple separate systems) and Increased reliability, also called graceful degradation or fault tolerance.
  • Speed-up with N processors is less than N, because of overhead and contention for shared resources.
  • Multicore = multiple CPU cores on one chip. It is faster and uses less power than multiple single-core chips.
  • UMA (Uniform Memory Access) vs NUMA (Non-Uniform Memory Access): in NUMA, each CPU's local memory is faster for it than remote memory.
⚠️ Exam trap (Multi-what?) Multiprocessing = many CPUs. Multiprogramming = many programs in memory on one CPU. Multitasking = many tasks time-shared on one CPU. Multithreading = many threads within one process. Multiprocessing gives true parallelism; the others give concurrency (interleaving) on a single CPU.

1.14Real-Time Operating System (Hard and Soft)

RTOS: an OS where time is the most crucial factor. Tasks have time limits (deadlines), and a result is correct only if it is logically correct AND delivered on time. Delay is not acceptable.
🎓 From the lecture — Time-critical examples
  • Missile launch: there is a timer down to the millisecond. If a step does not happen at its second, the missile can blow up.
  • Car airbag: during an accident the airbag must open in time to protect the face and head. If it opens after the head has already hit, "what bigger joke could there be?" Missing the deadline makes it useless.
Hard vs soft, like personalities: a hard person never bends their principles, whatever happens (very strict). A soft person is flexible ("chal jayega"), comparatively less strict, though not completely relaxed.

In a hard RTOS, usefulness is high until the deadline and then drops straight to zero. In a soft RTOS, missing the deadline does affect usefulness and efficiency, but the decline is gradual, not drastic.

BasisHard RTOSSoft RTOS
DeadlineMust never be missed; strictOccasional miss is tolerable; less strict
Missed deadlineSystem failure / catastrophe; result is uselessPerformance degrades gradually
Storage ADDEDData in ROM / limited memory; little or no virtual memory or secondary storageCan use advanced OS features (virtual memory, etc.)
ExamplesMissile systems, airbags, pacemaker, ABS brakes, nuclear reactor control, flight control, industrial robotsMultimedia/video streaming, online gaming, VR, video conferencing, ATM/railway reservation
➕ Added for exam — RTOS essentials
  • Firm RTOS: a third category. An occasional miss is tolerated, but a late result has zero value and is discarded. Examples: a lost video frame, a stock-trading quote.
  • Key properties: deterministic (predictable) behaviour, minimal interrupt latency, priority-based preemptive scheduling, small kernel, high reliability.
  • RTOS scheduling algorithms: Rate Monotonic (RMS), which gives a shorter period a higher priority, and Earliest Deadline First (EDF).
  • Priority inversion: a low-priority task holds a resource that a high-priority task needs. It is fixed by priority inheritance; the Mars Pathfinder case is the famous example.
  • Examples of RTOS: VxWorks (used on Mars rovers), QNX (cars), FreeRTOS, RTLinux, LynxOS.
🎯 IBPS exam alert (RTOS) "Which OS is used in a pacemaker / missile / ABS?" → Hard real-time OS. "Video streaming / online game?" → Soft real-time OS. RTOS is judged on predictability and meeting deadlines, not on raw speed or throughput.

1.15Process vs Program

Program: the executable code while it sits in secondary memory (hard disk). Process: a program in execution. When a program is loaded into main memory (RAM) so the CPU can execute it, it takes a new form and a new name: a process.
🎓 From the lecture A program on the disk cannot be executed there. For the CPU to execute it, it must be in main memory. So the program is picked up from secondary memory and placed in main memory, and the program becomes a process. The program is a static / passive entity; the process is a dynamic / active entity, because it is about to execute.
BasisProgramProcess
DefinitionSet of instructions (executable file)Program in execution
NatureStatic / passive entityDynamic / active entity
LocationSecondary memory (disk)Main memory (RAM)
Lifetime ADDEDLong: exists until deletedLimited: created → runs → terminates
Resources ADDEDNeeds only disk spaceNeeds CPU, memory, I/O, files, registers
Control block ADDEDNoneHas a PCB (Process Control Block) with ID, state, program counter, registers
Relationship ADDEDOne program can create many processes (e.g. 3 Chrome windows = 3 processes)Each process is a separate instance
⚠️ Exam trap A process is more than the program code, which is only its text section. A process also includes the program counter, registers, stack, heap and data section. "Process = active, Program = passive" is the most-asked one-liner.

1.16Process Layout in Memory (Stack, Heap, Data, Code)

The skeleton of a process in memory, from high address (top) to low address (bottom):

HeapDynamically allocated memory at run timemalloc()/free() in C, new/delete in C++/Java. Grows upward. Forgetting to free → memory leak.

🎓 From the lecture — The dotted line The dotted line between stack and heap is a fluctuating line that moves up or down as needed. If the stack needs more space, the line moves down. If the heap needs more, it moves up. Stack and heap grow towards each other and share the free space between them. More on the PCB comes in the Process Management module.
Numerical / code: where does each variable live? 
int g = 10;          // DATA (initialised global)
int u;               // BSS  (uninitialised global → 0)
int main() {
    static int s = 5; // DATA (static)
    int x = 3;        // STACK (local)
    int *p = malloc(4*sizeof(int)); // p → STACK, the 16 bytes it points to → HEAP
    return 0;         // main()'s machine code → TEXT
}
Conclusion: local variables and pointers go on the stack, what malloc returns goes on the heap, globals and statics go in data/BSS, and instructions go in text.
🎯 IBPS exam alert "Recursion uses which data structure / memory section?" → Stack. "Dynamic memory allocation happens in?" → Heap. "Global variables are stored in?" → Data section. "Stack grows towards?" → lower addresses (downward).

⚡ Rapid Revision — Chapter 1

  • Computer = hardware (physical) + software (set of programs). Hardware is the car, software is the driver (noob vs pro).
  • System software runs the system (OS, compiler, assembler, loader, drivers, utilities). Application software does user tasks (Word, Excel, DBMS package) and needs the OS.
  • OS = interface / intermediary between user and hardware; also a resource manager and a control program.
  • Kernel = core, always in RAM. Shell = command interpreter. Bootstrap loader in ROM loads the OS (BIOS/UEFI → POST → bootloader → kernel).
  • Objectives: Convenience (primary), Efficiency (secondary), Ability to evolve.
  • Functions: process, memory, file, I/O device, disk management; security (CIA), networking, error detection, accounting.
  • Batch: operator groups similar jobs; one job at a time; CPU idle during I/O; no interaction. Lecture example: 2 h busy of 6 h = 33% utilisation.
  • Spooling (Simultaneous Peripheral Operations On-Line) uses the disk as a buffer for slow devices, e.g. print queue. Buffer = only copy, in transit; cache = redundant copy. Driver = kernel software; controller = device hardware.
  • Multiprogramming: many programs in RAM; switch when a process waits → max CPU utilisation (lecture: non-preemptive). Utilisation = 1 − pⁿ.
  • Multitasking / Time-sharing: forced switching after a time slice (preemptive) → min response time. Selfie analogy: 10 selfies each vs 5 per turn.
  • Multiprocessing: 2+ CPUs sharing memory and I/O; true parallelism; SMP (peers) vs AMP (master–slave); tightly coupled; graceful degradation.
  • Clustered: nodes on a LAN with shared storage ("1+1 = 11" supercomputer); high availability; symmetric vs asymmetric (hot standby).
  • Distributed: geographically dispersed, loosely coupled, own memory; load balancing; no single point of failure; looks like one system. NOS: users know machines are separate.
  • Embedded: fixed, narrow function (AC, washing machine, microwave); ROM; low resources.
  • RTOS: deadlines. Hard: miss = failure, usefulness drops to 0 (missile, airbag, pacemaker). Soft: gradual degradation (streaming, gaming). Firm: late result discarded.
  • Program = static/passive, on disk. Process = program in execution, dynamic/active, in RAM, has a PCB.
  • Process layout (top→bottom): Stack (locals, recursion, grows ↓) · free space (fluctuating line) · Heap (malloc/new, grows ↑) · Data (global/static + BSS) · Text (code).
